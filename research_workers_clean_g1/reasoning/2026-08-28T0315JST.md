## C562 — One boundary observation has an exact antichain-local update rule

For fixed player `i`, retain only:
- `B0_max`: maximal observed zeroes on the upper slice `b(T)=v(T∪{i})`;
- `A1_min`: minimal observed ones on the lower slice `a(T)=v(T)`.

For a new upper-slice zero `z`:
1. if `z ⊆ Z` for some `Z∈B0_max`, it adds no new excluded coalition and the boundary is unchanged;
2. otherwise remove every `Z∈B0_max` with `Z⊂z`, then insert `z`.

For a new lower-slice one `a`:
1. if `A ⊆ a` for some `A∈A1_min`, it adds no new excluded coalition and the boundary is unchanged;
2. otherwise remove every `A∈A1_min` with `a⊂A`, then insert `a`.

The corresponding CNF clauses strengthen monotonically. `z` contributes `C_z = OR_{j∉z} x_j`; if an old `Z⊂z` is removed from the logical antichain, then `C_z` is a subclause of and therefore implies `C_Z`. Likewise `a` contributes `D_a = OR_{j∈a} ¬x_j`; when `a⊂A`, `D_a` implies `D_A`. Hence a persistent decision diagram does not need to delete physically subsumed clauses: it can conjoin only the new stronger clause and preserve exact semantics. Consistent lower-slice zeroes and upper-slice ones do not change this particular upper bound.

This was independently sanity-checked against batch `reduce_maximal`/`reduce_minimal` updates before the preregistered holdout.

## C564 — The boundary-CNF family directly embeds subsumption-minimal monotone CNF

Let a positive monotone CNF over local universe `U` have a subsumption-minimal clause `S`, i.e. `OR_{j∈S} x_j`. Define upper-zero boundary point `Z = U\S`. The clause is false exactly when the chosen coalition `T` satisfies `T⊆Z`, which is exactly the down-set excluded by `Z`. After positive-clause subsumption reduction, clause sets form an inclusion antichain, so their complements form a maximal-zero antichain. With `A1_min=∅`, the boundary CNF is therefore exactly the original monotone CNF.

A generated sanity check (`experiments/coalition_boundary_monotone_cnf_embedding_v0.py`) covered 8,000 random reduced clause families for `m=1..8` and exhaustively checked all 510,000 truth assignments within those cases: **0 mismatches**. This experiment checks the implementation of the algebraic mapping; the mapping itself follows directly from clause falsification = subset of the complement.

This mapping materially sharpens the worst-case scope. Amarilli, Monet & Senellart (`Connecting Width and Structure in Knowledge Compilation`, arXiv:1709.06188) prove that for constant-arity/degree monotone CNFs, OBDD width is exponential in formula pathwidth. Because that formula class embeds into the present boundary family, no variable-order heuristic can eliminate worst-case exponential OBDD growth for this certifier family.

Source: https://arxiv.org/abs/1709.06188

## C565 — Clause-at-a-time incrementality itself has a known worst-case separation

The current persistent update is a bottom-up compilation strategy that repeatedly conjoins one newly informative clause into one main representation. De Colnet, `Separating Incremental and Non-Incremental Bottom-Up Compilation` (SAT 2023), proves that for relevant bottom-up knowledge-compilation languages including OBDD there are CNF classes where some non-incremental bottom-up compilation keeps polynomial-size intermediate representations, while **every incremental core built by conjoining clauses one-by-one becomes exponential**.

Therefore C563 establishes a strong typical-case improvement on the frozen holdout but cannot justify a universal “always update the same core” policy. A future controller should retain an escape action that re-groups/recompiles clauses or changes representation when structural/node-growth signals deteriorate.

Source: https://doi.org/10.4230/LIPIcs.SAT.2023.7

## C566 — Width-aware representation switching is a plausible fallback, not yet validated for rank counts

Capelli, Choi, Mengel, Muñoz & Van den Broeck (2026) introduce Tree Decision Diagrams (TDDs), a canonical OBDD generalization with model counting/enumeration/conditioning/apply, and show that treewidth-`k` CNFs admit FPT-size TDDs where such an FPT bound is impossible for OBDDs. Combined with C564/C565, this argues for measuring boundary-CNF incidence/path width and testing a representation-switch action rather than spending all effort on OBDD variable ordering.

This is only a representation frontier: the current certifier needs exact **cardinality-by-rank** counts, and this pass did not validate an equally efficient rank-count implementation on TDDs.

Source: https://arxiv.org/abs/2604.05537
