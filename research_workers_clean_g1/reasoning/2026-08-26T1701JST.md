## New findings

### C221 — The smallest reachable two-consumer overwrite test can stay inside the real StructuredController runtime
The existing action-runtime test scaffold is already sufficient; a helper-only ledger test is unnecessary. `StructuredController` with `frontier_policy="action_cost_aware_v1"` can be driven by one deterministic/model-like structured generator through three phases:

1. First generation emits one valid `PROPOSE_ARGUMENT` that adds live step `s1` plus its unaligned alignment. This intentionally bumps workspace version and seeds a real live argument step.
2. Second generation emits **two distinct `REFINE_ARGUMENT` proposals in the same provider generation call/batch**. Both actions name `target_step_ids=("s1",)` so the action frontier regards each node as live-state valid, while their payload replacement IDs are `ghost_a` and `ghost_b` (with corresponding syntactically valid unaligned alignments). The reducer therefore finds no replacement hit and returns the same workspace for each.
3. The first no-op leaves workspace version unchanged, so the second same-batch sibling remains valid and is consumed without another generation replacing that batch.

The two proposal payloads differ, so `_make_node` produces distinct deterministic node IDs even though they share branch, obligation, workspace version, and proposal batch. This exactly exercises the reachable C216 path through the normal cache/frontier/controller/executor stack.

### C222 — Current-code integration assertions are now fully specified
For the second generation's `proposal_batch_id=B`, identify the two `action_selected` events of kind `refine_argument` as `N1` then `N2`. Current runtime calls `attribute_proposal_batch` before each reducer execution. Because that helper reconstructs every physical provider event for B with `metadata.action_id=<current node>`, the final serialized `metadata.cost_ledger.events` must show the B provider request/usage/charge events attributed to **N2**, not N1. This is direct end-to-end evidence of overwrite, not an inferred helper behavior.

The result serialization path is explicit: `build_structured_result()` places `state.cost_ledger.to_dict()` at `result.metadata["cost_ledger"]` and `state.proposal_cache_events` at `result.metadata["proposal_cache_events"]`. Therefore the regression test does not require private state access.

### C223 — Post-migration regression oracle is immutable shared physical cost + two consumption edges
After the attribution migration, the same fixture should require:
- physical provider-generation events for batch B remain immutable with no authoritative per-action attribution (`action_id` null/absent is acceptable);
- exactly two append-only `ProposalBatchConsumptionEvent` edges survive for B, one joining B→N1 and one B→N2 in execution order;
- replay/idempotence keys distinguish consumers, e.g. `(proposal_batch_id, decision_id/node_id)`, so the second consumer cannot overwrite the first;
- both action outcomes are `no_effect` with `workspace_version_before == workspace_version_after`.

This preserves the physical fact that one generation cost produced multiple cached alternatives while separately recording which alternatives were actually consumed.

### C225 — A boolean `effect_precondition` is too weak; use a reducer-owned pure structural effect report
The previous frontier called for a pure `effect_precondition(node, workspace)`. Inspection of `apply_decompose` and `ProofWorkspace.decompose` shows at least three materially different outcomes before execution:
- `EFFECTFUL`: reducer is expected to produce a successor under current state;
- `NO_EFFECT`: reducer deterministically returns the same workspace;
- `WOULD_ERROR`: the call is deterministically invalid and can raise before yielding a workspace (e.g. a decomposition child reuses the parent ID or duplicates an active/within-batch child ID).

A separate reimplementation of reducer conditions inside the policy layer would create semantic drift. Prefer a pure reducer-owned `StructuralEffectReport`/preview function that both the reducer and randomized-support builder call. Minimum fields: `status`, stable `reason_code`, and optionally `predicted_workspace_version_delta` (1 for the current successful structural transitions, 0 for no-effect). No model/tool/checker calls or mutations are allowed in preview.

### C226 — Current action-specific preview contract can be derived exactly from reducer semantics
For the currently randomized structural candidate family:

- **REFINE_ARGUMENT**: active branch; alignment specs valid; at least one payload step/alignment replacement ID intersects the live branch; resulting candidate validates. No intersection is `NO_EFFECT`. Invalid resulting candidate is `NO_EFFECT` under current reducer semantics, not an exception.
- **PROPOSE_ARGUMENT**: active branch; payload alignments exactly cover the new step IDs; alignment specs valid; resulting candidate validates. Failure of these reducer guards is `NO_EFFECT`. Importantly, an empty steps+alignments payload can still be semantically effectful today because the candidate's `last_action` changes and the reducer calls `workspace.successor`; filtering it as a no-op would be a separate substrate change and would break epsilon=0 equivalence.
- **CHANGE_REPRESENTATION**: active parent; alignment coverage; valid alignment specs; child branch validates. Guard failure is `NO_EFFECT`. Empty argument+alignment can still fork/supersede today and therefore is `EFFECTFUL` under current semantics.
- **DECOMPOSE**: target branch/current obligation version valid and children nonempty are necessary. Empty children is `NO_EFFECT`. Parent-as-child or duplicate active/within-batch child IDs are `WOULD_ERROR`; preview should also run the relevant graph/child validity checks so randomized support never knowingly chooses a deterministic exception.

### C227 — Baseline eligibility and exploration support must remain different objects
Existing `node_invalid_reason()` is a **frontier-liveness** check: exact workspace version, active branch, matching obligation version, target branch, live `target_step_ids`, and branch readiness. It intentionally does not inspect payload replacement IDs or structural effect. Therefore a learning trace should record separately:
- `baseline_frontier_eligible` / existing frontier+budget membership;
- `structural_effect_report` from the pure preview;
- `exploration_supported`, which for the initial randomized policy is true only for the prespecified safe action kinds whose preview status is `EFFECTFUL`.

At epsilon=0, D0 must still execute its historical top-ranked node even if preview says `NO_EFFECT` or `WOULD_ERROR`; otherwise the instrumentation silently changes the substrate. Any later pruning of baseline no-ops/errors is an explicit separately benchmarked substrate intervention.

### C228 — SemanticRunProjectionV0 needs effect/result fields but not journal mechanics
Before randomized outcomes, add to the semantic projection for each selected structural action:
- selected node/action identity and action kind;
- baseline eligibility/support classification;
- `effect_status` and stable reason code;
- `workspace_version_before` and `workspace_version_after`;
- terminal/checker class where applicable.

Exclude SQLite event IDs, commit timestamps, WAL size, journal flush latency, and other logging-only metadata. Epsilon=0 equivalence should compare the semantic projection, final workspace/proof, selected action sequence, checker/provider call counts, and budget semantics while permitting journal-only differences.

## Falsification / edge cases to lock into tests
1. **False-positive guard:** REFINE action has live `target_step_ids=("s1",)` but payload only `ghost` replacements → frontier eligible, preview `NO_EFFECT`.
2. **Positive refine:** payload replaces live `s1` and candidate validates → preview `EFFECTFUL`; actual workspace version increases.
3. **PROPOSE coverage failure:** a new step lacks alignment → preview `NO_EFFECT`; reducer returns input object.
4. **DECOMPOSE empty children:** preview `NO_EFFECT`; reducer returns input object.
5. **DECOMPOSE duplicate/parent child:** preview `WOULD_ERROR`; randomized alternative support must exclude it before execution.
6. **Representation guard failure:** mismatched alignment coverage → preview `NO_EFFECT`.
7. **Do-not-overfilter current semantics:** empty PROPOSE or empty CHANGE_REPRESENTATION payloads may still alter `last_action`/branch topology and must not be labeled no-effect merely because their mathematical payload is empty.
8. **Preview/reducer parity:** for pure structural fixtures, preview status must agree with actual `workspace.version`/exception behavior. This parity test is the main defense against later reducer drift.
