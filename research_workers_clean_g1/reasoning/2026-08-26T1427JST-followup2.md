## C185 — initial JournalWriter contract is now explicit enough to implement

Pseudo-contract around the existing CSSC `select_admissible_action` boundary:

```text
selection = select_admissible_action(frontier, frozen_budget_snapshot)
if selection.node is None: stop as today

decision_id = new stable id
payload = canonical_decision(selection, state/workspace/policy/probabilities)
BEGIN IMMEDIATE
  allocate consecutive run_seq values inside this transaction
  insert_idempotent(execution_decision)
  if node.proposal_batch_id is not null:
      insert_idempotent(proposal_batch_consumption)
COMMIT
read back event ids + hashes
if readback mismatch/failure: stop without consuming/executing

node = frontier.consume(selected_node_id)
cache = cache.remove(node_id)
execute_action_node_without_mutating_provider_batch_ledger(...)

outcome = canonical_outcome(...)
BEGIN IMMEDIATE
  allocate next run_seq
  insert_idempotent(execution_outcome)
COMMIT
read back outcome id + hash
if outcome commit/readback fails after effects: stop run; do not select again
```

`insert_idempotent` behavior:

1. normal absent id -> INSERT;
2. primary-key collision -> fetch by `event_id`;
3. if **all immutable identity/order/type/schema fields and canonical payload hash/bytes match**, return duplicate-identical without mutation;
4. otherwise raise `JournalConflict` and stop collection.

Never use `INSERT OR REPLACE`, UPSERT that performs UPDATE, or delete/reinsert because those defeat append-only provenance.

## C186 — v0 recovery policy should not resume a randomized run across an unmatched decision

Operational simplicity is valuable before OPE collection. On opening an existing `run_id`:

- parse and validate the complete event sequence first;
- if the last decision is matched by a valid outcome, a continuation is structurally allowed;
- if the last decision is unmatched, classify it `censored`, seal that run as truncated, and **do not reselect or re-execute inside that run**;
- start any later independent attempt under a new `run_id`.

This sacrifices some compute after a crash but prevents accidental duplicate effects and prevents a recovery heuristic from changing the logged behavior distribution after seeing a censored event. More sophisticated exactly-once/resume semantics can be a later version with explicit durable effect receipts.

## C187 — JournalReader finite-state machine

Per run, after generic schema/hash validation:

```text
READY
  execution_decision -> PENDING(decision_id, selected node, optional expected batch)

PENDING
  proposal_batch_consumption with exact same decision/node/batch -> PENDING_BOUND
  execution_outcome with exact same decision -> READY + emit matched transition
  end-of-run -> emit censored behavior decision and seal truncated run
  another execution_decision -> INVALID
  wrong decision/batch/outcome -> INVALID

PENDING_BOUND
  execution_outcome with exact same decision -> READY + emit matched transition
  end-of-run -> emit censored behavior decision and seal truncated run
  any new decision or mismatched join/outcome -> INVALID
```

Additional invariants:

- run_seq must be exactly monotonically increasing by one within each run for v0; gaps indicate missing/corrupt evidence and invalidate transition reconstruction;
- `execution_outcome` cannot exist without a prior decision;
- generated proposal decision with non-null selected batch id must have the batch-consumption join before outcome;
- deterministic/non-model proposal decisions must not fabricate a batch join;
- canonical choice-set order and exact mu vector must be present in the decision itself, not fetched from mutable later state;
- for every effective legal candidate `mu>0`, chosen node is in the pool, and exact rational probabilities sum to 1.

## C189 — cost joins must distinguish sunk pre-decision cost from selected execution cost

For Stage-A selector learning, proposal generation/retrieval/model-routing cost is already paid before the action choice. Therefore action-value training must not copy the full provider-batch charge into each sibling action.

Recommended evidence views:

1. **Run cost view:** includes all provider generation/retrieval/checker/assembly spend exactly once and is the authority for end-to-end policy efficiency.
2. **Decision execution view:** joins `execution_outcome.ledger_event_ids` produced strictly after decision commit/selection to estimate the marginal execution cost of the selected action.
3. **Proposal provenance view:** immutable provider batch cost joined many-to-many to the generated candidate nodes/decisions for attribution analysis, but never summed per sibling as though independently incurred.

A Stage-A learned selector can be trained on post-decision marginal cost while final evaluation still uses full run cost. If the deterministic provider pilot shows most cost is sunk before selection, that is evidence to move the learning boundary upstream rather than falsely credit Stage A with cost it cannot control.

## F0–F7 executable hook placement against current CSSC source

- **F0**: immediately before JournalWriter begins decision transaction.
- **F1**: after decision row INSERT (and before any batch row/COMMIT).
- **F2**: after decision(+batch) COMMIT/readback, immediately before `frontier.consume`.
- **F3**: generated-proposal case after same-transaction batch binding readback, before consume/action dispatch. (F2/F3 may be adjacent in implementation but stay distinct assertions.)
- **F4**: after `frontier.consume/cache.remove`, before `execute_action_node`.
- **F5**: after the first real checker/tool/workspace-changing effect inside execution, before outcome transaction.
- **F6**: after outcome INSERT before COMMIT.
- **F7**: after outcome COMMIT/readback before loop returns to selection.

Expected policy-data outcome remains as specified in the predecessor: F0/F1 no decision/no action; F2–F6 unmatched censored decision if committed; F7 one matched transition. In production, the reader does not infer effect/no-effect from which test hook was used; only controlled tests know the injection boundary.
