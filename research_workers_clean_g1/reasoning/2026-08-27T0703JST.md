## C452 — Tier-0 is now an explicit versionable generator language, not only a prose feature list

Current Regorus main observed for public-source inspection: `39f535e91392bc77a5f8367e35466be2366a2738`. Its parser and AST expose the exact constructs needed for a deliberately narrow common-intersection generator: strings, booleans, null, variables, static refs, equality/inequality, `:=` assignment and complete-rule assignment. In Rego-v1 mode, `if` is required before a rule body, while an assignment-only complete rule is valid. Regorus also rejects shadowing `input`/`data` with `:=` in v1.

A first generator schema can therefore be frozen as follows before any outcomes are observed:

```text
Module ::= "package fuzz\n" Rule
Rule   ::= "r := " Expr
         | "r := " Expr " if {\n" Stmt+ "\n}"
Stmt   ::= Local ":=" Expr
         | Expr "==" Expr
         | Expr "!=" Expr
Expr   ::= String | "true" | "false" | "null"
         | Local
         | Ref
Ref    ::= "input" Path | "data" Path
Path   ::= ("." Field)+
```

Generator invariants:
- Rego v1 is explicitly selected on every route.
- Exactly one package `fuzz`, one complete rule `r`, and one entrypoint `data.fuzz.r`/route-equivalent path.
- Local identifiers are fresh lowercase safe identifiers, assigned exactly once with `:=`, and every use is dominated by the assignment.
- Direct `=` unification is excluded from Tier-0; only `:=`, `==`, and `!=` are generated.
- No imports, default/else, partial set/object rules, functions, calls, builtins, `with`, comprehensions, `not`, `some`, `every`, membership, arithmetic, or numbers.
- Policy expressions use only string/bool/null plus statically rooted `input`/`data` dot refs. Initial input/data are finite JSON objects with string-safe keys and string/bool/null leaves; arrays/sets are deferred.

This is intentionally smaller than Regorus or OPA can execute. The purpose is to maximize the semantic intersection and make route-support decidable before evaluation.

## C453 — Brown thesis evidence narrows the formal-model intersection and justifies keeping Tier-0 smaller than the executable routes

The Brown Rego formalization thesis models null, bool, strings, arrays, sets and objects and uses a `Nat`-based number model, while explicitly noting that the numeric model does not faithfully match production Rego. Its examples and semantics cover local assignment with `:=`, comparison/equality, and references/object fields. The thesis also states important gaps: imports are not generally handled by its compiler except keyword-related cases, `with` and comprehensions are poorly supported, the standard library is incomplete, and numbers are inaccurate relative to production Rego.

Therefore Tier-0 should keep numbers/arithmetic, imports, `with`, comprehensions and builtins out entirely. It should also avoid direct unification in the first campaign: bind locals explicitly with `:=` and compare already-bound values with `==`/`!=`. This does not prove that the Brown translator accepts every Tier-0 generated case: the exact published source location `https://git.sr.ht/~jakob/rego-proofs` remains source-known but unread through the current transport. Until source readback succeeds, Brown route support is thesis-backed only, not implementation-backed.

OPA's v1 AST defaults to Rego-v1, and the build path documents `wasm` as a target that emits WebAssembly modules for specified entrypoints. The campaign should nevertheless set Rego-v1 explicitly and version the exact compiler route.

The exact-artifact adapter must:
1. compile the frozen policy/data with `opa build -t wasm -e fuzz/r` or an equivalent pinned API;
2. extract the actual `policy.wasm` bytes;
3. persist a SHA-256 digest of those bytes plus the OPA commit/version and build options;
4. load those exact bytes into an OPA-Wasm-compatible runtime/SDK;
5. provide the same frozen data and input as the topdown route;
6. persist runtime version and raw/canonical output.

This distinction matters because the open OPA issue `#8124` documents that `opa eval -t wasm` is not a trustworthy way to execute an already-compiled Wasm bundle as an immutable artifact: that path can attempt compilation again. Therefore source-level `-t wasm` evaluation must not be counted as exact emitted-artifact evidence.

## C455 — Canonical outcome projection can be made route-independent for Tier-0

Regorus has an explicit `Value::Undefined` variant for absence of a value. OPA-Wasm's documented ABI-level result convention represents an undefined decision as an empty assignment/result set and a defined decision as an assignment containing `result`. This gives a clean projection that can be frozen before generated execution:

- `DEFINED(v)`: successful route result with canonical value `v`.
- `UNDEFINED`: Regorus `Value::Undefined`; OPA topdown zero-result/undefined decision; OPA-Wasm empty assignment set.
- `ERROR(class)`: parse/compile/evaluation/runtime failure, mapped to a versioned semantic error class while retaining raw diagnostics.
- `UNSUPPORTED(reason)`: emitted only by the frozen pre-execution route-support predicate; a runtime failure must never be relabeled unsupported after the outcome is known.

For Tier-0, successful values are only string/bool/null, so canonical equality is exact and no set/order/numeric projection is needed. If object-valued outputs are later admitted, object keys must be canonicalized before comparison.

## C456 — Executable support predicates and shrinking rules can now be frozen independently of results

The four executable routes are OPA topdown, exact OPA Wasm, Regorus interpreter and Regorus RVM. A Tier-0 case joins a route comparison only if a deterministic pre-outcome support check proves all of the following:

- generator schema/version is the frozen Tier-0 version;
- Rego mode is v1;
- only the allowed node kinds/operators occur;
- builtin set is empty;
- exactly one complete rule/entrypoint exists;
- every local is bound once before first use;
- refs are static dot paths rooted only at `input` or `data`;
- policy/input/data values stay in the frozen scalar/object domain;
- Regorus RVM execution is run-to-completion, no host-await, exactly one entrypoint;
- exact OPA-Wasm route has a persisted emitted-artifact digest and runtime identity.

Regorus already contains a near-ready matched adapter: its RVM test harness builds one `Engine`, compiles the same policy and entrypoint, evaluates with the ordinary interpreter, compiles to `Program`, checks program serialization round-trip, executes it in `RegoVM` with the same data/input, and normally requires interpreter and RVM results to agree. This should be reused rather than inventing a new semantic boundary.

A mismatch shrinker must preserve Rego version, allowed AST class, empty builtin set, route-support membership, bind-before-use, scalar domain and canonical outcome semantics. Safe initial shrink operations are: delete a trailing statement only when dependency closure remains valid; replace a reference leaf with a frozen scalar; remove unused input/data fields; simplify the head expression; shorten a static path only when the new path remains supported. Crossing out of support is not a valid minimized witness.
