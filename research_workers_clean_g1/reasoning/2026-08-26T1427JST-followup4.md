## C196 — typed event records should carry semantic identity, exact policy probability and immutable provenance, not arbitrary runtime objects

Recommended source-level records:

```text
ExactRational
  num: int >= 0
  den: int > 0
  invariant gcd(num,den)=1

DecisionChoice
  d0_rank: int
  node_id: str
  branch_id: str
  obligation_id: str
  action_kind: enum/string
  supported_by_logging_policy: bool
  behavior_probability: ExactRational        # 0 for recorded-but-unsupported legal actions
  estimated_execution_cost: canonical cost snapshot
  budget_admission: canonical admission snapshot
  proposal_batch_id: str | null
  proposal_source: controlled/model/cache metadata class, no free-form hidden reasoning

ExecutionDecisionRecord
  schema_version
  journal_protocol_id
  run_id / task_id / decision_id / decision_index
  frozen_code_revision / feature_manifest_digest / cost_estimator_version
  workspace_version_before
  policy_id / policy_version / epsilon ExactRational
  rng_algorithm_version / sampled_pool_index when randomized
  choices: ordered tuple[DecisionChoice]
  supported_pool_size / legal_but_excluded_count
  selected_node_id / selected_action_kind
  chosen_propensity ExactRational
  budget_snapshot
  pre_decision_cost_ledger_event_count + optional immutable ledger digest

ProposalBatchConsumptionRecord
  schema_version
  run_id / decision_id / node_id
  proposal_batch_id
  provider request/source ids or immutable batch digest if present
  no copied token/charge total that could be double-counted

ExecutionOutcomeRecord
  schema_version
  run_id / task_id / decision_id
  selected node/action identity
  workspace_version_before / workspace_version_after
  execution_status
  verifier/check category and accepted flag when applicable
  local_verified_progress fields separately
  terminal_verified_success separately
  post_decision_ledger_event_ids or [start,end) boundary + immutable digest
  stop_reason / terminal_reason
  final_assembly_executed: bool

JournalAck
  committed: bool
  event_ids
  canonical_hashes
  readback_valid: bool
```

The decision record must be derivable entirely before action execution. The outcome record must not repeat mutable representations of the choice set or behavior probability.

## C197 — not every F0–F7 injection belongs inside the journal; split journal faults from controller/executor faults

A realistic deterministic test harness should expose:

```text
FaultingDecisionJournal:
  F0 before decision transaction
  F1 after decision INSERT before decision COMMIT
  F6 after outcome INSERT before outcome COMMIT

ActionRuntimeFaultHooks (test-only):
  F2 after decision ack/readback before consume
  F3 after batch-binding ack/readback before consume/dispatch
  F4 after consume/remove before execute_action_node
  F7 after outcome ack/readback before next selection

Fake adapter/tool/executor hook:
  F5 after first observable action effect/check before outcome transaction
```

Trying to force all failures through one journal class would test the wrong boundaries. Production code needs only the journal injection; the extra runtime hooks can remain test-only callbacks/subclass overrides.

## C198 — reader property/fuzz corpus is finite and high-value

Start with a valid matched one-decision run and a valid censored one-decision run, then systematically mutate:

- delete decision, batch link or outcome;
- duplicate each event exactly;
- duplicate with same id + changed payload;
- swap event order;
- create run_seq gap/duplicate;
- orphan batch link/outcome;
- wrong decision id/node id/batch id;
- two outcomes for one decision;
- second decision while first remains pending;
- generated-proposal decision missing required batch link;
- deterministic proposal with fabricated batch link;
- chosen node absent from choice set;
- chosen propensity differs from selected choice probability;
- negative/zero denominator/non-reduced rational;
- behavior probabilities do not sum exactly to 1 over the supported pool;
- selected action has zero support;
- pool size/protocol id incompatible with frozen epsilon-v0 rules;
- payload bytes/hash mismatch;
- unknown schema/protocol version.

Expected classes are only `valid_matched`, `valid_censored`, or `invalid`; do not create a permissive repair class in v0. Exact duplicate replay is normalized before state-machine traversal and remains idempotent.

## C199 — provider-batch migration can probably be global rather than OPE-only, because current cost summary has another attribution path

At the pinned source:

- run-level authoritative provider usage/charge is already in the cost ledger;
- branch/obligation cost summary uses `model_usage` entries tagged with `structured_branch_id` plus attempts;
- `attribute_proposal_batch` is not needed by that cost-summary computation.

Therefore the cleaner migration is likely:

1. delete/retire historical event rewriting in `attribute_proposal_batch`;
2. keep provider request/usage/charge metadata immutable from creation;
3. add append-only proposal-batch consumption records for causal attribution;
4. retain `model_usage` branch tags for backward-compatible branch summary until a later unified projection replaces them;
5. add regression tests that existing run/branch cost totals are unchanged for one-proposal runs and shared-batch run total is counted once.

Before implementation, scan all public tests/callers for consumers that explicitly expect provider ledger `metadata.action_id`; none were identified in the inspected core cost-summary/test paths, but absence is not yet proven repository-wide.

## C200 — randomized-policy reader must retain unsupported legal candidates without pretending they had positive probability

For epsilon-v0, the decision event should distinguish:

- hard-illegal/budget-rejected candidates;
- effective legal candidates included in top-5 randomized support (`mu>0`);
- legal-but-excluded candidates below rank 5 (`mu=0`, explicitly unsupported).

This lets later diagnostics answer whether the support cap is excluding important choices. But ordinary IPS/DR target evaluation remains restricted to actions with positive behavior probability. The presence of an excluded legal candidate in the record is observational metadata, not overlap.

## C201 — exact semantic projection should be implemented as a pure normalization helper and snapshot-tested

Rather than comparing ad hoc assertions across many tests, define a test-only/public-evaluation helper that maps `ControllerResult` to a canonical JSON-like semantic object. It strips unique run id, temp-path prefixes, wall/CPU/elapsed values and journal artifacts; it retains proof/action/workspace/budget/token/charge/checker/provider semantics specified in C192.

Then:

```text
assert semantic_projection(run_null_journal_eps0)
    == semantic_projection(run_sqlite_journal_eps0)
```

for all deterministic fixtures. Store the projection schema/version with the experiment so a later code change cannot silently weaken the equality oracle.
