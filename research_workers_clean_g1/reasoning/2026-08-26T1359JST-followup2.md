## New findings

### C129 — the exact raw-vs-effective budget mismatch already has a focused regression fixture

`tests/test_action_frontier.py::test_constrained_selection_skips_rejected_higher_ranked_action` constructs two ranked actions where the top action is rejected by raw API-cost admission. With budget enforcement on, the lower-ranked admissible action is selected and the first choice row is `allowed=false`. The same test then disables remaining-budget enforcement and verifies that the previously raw-rejected top action is selected while the returned effective admission is synthetic `allowed=true` with `remaining_budget_policy_disabled`.

This is the ideal fixture to extend for causal logging. New assertions should require a serialized decision row to preserve simultaneously:

- top action raw admission = false;
- top action effective runtime eligibility = true when policy is disabled;
- deterministic baseline = top action under disabled policy;
- experiment pool membership independent of raw admission.

No new artificial budget test case is needed for this semantic distinction.

### C130 — trace-store tests show atomicity exists but idempotence deliberately does not yet exist

`tests/test_trace_store.py` already has two useful anchors:

1. `test_atomic_append_preserves_old_file_when_replace_fails` proves the temp-file + fsync/replace path preserves the old file on installation failure and cleans the temp file;
2. `test_jsonl_trace_store_appends_events` intentionally appends the same complete result twice and expects duplicate rows.

Therefore `append_event` should not silently change the semantics of existing `append_result`. Decision-event idempotence should be scoped specifically to events carrying stable `event_id`. A clean API is:

- `append_result`: existing summary behavior unchanged;
- `append_event`: stable-id event append with duplicate lookup/reject-or-byte-identical semantics;
- optionally `append_events`: atomic batch of individually idempotent events.

Regression tests belong in `test_trace_store.py` and should cover identical replay, conflicting duplicate payload, replace failure, and an unmatched durable decision surviving a simulated later crash.

### C131 — an existing end-to-end action-runtime test is a strong epsilon=0 instrumentation-equivalence control

`tests/test_structured_controller.py::test_action_frontier_runs_real_controller_and_writes_ledger` already checks the action-cost-aware runtime end to end: accepted proof, exact frontier policy, exactly one selected action, selected choice identity, observed execution checks, assembly separated from action cost, checker event sequence `[candidate, assembly]`, reconciled ledger, and zero provider model calls for the controlled proposal.

Instrumentation should first run this exact fixture with a recording sink and assert all existing behavioral/cost assertions remain unchanged, while additionally verifying `decision -> [optional batch consumption] -> outcome` event order. This is stronger than a synthetic unit test because it detects accidental mutation of selection, budget use, checker count or assembly accounting.

### C132 — the first learned Stage-A state can be substantially smaller than the lossless trace and smaller than the existing text-heavy `EncodedProofState`

The generic `EncodedProofState` contains raw `proof_prefix`, error message and raw goal strings. These are useful for model prompts but are poor default features for a small causal selector: they are large, lexical, task-identifying and can make offline generalization depend on text memorization.

CSSC already computes replay-stable structured signals that are better aligned with Stage-A selection:

**Decision/global features**
- normalized/explicit unified budget statuses and remaining ratios;
- counts of active/open/accepted obligations, accepted facts and active branches;
- current workspace version/depth statistics;
- recent diagnostic-category counts/streaks, not raw messages.

**Target branch/obligation features**
- `depth_from_root`;
- `attempt_count` and `local_attempt_count`;
- `stalled_streak`;
- count/change indicator for latest goal fingerprints, with fingerprints used for equality/history but not necessarily exposed as categorical IDs;
- `unlock_value` / dependent count;
- `progress_likelihood`;
- `information_gain`;
- root/accepted-neighbor/readiness indicators.

**Candidate features**
- typed action kind/effect class;
- proposal source and model tier;
- proposal score only if its generation semantics are frozen with the substrate;
- rank index and deterministic priority components;
- estimated cost dimensions, estimate source/sample count/version;
- raw budget admission, effective runtime eligibility and experiment eligibility.

Start without task ID, raw theorem/proof text, raw compiler message or raw goal text. A text/embedding augmentation can be a later ablation, not a hidden default. This cleanly separates a compact selector experiment from a second prover-language model.

### C133 — OPE readiness should be gated by measured overlap/support, not just by having logged propensities

For every candidate target policy, report at minimum:

- decision count and randomized-decision fraction;
- support/coverage by action kind and effect class;
- minimum/quantiles of nonzero behavior propensity for actions receiving target-policy mass;
- fraction of target-policy probability mass on zero-support actions/states;
- importance-weight distribution and effective sample size `ESS=(sum w)^2/sum(w^2)`;
- result stratification by benchmark/task regime and budget regime;
- fraction of decisions forced to deterministic fallback because the safe experiment pool was too small or excluded the baseline.

If material target-policy mass lies on zero support, do not report a DR/FQE number as if extrapolation were identification. Restrict the evaluated policy to supported actions/states or fall back to the deterministic baseline there. This turns the safety fallback into part of the estimand rather than a post-hoc patch.

### C134 — outcome status and proof outcome must be orthogonal fields

A single `status=failed` would conflate infrastructure/controller failure with a proof attempt that was correctly checked and rejected. Recommended `ExecutionOutcomeEvent` separation:

**execution_status**
- `executed_nonterminal`;
- `executed_terminal`;
- `not_executed_after_decision` (e.g. branch became missing/inactive between durable decision and execution guard);
- `exception_after_decision`.

**proof_outcome**
- `accepted`;
- `rejected`;
- `not_checked`;
- `unknown`.

Include structured `reason_code`, sanitized exception class if applicable, pre/post workspace version/hash, ledger ids and verified-progress deltas. A crash that leaves no outcome event is **not** an outcome status; `censored_no_outcome` is a reader-derived trajectory state based on absence of a matching event.

This preserves the ability to learn proof value without rewarding/penalizing controller infrastructure artifacts as theorem difficulty.

### C135 — removing mutable proposal-batch attribution is not only provenance cleanup; it restores the cost-ledger immutability contract

`action_runtime_ledger.py` creates provider events with batch identity and `action_id=None`, but `attribute_proposal_batch()` later rebuilds the entire `CostLedger`, replacing matching events' metadata with the latest node's action id. The core `CostLedger` is otherwise specified as append-only/immutable-event accounting.

Therefore append-only `ProposalBatchConsumptionEvent` is architecturally better aligned with the existing ledger model than the current replacement helper. A regression should assert that two consumptions of the same batch do not change any existing provider event's canonical serialization or reconciled total; only two join events are added outside the charge ledger.

A useful implementation boundary is to keep proposal-batch consumption in the causal decision trace rather than the monetary `CostLedger`, because the join carries no new resource consumption. This avoids teaching reconciliation code about zero-cost relational events.

## Updated synthesis

The research risk has shifted from feature availability to **causal hygiene**: exact production eligibility, durable propensities, censored-run retention, immutable shared-cost provenance, and supported-policy evaluation.

The most conservative first model should therefore be deliberately small and text-free. It can operate on the existing frontier/workspace/budget/cost signals while the full lossless event trace remains available for audit and later feature ablations. This keeps the experiment about control/allocation rather than silently adding a second semantic model.
