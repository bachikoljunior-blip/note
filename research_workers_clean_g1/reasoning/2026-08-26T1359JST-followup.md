## New findings

### C121 — budget logging should preserve the exact frozen snapshot plus raw candidate admissions; do not duplicate budget semantics into a second ad-hoc schema

`UnifiedBudgetSnapshot.to_dict()` already exposes the complete selection-time budget state across model requests, input/output/billed tokens, checks, wall time and API cost, including limit/spent status, remaining amount/ratio, obligation soft-budget context and global reserves. `BudgetAdmission.to_dict()` already expresses each candidate comparison as `allowed`, `rejected_dimensions`, and `not_compared_dimensions`.

Therefore the decision event should store the exact `budget_snapshot` once and each candidate row's raw `budget_admission`; any learning feature projection should be derived downstream. Duplicating per-dimension remaining values into the candidate row risks drift between two representations of the same frozen decision boundary.

### C122 — raw budget admission and *effective* runtime eligibility diverge when `remaining_budget_policy=false`

This is a subtle but important causal-logging issue. `select_admissible_action()` always computes a raw `BudgetAdmission` for every ranked node and places it in `choice_set`. However, when `enforce_remaining_budget=False`, selection ignores that raw admission and chooses the first ranked node anyway; the selected admission is then replaced by synthetic `BudgetAdmission(True, (), ("remaining_budget_policy_disabled",))`.

Consequently a current `choice_set` row can say `budget_admission.allowed=false` even though the production selector is permitted to execute that node. An OPE/legal mask inferred only from the row's raw admission would therefore misrepresent the behavior policy.

Required decision fields:

- `remaining_budget_policy_enabled` from the frozen `ActionRuntimeConfig`;
- per candidate `raw_budget_admission`;
- per candidate `effective_selection_allowed` under the *actual* runtime policy;
- selected `effective_budget_admission` exactly as used by the production selector.

The experiment legal mask must bind effective production eligibility, not silently reinterpret the raw comparator.

### C123 — runtime eligibility and experiment eligibility are separate axes and must remain distinguishable

The canonical candidate row should extend the full `ActionFrontierNode.to_dict()` provenance with decision-local fields:

```json
{
  "rank_index": 0,
  "node": {"...": "full ActionFrontierNode.to_dict()"},
  "raw_budget_admission": {},
  "effective_selection_allowed": true,
  "experiment_effect_class": "p0_structural_local",
  "experiment_allowed": true,
  "experiment_exclusion_reason": null,
  "randomization_pool_member": true
}
```

This preserves three distinct states that must not collapse into one boolean:

1. candidate absent from current valid frontier;
2. candidate present but production-runtime ineligible;
3. candidate production-eligible but intentionally excluded from randomized experimentation.

That distinction is necessary both for safe collection and for later support diagnostics.

### C124 — the deterministic baseline must be defined by the exact existing selector semantics, not reconstructed by a learned-data convenience rule

For each decision, `deterministic_baseline_node_id` is the node that the current production `select_admissible_action()` would choose under the frozen runtime config and snapshot. Safe epsilon collection is then a perturbation around that baseline, not a replacement scheduler.

Randomization rule:

1. form the experiment pool from current valid frontier nodes that are effectively production-eligible and experiment-allowed;
2. if the deterministic baseline belongs to that pool and pool size `L >= 2`, use the epsilon mixture: baseline `(1-epsilon)+epsilon/L`, every other pool member `epsilon/L`;
3. otherwise execute the deterministic baseline with propensity `1.0` and record `randomization_skipped_reason`.

In particular, disabling the production remaining-budget policy must not be accidentally reversed by the experiment logger.

### C125 — crash/restart semantics should preserve unmatched decisions as censored trajectories, never as zero reward

Use deterministic per-run event identities such as:

- `<run_id>:execution_decision:<decision_index>`;
- `<run_id>:execution_outcome:<decision_index>`;
- `<run_id>:proposal_batch_consumption:<decision_index>:<node_id>`.

If a crash occurs after a durable decision event but before its outcome, retain the unmatched decision. It represents a censored/truncated trajectory and must not be imputed as failure, zero reward, or zero execution cost. A normal restart should receive a new `run_id`; if same-run recovery is later added, the next unused monotone decision index must be used.

Idempotence rule: a repeated event id is accepted only if the canonical serialized payload is byte-identical to the existing event; otherwise fail closed with an explicit duplicate-conflict error. Silent duplicate appends would corrupt propensities and trajectory length.

### C126 — the least invasive durable-sink plumbing is an optional controller dependency, not task/proposal metadata

`StructuredController.__init__()` currently accepts the prover/runtime dependencies and frozen action-runtime config but no trace or event sink. The smallest clean change is to add an optional narrow protocol/callback such as `decision_event_sink.append(event)` with a no-op default.

The action runtime calls it:

1. after frozen selection and before `frontier.consume` for `execution_decision`;
2. when a shared model-batch proposal is consumed for `proposal_batch_consumption`;
3. after every post-decision path for `execution_outcome`.

A `JsonlTraceStore` adapter can implement this with the existing atomic append primitive. The sink should **not** be smuggled through `ProofTask.metadata` or proposal metadata: that would mix runtime I/O capability with semantic/model-visible task data, create serialization hazards, and make replay fingerprints depend on a nonsemantic callback object.

### C127 — the first provider-enabled collection should stop on a prespecified precision target, not an arbitrary task count

Before Stage-A policy training, collect a pinned pilot under the unchanged deterministic selector and partition reconciled run cost into canonical scopes/categories:

- proposal generation/shared model batches;
- selected execution/checking;
- terminal assembly;
- other/unallocated.

Use task-level observations as the resampling unit, stratify the pilot over task/difficulty regimes where practical, and estimate mean/median cost shares plus bootstrap confidence intervals. Continue in fixed-size batches until a prospectively chosen precision target for the major shares is reached (for example, an absolute 5 percentage-point CI half-width), or report that the budget was insufficient to attain that precision. This recommendation is an experiment-design rule, not evidence about the eventual cost shares.

This prevents a small convenience sample from being mistaken for evidence that post-generation selection has large economic headroom.

### C128 — canonical hashing tests can make provenance/ranking drift machine-detectable with a very small utility

Recommended canonical JSON function:

- recursively JSON-serializable objects only;
- UTF-8 encoding;
- object keys sorted;
- compact separators `(',', ':')`;
- `ensure_ascii=false`;
- no timestamps or process-local object identities in the hashed payload;
- SHA-256 of the exact encoded bytes.

Regression tests:

1. reorder the input candidate rows before set canonicalization: `candidate_set_sha256` stays equal;
2. keep the same candidate set but swap scheduler/rank order: `candidate_set_sha256` stays equal and `ranked_choice_sha256` changes;
3. mutate obligation version, proposal batch/model provenance, budget admission or estimated-cost estimator version: the appropriate hash changes;
4. serialize the same frozen candidate/workspace in separate processes/runs: hash remains stable;
5. canonical duplicate event replay uses the same canonicalizer for byte-identity/idempotence checks.

## Updated synthesis

The instrumentation contract is now close to implementation-complete at the source-design level. The most important correction in this followup is that **budget admissibility is not itself the legal mask**: when the runtime's remaining-budget policy is disabled, raw budget comparison and production execution eligibility intentionally diverge. Causal logs and safe randomization therefore need separate raw-admission, effective-runtime, and experiment-gate fields.

The durable event sink can be added without altering the low-level prover or semantic task inputs, and the existing atomic JSONL primitive is reusable. With idempotent event IDs and unmatched-decision semantics, interrupted runs become valid censored data rather than silently disappearing from the dataset.
