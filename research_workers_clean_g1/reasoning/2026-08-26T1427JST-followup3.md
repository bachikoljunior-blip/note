## C190 — smallest safe code surface is one injected DecisionJournal plus a null implementation

No journal logic needs to enter the prover adapter, proposal generator, reducer, cost estimator or ordinary non-action-runtime controller path.

Proposed interface:

```python
class DecisionJournal(Protocol):
    def commit_decision(
        self,
        decision: ExecutionDecisionRecord,
        batch_consumption: ProposalBatchConsumptionRecord | None,
    ) -> JournalAck: ...

    def commit_outcome(self, outcome: ExecutionOutcomeRecord) -> JournalAck: ...

class NullDecisionJournal:
    # default production behavior before explicit collection enablement
    def commit_decision(...): return JournalAck.noop()
    def commit_outcome(...): return JournalAck.noop()
```

Add an optional `decision_journal` constructor argument to `StructuredController`, defaulting to null. Only `_run_action_runtime` uses it. The SQLite implementation owns canonical serialization, transactions, readback and conflict checks; the controller only passes typed immutable records and refuses to cross an effect boundary when the returned ack is not committed/read-back valid.

For journal-enabled collection, add a frozen `LoggingPolicyConfig` separately from `ActionRuntimeConfig`; do not overload cost-source/budget flags. Epsilon=0 is an explicit logging-policy mode, not absence of journaling.

This layout allows exact A/B tests:

- baseline: NullDecisionJournal + deterministic D0 selection;
- instrumentation arm: SQLiteDecisionJournal + deterministic D0 selection (`epsilon=0`);
- randomized arm later: same SQLiteDecisionJournal + versioned epsilon policy.

## C191 — do not call the existing mutable provider-batch attribution in journal/OPE mode

At the pinned source, `execute_action_node` calls `attribute_proposal_batch` before executing the action. That routine rewrites historical provider ledger event metadata. The clean integration should either:

- remove that call entirely and replace it with append-only batch-consumption evidence, or
- gate it off in journal/OPE mode while retaining it temporarily for backward-compatible non-OPE traces.

Preferred long-term result is immutable provider events in every mode. For epsilon=0 equivalence, semantic/cost equality must be defined against the **corrected immutable ledger projection**, not require reproducing a known provenance-destroying mutation.

A migration test should explicitly show that aggregate run provider cost is unchanged while historical `action_id` mutation disappears.

## C192 — semantic-equivalence projection can be defined field-by-field

For deterministic fixtures, construct a normalization `semantic_projection(ControllerResult)` and require exact equality baseline vs SQLite-journal epsilon=0.

### Include exactly

- `accepted`, `stop_reason`;
- attempts in order: attempt index, candidate proof/edit text, action, parent id, accepted/category, exit code, normalized command excluding temp-directory prefix, parsed feedback message/line/column/unsolved goals/goal fingerprints/state flags;
- budget: checks used, model calls used, remaining checks/calls, exhausted reason;
- run metrics except run-unique id and elapsed seconds: task id, accepted, stop reason, execution mode, attempt actions/categories/acceptance/goal fingerprints/error messages, token counters;
- serialized proof workspace except run-ephemeral file paths/timestamps if any: obligation graph, statuses, branch ids/versions, parent relationships, proof/argument/alignment state, final workspace status/version;
- frontier/action semantics: priority explanations, choice-set ordered nodes, estimated non-time cost dimensions, budget admissions, selected node/action sequence, cache invalidations/fills;
- safety rejections/verdict-relevant fields;
- skipped proposal/decompose/argument/representation/generation-failure semantic fields;
- provider request identity/retry status/model/model-tier/token usage/API charge/pricing source;
- checker/tool semantic events and counts;
- final assembly acceptance/errors and result summary;
- cost-scope totals excluding measured timing dimensions;
- deterministic model/checker call counts.

### Normalize/exclude from exact equality

- `sample_id/run_id` UUID;
- absolute temp/candidate paths while retaining relative role/identity where semantic;
- filesystem timestamps/monotonic counters;
- attempt/check/provider/tool elapsed/wall/CPU time;
- new journal events/ids/hashes themselves;
- journal SQLite file size/checkpoint timing;
- trace-store output path;
- mutable provider `action_id` attribution that C191 deliberately corrects.

### Measure separately, never silently drop

- total run wall-clock delta;
- checker/provider wall-clock delta;
- journal commit latency distribution;
- bytes written / WAL growth / checkpoint overhead.

If an elapsed-time budget is active, it can change search semantics merely because journaling takes time. Therefore the first causal semantic-equivalence fixtures must freeze elapsed-time budget as non-binding/disabled. A separate experiment then quantifies how journal overhead interacts with a real elapsed budget.

## C193 — instrumentation must not perturb RNG or selection order at epsilon=0

The epsilon=0 path should not call a random sampler and discard the result. It deterministically chooses D0 top after constructing/logging the exact pool. This prevents RNG consumption from changing downstream stochastic model calls in experiments that share one process-level RNG.

When epsilon>0 later, use a dedicated logging-policy RNG with a recorded algorithm/version and per-decision draw token/seed derivation. Do not share the generator's sampling RNG. Exact behavior propensity is determined from the frozen policy formula, not inferred from the sampled random variate.

## C194 — F0–F7 tests can be implemented without a real provider, then one provider-backed integration test checks pre-decision cost separation

Unit layer: existing deterministic structured generators are sufficient to test journal ordering, rollback, censoring, action sequence and epsilon=0 equivalence without network/model nondeterminism.

Integration layer: use one controlled/fake provider that emits realistic provider-request/usage/charge metadata and two sibling proposals under one batch. Assert:

- provider batch cost is durably recorded before execution decision;
- decision commits before selected action execution;
- provider events remain unchanged after N1 and N2 consumption;
- the run cost counts the batch once;
- each decision has a distinct consumption join;
- post-selection execution cost contains only new checker/tool/etc. events;
- failure of provider generation before choice produces provider cost but no execution decision.

A live external-model provider is unnecessary for the correctness gate and would make equivalence hard to interpret.

## C195 — current end-of-run JsonlTraceStore remains useful, but it is not the causal journal

The public trace store atomically replaces a complete JSONL file after constructing all result events and has a test that preserves the old file if `os.replace` fails. This is good final-result durability, but it cannot fill the mid-run decision/outcome gap because `append_result` is called only with a complete `ControllerResult`.

Keep it as a human/replay snapshot output. The causal SQLite journal is a separate pre-effect evidence path. At finalization, a trace may include a pointer/digest to the journal, but the trace must not be the sole source for behavior propensities or censoring.
