## C15 — CARTS: diversify tactics inside Lean tree search and debias the value function

Primary source: `CARTS: Advancing Neural Theorem Proving with Diversified Tactic Calibration and Bias-Resistant Tree Search`, ICLR 2025.

Mechanism:
- LLM-generated tactics are frequently semantically/strategically redundant.
- CARTS reorders/rescores tactic candidates using Maximal Marginal Relevance to balance importance and diversity before MCTS expansion.
- A separate bias-resistant value function uses preference modeling plus a valid-tactic-ratio adjustment to reduce false-negative/imbalance/domain-gap effects.

Matched fixed-policy evidence on miniF2F-test (Table 3):
- ReProver-Lean4: BFS 35.7%, MCTS 36.5%, diversified tactic calibration alone 36.1%, bias-resistant value function alone 36.9%, CARTS without adjustment 37.3%, full CARTS 37.7%.
- InternLM2-Math-Plus-1.8B: BFS 38.9%, MCTS 39.3%, diversity 41.0%, value 40.6%, no-adjustment CARTS 41.3%, full CARTS 41.0%.
- StepProver: BFS 48.8%, MCTS 46.7%, diversity 49.2%, value 46.3%, no-adjustment CARTS 49.2%, full CARTS 49.6%.
- ProofNet under fixed sample budgets: ReProver BFS 11.1%, MCTS 11.7%, CARTS 11.9%; StepProver BFS 18.1%, MCTS 18.3%, CARTS 18.8%.

Negative/limiting evidence:
- Components are not uniformly additive: for InternLM2-Math-Plus-1.8B, full CARTS (41.0%) is below CARTS without the adjustment term (41.3%). The authors explicitly describe the adjustment as heuristic and not universally valid.
- CARTS supports one-step tree search in the reported system; the paper lists integration with multi-step search as future work.

Interpretation:
- This closes part of the earlier frontier: Lean has direct evidence that semantic/strategic tactic diversity can improve a tree search with the policy model fixed.
- However CARTS does not perform whole-proof compiler-guided repair of failed branches, so the exact composite `structural diversity + learned repair + restart/repair router` remains open.

## C16 — 3D-Prover: learn tactic semantics from environment transitions, then select a diverse/high-quality subset before execution

Primary source: `3D-Prover: Diversity Driven Theorem Proving With Determinantal Point Processes`, NeurIPS 2025.

Mechanism:
- Learn transition-aware representations from previous proof attempts that predict tactic success/error, execution time, and resulting environment output.
- Use these representations inside a Determinantal Point Process to choose a fixed-K subset balancing semantic diversity and quality before tactics are executed.
- This differs from surface-text diversity: the representation is trained on predicted environment effects.

Quantitative evidence (ReProver, miniF2F-test, Table 2):
- K=8: Top-K 22.4%, Random 19.0%, 3D-Prover 24.4% pass@1.
- K=16: 26.5%, 25.4%, 27.3%.
- K=32: 27.8%, 27.4%, 28.2%.
- Relative gain over Top-K is largest when filtering is strongest: +8.9% at K=8, +3.0% at K=16, +1.4% at K=32.

Repeated-attempt evidence (miniF2F-test):
- At K=8, pass@4 is Random 25.7% vs 3D-Prover 28.6% (+11.3% relative).
- At K=16, 30.2% vs 31.0% (+2.6%).
- At K=32, both 29.8%.

Larger LeanDojo Novel Premises evaluation (2,000 proofs):
- 3D-Prover K=32: 646 solved, pass@1 32.3%.
- Top-K K=32: 626, 31.3%.
- No Filtering K=64: 622, 31.1%.
- 3D-Prover finds more long proofs: lengths 5/6/7 = 40/7/2 vs Top-K 39/6/0 and No Filtering 24/2/0.

Important tradeoff / negative evidence:
- More diversity is not monotonically better for pass@1. In the hyperparameter sweep, increasing the diversity temperature can reduce pass@1; the paper explicitly frames this as exploration-vs-pass@1 tradeoff.
- The advantage shrinks at larger K because less aggressive filtering leaves less redundancy to remove.

Interpretation:
- This provides a concrete, reproducible diversity diagnostic/control primitive: predicted environment transition, error probability, execution time, and semantic response can be used before spending verifier/search budget.
- Along with C12, it weakens static lexical/surface diversity as the preferred gate; realized or learned environment effects are more decision-relevant.
- It also suggests a natural bridge to C6: a future router could score both unexecuted tactic branches (3D-Prover-style predicted transition value/diversity) and already-failed branches (compiler-conditioned repairability) in one budget allocator.

## Frontier update

The earlier frontier `does Lean have structural/semantic diversity integrated with search?` is now partly resolved by CARTS and 3D-Prover.

What remains unresolved and higher-value:
1. **Direct composite:** same Lean prover + same verifier/token/wall-clock budget comparing semantic/structural branch diversification, compiler-guided repair, and their combination, with a router allowed to choose fresh tactic/whole-proof branch vs repair.
2. **Causal gating:** test whether transition-model diversity/error predictions (3D-Prover), tactic entropy (C10), or compiler error class/repairability (C6) predicts the marginal value of diversity vs repair on each state.
3. **Multi-step integration:** CARTS explicitly stops at one-step tree search; look for a multi-step successor or combination with whole-proof/refinement systems.
4. **Compute-normalized comparison:** quantify whether diversity filtering reduces total tactic executions/Lean calls/token generation at equal solve rate, not only pass@1 at nominal search budgets.
5. **Benchmark-audited replication:** repeat the largest claimed deltas on pinned/audited miniF2F/ProofNet variants in light of C13.
