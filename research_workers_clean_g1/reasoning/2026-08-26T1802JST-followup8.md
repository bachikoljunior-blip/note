## C302 — D0 is the first *feasible* ranked node, not necessarily frontier rank 0
`select_admissible_action()` iterates `frontier.ranked()`, computes `BudgetAdmission` for every node against one frozen `UnifiedBudgetSnapshot`, logs every row, and selects the first node whose admission is allowed (unless remaining-budget enforcement is disabled).

Therefore the baseline action for propensity/OPE must be `ConstrainedSelection.node`, not simply the first raw-ranked node. Any randomized wrapper that uses frontier rank 0 as D0 will be wrong when the highest-ranked action is budget-inadmissible.

## C303 — randomization must occur after one frozen budget choice set is computed and before frontier consumption
The clean insertion seam is:

```text
snapshot = unified_budget_snapshot(...)
baseline_selection = select_admissible_action(frontier, snapshot, ...)
behavior_selection = logging_policy.choose(baseline_selection, frozen support annotations, rng)
commit Decision / propensity / full choice refs
consume behavior_selection.node
execute
```

Do not randomize before `select_admissible_action()`: that would let the RNG choose a node whose budget feasibility is not evaluated against the same snapshot as D0. Do not randomize after `frontier.consume()`: that would mutate scheduler state before the behavior action is durably determined.

## C304 — behavior support must preserve the runtime's `remaining_budget_policy` semantics
Each choice row records raw `admit_estimate(...)`. When `remaining_budget_policy` is disabled, D0 may select the first ranked node even if raw admission is false, and the selected effective admission is replaced by `remaining_budget_policy_disabled`.

The logging policy must use the same effective feasibility rule for alternatives:

```text
effective_feasible(node) = raw_admission.allowed OR NOT enforce_remaining_budget
```

Otherwise enabling instrumentation would change which actions can be selected even at epsilon=0 or create a support mismatch between D0 and exploration.

Persist both raw budget admission and effective feasibility/config flag.

## C305 — distinguish baseline-D0 selection from behavior-policy selection in traces and explanations

Do not rewrite the D0 identity after choosing an exploratory action; that destroys the counterfactual baseline label needed for BC/OPE analysis.

## C306 — define a narrow `BehaviorSelectionV0` rather than replacing budget selection wholesale
A minimal immutable wrapper can hold:


It should not own proposal generation, frontier refresh, budget estimation or reducer execution. Keeping these existing mechanisms fixed makes the learned/randomized selector a cleaner causal substitution and keeps epsilon=0 equivalence testable.

## C307 — safe alternatives must be both recovery-supported and effectively budget-feasible
At an eligible state, an exploration alternative enters support only if:

1. its action kind/effect class is in the predeclared Stage-A support;
2. its mechanical transition contract is allowed by the frozen support rule;
3. it is effectively feasible under the same remaining-budget policy/snapshot;
4. its proposal envelope is durably finalized and referentially complete;
5. it is not a duplicate of another semantic proposal/support entry under the frozen identity rule.

The D0 action itself remains the baseline member under C297 semantics; if D0 is not in the verified randomizable action class, the whole state is deterministic D0 rather than randomizing around it.
