## New findings

### C93 — CSSC is already an unusually complete instrumented *heuristic-controller substrate*, so the compact learned-controller experiment can be a policy-replacement ablation rather than a new environment build

Public source: `anetigone/cssc`, especially `agent/search/structured/`, `agent/proof_system/workspace/action.py`, and `docs/development-roadmap.md`.

Source-level inspection shows substantially more machinery than the README-level summary captured previously. The structured mode already has: a versioned `ProofWorkspace`; obligation/branch structure; typed `SearchAction`; action proposal caching; deterministic validity/invalidation; action-level frontiers; unified budget snapshots; cheap/strong model routing; append-only runtime cost ledger; frozen-history cost estimation; per-obligation budget hints; and final traces carrying workspace, priority explanations, action records, cost ledger, and result summary.

Concrete typed action kinds currently include `FORMALIZE`, `DECOMPOSE`, `PROPOSE_ARGUMENT`, `REFINE_ARGUMENT`, `IMPLEMENT`, `REPAIR_IMPLEMENTATION`, `CHANGE_REPRESENTATION`, `ADD_OBLIGATION`, `REVISE_OBLIGATION`, `RUN_CHECK`, `RUN_CAPABILITY_TEST`, and `ASSEMBLE`. Each action identifies a target branch and declares a mutation scope. The validator allows an action to narrow below its action-kind default scope but not broaden it. For example, `REPAIR_IMPLEMENTATION` is restricted to Lean artifact plus alignment surfaces; changing mathematical argument or assumptions requires another explicit action. This gives the search tree an auditable semantic identity for “what changed”.

The action runtime also materializes a concrete, version-pinned candidate set before selection. An `ActionFrontierNode` carries action identity, branch/obligation identity and version, source batch/model tier, workspace version, estimated cost and priority explanation. Cached nodes are deterministically invalidated on workspace-version changes, inactive/missing branches, obligation-version changes, missing target steps or readiness failure. Thus a learned selector can in principle be inserted *above* the existing typed executor while freezing action semantics, checker, retrieval, workspace and cost accounting.

Interpretation: the strongest next experiment does not need to invent a Lean harness from scratch. Replace or wrap the deterministic frontier ranking with a compact typed policy, while holding the rest of CSSC-like substrate fixed.

Scope guard: CSSC is a public engineering project, not evidence that a learned controller improves theorem-proving outcomes. Its current controller remains heuristic/deterministic; implementation richness must not be converted into a success claim.

### C94 — CSSC makes the exact OPE blocker sharper: feasibility exists, but it is distributed across validators/runtime guards rather than exposed as one canonical pre-decision legal-action mask

Public source: `anetigone/cssc` source plus `docs/development-roadmap.md`.

`select_admissible_action(...)` iterates the ranked action frontier and records a `choice_set` containing node id, branch id, action kind, estimated execution cost and per-action budget admission. The selected action is the first feasible item under the deterministic ranking. `budgeted_priority_explanation(...)` also records the selected admission and budget-rejected alternatives. Separately, legality/feasibility is enforced by several layers: action mutation-scope validation, structured-proposal validation, workspace/cache version validity, branch readiness/status, obligation versions, target-step existence, budget admission and execution-time guards.

The project roadmap explicitly lists as an outstanding fair-ablation item: provide explicit `allowed_action_kinds` or an equivalent action mask. Therefore current traces are close to an OPE-ready decision record, but they are not yet a single authoritative `legal_action_mask(s)` over the complete choice universe.

For OPE-ready collection, materialize one canonical decision record *before selection*:

`state_id + workspace_version + candidate_action_ids/kinds + legal_mask + reason_per_illegal_action + budget_admission + deterministic_baseline_action + randomized_safe_subset + full behavior distribution mu(a|s) + chosen_action + mu_chosen`.

Do not reconstruct the legal mask after the outcome, and do not infer hidden probabilities from a deterministic/free-form planner.

Scope guard: distributed validity checks are real safety/feasibility constraints, but the absence of one explicit mask does not mean actions are currently unconstrained. It means policy-learning/OPE instrumentation needs a canonical projection of constraints already present.

### C95 — The cost model is already substantially more rigorous than the value model, creating a clean factorization for a learned-policy experiment

Public source: `agent/search/structured/cost_estimator.py`, action runtime ledger, and frontier-priority code.

CSSC's `CostEstimate` supports a multi-dimensional vector: model requests, input/output/billed tokens, checker calls, checker wall/CPU time and API USD. Runtime events preserve provider requests, usage including cached/reasoning/billed tokens where reported, pricing provenance, observed or explicitly estimated charges, tool calls and wall time. Missing measurements remain unavailable rather than silently becoming zero.

Historical action-cost estimation is deliberately frozen before replay: completed action events are bucketed by model/tier, action kind, imports profile, goal-size bucket, obligation-size bucket, repair state and stalled status. Snapshots are immutable/fingerprinted. The estimator uses a median only after a minimum sample count and otherwise falls back explicitly to a prior with `cold_start`/`insufficient_matching_samples`. It exposes held-out coverage and median absolute error by cost dimension.

By contrast, selection value remains hand-designed. Branch `VALUE_PER_COST_V1` uses a deterministic product of `unlock_value * progress_likelihood * information_gain / expected_cost` with fixed tie-breakers; structured failure-hypothesis tests also use hard action-kind ranking plus confidence.

Interpretation: a high-information experiment can **freeze the existing cost estimator and executor**, then learn only a success/progress value or action advantage. This isolates whether learning the numerator/selection rule helps, without confounding it with better cost measurement.

Candidate arms on the same frozen traces/executor: deterministic current priority; BC imitation; terminal-trajectory advantage weighting; fitted action-value/advantage with verifier-grounded progress; constrained contextual bandit; cost-aware conservative policy with baseline fallback. Compare verified terminal solve and reusable verified progress under the same actual-cost vector.

Scope guard: held-out cost-calibration MAE is not probability calibration of solve/value. A separate value calibration evaluation remains required (Brier/ECE/selective-risk or equivalent where a probabilistic value is claimed).

### C96 — CSSC's external-evaluation infrastructure is close to usable, but no formal controller-outcome claim is yet justified

Public source: `docs/development-roadmap.md`.

The roadmap reports an offline preparation adapter for a public Google DeepMind Lean 4 miniF2F checkout, pinned source/toolchain/dependency metadata, 244/244 split handling, 488 generated single-hole scaffolds, 488/488 real Lean 4.27 eligibility with zero reported infrastructure failure and zero cross-task identifier-reference leakage in its audit, plus a persistent Lean-server benchmark runner and a two-task real-server pilot. However, the formal experiment's model, arms, task ids and repeat counts are explicitly not yet frozen.

The project also states the right causal ablations as open work: compare attempt/terminate, implement/repair, and richer action spaces under the same structured prompt, generator, workspace, frontier and budget; separate action-space gains from cost-aware selection gains and cheap/strong routing gains. Planned main thresholds are accepted-rate non-inferiority plus stable 15–25% token/USD savings, or +3–5 percentage points accepted rate at matched actual cost, with a proposed pre-registered non-inferiority margin near 1 percentage point (up to 2 pp when declared in advance for small samples).

Interpretation: CSSC contributes a ready evaluation blueprint and runner, not positive evidence for the heuristic policy. It is particularly well suited to the matched policy-replacement experiment because the roadmap already acknowledges the required action-mask and causal-ablation gaps.

### C97 — The preserved Leanstral evaluation artifact is more useful for supervised cost/error modeling than previously stated, but its mixed adaptive regimes make naïve OPE especially unsafe

Public artifact: `yidannwang/Leanstral-1-5-results` on Hugging Face (third-party; not official Mistral training data).

The preserved artifact contains generated Lean files, trajectory streams, per-attempt metadata, compilation/SafeVerify logs and problem summaries. Exposed per-attempt metadata includes fields such as attempt index, token budget, exit code, timeout, `compile_ok`, verdict, reason, selected attempt and problem identity. Its own reporting separates fixed-budget attempts from targeted rescue: miniF2F reports four fixed-budget 2M-token trajectories and a later targeted higher-budget rescue; ProofNet reports primary groups plus targeted 16M/32M rescue, with later attempt groups run only on still-unsolved problems.

This means the corpus can support supervised models of diagnostic classes, runtime/cost, proof-state/trajectory representations and per-attempt outcome prediction. But it cannot be pooled as if every state/action were generated by one known stationary behavior policy: later rescue is selected conditionally on earlier failures, budgets differ, and no authoritative per-decision legal action set or exact behavior propensity has been verified.

Scope guard: use fixed-budget primary attempts separately from adaptive rescue. Do not promote third-party evaluation traces to official Leanstral training trajectories, and do not claim unbiased policy value/OPE without a verified logging policy and support.

## Updated synthesis

The most direct falsifiable experiment now looks like this:

1. Freeze a public Lean benchmark split, Lean/Mathlib revision, checker/SafeVerify rule, low-level proposer model(s), prompts, retrieval corpus, structured workspace, action executors and CSSC-style cost estimator.
2. Expose one canonical pre-decision legal action mask and a version-pinned action choice set. Keep typed mutation scopes and executor safety checks authoritative.
3. Collect a Stage-A dataset by randomizing only safe P0/pure-local and bounded deterministic/read-compute E1 decisions around a deterministic heuristic baseline with exact known propensities. E2 persistent writes/caches and E3 terminal/resource commitments remain baseline/gated until idempotency/authorization/exact-once semantics are explicit.
4. Train policies that modify only action selection/value: BC; terminal trajectory AW; fitted sequential action value/advantage; contextual bandit; cost-aware conservative policy. Keep cost estimator and low-level generation/execution frozen.
5. Evaluate on held-out theorem families/repositories/version shifts with verified terminal solve and reusable verified progress versus the full real-cost vector. Report support/coverage and abstain/fallback where behavior support is weak.
6. Only after a supported Stage-A gain, expand randomization to carefully authorized effectful actions and model escalation.

This design directly tests whether a compact learned controller adds value beyond a mature deterministic cost-aware controller, rather than comparing two unrelated agent stacks.

- Do not treat `choice_set` plus budget admission as a complete legal action mask; feasibility is distributed and the roadmap itself lists explicit action-mask support as unfinished.
- Do not treat cost-estimator calibration as solve-value calibration.
- Do not treat miniF2F eligibility/pilot success as controller performance evidence; formal model/arm/task/repeat freezing is still open.
- Do not pool Leanstral targeted rescue with primary fixed-budget attempts for OPE or simple pass@K causal comparisons.
- Do not let a learned policy broaden typed mutation scope; policy selects among actions whose executor-level mutation/safety contracts remain fixed.
