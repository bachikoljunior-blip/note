## C426 — A Lean-verified Datalog certificate checker offers an alternate assurance architecture to fully verifying an optimized policy engine/compiler

Primary source: Tantow, Gerlach, Mennicke, Krötzsch, *Verifying Datalog Reasoning with Lean*, ITP 2025, DOI `10.4230/LIPIcs.ITP.2025.36`.

**Observed.** The work keeps the high-performance Datalog reasoner outside the trusted core and validates individual reasoning results with a Lean 4 checker proved correct against direct formalizations of Datalog semantics. It supports tool-independent JSON proof certificates both as proof trees and as DAGs for succinctness, and evaluates the approach by converting derivation traces from an existing Datalog reasoner.

Source:
- https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.ITP.2025.36

**Inference for the current policy-assurance frontier.** For a suitably formalized Rego/IR fragment, a production evaluator/compiler could emit a derivation/decision certificate and a small verified checker could validate the result against direct semantics. This would not prove the whole compiler/runtime correct, but it could move each accepted authorization decision onto a much smaller trusted checker path. DAG certificates are especially relevant if proof-tree duplication is large.

**Critical limitation.** Rego is not identical to pure Datalog. Host builtins, negation/undefined/error semantics, data/input behavior, recursion restrictions, versions and Wasm-host boundaries require explicit fragment and semantic coverage. The Datalog result is a design precedent, not direct Rego correctness evidence.

## C427 — Datalog optimization/dependency metamorphic testing supplies a concrete randomized oracle family for a scoped Rego differential campaign

Primary evidence:
- Zhang, Wang, Rigger, *Finding Cross-Rule Optimization Bugs in Datalog Engines* (OOPSLA 2024 / arXiv:2402.12863): Deopt compares optimized execution with a constructed reference program that disables cross-rule optimizations; across Soufflé, CozoDB, μZ and DDlog it found 30 bugs, including 13 logic bugs. For 60-rule cases, incremental generation produced 1.17x–31.02x as many valid non-empty tests as naive random generation depending on engine.
- Mansur, Wüstholz, Christakis, *Dependency-Aware Metamorphic Testing of Datalog Engines* (ISSTA 2023): DLSmith found 16 previously unknown query bugs in four engines.
- Mansur, Christakis, Wüstholz, *Metamorphic Testing of Datalog Engines* (ESEC/FSE 2021): queryFuzz found 13 previously unknown query bugs in three mature engines.

Sources:
- https://arxiv.org/abs/2402.12863
- https://doi.org/10.1145/3597926.3598052
- https://doi.org/10.1145/3468264.3468573

**Inference.** A high-value OPA experiment is now concrete: generate Rego programs inside an explicitly supported subset, apply semantics-preserving/metamorphic transformations or deoptimization-style reference constructions where valid, and compare canonical outputs across (1) topdown source evaluation and (2) the exact compiled Wasm artifact through the actual intended Wasm runtime. Preserve exact Rego version, capabilities, input/data, host builtin implementation, strict-error semantics, entrypoint, result canonicalization, compiler SHA, artifact digest and runtime route.

This would add a randomized semantic-testing axis without pretending that one backend is a universally trustworthy oracle. Metamorphic relations can provide independent oracles for transformations whose semantics are established.

## C428 — current best assurance stack is plural: proof/certificates + fixed E2E + randomized differential/metamorphic testing + exact artifact/runtime identity

**Observed/search result.** Targeted searches still did not establish a machine-checked semantic-preservation theorem for the production Rego -> IR -> Wasm chain. OPA's documented/interpreted IR, JSON schema, Wasm ABI and fixed test suites remain useful but are not substitutes for such a theorem.

**Synthesis.** The near-term assurance stack should preserve distinct evidence rather than collapse it:
1. theorem/certificate evidence for explicitly formalized fragments;
2. fixed expected-result E2E suites over exact compiled artifacts;
3. randomized cross-backend differential and metamorphic campaigns with replayable seeds/cases;
4. schema/ABI/interface evidence;
5. exact deployed artifact digest and runtime route;
6. explicit exceptions where source and target semantics intentionally differ.

No one layer is sufficient alone.
