### C602 — The 62% oracle gap is an oracle for *current-target next-attempt quality*, not evidence for a rich multi-action controller

The evaluated v3 control-plane action space is explicitly `A={Attempt, Terminate}`. Every target receives two proof attempts before the first routing decision. At a decision state, the router estimates the chance that **one additional attempt** solves the current target and its generation cost, and selects Attempt iff `q_hat(s) - lambda*c_hat(s) > 0`. Termination abandons the current trajectory and lets the outer data plane move to another breakdown.

The zero-noise oracle replaces trajectory features with the ground-truth success probability of the current target and yields a 62.0% average cost decrease, versus 28.9% for the learned router. This is a strong bound on better *difficulty/next-attempt estimation inside this binary architecture*. It is **not** an oracle over model switching, self-correction, recursive decomposition, retrieval escalation, or repair-vs-restart choices. The paper itself lists these richer actions as future extensions that were not experimentally explored.

Therefore the oracle gap should motivate better state/value estimation, but must not be overread as a measured 62% ceiling for the richer controller frontier tracked here.

### C603 — Verifier-grounded trajectory features transfer better conceptually than raw scale, but cost scope must remain explicit

Current v3 quality features are normalized proof similarity, compiler-error diversity, and attempt count. Its ablation table reports average cost decrease of **28.9%** for all three, **23.6%** for similarity+error diversity, **20.3%** for error diversity+attempt count, **19.7%** for similarity+attempt count, and **13.1%** for attempt count alone; the authors identify error diversity as the most important of the three.

The exact public implementation computes normalized tactic-code similarity across prior attempts, unique-error/total-error diversity, and inverse attempt count in the one-stage logistic configuration. The same repository also contains richer trajectory-oriented feature code (error persistence, structural proof fingerprints, reasoning-uncertainty markers, subgoal repetition, unique failed proofs), but no current paper ablation establishes causal control-plane value for those extra features.

The v3 cost estimator uses average previous-attempt generation cost and measures cost through generated output tokens/SFLOPs while treating Lean compilation as negligible. That scope is legitimate for its experiment but cannot be silently imported into our ROBDD controller or future proof-search systems where verifier execution, state reconstruction, retrieval, or branch materialization may be material. The transferable principle is **trajectory-relative verifier-grounded state + separately modeled action cost**, not the exact cost proxy.

### C604 — VERITAS is a direct formal-proof analogue of the retained-incumbent / optional-challenger architecture

Primary source: Acharya et al., *VERITAS: Verifier-Guided Proof Search for Zero-Shot Formal Theorem Proving*, arXiv:2606.19399v1, 17 Jun 2026, `https://arxiv.org/html/2606.19399`.

VERITAS uses a deliberately conservative two-phase protocol: Phase 1 is a Best-of-N sweep; critic-guided MCTS Phase 2 runs **only on theorems that Phase 1 failed**. The paper states the internal monotonicity property directly: every theorem solved by VERITAS's own Phase 1 remains solved in the final system, because Phase 2 never replaces Phase-1 successes. Its abstract reports 99/244 = 40.6% on miniF2F and attributes additional within-run solves to Phase-2 feedback-guided exploration. Batched Lean validation also amortizes multiple tactic candidates into one verifier invocation.

This is the closest public formal-proof analogue found so far to C592's architecture: **lock in a verified baseline result, then spend optional compute only on unresolved cases**. However, VERITAS uses a fixed Phase-2 search budget rather than learning how much second-stage compute to purchase. Thus it supports the monotone architecture but leaves our sequential value-of-computation question open.

## Updated synthesis

The strongest cross-domain principle is now independently supported by two formal-proof lines:

1. **Cost-quality routing:** failed verifier trajectories contain actionable information for deciding whether one more attempt is worth its cost; current Lean v3 achieves a measured 28.9% cost reduction in its binary Attempt/Terminate setting.
2. **Monotone optional second stage:** VERITAS preserves every own-Phase-1 solve and sends only failures to a richer second-stage search.

Together with C592–C599, this favors a layered design: first obtain/retain a verified incumbent or strong simple-policy result; then expose only unresolved/rejected states to an optional challenger controller; learn incremental continuation value relative to that simple policy; abstain under OOD/uncertainty; and charge the true marginal compute of the optional action. A high AUC or aggregate gain dominated by decisions already made by the baseline is not evidence that the learned layer adds value.
