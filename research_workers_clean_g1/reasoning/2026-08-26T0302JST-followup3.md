## C52 — AxProverBase directly quantifies context-pollution control: a compact self-managed proof notebook beats raw recent-history memory

Primary/public sources:
- `A Minimal Agent for Automated Theorem Proving`, arXiv:2602.24273 (2026-02), with open-source AxProverBase implementation.

Mechanism:
- The agent iteratively proposes a whole Lean proof, receives exact compiler/reviewer feedback, stores selected information in memory, and optionally searches Mathlib/web before the next attempt.
- The memory ablation compares: no memory; the previous `n=5` full attempts (reasoning + code + feedback); and a **self-managed short context** in which the model updates a lab-notebook-like summary of technical insights and prior mistakes after each iteration.
- The paper explicitly motivates this by context growth: full history makes calls slower/more expensive, can degrade model behavior, and eventually exceeds the context window.

Quantitative evidence on the paper's fixed 100-problem PutnamBench ablation subset with Claude Opus 4.5 / 10k thinking budget:
- Both longer-memory variants improve over feedback-only iteration.
- The self-managed context proves **7% more theorems on average** than recent full-history memory while costing **20% less in total**; at an equal number of iterations its cost is **10% lower**.
- Run-to-run dispersion is about **half** that of the full-history variant.
- The paper therefore chooses self-managed memory for its subsequent full-system experiments.

Other controller-relevant evidence:
- Iterative compiler-feedback refinement is the largest architecture ablation; extra iterations show diminishing returns as the prover cycles through repeated mistakes.
- Full-system evaluations still use a fixed maximum of **50 iterations**, so stopping/continuation is not learned.
- Thinking-budget value is strongly model dependent. Gemini 3 Pro shows no significant high-vs-low improvement, Gemini 3 Flash minimal-vs-low is also flat, Sonnet saturates, while Opus improves from 10k to 32k; for Opus the paper reports that the higher thinking budget can match the performance of doubling iterations at materially lower cost.

Interpretation:
- This is direct Lean evidence for **compressed online trajectory sufficiency**: the controller need not carry raw recent transcripts to preserve useful failure history. A model-maintained summary can improve both performance and cost in the tested setting.
- It also gives a concrete context-pollution mechanism: adding semantically relevant history indiscriminately can still hurt because token volume, repeated stale attempts and conflicting local traces compete with the current proof task.
- The future learned controller state should therefore contain compact, updatable sufficient statistics/notes (progress, failure classes, tried lemmas/tactics, unresolved blockers) rather than raw action history by default.
- Thinking budget and iteration count should be treated as **substitutable compute actions with model-specific marginal value**, not independent fixed knobs.

Critical scope / caution:
- The memory ablations use only two runs per variant, and the test subset is 100 PutnamBench problems; the 7%/20% result should not be universalized without replication.
- Self-managed memory is LLM-written and can omit useful evidence or preserve mistakes; it is not a guaranteed sufficient statistic.
- The study does not report probability calibration for when to stop iterating, increase thinking budget, or invoke tools.

Source:
- https://arxiv.org/abs/2602.24273

## C53 — Numina-Lean-Agent is a strong free-form heterogeneous-tool-routing baseline, but hard-case compute/controller escalation remains only weakly controlled

Primary/public sources:
- `Numina-Lean-Agent: An Open and General Agentic Reasoning System for Formal Mathematics`, arXiv:2601.14027.
- Public repositories `project-numina/numina-lean-agent` and `project-numina/Numina-Putnam2025`.

Mechanism:
- A general coding agent autonomously interacts with Lean through MCP and can choose among proof-state/diagnostic inspection, theorem retrieval, code execution, informal proving, discussion/auxiliary reasoning tools and ordinary file/code operations.
- This is important because heterogeneous tool selection is delegated to the base coding agent rather than a handcrafted theorem-specific pipeline or separately trained router.

Direct evidence:
- With Claude Opus 4.5, the system reports Lean-verified solutions for all **12/12 Putnam 2025** problems under sequential execution and with internet search disabled for API calls.
- Public result metadata shows most problems with an approximate **$50** proving budget, but A5 at **$1000** and B6 at **$300**, reflecting dramatically larger effort on difficult cases.
- On Putnam B4, the paper compares equal-call informal-prover strategies: independent sampling fails to complete the formal proof within **10 rounds**, while iterative refinement succeeds in **5 rounds**.
- A5 uses a subagent mechanism intended to isolate a key lemma from an overlong main context; the subagent first obtains an informal hint and formalizes the isolated goal.
- The paper's tool/architecture table reports 4/12 solved without the informal prover, 11/12 with the informal prover, and 12/12 after adding the A5 subagent mechanism. This is not compute-matched across whole configurations.

Important provenance nuance:
- Public Lean-community discussion records an author clarification that the displayed dollar budgets were calculated after the proofs completed rather than selected by an autonomous pre-run difficulty router. The A5 subagent decomposition itself was reported as agent-selected, not a human mid-proof intervention.

Interpretation:
- Numina is a valuable **behavioral baseline for free-form tool routing**: a capable coding agent can choose and combine heterogeneous formal tools without a separately trained controller.
- But its hard-case budget pattern is not evidence of an automatic value-of-computation policy. A controller should predict difficult cases early and allocate extra tool/model/search budget prospectively rather than retrospectively summarizing cost.
- The B4 matched-call result again favors feedback-driven refinement over independent resampling on a hard case, while A5 supports isolating a subgoal when context growth itself becomes a bottleneck.
- A learned typed controller should be compared against this free-form agent baseline; otherwise improvements could simply come from restricting a capable model unnecessarily.

Critical scope / caution:
- Putnam 2025 is only 12 problems and the architecture changes for A5; no matched controller-wide ablation isolates autonomous tool routing.
- Dollar budgets are approximate effort indicators, not predeclared experimental caps.
- The 4/12 -> 11/12 -> 12/12 configuration table changes available tools/actions and therefore does not isolate routing quality.

Sources:
- https://arxiv.org/abs/2601.14027
- https://github.com/project-numina/numina-lean-agent
- https://github.com/project-numina/Numina-Putnam2025

## C54 — Constrained policy optimization supplies a clean mathematical template for global compute allocation, but only over compute levels rather than heterogeneous Lean actions

Primary source:
- `Adaptive Test-Time Compute Allocation for Reasoning LLMs via Constrained Policy Optimization`, arXiv:2604.14853 (2026-04).

Problem formulation:
- Maximize expected task accuracy subject to an **average inference-compute budget** across the workload rather than giving every problem the same amount of compute.
- Lagrangian relaxation decomposes the global budget into per-instance subproblems, yielding a closed-form oracle action that prices accuracy against cost.
- Expected compute is monotone in the dual variable, so the desired fleet-wide budget can be hit by binary search.
- A lightweight classifier then imitates the oracle from cheap input features, amortizing the allocation rule at deployment.

Evidence on MATH/GSM8K with DeepSeek-V3, GPT-4o-mini and Qwen2.5-7B:
- Up to **12.8% relative accuracy improvement on MATH** versus uniform/heuristic allocation under matched average-budget constraints.
- Learned policy follows the Lagrangian oracle with **over 91% action-imitation accuracy**.
- The paper bounds task-level regret by oracle-imitation error times the worst per-instance action gap.

Transfer relevance:
- This gives a rigorous objective for the emerging Lean controller-of-controllers: allocate expensive proof actions only where their marginal expected accuracy/information benefit exceeds their shadow price under a global budget.
- A Lean extension could let the action set include `cheap continue`, `high-thinking attempt`, `retrieve`, `repair`, `extra agent`, `specialized prover`, `replan`, `population search`, or `stop`, each with substrate-aware cost.
- The dual variable is especially useful when the service has a hard average latency/token/GPU budget but highly heterogeneous theorem difficulty.

Critical scope / caution:
- This is not formal theorem proving; actions are test-time compute levels/modes, not Lean-specific heterogeneous tools.
- Oracle outcomes are estimated from repeated benchmark inference, whereas a proof controller observes a nonstationary trajectory where action outcomes depend on previous attempts, caches and proof state.
- >91% imitation accuracy is not probability calibration and does not guarantee low decision regret when rare errors occur on high-value expensive actions.

Source:
- https://arxiv.org/abs/2604.14853

## Updated synthesis

The controller frontier now has three distinct baselines that should not be conflated:

1. **Fixed deterministic workflow** — HILBERT/BFS/LEAP/LeanFlow encode useful action hierarchies and memory but use fixed budgets/triggers/DFS-like control.
2. **Free-form coding-agent control** — Numina lets a strong base model autonomously choose heterogeneous tools, while hard-case budget scaling remains largely uncalibrated/manual/post-hoc.
3. **Learned budget allocator** — constrained policy optimization learns where to spend more compute under a global budget, but only for generic reasoning compute levels rather than stateful formal-proof actions.

A strong next experiment should compare all three under one Lean environment:
- preserve the same action/tool library and verifier;
- include compact AxProver-style memory rather than raw transcripts;
- compare fixed thresholds, free-form tool choice, and a learned typed policy;
- train the learned policy against a global token/latency/Lean-execution budget, not only per-theorem caps;
- include a `buy more controller complexity` action (extra agent, higher thinking budget, population search) and a `stop/abstain` action;
- report end-to-end success, Brier/ECE/selective risk, real cost, and model/backbone-conditioned results.

## Rejected / narrowed leads this pass

- **More history is always more useful context:** rejected by AxProverBase's direct memory ablation; compact self-managed notes outperform recent full attempts in the tested setting.
- **Numina's large A5/B6 budgets demonstrate autonomous difficulty-based resource allocation:** too strong; public author clarification says those budgets were calculated after proof completion.
- **A capable general coding agent requires a dedicated learned tool router to use heterogeneous Lean tools:** not established; Numina is a strong counterexample baseline for free-form autonomous tool use.
- **Global compute-allocation theory already solves Lean meta-action routing:** false; C54 optimizes generic compute levels and lacks stateful formal action transitions, verifier caches and calibration.

## Nonempty unresolved frontier

1. **Matched fixed-vs-free-form-vs-learned Lean controller:** same tools/actions, same verifier/model family, same real budget.
2. **Controller-of-controllers with global resource constraint:** learn both local proof action and whether to purchase higher thinking, extra agent, specialized prover, population search or global replan.
3. **Compact sufficient memory:** compare self-managed notebook, learned Delta/progress/error summary and raw history on downstream action value, not only proof success.
4. **Calibrated prospective difficulty/resource prediction:** allocate hard-case budgets before exhaustive search, with selective abstention when confidence is poor.
5. **Backbone-conditioned action value:** formalize the repeated finding that feedback/diversity/search helps some models and harms/saturates others.
6. **Stateful constrained policy optimization:** extend global-budget allocation to Markov/partial-observation Lean trajectories with action-specific real costs and reusable cache state.
7. Continue matched subgoal scheduling, triggered global retrieval, snapshot+semantic repair and benchmark-audited cost normalization.
