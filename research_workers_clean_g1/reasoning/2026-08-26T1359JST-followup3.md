## New findings

### C136 — naïvely reusing `_atomic_append_text` for every decision would create quadratic write amplification

The current atomic trace primitive does not append in-place. For every call it creates a temporary file, copies the **entire existing trace**, writes the new payload, fsyncs, then `os.replace`s the whole file. This is excellent for avoiding a partial JSON line when called once per completed run, but it is not a neutral high-frequency decision journal.

If `M` equally sized decision events are appended one at a time, total data rewritten is proportional to `1+2+...+M = M(M+1)/2`; relative to the final `M`-event file, the write amplification is approximately `(M+1)/2`. Thus 100 per-decision appends imply about 50.5× final-file bytes rewritten; 1000 imply about 500.5×. Even if events are small, this can contaminate the wall-clock quantity the cost-aware controller is supposed to optimize.

Therefore C118 is refined: **reuse the event schema/JSON machinery and atomic-install pattern, but do not call the current whole-file replacement append once per decision without measuring the distortion.**

### C137 — use a dedicated decision-event journal with O(1)-ish per-event durable writes, then compact to existing JSONL

The cleanest dependency boundary is a `DecisionEventJournal` protocol separate from final `JsonlTraceStore` summaries. Two viable implementations are:

1. **segmented JSON journal** — one immutable canonical JSON file per `event_id`, written to a same-directory temp file, fsynced and atomically renamed; duplicate event id reads the existing segment and accepts only byte-identical canonical payload; finalization compacts verified segments to normal JSONL;
2. **SQLite journal** — stdlib `sqlite3`, `event_id PRIMARY KEY`, canonical JSON payload/hash, transaction per event under WAL/FULL-sync semantics, with export to JSONL afterward.

For a minimal no-schema-migration prototype, segmented JSON is easier to audit and aligns with current JSON traces. SQLite is likely better if decision counts become large. The journal abstraction lets the experiment compare durability/overhead without changing proving semantics.

For strongest power-loss durability on POSIX-like filesystems, an atomic-rename implementation should also fsync the containing directory after installing a new segment; file fsync + rename alone mainly protects process/interruption atomicity and may not guarantee directory-entry persistence across sudden power loss on all filesystems.

### C138 — persistence failure must have explicit fail-closed semantics during randomized data collection

Because exact propensities and causal decision order are part of the experiment, a selected randomized action must not execute if its decision record cannot be durably persisted first.

Required order and failure behavior:

1. freeze decision and behavior probabilities;
2. persist `execution_decision`; if this fails, **do not consume/execute the action** and fail/stop the experimental run;
3. if the selected proposal comes from a shared model batch, persist the batch-consumption join; if this fails, do not execute;
4. execute the action;
5. persist `execution_outcome` before another randomized decision.

If step 5 repeatedly fails, the action cannot be rolled back. Stop further randomized decisions and leave the already durable decision unmatched; downstream reconstruction correctly treats it as censored. Continuing randomized actions after losing one outcome would make later state transitions impossible to attribute cleanly.

Instrumentation-disabled production need not pay this journal contract; but all baseline and treatment arms used in causal comparison should run with the same journal so persistence overhead is matched.

### C139 — run identity is already adequate; do not invent a second run identifier

`_StructuredRunState.sample_id` is created by `new_sample_id()`, which returns UUID4 hex, and final run metrics/trace summaries prefer that same sample id as `run_id`. Decision events should therefore use `state.sample_id` directly.

A redundant second run UUID would create avoidable join/recovery ambiguity. Stable event identity can be constructed as `{sample_id, decision_index, event_type[, node_id]}` and canonicalized/hash-checked by the journal.

### C140 — freeze a deliberately small Stage-A v0 feature schema before collection

The first learned post-generation selector should be a **candidate-scoring policy over a variable legal set**, not a text model. Proposed v0 features are all derivable from already pinned structured state.

**Shared decision features**
- `remaining_budget_policy_enabled`;
- for each unified dimension `model_requests, input_tokens, output_tokens, billed_tokens, checks, wall_time, api_cost_usd`: status categories plus remaining-ratio value+missing bit;
- global reserve checks/model requests;
- number of active/open/in-progress/accepted obligations;
- active branch count, accepted-fact count, current candidate count.

**Candidate target branch features** from the existing pure frontier projections
- root indicator;
- `depth_from_root`;
- `attempt_count`;
- `local_attempt_count`;
- `stalled_streak`;
- latest goal-fingerprint count (not the fingerprint identity itself in v0);
- `unlock_value`;
- `progress_likelihood`;
- `information_gain`.

**Candidate/action features**
- one-hot typed action kind over the seven supported structured actions;
- proposal source/model tier categories;
- proposal score value+missing bit;
- normalized rank (`rank/(L-1)` when `L>1`, else 0);
- priority expected incremental cost value+missing bit plus its unlock/progress/information components;
- each `CostEstimate` dimension as value+missing bit;
- `log1p(sample_count)`, estimate-source category;
- raw rejected-dimension and not-compared-dimension bitsets;
- effective runtime eligible and experiment eligible bits.

Provenance-only fields such as estimator version, exact node id, task id, obligation id and proposal-batch id remain in the lossless event but are **not** v0 predictive inputs. This reduces accidental memorization while retaining auditability.

### C141 — missing cost/budget values require explicit masks; zero-imputation without a mask would invert semantics

CSSC deliberately distinguishes unknown/unavailable/unbounded from numerical zero. The learned feature projection must preserve that distinction.

For a scalar estimate `x`:

- if known: feature `log1p(x)` and `known=1`;
- if missing/unavailable: numeric channel `0` and `known=0`.

For remaining ratios, keep a numeric channel and a presence bit plus the source status category. Never treat `CostEstimate.checks=None` as `checks=0`; existing frontier tests explicitly preserve unknown cost as a real competitor rather than assigning infinite or free cost.

### C142 — a shared per-candidate scorer is the cleanest initial model family

Given variable-size candidate sets, use a shared function `q_theta(global_features, branch_features, candidate_features)` to score each effectively legal action, then a masked softmax/argmax over the current set. A small MLP (for example one or two hidden layers, tens rather than billions of parameters) is sufficient as a first causal ablation.

This factorization has useful controls:

- BC can imitate the deterministic baseline using the same scorer;
- terminal/verified-return weighting can change only the objective;
- value/Q or conservative contextual-bandit variants reuse the same state/action representation;
- action masks and exact behavior probabilities remain outside the learned model and independently auditable.

Do not let model architecture changes become confounded with controller-learning claims in the first experiment.

### C143 — randomization should log the realized uniform draw as well as the probability vector

For deterministic replay, log:

- experiment/policy version;
- epsilon;
- exact probability-by-node vector;
- PRNG algorithm/version or deterministic sampler implementation id;
- experiment seed identifier;
- realized `u in [0,1)` (or equivalent sampled index);
- selected node and chosen propensity.

The probability vector is what causal estimation needs; the realized draw makes selection replay/audit independent of future PRNG-library changes. The random seed itself should not be used as a predictive model feature.

### C144 — instrumentation overhead is a first-class matched measurement, not “free logging”

Before provider RL/OPE collection, run the deterministic policy with and without the journal on the same controlled fixtures and report:

- selected action sequence equality;
- checker/model-call/token/API-cost equality;
- accepted result equality;
- trace/journal bytes written;
- journal fsync count;
- wall-clock delta.

For the actual baseline-vs-learned policy experiment, **both** arms use identical instrumentation so journal overhead cancels as much as possible. A separate uninstrumented reference estimates observational overhead but is not the primary causal comparison.

If logging overhead is material relative to Lean checking or local structural actions, batching/SQLite/segmented-journal engineering is required before drawing cost-efficiency conclusions.

## Updated synthesis

The primary technical risk is no longer whether a compact controller can be represented. CSSC already exposes a compact, structured, variable-action-set state with explicit cost/budget and proof-progress signals. The immediate research risk is whether the **measurement substrate perturbs the cost objective** or misstates support/eligibility.

The event journal must therefore be treated as part of the experimental apparatus: durable before action, idempotent, low-overhead, and identical across comparison arms. With that in place, a very small text-free candidate scorer becomes a high-value first test because any gain is much easier to attribute to allocation policy rather than semantic-model capacity.
