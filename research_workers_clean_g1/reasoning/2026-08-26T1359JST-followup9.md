## New external evidence: A-IC3

Fresh targeted search found a stronger cross-domain formal-verification precedent than previously recorded: **A-IC3: Learning-Guided Adaptive Inductive Generalization for Hardware Model Checking** by Xiaofeng Zhou, Guangyu Hu, Hongce Zhang, and Wei Zhang, arXiv:2604.21688, submitted 2026-04-23 and revised 2026-07-15; accepted at CAV 2026 with a public Zenodo artifact.

The paper embeds a lightweight proof-aware contextual-bandit controller inside the fixed symbolic IC3 model checker. It uses PA-LinUCB to select among predefined generalization strategies of different aggressiveness on every inductive-generalization call. Its context is a compact eight-dimensional vector: normalized recursion depth, CTI cube size, proof-obligation queue length, current/frontier frame relation, frame saturation, queue-growth rate, activity, and a bias. The strategy arms adjust CTG attempts/depth/budget rather than replacing the underlying SAT/IC3 solver.

The immediate reward combines clause-size reduction, propagation/push quality, and event bonuses/penalties. The paper explicitly notes that each generalization affects future proof obligations and frames, so the environment is sequential/non-stationary even though the controller is trained as a contextual bandit. On 914 HWMCC instances with rIC3, the paper reports 26–50 more solved cases than its baselines and PAR-2 improvements of 194.72–389.29. The public artifact is archived on Zenodo.

## New findings

### C179 — the broad “compact learned controller over a fixed formal-verification substrate” gap is closed by A-IC3

The previous absence statement was too broad if interpreted across all formal verification. A-IC3 is a direct counterexample:

- fixed low-level symbolic solver/model checker;
- low-dimensional structured proof-state context;
- discrete strategy arms controlling search aggressiveness;
- lightweight learned controller invoked in the inner proof loop;
- verifier-native feedback and end-to-end solved/runtime gains.

Therefore the remaining gap must be stated more narrowly: **interactive theorem proving / Lean-like proof synthesis with heterogeneous outer actions (repair/decompose/retrieve/fork/escalate/etc.), explicit legal masks, exact logged behavior propensities, and cost-aware causal/offline evaluation under a fixed/factored prover substrate.**

### C180 — A-IC3 makes a linear contextual-bandit baseline mandatory for the first CSSC Stage-A comparison

The current model suite should add a very small linear/arm-conditioned contextual bandit before concluding a nonlinear MLP is needed. A-IC3 uses only an eight-dimensional proof-aware vector and standard LinUCB-style updates, yet improves a production-grade formal-verification loop.

For CSSC Stage A, compare at least:

- deterministic production heuristic;
- BC with the frozen 154-channel shared scorer;
- **linear contextual bandit / LinUCB-style arm-conditioned baseline** on a smaller aggregate feature projection;
- small nonlinear shared scorer/value model;
- conservative offline/bandit policy with exact propensity support diagnostics.

The point is not that LinUCB will transfer directly, but that any claimed benefit from a more complex controller should beat a cheap proof-aware linear policy under matched overhead.

### C181 — A-IC3 supports the “local + global progress” feature pattern already emerging in CSSC

A-IC3 combines local CTI difficulty signals with global proof-progress signals such as frame saturation and proof-obligation queue growth. This independently supports the CSSC v0 decision to include both:

- local branch features (`depth`, attempts, stalled streak, unlock/progress/information signals);
- global search/budget/workspace features.

It also suggests that **change/growth features** may be more useful than static counts alone. A future preregistered v1 feature ablation could add recent changes in active obligations, accepted facts, and candidate/frontier width, but v0 should remain frozen before provider outcomes.

### C182 — A-IC3 is also a warning about surrogate reward transfer

A-IC3's reward is domain-specific and hand-engineered from clause-size reduction and push quality, plus bonus events. That surrogate is tightly coupled to IC3 mechanics; it cannot justify inventing analogous “looks like progress” rewards for Lean structural edits.

The CSSC design should retain verifier-grounded terminal/local labels and separate costs. If a learned local surrogate is introduced later, it should be validated against downstream verified success rather than assumed from surface structural changes.

### C183 — contextual-bandit success does not remove the need for sequential/OPE evaluation in CSSC

A-IC3 itself acknowledges that each generalization changes future CTIs and proof dynamics. Its online LinUCB approach can still work empirically, but CSSC's heterogeneous meta-actions can have even stronger delayed effects (decomposition changes future obligations; representation changes alter later candidates; repair may unlock facts).

Therefore A-IC3 strengthens the case for trying a cheap bandit baseline but does **not** establish that myopic immediate reward is sufficient for theorem-proving meta-control. Terminal Monte Carlo/value heads remain necessary comparison points.

### C184 — the randomized protocol correction demonstrates why protocol hashing/change control is useful before collection

The first protocol draft named a seed but did not unambiguously state how it entered SHA-256. Before any data collection, it was corrected to HMAC-SHA256 with explicit key/message semantics and assigned a new semantic-body hash.

This is exactly the kind of ambiguity that would make propensities irreproducible after the fact. The protocol artifact/change-control rule caught it while no evidence was yet collected, so there is no mixed-policy dataset to repair.

## Updated synthesis

The compact-controller hypothesis is no longer supported only by general-agent work or a negative gap. A-IC3 demonstrates the core factorization inside formal verification itself: a tiny proof-aware controller can dynamically allocate strategy strength while leaving the symbolic solver fixed and improve end-to-end verification performance.

The research opportunity is now more precise: translate that control-plane idea into Lean/CSSC's much more heterogeneous action space **without sacrificing causal identifiability, verifier-grounded rewards, support accounting, and real cost measurement**.
