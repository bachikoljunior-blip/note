## C487 — All-minimal-justification enumeration is a direct symbolic precedent for alternative proof-support families

The 2024/2025 Reasoning Web tutorial on description-logic explanations defines a justification for an entailment `K |= alpha` as a subset-minimal `J ⊆ K` with `J |= alpha`. It gives a black-box divide-and-conquer procedure for one justification using polynomially many entailment checks, and a Reiter hitting-set-tree procedure that enumerates all justifications. The tutorial also proves an `EL` family with `3n` axioms and exactly `2^n` distinct justifications, so exhaustive support enumeration is inherently exponential in the worst case.

This is stronger than the current one-proof Sledgehammer minimization precedent: it supplies a semantics-level notion of *all alternative minimal sufficient supports* plus a complete enumeration pattern. It is not Lean-specific and assumes a decidable entailment oracle for the logic in question.

## C488 — Weighted sums of minimal supports give a modern Shapley-equivalent attribution route without full coalition enumeration

Bienvenu, Figueira and Lafourcade (PODS/PACM 2025, arXiv:2503.22358) revisit Shapley responsibility for database query answers. Standard drastic-Shapley treats each database fact as a player and assigns coalition value 1 iff the selected facts suffice for the Boolean query answer. Exact Shapley computation is #P-hard even for simple conjunctive queries. They introduce *weighted sums of minimal supports* (WSMS): responsibility is computed from minimal supports rather than all coalitions. Every WSMS measure is shown equivalent to the Shapley value of a suitably defined cooperative game, while WSMS has tractable data complexity for a broad class including all unions of conjunctive queries.

This is the closest direct precedent found for the current multi-lemma-credit frontier: minimal sufficient supports can be the primitive object for fair coalition credit, rather than giving every premise in one successful proof full terminal reward or sampling the full powerset.

Source: https://arxiv.org/abs/2503.22358

## C489 — Query-answer Shapley is a direct logical-contribution analogue, but semantic entailment and bounded prover utility must stay separate

Livshits, Bertossi, Kimelfeld and Sebag define the Shapley value of database tuples by treating facts as players and a query answer as coalition wealth. Their LMCS/ICDT work provides exact/approximation algorithms and complexity results; the later WSMS work confirms that the usual Boolean-query game is simply `v(S)=1` when `S` supports the query and `0` otherwise.

For a finite candidate lemma set and a *semantic* entailment oracle, the analogous game `v(S)=1[S entails goal]` is monotone: adding assumptions cannot destroy logical entailment. In that idealized game, the complete family of minimal sufficient supports determines every winning coalition by upward closure, so alternative-support enumeration is sufficient structural information for Shapley/WSMS-style semantic attribution.

However this does **not** carry over unchanged to actual Lean search under a fixed token/verifier/wall-clock budget. Resource-bounded prover success can be non-monotone because extra premises can pollute retrieval/context or redirect search. Therefore semantic support credit cannot substitute for the existing counterfactual operational-utility tests.

Sources:

- https://arxiv.org/abs/2503.22358

## C490 — Three support layers should be logged separately in Lean

Design synthesis, not a published theorem:

1. `proof_specific_support`: exact environment/proof-term dependencies plus tactic-explicit `rw`/`simp` references for the particular verified proof obtained.
2. `semantic_minimal_support_family`: alternative subset-minimal candidate-lemma sets sufficient for the theorem under a declared entailment/search oracle and declared scope. In full Lean this cannot be treated as complete semantic entailment unless the oracle is complete for the restricted fragment; otherwise label it `oracle_relative_support`.
3. `operational_marginal_utility`: chronologically future fixed-compute add/remove or coalition tests measuring solve delta, token/Lean-execution/wall-clock delta, regression and retrieval/context pollution.

Do not infer theorem-level necessity from one proof-term dependency set, and do not infer operational usefulness from semantic Shapley/WSMS credit alone.
