**Inference.** Preserve two evidence classes:
1. `source_target_differential`: same Rego source/configuration evaluated by topdown and by a fresh Wasm compilation;

Only the second catches compiler/artifact/runtime-route drift between test and deployment.

## C433 — a practical randomized assurance harness should triangulate source, exact Wasm artifact and optionally independent IR/source implementations

The concrete next experiment is now narrower and more reproducible:

1. Generate AST-aware Rego v1 programs inside an explicitly declared supported fragment.
2. Persist `{seed, case_id, source, input, data, capabilities, entrypoint, strict-error mode, builtin set}` before evaluation.
3. Evaluate the same case through:
   - OPA topdown;
   - OPA compile → **exact emitted Wasm bytes** → intended Wasm SDK/runtime;
   - optionally OPA plan/IR → exact Swift-OPA version for independent IR execution;
   - optionally a separately implemented source interpreter when its supported semantic subset is explicit.
4. Canonicalize into `defined result`, `undefined`, `deterministic error class`, or `declared target-specific non-equivalence`.
5. Partition strict-error-only and >64-bit numeric cases rather than treating them as generic mismatches.
6. Add only semantics-preserving transformations whose validity is explicit for the chosen fragment; retain deoptimization/metamorphic relations as independent oracles rather than assuming topdown is infallible.
7. On mismatch persist exact OPA/compiler SHA, Wasm digest, runtime/SDK identity, optional plan digest and independent-engine version, plus the seed and minimized replay case.
8. Shrink only while preserving the same semantic configuration and mismatch class.

This directly extends C426-C428: shared-corpus E2E, generated differential/metamorphic evidence, independent execution implementations, proof/certificate evidence and exact artifact/runtime identity remain distinct evidence classes.
