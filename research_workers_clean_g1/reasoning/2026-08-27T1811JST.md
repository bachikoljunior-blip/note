## C505 — A deterministic support-family fixture shows why both single leave-one-out and support frequency can misattribute reusable premises

A five-premise monotone Horn fixture was implemented and executed locally with three exact subset-minimal supports:
- `{a_P, b_P_implies_R}`
- `{c_Q, d_Q_implies_R}`
- `{a_P, d_Q_implies_R, e_P_implies_Q}`

Because the full premise set contains substitutable proof routes, deleting any single premise from the full coalition leaves the goal provable. Full-coalition leave-one-out therefore assigns **zero to all five premises**.

Raw minimal-support frequency fails differently: `b_P_implies_R`, `c_Q`, and bridge premise `e_P_implies_Q` each occur in one of three minimal supports. Exact coalition values distinguish them: Shapley gives `b = 1/5`, `c = 1/5`, but `e = 1/30`; normalized Banzhaf gives `b = 1/5`, `c = 1/5`, `e = 1/25`. The bridge premise only matters in a narrow set of coalitions, which support frequency cannot see.

Design implication: when alternative supports exist, neither one-shot deletion from the full library nor raw support-membership count is sufficient causal attribution. Coalition-aware diagnostics are worth computing on a bounded candidate set, while final global promotion must still be tested against chronologically future proof utility.

## C507 — Exact-coalition diagnostics should be a bounded evaluator, not a global-library default

CapaBench can exhaustively enumerate four workflow players, and the five-premise fixture can exhaustively enumerate all coalitions. Real proof libraries have orders of magnitude more candidate lemmas, so exact Shapley/Banzhaf is not a scalable default. The emerging design is therefore hierarchical:
1. cheap observational priors and support discovery narrow the candidate set;
2. bounded coalition-aware attribution is computed only inside a small frozen candidate universe;
3. expensive future fixed-compute theorem proving remains the authoritative promotion/demotion test.

This avoids both combinatorial explosion and the opposite error of treating raw usage/support frequency as causal value.
