## New finding C84 — Adapt is a direct learned outer-strategy-selector result, and it is negative evidence against shallow imitation features

Primary paper: Minghai Lu, Zhe Zhou, Danning Xie, Songlin Jia, Benjamin Delaware, Tianyi Zhang, **Adaptive Proof Refinement with LLM-Guided Strategy Selection**, arXiv:2510.25103 (submitted 2025-10-29; authors list it as ASE 2026 / to appear).

Source-qualified URLs:
- https://arxiv.org/abs/2510.25103
- https://www.researchgate.net/publication/397041156_Adaptive_Proof_Refinement_with_LLM-Guided_Strategy_Selection
- https://songlinj.github.io/  (publication status only)

Adapt's outer loop chooses among three heterogeneous refinement strategies after a Coq proof failure:
1. `Lemma Discovery` — synthesize or refine helper lemmas, then regenerate using verified additions;
2. `Context Enrichment` — search the project/library for more relevant definitions/lemmas/proofs, then regenerate;
3. `Regeneration` — regenerate/repair directly from current proof state/context.

This is materially closer to the targeted typed outer controller than tactic generation alone: the selected action changes *what kind of proving operation happens next*, including expensive knowledge acquisition and lemma synthesis.

### Learning-based selector

The paper explicitly evaluates a learned decision-maker rather than only a prompted LLM or heuristic router. It constructs `18,628` examples from human-written CoqDev proofs. At each proof step, it simulates working context and extracts six hand-engineered quantitative features:
- number of unique definitions in the goal;
- number in local hypotheses;
- number in goal but not hypotheses;
- number in goal but not existing working-context lemmas;
- similarity score of the retrieved similar theorem;
- number of lemmas used by that similar theorem but absent from working context.

Labels are derived from the human-written tactic: use of a new helper lemma from the same commit => Lemma Discovery; use of a previously existing lemma => Context Enrichment; otherwise => Regeneration. Ten-fold CV gives the best classifier, a 3-layer DNN, `82%` average accuracy and `0.78` F1 (XGBoost 71% / 0.74; SVM and Random Forest 41%; Decision Tree 25%).

### End-to-end result contradicts classifier accuracy

On CoqDev, Table 5 reports:
- prompted LLM decision-maker (`Adapt`): `651/1720 = 37.85%`, avg `1.35` refinement iterations, avg input/output tokens `16348 / 4383`;
- rule router: `647 = 37.62%`, `1.37` iterations, `24244 / 6109` tokens;
- learned DNN router: `595 = 34.77%`, `1.24` iterations, `9801 / 3157` tokens;
- random router: `605 = 35.17%`, `1.61` iterations, `12568 / 3476` tokens.

Thus the DNN is cheaper but proves *fewer* theorems than random despite high cross-validated imitation accuracy. The paper attributes the underperformance to quantitative features failing to capture proof-state semantics and data scarcity (especially lemma discovery), making the model overly conservative.

**Scope guard:** this is Coq, not Lean; the learned selector is supervised imitation of human-tactic-derived labels, not sequential RL/offline RL/OPE; its three actions are coarse refinement strategies and do not cover the full D3 ontology. Therefore it closes the claim “no learned formal-proof outer selector exists” but does **not** establish a strong learned cost-aware controller.

**Design consequence:** the frontier narrows from “learn the outer selector at all” to “learn it from replay-complete semantic/structural state with terminal verifier-grounded utility and explicit cost/support, rather than shallow human-action imitation.” High classification accuracy on behavior labels is not an adequate controller objective.

## New finding C85 — dynamic heterogeneous routing itself has strong value, but the strongest selector is still a free-form LLM

The same Adapt study shows that dynamic strategy selection is practically useful. Full Adapt proves `651/1720` CoqDev theorems. Removing lemma discovery yields `590` (`34.30%`), while removing context enrichment yields `622` (`36.16%`). Random strategy choice solves 7.07% fewer theorems than the LLM decision-maker and uses 19.26% more refinement iterations on average. The rule router nearly matches success rate but consumes roughly 50% more tokens, because its heuristics over-select expensive lemma discovery.

This provides a proof-specific cost-allocation pattern matching the current frontier: expensive actions should be invoked conditionally, not as a fixed pipeline. But the best observed selector remains a prompted general LLM, so it remains a free-form baseline rather than evidence that a compact learned controller has solved the problem.

## D4 — refine the typed action ontology by execution-effect class

The prior D3 action list conflates pure controller-state transitions with irreversible or externally effectful operations. That makes rollback, legal masks, propensity logging, and OPE ambiguous. Split the ontology so each atomic action has one execution-effect class.

### Class P0 — pure local control state

Examples: inspect already-frozen local proof/context structures; choose a local proof-state snapshot; fork an in-memory proof state; local backtrack/prune when no child execution is in flight.

Minimum trusted record:
- decision id / parent decision id;
- input structural-state digest and active rule/config epoch;
- legal-action mask digest;
- chosen action + behavior probability;
- pre/post local-state digests;
- deterministic executor version.

These are the safest Stage-A randomized actions because rollback is genuinely local and compute/persistent effects are bounded.

### Class E1 — read/compute effect, non-persistent result

Examples: retrieval/search, LLM local repair, decomposition/replan call, launching a worker/model branch, Lean execution whose only result is a transient checked state.

Rollback cannot refund consumed tokens/time or revoke a request already sent. Minimum trusted record therefore additionally needs:
- stable operation id and idempotency/request hash;
- resource/model/tool identity and version;
- budget reservation and actual cost vector;
- call phase (`authorized/requested/running/returned/cancelled/failed`);
- child-operation lineage;
- result digest and `required/consumed/ignored` disposition;
- cancellation/late-result policy.

Stage-A randomization is safe only when cost is bounded and executor/cancellation semantics are deterministic. Late results must never silently attach to a restored branch.

### Class E2 — persistent write/cache effect

Examples: `STORE_VERIFIED`, durable retrieval/cache update, persistent scratch/checkpoint writes that later decisions can reference.

Rollback cannot literally undo an already published write. Prefer content-addressed/idempotent writes and monotone provenance rather than deletion. Add:
- target namespace/path/key;
- content hash plus verification evidence hash;
- predecessor/parent epoch;
- CAS/idempotency key and commit/write receipt;
- supersession/tombstone linkage if later abandoned.

A verified artifact should become referenceable only after write/readback succeeds under the recorded identity.

### Class E3 — terminal/external commitment or resource acquisition

Examples: terminal `SUBMIT`; unconstrained compute escalation; any external mutation/merge/publication that changes non-local authority.

These remain baseline-only or separately gated Stage B until exact-once semantics, authorization, budget bounds, and irreversible-effect policy are explicit. Required record includes authorization identity, precondition certificate, operation id, committed outcome, and exact terminal/result linkage.

### Ontology corrections implied by D4

- Replace `SPAWN_BRANCH` with `FORK_STATE` (P0) plus `LAUNCH_BRANCH` (E1). Forking a snapshot and starting a worker are not one safe atomic action.
- Replace `BACKTRACK_OR_PRUNE` with `BACKTRACK_LOCAL` (P0) and `CANCEL_OR_ABANDON_BRANCH` (E1 when external work is in flight).
- Treat `UPDATE_SCRATCH` as P0 only if transaction-local; if durably persisted, it is E2.
- Treat `LOCAL_REPAIR` and `DECOMPOSE_OR_REPLAN` as E1 whenever they invoke a model/tool, even if their semantic output only updates local proof state.
- Keep `STORE_VERIFIED` as E2 and `SUBMIT` as E3.
- Treat `ESCALATE_COMPUTE` as E3-like resource acquisition, not a proof-state edit; it must reserve and log a real budget vector before dispatch.

**Design consequence:** legal-action masks and behavior propensities should operate over these atomic effect-classed actions, not over bundled operations. This also makes deterministic replay possible: P0 is replayable from state; E1-E3 replay uses recorded outcomes/receipts rather than reissuing effects.

## Updated synthesis

1. A learned outer selector in formal proof now has a direct 2025/ASE-2026 example (Adapt DNN), but it underperforms random end-to-end despite 82% imitation accuracy. This is strong negative evidence against optimizing human-action classification as a proxy for verified solve utility.
2. Dynamic heterogeneous action selection itself is valuable: Adapt's LLM router beats fixed/refinement baselines and random, while a rule router spends much more token budget for similar solve rate.
3. The most useful next controller objective is terminal verified success/reusable verified progress minus explicit real cost, with sequential credit and support-aware deployment—not per-step imitation accuracy alone.
4. D3 must be decomposed by execution effect. A proof-state fork is not the same action as launching a branch; local pruning is not the same as cancelling an in-flight worker; persistent verified-cache writes are not rollback-equivalent to transient local state.
5. Historical free-form/planner traces can still inform representation and BC, but causal/OPE claims require new randomized typed data with exact mask, behavior distribution, effect record, and frozen executor version.
