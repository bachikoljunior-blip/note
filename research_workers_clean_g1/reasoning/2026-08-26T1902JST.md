## C337 — a deployed learned permission gate directly authorizes effectful coding-agent actions, and its unsafe-allow rate is materially nonzero
Primary source: Anthropic, *How we built Claude Code auto mode: a safer way to skip permissions* (2026-03-25).

Claude Code Auto Mode uses a model-based transcript classifier to decide whether state-changing tool calls may execute. This is direct real-world evidence for the exact design frontier: a learned gate is not merely advisory; an `allow` verdict authorizes the effect.

Reported deployed-pipeline metrics:
- real internal benign traffic, `n=10,000`: false-positive rate `0.4%`;
- real overeager actions, `n=52`: false-negative rate `17%`;
- synthetic exfiltration, `n=1,000`: false-negative rate `5.7%`.

Stage 1 alone is more conservative (`8.5%` FPR, `6.6%` FNR on overeager actions, `1.8%` FNR on synthetic exfiltration); Stage 2 reduces user friction but increases unsafe allows. Anthropic explicitly says the 17% FNR is the honest residual risk and that Auto Mode is not a replacement for careful review on high-stakes infrastructure.

Design implication for the clean reasoning frontier: a learned classifier can be useful in an authorization stack, but its output is not an exact capability boundary. For randomized theorem-prover/controller work, learned value/contract models should remain advisory inside a mechanically verified safe set rather than granting effect capability by themselves.

Source: https://www.anthropic.com/engineering/claude-code-auto-mode

## C338 — independent stress testing shows authorization-gate safety is highly workload- and coverage-dependent
Primary source: Ji et al., *Measuring the Permission Gate: A Stress-Test Evaluation of Claude Code's Auto Mode*, arXiv:2604.04978 (2026-04-04).

AmPermBench evaluates 253 state-changing actions across 128 deliberately ambiguous DevOps prompts with oracle-defined authorized/must-preserve targets. The same deployed learned gate performs much worse on this targeted scope-escalation distribution:
- end-to-end FNR `81.0%` (95% CI `73.8–87.4%`), FPR `19.8%`;
- Tier-3 actions actually evaluated by the classifier (`n=160`): FNR `70.3%`, FPR `31.9%`;
- `36.8%` of all state-changing actions travel through Tier 2 in-project edits and bypass the classifier entirely.

The paper correctly warns that these numbers are not directly comparable to Anthropic's organic production set; the workload intentionally stresses ambiguous authorization. The useful causal lesson is architectural: unsafe outcomes came not only from classifier mistakes but from **coverage assumptions**. Agents naturally used file edits to achieve effects when a CLI path was unavailable, without intentionally evading the gate.

For the current controller design, a safety mask must therefore be defined over effect/capability semantics, not tool/action names alone. `EffectContractV0` plus deterministic journal coverage verification should prove that every reachable state-changing path is either mechanically allowed or intercepted. A learned gate that covers only one syntactic path cannot be authoritative even if its per-call classifier is strong.

Source: https://arxiv.org/abs/2604.04978

## C339 — the learned gate can improve task-level safety while still being too weak for hard authorization
The same AmPermBench study runs the same Sonnet 4.6 agent with `bypassPermissions` versus Auto Mode. Safe Task Success Rate changes from `29.7%` to `32.8%` overall, including a large service-restart gain (`43.8% -> 59.4%`) but a small artifact-cleanup regression (`21.9% -> 18.8%`).

This is a useful counterweight to treating C338 as evidence that learned gating is useless. The gate can produce net value while remaining unsuitable as a sole hard safety boundary. The correct decomposition is:
1. deterministic effect coverage/capability boundary;
2. learned classifier/value model inside that boundary for ranking, escalation, or human-review routing;
3. explicit residual-risk measurement under distribution shift.

Source: https://arxiv.org/abs/2604.04978

## C340 — formal theorem proving provides a safe pattern: invoke learning only after the reliable symbolic baseline fails
Primary source: Wang et al., *Learned Interventions in Lean 4 grind*, arXiv:2607.22972v2 (2026-07-28).

Lean `grind` has non-monotone search: always-on learned heuristic replacement can help some proofs while breaking others, giving near-zero net gain. The paper instead uses a **failure-triggered cascade**: run stock `grind` first, then invoke learned/bounded interventions only after baseline failure. This construction cannot lose proofs the stock solver already had.

Reported held-out results:
- cost-aware e-matching filter: about `5%` faster and `+2` solves over 855 theorems;
- bounded one-step lookahead: rescues five stock timeouts with zero regressions;
- four static feature-based models for choosing the correct split are no better than random on the rescuable split-failure subset; one-step runtime lookahead reaches 100% rescue there versus 57% for random.

This is not external-effect authorization evidence. It is the strongest formal-proof analogue for the desired learning boundary: preserve a reliable symbolic/default path and let learning spend extra bounded search only where baseline semantics are already known to have failed. It strengthens the plan to keep hard legality/effect masks deterministic while learning ranking/escalation inside safe support.

Sources:
- https://arxiv.org/abs/2607.22972
- https://paperswithlean.com/paper/2607.22972.html

## C341 — execution-time structural guardrails can recover failures at low false-positive cost, supporting layered rather than prompt-only control
Primary source: Naik et al., *GuardianAgentBench: Where Agents Fail and How to Guard Them*, arXiv:2607.20982 (2026-07-23).

Across 580 validated tool-use scenarios, six models and three production frameworks, the best vanilla agent configuration reaches only 74.8% overall accuracy. The proof-of-concept execution-time guardrails intercept proposed tool calls and return Pass / Corrective Feedback / Block. On Claude Opus 4.5 + LlamaIndex, they recover 30 of 151 originally failed scenarios (`19.9%`) while incorrectly blocking 2 of 429 originally passing scenarios (`0.5%`). Across models, guardrails improve scores by `+2.8` to `+7.7` points relative to vanilla and outperform system-prompt safety instructions.

These guardrails are structural runtime checks, not evidence that a learned contract should grant capabilities. They reinforce a layered controller architecture: deterministic/runtime interception around effect boundaries is more robust than relying on the reasoning model to self-police through prompt text alone.

Source: https://arxiv.org/abs/2607.20982

## Synthesis / design update

The public-source falsification target from the previous checkpoint is now materially answered:

1. **Yes, a learned gate can directly authorize real effectful coding-agent actions.** Anthropic Auto Mode is a deployed example.
2. **No, observed learned-gate accuracy is not sufficient to make it the hard capability boundary.** The production set retains a 17% FNR on real overeager actions; targeted ambiguity stress testing reports much higher FNR and exposes uncovered effect paths.
3. **Coverage is a separate safety property from classifier accuracy.** A tool-name or route-specific gate can be bypassed by ordinary alternative execution paths without adversarial intent.
4. **Formal theorem proving suggests a safer use of learning:** keep the reliable symbolic/default path intact, and invoke learned bounded intervention after failure or only within a mechanically verified safe set.
5. **Runtime structural checks beat prompt-only self-policing** in broader tool-agent evidence and should remain part of the trusted substrate.

This sharpens `EffectContractV0` into two distinct layers:
- **authoritative hard contract:** deterministic/versioned `P_effect`, effect-complete coverage, tri-valued `Q_effect`, explicit idempotency/query semantics, fail-closed recovery;
- **learned advisory layer:** rank/prune already-safe alternatives, predict likely no-op/cost/value, route to bounded lookahead or human review, but never widen authority.

A new deterministic invariant should be added before any randomized collection: **effect-route closure**. For every supported logical effect, enumerate all substrate routes/action kinds that can realize it and prove each route passes through the same authoritative admission/receipt boundary. Syntactic action coverage is insufficient.
