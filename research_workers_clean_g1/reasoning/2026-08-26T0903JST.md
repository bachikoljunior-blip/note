## New finding C86 — Seed-Prover 1.5 directly closes the broad “no sequential/terminal-reward formal-proof outer policy” gap

Primary source: Jiangjie Chen et al., **Seed-Prover 1.5: Mastering Undergraduate-Level Theorem Proving via Learning from Experience**, arXiv:2512.17260 (2025-12-19).

Source-qualified URLs:
- https://arxiv.org/abs/2512.17260
- https://seed.bytedance.com/en/blog/seed-prover-1-5-advanced-mathematical-reasoning-through-a-novel-agentic-architecture
- https://github.com/ByteDance-Seed/Seed-Prover/tree/38c59cebaf969ac259196eb091757518d5b54c67/SeedProver-1.5

Seed-Prover 1.5 is not merely a tactic policy. Its agentic prover interleaves natural-language reasoning with multiple tool classes: Lean verification, Mathlib semantic search and Python execution. Multiple tool calls may occur in a turn, and the model dynamically chooses their ordering/granularity while incrementally proving and caching verified lemmas.

The post-training objective is explicitly sequential and terminal verifier-grounded:
- rollouts interleave tool calls and tool responses;
- VAPO/PPO-style RL optimizes the same autoregressive policy over those interaction trajectories;
- reward is `+1` if Lean verifies a completed proof and `-1` otherwise;
- the paper says the agent is trained to learn interaction strategies and tool usage rather than only next-tactic prediction.

This directly invalidates the earlier broad frontier wording that no formal-proof outer selector is trained from terminal/sequential reward. At full-agent-model granularity, such a policy exists.

### Behavioral evidence that RL changes tool allocation, not only proof text

The paper reports:
- average function calls across RL training decrease from roughly 15–16 to roughly 10 while training/test performance rises;
- average total response length drops from roughly 29k to roughly 17k tokens across training;
- Mathlib-search behavior is task dependent: about 10 search calls/trajectory on FATE-H versus only 1–2 on Putnam;
- later checkpoints make fewer search calls while performance continues improving;
- the agentic prover alone at `pass@8 × 8` solves 359/660 PutnamBench, 57/100 FATE-H and 10/100 FATE-X, outperforming the much more expensive Seed-Prover 1.0 medium workflow on the latter two and on Putnam count despite much lower quoted inference compute.

These observations are not a clean causal decomposition of “tool routing skill” from general reasoning improvement, but they are direct evidence that terminal verifier RL co-trains heterogeneous interaction behavior and that the learned policy changes its tool-use distribution by problem family.

### Scope guard

Seed-Prover 1.5 does **not** close the narrower typed-controller problem:
- the policy is a large autoregressive model over free-form reasoning, Lean code and tool-call tokens, not a compact one-decision/one-typed-action controller;
- the reward is binary proof success, with no explicit token/$/Lean-time/wall-clock/resource cost term;
- no behavior propensity / legal action mask / OPE protocol is exposed;
- no matched ablation isolates a compact outer controller from proof-generation capability;
- credit assignment details across long tool-interleaved trajectories are not sufficiently exposed for replay/OPE-style auditing.

The research target therefore moves from “can sequential verified reward train outer formal-proof behavior?” to “can a **compact, typed, effect-aware, cost-aware controller** match or improve a full agentic RL prover under fixed substrate and real budget?”

## New finding C87 — Leanstral 1.5 independently confirms open-weight agentic RL for formal proof engineering

Primary source: Mistral AI, **Leanstral 1.5: Proof Abundance for All**, 2026-07-02.

Source-qualified URLs:
- https://mistral.ai/news/leanstral-1-5/
- https://docs.mistral.ai/models/leanstral-1-5

Officially reported training has three stages: mid-training, SFT and reinforcement learning with CISPO, using two RL environments:
1. a multiturn theorem environment where the model submits a Lean proof, receives compiler feedback and iteratively refines until success or budget exhaustion;
2. a code-agent environment where it edits a raw filesystem, runs shell commands, queries the Lean language server for goals/errors/types, builds auxiliary lemmas and continues through repeated context compaction.

The official release says the model learns the full proof-engineering workflow and then uses a SafeVerify fork for final target-theorem verification. This is a second, independent formal-proof example where RL trains long-horizon environment-facing behavior rather than only tactic prediction.

Reported evaluation under the released model includes:
- miniF2F validation/test 100%;
- PutnamBench 587/672;
- FATE-H 87%, FATE-X 34%;
- FLTEval pass@1 28.9 and pass@8 43.2;
- monotonic Putnam test-time scaling up to a 4M-token budget per attempt, and a 2.7M-token/22-compaction AVL proof-engineering case study.

The weights are Apache-2.0 and an API is available, which makes Leanstral substantially more inspectable/deployable than Seed-Prover 1.5. But the public release description still does not provide a matched ablation isolating heterogeneous meta-action selection, nor an explicit cost-aware controller objective. Treat it as strong evidence for **full-model agentic RL**, not as evidence that the narrower typed-control/OPE design has already been solved.

## Updated synthesis

1. **Broad sequential-reward gap closed:** Seed-Prover 1.5 is a direct Lean formal-proof agent trained with terminal kernel-verified reward over interleaved tool/reasoning trajectories. Leanstral 1.5 independently confirms the paradigm with an open-weight 2026 system.
2. **Narrow controller gap remains:** neither result isolates a small typed meta-controller with a hard legal mask, exact behavior propensities, effect-classed actions, explicit cost vector and support-aware/OPE evaluation.
3. **Imitation remains a weak target:** Adapt's 82%-accurate supervised DNN underperforms random end-to-end, while agentic RL systems optimize terminal verified success directly. This strengthens the case for terminal/sequential verifier-grounded objectives over human-action classification.
4. **Cost must be made explicit:** Seed-Prover's binary reward can learn fewer tool calls incidentally, but there is no guarantee of optimal cost-quality tradeoff. The target experiment should explicitly optimize verified utility under token/$/Lean-time/wall-clock/worker-slot constraints.
5. **Matched comparison becomes clearer:** deterministic/rule router vs free-form LLM planner vs full-model agentic RL baseline vs compact typed BC/AW/value/offline-RL controller, all on the same Lean executor/tool/memory/cache substrate and fixed real budget.
6. **Artifact asymmetry matters:** Leanstral 1.5 is open weight/API; Seed-Prover 1.5 publishes proofs/report but not the agentic training/controller code in its 1.5 directory; Adapt's learned-selector data/code were not found through the currently linked preprint metadata/search.
