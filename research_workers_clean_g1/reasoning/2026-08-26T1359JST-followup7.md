## New findings

### C164 — abrupt-process smoke test supports the proposed “decision commit survives / uncommitted action journal does not” censoring model

The observed local behavior matches the desired causal semantics:

- a committed decision can survive abrupt process death and later appear as an unmatched/censored decision if no outcome was committed;
- an uncommitted event does not become a phantom committed action record;
- reopening the database remained structurally valid in this smoke test.

Therefore the journal reader can rely on ordinary transaction commit state for the first prototype instead of inventing an extra application-level `committed` flag. Such a flag could itself drift from database reality.

### C166 — use theorem/task as the split unit and preserve entire trajectories inside one split

The first learned selector comparison should split at theorem/task identity **before** expanding decisions/candidates. All decisions, candidate rows, shared proposal batches and outcomes from one theorem stay in the same split.

Reasons:

- random decision-level splitting leaks nearly identical workspace states and candidate templates across train/test;
- repeated attempts on one theorem are highly correlated;
- provider batch siblings must not straddle splits;
- v0 deliberately excludes task id as a feature, but split leakage can still occur through state/action/cost fingerprints.

If multiple independent runs of the same theorem are collected, group them by theorem identity as well. A later benchmark-transfer test can use an entirely separate source/benchmark as stronger OOD evaluation.

### C167 — preserve three label layers instead of collapsing to one scalar reward at collection time

Raw dataset builder should attach separate observed outcomes:

1. **terminal verified success**: final run accepted by checker+safety/assembly;
2. **local verified progress**: newly accepted fact/obligation deltas attributable after the action;
3. **real cost vector**: model/tokens/checks/checker wall+CPU/API/wall by causal scope.

Then model/objective variants can define returns without recollecting traces. For example:

- BC: no outcome reward, imitate baseline choice;
- terminal-outcome weighting: weight chosen action by eventual verified run success;
- sequential value/Q: discounted/undiscounted future terminal/local verified return minus prespecified cost scalarization;
- conservative contextual bandit: immediate/short-horizon verified progress and/or terminal attribution only where support is adequate.

Do not bake one unvalidated scalarization of money, tokens and wall-clock into the raw journal.

### C168 — censored decisions require objective-specific treatment, not universal deletion

A committed decision with no matching outcome can arise from abrupt termination or post-action outcome persistence failure. Recommended handling:

- BC on the chosen action can still use the decision if the behavior action is known and its state/candidates are complete, provided the task split is retained;
- reward/value objectives requiring post-action/terminal return must treat it as censored and exclude or model censoring explicitly, not label it zero;
- support/behavior-policy diagnostics still count it because the action probability was actually assigned/executed or at least irrevocably selected depending on the censoring point;
- separate field `execution_may_have_occurred` can be reader-derived only when journal ordering/other durable evidence permits; do not guess.

This avoids survivorship bias from dropping all interrupted decisions while also avoiding false failure labels.

### C169 — initial model comparison should hold representation and candidate mask fixed

Prespecified Stage-A v0 objective suite:

- **D0 deterministic production heuristic** — primary deployed baseline;
- **BC** — shared scorer trained to reproduce D0, tests representation/model capacity without outcome learning;
- **success-weighted/advantage-weighted classifier** — chosen-action likelihood reweighted by verified future outcome/advantage;
- **small Q/value scorer** — predicts supported future verified utility/cost for candidate actions;
- **conservative bandit/OPE-selected policy** — allowed only under measured support, with deterministic fallback outside support.

All learned variants use the same 154-channel manifest, legal/effective mask and underlying prover/cost estimator. This separates “learn from outcomes” from “changed state representation/action space/model capacity.”

### C170 — prespecify a provider-pilot precision rule around cost shares, not solve-rate deltas

The deterministic pilot's first purpose is deciding whether Stage A has economic headroom, not estimating a policy improvement. A practical prospective target is a task-level bootstrap 95% confidence-interval half-width of at most **5 percentage points** for the major mean cost shares (`proposal_generation`, `selected_execution`, `assembly`, `other`), subject to a maximum collection budget.

Report median shares and dispersion too, but use mean share for additive run-cost decomposition. If the precision target is not reached within the collection cap, report insufficient precision rather than choosing the most favorable partial estimate.

The 5-point threshold is a design choice, not a result. It should be frozen before provider data are inspected and can be tightened/loosened only in a new protocol version.
