## C37 — Search structure has difficulty-dependent value in Lean vericoding; uninterrupted iteration can beat branching on the hardest tasks

Primary source:
- Leo Yao, `Automating Formal Verification with Agent-Guided Tree Search`, arXiv:2605.27485 (2026).

Setup / evidence:
- The work evaluates 423 Lean verified-code specifications and upgrades a simple iterative correction baseline into an agent loop with Lean/compiler feedback and Mathlib search.
- GPT-5.4 reaches **95.0%** solve rate at an agent budget of `K=50` LLM calls on the 423-spec benchmark.
- Two explicit search structures are then compared: a state-based orchestrator branching on partial-proof states and a context-based orchestrator branching on full subagent contexts.
- The primary abstract reports a **selective** result rather than universal dominance: the context-based design solves a broader range of intermediate-difficulty specifications at lower token cost, while the uninterrupted agent baseline remains better on the hardest specifications.

Implication:
- This is direct Lean evidence against a universal `more branching/search structure is always better` rule.
- Difficulty / trajectory state should gate whether to fork context, preserve the current iterative trajectory, or restart. This aligns with the broader multi-action router frontier: branching is an action whose utility depends on current state, not a fixed search architecture.
- Full-context branching also suggests that proof-state features alone may omit useful controller state such as retrieval/tool history and recent failure trajectory. However, carrying full context increases interference/token cost, so the relevant question is **when** context branching beats a compact proof-state representation.

Scope:
- Verified-code generation, not pure theorem proving.
- Strong frontier model and a benchmark that nearly saturates at high budget; transfer to smaller open provers and harder theorem sets is unestablished.
- Public code is not released with the paper (available upon request), limiting immediate reproducibility.

Source:
- https://arxiv.org/abs/2605.27485

## Frontier refinement

The controller should likely include at least four meta-actions above low-level proof generation:
1. preserve uninterrupted iteration;
2. fork a compact proof-state branch;
3. fork/resume a richer agent-context branch;
4. escalate retrieval from local/standard to fresh global reasoning retrieval.

The core unresolved problem is a calibrated utility estimator that decides among those actions under a substrate-aware cost model and partial-observation/coverage constraints.
