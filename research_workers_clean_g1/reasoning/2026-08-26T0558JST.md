## C74 — The released training objective uses only terminal rubric score even though the codebase computes a richer cost/error/early-submit aggregate

The paper says AW uses only terminal task-rubric rewards. Code inspection resolves a possible ambiguity:
- `code/harness/submission.py` computes a rich `aggregate_reward` containing rubric, verifier, format, task, error penalty, cost penalty, and early-submit penalty, and returns it under `R_total_breakdown`.
- `examples/running_main_driver.py`, however, stores both `structural_score` and `return_G` as `scored["rubric_score_norm"]`.
- `code/rl/offline_aw.py` computes per-task advantages from `return_G`, then assigns every step in a trajectory the same clipped weight `exp((G_i - mean_task_G)/beta)` with beta=0.2, clip [0.1,10], 64-hidden-unit MLP, Adam 1e-3, 20 epochs, batch 256, entropy coefficient 0.01.

So the published AW policy is terminal-rubric advantage weighting, not direct optimization of the richer cost-aware aggregate. This strengthens the Lean experiment design: retain terminal kernel-verified solve/reusable verified progress as reward targets, but log model/token/$/Lean execution/state reconstruction/concurrency wall-clock as a separate cost vector first. Do not silently claim cost-aware policy learning merely because the harness computes cost diagnostics.

It also sharpens the credit-assignment gap: all actions in a high-return trajectory inherit the same scalar trajectory weight. Lean can test whether deterministic compiler/kernel transitions permit better step credit without changing the terminal objective.

## C75 — The perturbed-base collector gives an exact propensity formula, but the released trajectory record does not make propensity a first-class logged field

In `code/rl/generic_harness.py`, collection uses a deterministic Base policy perturbed with epsilon (default 0.25): with probability epsilon choose uniformly from the currently legal action mask; otherwise execute the deterministic Base action. If the legal set has size L and deterministic legal Base action is b, the exact behavior policy is:

- mu(b|s) = (1-epsilon) + epsilon/L
- mu(a|s) = epsilon/L for every other legal a
- mu(a|s) = 0 for masked actions.

The action mask prevents submit/check/revise/citation before a draft and removes pad/no-op slots; invalid sampled actions are replaced with a deterministic first-legal fallback. The episode runner also force-submits on budget exhaustion, no legal action, or max steps.

This is a good OPE-identifiable template, but the release's ordinary trajectory records do not explicitly log the legal mask, Base action, epsilon, full behavior probability vector, or chosen-action propensity. In principle they can be reconstructed only if the exact harness version, task, replayable state and fallback semantics are retained. A Lean dataset should instead log them directly at each controller decision.

### Safe Lean randomized behavior matrix

Use a more general mixture that permits terminal/expensive actions to be baseline-only rather than random exploration alternatives.

At state s:
1. Construct full legal action set L(s) from verifier/environment hard constraints.
2. Compute deterministic baseline action b(s) in L(s), applying a deterministic fallback if the nominal baseline action is illegal.
3. Construct randomized exploration subset R(s) subseteq L(s), initially containing only reversible/bounded actions (for example local continue/tactic branch, bounded compiler-guided repair, bounded retrieval/read, local backtrack to a saved proof state). Exclude destructive repository writes, unbounded worker/model escalation and premature terminal submit from R(s) in Stage A.
4. For epsilon in [0,1], define
   - mu(a|s) = (1-epsilon) * 1[a=b(s)] + epsilon/|R(s)| * 1[a in R(s)] when R(s) is nonempty;
   - mu(b(s)|s)=1 when R(s) is empty.

This handles the case b(s) is not itself randomized: if b notin R, Base gets exactly 1-epsilon rather than `(1-epsilon)+epsilon/|R|`. Log `{legal_actions, randomized_actions, base_action, fallback_rule_version, epsilon, chosen_action, mu_chosen, full_mu_vector, controller_state_hash}`.

Stage B can introduce a separately bounded expensive-action mixture only in preregistered eligible states, with an independent mixture weight delta and exact propensity. This avoids paying for broad random expensive actions merely to achieve support.
