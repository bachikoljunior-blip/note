## C267 — semantic idempotence is weaker than causal/cost idempotence
CSSC's `AttemptWorkspace.write_candidate()` is encouraging but not enough to make checker-bearing actions replay-safe for policy data. Candidate identity is a deterministic SHA-256 prefix over task ID, parent node ID, action and edit text, and writing the same candidate rewrites the same deterministic path. Thus candidate *materialization* can often be replayed without creating a second semantic candidate.

However, `IMPLEMENT`, `REPAIR_IMPLEMENTATION` and capability-test paths also invoke a checker after materialization. If the process crashes after the checker starts or finishes but before a durable Outcome/receipt, re-running the same deterministic candidate can consume checker wall time/CPU again while the first invocation's cost/result is missing from the journal. Final proof semantics might match while the action's causal cost label is wrong.

Therefore `same candidate bytes/path` must not be conflated with `exactly-once action execution` or `OPE-safe replay`.

## C268 — effectful support needs a durable effect-attempt/receipt layer, not just Decision/Outcome
Before checker/tool/model-bearing actions can enter randomized support, add an explicit effect protocol underneath the action Outcome:

```text
EffectAttemptEventV0:
  effect_operation_id
  decision_id
  effect_kind
  input_semantic_sha256
  substrate/version identity
  started_at
  idempotency_contract nullable

EffectReceiptEventV0:
  effect_operation_id
  status
  result_semantic_sha256 or queryable receipt ref
  measured resource/cost vector
  completed_at
```

The Attempt must be committed before dispatch. The Receipt is committed after the effect returns. A committed Attempt without Receipt is `in_doubt`; it is never interpreted as zero-cost, failed, or not-started merely because the action Outcome is missing.

For a substrate that later offers true idempotency/queryability, recovery may reconcile the same `effect_operation_id`. Without such a verified contract, v0 remains fail-closed.

## C269 — crash-censored effectful trajectories require explicit statistical treatment
For randomized/OPE data, an in-doubt checker/tool action creates missing outcome and potentially missing cost *after a known behavior-policy choice*. Treating it as reward 0 or cost 0 would bias both utility and value-per-cost estimates.

Minimum v0 contract:
- preserve the original Decision and exact behavior propensity;
- preserve the committed EffectAttempt as proof that execution may have begun;
- mark the action/trajectory suffix `censored_effect_in_doubt`;
- do not synthesize a terminal reward or measured cost for the unreceipted effect;
- do not silently drop the row before coverage/support diagnostics, because crash frequency itself may be action-dependent;
- any later estimator using these rows must state its censoring assumption or exclude unsupported suffixes conservatively.

This is distinct from pure-reducer recovery, where the selected deterministic transition can be replayed under the same decision identity and completed normally.

## C270 — narrow structural Stage A has an additional scientific advantage
Keeping the first randomized support to verified pure-reducer structural actions is not only an engineering convenience. It removes ambiguous external/checker effect recovery from the first causal comparison, so:

- behavior propensity is still exact;
- provider-generation cost remains upstream/fixed for the Stage-A selector;
- selected transition can be replayed from a content-addressed workspace snapshot;
- outcome/cost censoring from checker effects cannot differentially distort the compared structural alternatives;
- epsilon=0 equivalence and fault-injection are substantially easier to falsify.

The full baseline frontier should still be recorded. The exploration distribution may be narrower than the baseline action set until each effectful kind has a verified effect-attempt/receipt/idempotency contract.

## Falsification / limits

- This checkpoint does not claim an effect journal exists in current CSSC.
- The proposed censoring treatment is a data contract, not a claim that a particular OPE estimator is unbiased under informative crashes.
