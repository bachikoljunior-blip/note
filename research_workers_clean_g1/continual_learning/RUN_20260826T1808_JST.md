### Replay path
For buffer experiments, the stream minibatch is 32 and replay minibatch is 32 under script-level `batchsize=64`. Memory replacement is standard reservoir-style sampling over the seen stream: after the buffer fills, a random integer in `[0, seen)` decides whether and which memory slot is replaced. Replay batches are sampled uniformly by random permutation of the current memory, with no explicit class-balancing or importance weighting in the inspected path. Memory is updated after the current sample's `online_iter=3` updates, so the same incoming example is not first inserted and then replayed within those three updates.

This matters for causal interpretation: SinglePrompt's buffer gains are not evidence for a sophisticated replay selector. They sit on top of ordinary reservoir retention + uniform random replay, making the classifier-interference/prefix mechanism easier to separate from replay-policy complexity.
