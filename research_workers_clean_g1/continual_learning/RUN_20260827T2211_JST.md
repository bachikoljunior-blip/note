## Critical paper ↔ release-code mismatch 1: support selection topology

Paper Eq. 16 describes protecting the global top `p%` of all parameter coordinates by absolute realized movement.

The released `src/compute_importance_mask.py` instead applies `k=floor(numel*p/100)` and `torch.topk` **inside every floating parameter tensor independently**; the source comment explicitly calls this per-parameter selection with `no global threshold`. The 2B/4B/8B public CPO launchers all use `p=10%`.

This changes the mechanism materially. Global TopP can concentrate protection in high-movement tensors/layers. Per-tensor TopP forces approximately 10% protected support in each sufficiently large tensor even when its absolute movements are globally small.

## Critical mismatch 2: normalization topology

Paper objective uses one global denominator `M = ||m||_0`:

`lambda/M * sum_{all protected k} |theta_k - theta_ref,k|`.

Released `CLGRPOTrainer` instead normalizes each tensor independently. For tensor `t` with `m_t` protected coordinates it injects approximately:

`lambda/m_t * sign(theta_t - ref_t)`

at those coordinates, then sums contributions over tensors.

Therefore, for a protected nonzero coordinate in tensor `t`, the release-code/paper per-coordinate gradient-magnitude ratio is:

`M / m_t`.

Small protected tensors can consequently receive far stronger per-coordinate regularization than under the paper objective. Ignoring zero deviations, the paper allocates roughly one total L1-gradient budget `lambda`, whereas the release code allocates roughly one `lambda` budget per protected tensor. This is a major mechanistic distinction.

## Theory-to-practice scope

The paper's movement-to-Fisher argument is a conditional locally-stationary SGD-style approximation. Public launchers use AdamW, weight decay 0.1, warmup, cosine LR, GRPO/GSPO noise, and ZeRO-3 offload. This is not an implementation bug, but it means observed movement is only a hypothesis-level proxy for Fisher importance in the released training regime; optimizer preconditioning, decay, schedule and RL noise can change coordinate ranking.

## Durable-state cost is not zero even though replay data is zero

The public mask artifact stores a dense `torch.bool` mask over protected parameter tensors plus float32 reference values at all cumulative protected coordinates. Hence replay-free does not imply negligible durable state.

Order-of-magnitude example only, not a measured artifact: with ~8.8B float parameters and 10% protected support, one cumulative file is roughly `8.8 GB` of dense one-byte boolean mask plus `3.52 GB` of float32 references, around `12.32 GB` before serialization overhead. If four 10%-supports were independent, expected union is `1-0.9^4 = 34.39%`, giving roughly `20.9 GB` for the fourth cumulative mask file. Actual Qwen float-parameter count, support overlap, serialization and runtime transfer cost must be measured before reporting realized numbers.
