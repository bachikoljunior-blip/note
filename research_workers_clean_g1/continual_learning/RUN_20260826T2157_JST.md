## Branch A — Share public artifact is a constant-size current adapter, not an internal task bank

Official public source anchor: `ankit-vaidya19/Share@ed4bc9c261f4389b1c2abd639e4f55ae81a1028b`.

The strict NLU continual driver uses a 6-task order COLA→MRPC→RTE→STSB→QNLI→SST2 with EigenFlux rank 8, 32 components and two rank-update factors. Each new task consumes only the immediately previous trained task artifact as its previous EigenFlux state. During final evaluation the code folds the trainable rank-update factors into a recalculated EigenFlux basis, then its custom PEFT save path writes only `components` and `loadings`. The saved CURRENT task artifact therefore contains one standalone current EigenFlux state; it does not contain a selector-indexed bank of historical task coefficient sets.

`NLU/weight_update.py` is a separate post-hoc archival operation. It PCA-fuses the immediately previous and current EigenFlux matrices and writes an `updated.safetensors` for the previous task. That updated previous artifact is not fed into the next task's continuation path. This strengthens the paper/code contract distinction: paper storage discussion can describe shared-basis + lightweight per-task coefficients, but the released strict GLUE runtime deploys one evolving current adapter and keeps historical states as separate files rather than routing among them.

For RoBERTa, the released EigenFlux target mapping is `query` and `value` in every layer. With RoBERTa-base dimensions 768, 12 layers, rank 8 and 32 components, one saved adapter state contributes 1,191,936 EigenFlux tensor parameters (24 adapted linears × [2×768×32 + 2×32×8]), excluding classifier/modules-to-save and metadata. That is 4.546875 MiB fp32-equivalent or 2.2734375 MiB fp16/bf16-equivalent per task. Six task snapshots duplicate 7,151,616 EigenFlux parameters (27.28125 MiB fp32-equivalent). If the five post-hoc updated-previous copies are also retained, 11 copies total 13,111,296 EigenFlux parameters (50.015625 MiB fp32-equivalent). These are parameter-equivalent lower bounds, not measured repository artifact bytes.

Scope guard: this does not refute Share's algorithmic parameter efficiency; it shows that paper-level compact storage and the released checkpoint/archive lifecycle are distinct contracts. Actual saved classifier/head bytes and dtype still need artifact-level measurement.

## Branch B — SLoRA has constant active deploy state but linear released reconstruction archive

Official source anchor: `alina1031/SLoRA@0faf15fd6562ed3e146e8733205f59ef9742ba0f`.

For each later TRACE task, the public training code reloads every preceding denoised `max.safetensors` in order and calls `merge_and_unload()` before creating one fresh LoRA for the current task. The inference builder performs the same sequential reconstruction over all saved `order*` directories. Hence after reconstruction there is no active historical adapter bank or inference router: all prior deltas have been merged into the base. Active deployed state is constant-size, while archive size and merge/reconstruction work grow with task count.

The released LLaMA-3-8B SLoRA configuration uses rank 64 and targets q/k/v/o plus up/gate/down projections across 32 layers. Using Llama-3-8B dimensions (hidden 4096, KV projection output 1024, intermediate 14336), a rank-64 raw LoRA contains 167,772,160 A/B parameters per task, or 320 MiB at bf16. Eight raw task adapters therefore represent about 2.5 GiB of LoRA tensors. The training directory also retains a denoised `max.safetensors`; its selected rank may be smaller than 64, so 320 MiB is only an upper bound for each denoised copy. Root-level raw+denoised task archives can therefore materially exceed the 2.5 GiB raw-only floor, before trainer checkpoints/config/tokenizer files.

Because reconstruction literally merges each historical LoRA delta into base weights, a standalone full-model checkpoint saved after all merges can in principle reproduce the final inference weights without keeping the historical deltas, modulo serialization/dtype fidelity. The public scripts do not provide such a compacted merged-checkpoint path. This is also a storage trade: a standalone fp16/bf16 8B-class model is much larger than one LoRA delta and may exceed the adapter archive for short horizons. Exact future-training equivalence from a compacted checkpoint remains untested because the training/denoising lifecycle should be matched before claiming it.

## Branch C — FLEX routing is explicitly task-supervised during continual training

Official source anchor: `RINC-CL/FLEX@ba5bbccbfbad4ab9ba2985a56930a814aa1076be` (public head observed this invocation).

FLEX is a 34-task fingerprint-reduced MCIT benchmark, but its released benchmark configuration explicitly enumerates `cur_task` 0..33, a fixed task sequence, per-task train/test paths and previous-task checkpoint paths. PureLoRA allocates a fixed expert budget across all 34 tasks (total rank 272 = rank 8 per task expert). The routing implementation treats each continual-learning task as one class: router updates receive the current `task_id`, store per-task feature buffers/prototypes, and finalize those class-specific prototypes at task end. Thus FLEX is valuable as a long-horizon *inference task-identification/routing* stress test, but it is not evidence that those routers discover train-time task boundaries or latent task classes without supervision.

The released routing features use a dedicated/legacy vision tower and optional text tower. Fingerprint reduction therefore makes inference routing harder, but it does not remove the explicit training-time `cur_task` contract. Any shared-vs-router comparison must score train-time task labels/boundaries separately from inference-time task-ID freedom.

## Branch D — TFGN is a high-value boundary-free-language candidate but currently non-reproducible

Public preprint: Ganguli, `arXiv:2605.15053v2`, *TFGN: Task-Free, Replay-Free Continual Pre-Training Without Catastrophic Forgetting at LLM Scale* (May 2026). It reports six sequential text domains (Prose, Python, Math, Biomedical, Chinese, JavaScript), 1B tokens/phase, no replay/task IDs/Fisher penalty, and at LLaMA-3.1-8B Retrofit BWT about -0.007 with ≥99.59% reported L2 gradient separation. The accompanying author explainer states the routing mechanism is learned from Prose-only Phase 1, later domains are held out to that routing formation, and no external task-boundary hook drives the protection.

This is unusually close to the missing continual-language control: content-conditioned write separation with a single dense read pathway and no inference router/task ID. However, the architecture's central mechanism is explicitly withheld under NDA/patent prosecution, no implementation was found, and this search found no independent reproduction. Training is also executed as six known 1B-token domain phases, so the experiment demonstrates task-ID-free mechanism behavior under discrete dataset switches; it does not by itself establish performance on a continuously drifting mixture with unknown boundaries. Treat TFGN as a high-priority *unverified* mechanism family, not as adopted or reproduced evidence.

Public URLs: https://arxiv.org/abs/2605.15053 ; https://www.anurupganguli.com/tfgn
