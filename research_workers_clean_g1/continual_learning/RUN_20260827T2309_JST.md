### Selection effect

At `p=10%`, synthetic tensor sizes `10 / 100 / 1000` with movement concentrated in the largest tensor produce:

- global TopP: selected support `small=0, medium=0, large=111`;
- per-tensor TopP: selected support `small=1, medium=10, large=100`.

Thus public release selection can force protected coordinates into low-movement tensors that a global ranking would not protect. This is a mechanism change, not an implementation-detail equivalence.

### Normalization effect

A second synthetic case was constructed so both selectors choose the exact same support: `small=1`, `large=9`.

- global normalization gives aggregate masked-coordinate L1 gradient budget `1.0 * lambda`;
- per-tensor normalization gives aggregate budget `2.0 * lambda`;
- the single protected coordinate in the small tensor receives absolute gradient `0.1 * lambda` under global normalization but `1.0 * lambda` under per-tensor normalization, a `10x` ratio.

In general, for a protected coordinate in tensor `t`, public-release versus paper-global per-coordinate magnitude is `M/m_t`. With nonzero deviations in `T` protected tensors, the release objective is effectively `lambda * sum_t mean_t(|theta-ref|)`, whereas the paper objective is `lambda * mean_all_masked(|theta-ref|)`. Consequently aggregate coordinate-gradient budget can scale roughly with the number of protected tensors rather than staying at one global `lambda` budget. Actual optimization behavior still depends on sign patterns, gradient accumulation, optimizer dynamics, ZeRO partitioning and interaction with the RL gradient.

## Durable-state and normalization topology remain high-priority costs

Release code stores a dense boolean mask for every included tensor plus float32 reference values at all cumulative protected coordinates. It also uses full-model continual training in the public GSPO launcher (`freeze_vision_tower=False`, `freeze_llm=False`, `freeze_merger=False`) and `top_percent=10`.

The public Qwen3-VL-2B bf16 weight topology can only be used as a reconstruction proxy, not as an author checkpoint measurement. A public bf16 mirror reports `4,255,064,064` serialized weight bytes and 625 weight-map entries, corresponding to roughly `2.128B` bf16 weight elements if the payload is entirely bf16. If nearly all such weight tensors moved, a first-task raw mask/reference payload at 10% would be on the order of `2.13 GB` dense bool plus `0.85 GB` float32 references before serialization overhead. Do not report this as measured CPO storage: unchanged tensors can be skipped, cumulative overlap is unknown, and actual author artifacts are unavailable.

The tensor count also makes the release normalization topology potentially consequential: if hundreds of tensors have nonzero protected support, the release objective can distribute roughly one `lambda`-normalized mean-L1 contribution per tensor, unlike the paper's single global normalization. Exact active tensor count and realized regularizer/RL gradient ratio must be measured, not inferred from weight-map entry count.
