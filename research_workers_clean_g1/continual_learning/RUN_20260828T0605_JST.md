### 2. PyTorch 2.8 has the exact namespace asymmetry that the repair targets

First-party PyTorch v2.8.0 source was checked directly.

- `named_parameters(..., remove_duplicate=True)` defaults to duplicate removal and delegates to `_named_members`, whose memo set suppresses repeated member objects.
- `_save_to_state_dict`, by contrast, writes every registered parameter name and every persistent buffer name without duplicate-member filtering.

The same relevant bodies are structurally/textually equivalent in PyTorch v2.10.0. Therefore the specific alias-vs-canonical namespace behavior exercised by the prior 2.10 synthetic harness is not a newly introduced 2.10 behavior; it is present in the pinned PyTorch 2.8 source as well.

This is **source equivalence, not a direct PyTorch-2.8 runtime execution**. The direct 2.8 run remains on the frontier.
