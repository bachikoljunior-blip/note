## Branch G — SpaRTA: structural write separation does most of the work; routing is a smaller marginal gain and still relies on task-bounded training

Primary source: Zhang et al., `SpaRTA: Spectral Disentanglement for Continual Learning in Large Language Models`, ACL 2026. Public ACL paper/PDF and public repository `Xnhyacinth/SpaRTA` were inspected where available.

Mechanism: SpaRTA splits adaptation into shared low-rank and task-specific high-rank spectral branches, restores shared components stochastically, learns modulation weights, adds an input-conditioned router, and regularizes task-specific components for orthogonality. The valuable mechanistic result is the component ablation, not merely the headline accuracy.

Ablation on the paper's reported FP metric:
- baseline E1: `73.0`
- high-rank only: `73.7`
- low-rank only: `75.4`
- dual branches: `77.6`
- + stochastic restoration: `78.1`
- + learned static modulation weights: `78.6`
- + full dynamic router: `79.2`
- + orthogonality: `79.5`

This makes the current working interpretation precise: dual shared/specific structure contributes `+4.6` points over baseline, whereas replacing learned static modulation with the full dynamic router contributes only `+0.6`, and orthogonality adds another `+0.3` under this setup. Routing is therefore not the dominant causal ingredient in the reported ablation.

Main rehearsal-free results are still strong. On LLaMA-3.1-8B the paper reports SpaRTA SC FP/AP/Forget `80.9/80.6/-0.3`, LS `80.0/82.3/2.3`, TRACE `72.7/80.4/7.7`, while O-LoRA reports `72.3/73.9/1.6`, `71.4/74.8/3.7`, and `36.7/50.1/13.4`. Training-efficiency table reports SpaRTA `4.6e16` FLOPs, `0.38%` trainable parameters, zero stored features, and 141 ms prediction versus SeqLoRA `2.6e16/0.30%/89 ms`, LoRAReplay `4.8e16/0.30%/2% stored features/90 ms`, and O-LoRA `8.8e16/0.46%/196 ms`.

Critical scope guard: SpaRTA training is not task-free. Progressive Subspace Isolation partitions a fixed component pool into task-specific subsets and unlocks only `M/N` fresh components when task `T_t` arrives; the appendix allocates `N_layer/4` components per task, so total router/component capacity grows with declared task count `N`. The authors explicitly list clear task boundaries/supervised objectives as a limitation and say task-free continual learning is untested. Therefore `stored features = 0` must not be interpreted as horizon-constant total adaptive state, and the routing result must not be exported to unknown-boundary streams.

Status: **strong task-bounded structural-adaptation evidence; routing is a modest incremental component under the tested ablation, not a demonstrated necessity for boundary-free continual learning.**

## Branch H — Transfer-Selective Replay (TSR): audit transfer opportunity before paying for replay routing, and count the full task memory

Primary source: Meng et al., `Rethinking Transfer in Continual Learning: A Replay-Based Realisation`, arXiv:2607.15587 (2026-07-17), plus official public code `ymeng3/transfer-selective-replay`.

Mechanism: estimate a task signature from gradients at a fixed shared LoRA initialization, compare it to signatures of completed tasks, select/weight replay sources by cosine similarity, and optionally distill from task-era LoRA snapshots. The paper's useful conceptual decomposition is: transfer requires (1) target headroom, (2) a persistent carrier, and (3) compatible source experience.

Low-budget TRACE-8 / NumGLUE-8 results (overall / plasticity / BWT):
- TRACE 0.5B ER: `.451/.427/+0.025`; TSR: `.475/.439/+0.035`.
- TRACE 7B ER: `.656/.662/-0.006`; TSR: `.684/.670/+0.014`.
- NumGLUE 0.5B ER: `.336/.314/+0.025`; TSR: `.353/.330/+0.026`.
- NumGLUE 7B ER: `.578/.579/-0.001`; TSR: `.588/.582/+0.007`.

The paper reports that target headroom shrinks with model scale: on the TRACE transfer probe at 7B the oracle buys essentially nothing, while signature picks remain largely scale-stable. It also finds heterogeneous TRACE benefits more from source selection than homogeneous NumGLUE, where pooling can be competitive. This supports a general gate: **do not add selector/router complexity before verifying that target data leave transfer headroom and that source compatibility is heterogeneous enough to matter.**

Routing/teacher evidence also limits mechanism claims. On TRACE 0.5B, uniform ER is `.451/.427/+0.025`, argmax selection `.439/.430/+0.010`, soft routing with recent teacher `.459/.436/+0.023`, pool-hybrid `.459/.435/+0.024`, and the full routed-triple `.475/.439/+0.035`. In a teacher audit, random and oracle teacher identities are close to the cosine prototype, while no distillation is much worse; the paper interprets KD mainly as anchoring/regularization rather than reliable cross-task knowledge transfer in this low-rank frozen-base regime.

Critical durability/storage correction from the official code:
- `src/train_stream.py` keeps `buffer`, `sigs`, and `snaps` dictionaries in memory.
- after every task it executes `snaps[t_idx] = snapshot(layers)`.
- `src/lora.py` defines `snapshot` as a detached clone of every LoRA layer's `A` and `B` tensors.
- the public result JSON persists metrics, but this task memory is not durably saved/reloaded by the shown training path.

Therefore the operational memory is not just the paper's small raw replay-buffer byte count: it also includes one full LoRA snapshot per completed task plus signatures, and the evaluated task-memory lifecycle is not restart-persistent in the inspected public path. Snapshot archive cost scales linearly with task count. Do not convert this into an exact byte estimate until the exact target-module/model architecture accounting is fixed.

Scope guard: TSR is also task-incremental at training: tasks arrive one at a time with labelled data and known segmentation. It is task-ID-free at inference, not unknown-boundary training.

Status: **medium-strong evidence for headroom/compatibility-gated replay selection; incomplete full-memory/restart accounting is a concrete implementation caveat.**

## Branch I — ELLA: constant-memory selective de-correlation is a stronger non-routing baseline, but the camera-ready paper itself clarifies that training is task-labelled

Primary source: Das Biswas et al., `ELLA: Efficient Lifelong Learning for Adapters in Large Language Models`, EACL 2026, ACL Anthology `2026.eacl-long.84`.

Mechanism: instead of storing all past LoRA adapters or enforcing strict orthogonality, maintain one aggregated past-update matrix `W_past = sum_i ΔW_i` and penalize element-wise alignment of the current update with high-energy coordinates: `||ΔW_t * W_past||_F^2`. The paper characterizes this as anisotropic shrinkage: heavily used past coordinates are suppressed more, low-energy coordinates remain reusable. Appendix scalability discussion states the aggregated matrix is about `4 MB` and memory/compute are constant with task-sequence length.

Representative results:
- T5-Large OA: Standard CL `79.9`, Long Sequence `73.6`, TRACE `40.0`.
- LLaMA-3.1-8B OA: Standard CL `77.57`, Long Sequence `74.18`, TRACE `33.29`; corresponding SeqLoRA values are `74.86/65.85/28.23` and SeqLoRAReplay `76.58/73.46/33.02`.
- T5-Large efficiency table: trainable params `0.062`, storage `4.19 MB`, replay `0`, `4.5 min/epoch`, versus O-LoRA storage `31.46 MB` and DATA storage `147.46 MB`.
- zero-shot general-ability table reports ELLA `ΔGA +5.48` versus SeqLoRA `-11.02`, O-LoRA `-14.81`, SeqLoRAReplay `-16.81`, DATA `-110.14` under that paper's evaluation.

Important scope correction: parts of the method narrative/caption/conclusion say no task labels or task identifiers, but the Limitations section explicitly states that **training still assumes task labels to assign task-specific LoRA parameters**; only inference is task-identification-free. The experiment protocol also uses explicit task sequences and per-order/per-task `λ` settings selected from held-out validation; e.g. TRACE/LLaMA uses a sequence of `λ` values changing across tasks. ELLA is therefore not evidence for boundary-free training. This internal clarification should override broader wording elsewhere in the paper.

A second caveat is reproducibility: a direct public code repository was not located in this invocation. The method is peer-reviewed and equations/hyperparameters are public, but implementation-level lifecycle/merge semantics have not yet been independently inspected.

Status: **high-value constant-memory non-routing comparator for task-bounded streams. It strengthens the hypothesis that selective protected writes can capture much of the stability/transfer benefit without a router, but it does not solve unsupervised task discovery.**

## Updated cross-mechanism principle

The current frontier is more specific than `shared state vs routing`:
1. **Audit whether transfer is available at all.** Measure target-data headroom and source heterogeneity before paying for replay/router complexity.
2. **Separate structural write partition from routing.** SpaRTA's ablation assigns most gain to shared/specific dual branches; the router adds a smaller marginal gain under known boundaries.
3. **Prefer horizon-constant protected-write controls in every routed comparison.** ELLA provides a concrete selective-decorrelation baseline with one aggregated state matrix, avoiding orthogonal-space exhaustion and task-linear adapter archives at inference-time state.
4. **Account all durable state, not only headline replay bytes or `stored features`.** Include signatures, router/component pools, teacher snapshots, prompt populations, optimizer/controller state, restart reconstruction and archival checkpoints.
5. **Do not conflate task-ID-free inference with boundary-free training.** SpaRTA, TSR and ELLA all use task segmentation/labels during training despite different inference contracts.
