## 3. The released parquet cannot recover those hyperparameters even if its bytes become reachable
`collect.py::collect_dataset()` intentionally writes only these parquet columns: `boundary`, `strategy`, `detector`, `seed`, `error_stream`, `trues`, `preds`, `max_delay`, `max_early`. It does **not** serialize detector configuration, Optuna trial number, best score, parameter values, source SHA, or CapyMOA version.

Therefore raw `CLDD_A.parquet` is still valuable for MD5/row-count/seed/event-array verification, but **it cannot resolve five-stream-vs-ten-stream winning-HP provenance by itself**. That requires the ignored `best_params.yml` / `best_trial.yml`, console logs, an experiment archive, or an external execution receipt binding those artifacts to the uploaded dataset.
