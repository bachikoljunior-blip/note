The paper states a batch size of **32**, which initially looks like a code-paper mismatch. Reading the shared trainer resolves it: `_Trainer.__init__` unconditionally sets `self.temp_batchsize = self.batchsize // 2`, and the stream training DataLoader uses `batch_size=self.temp_batchsize`. Thus the official script's `BATCHSIZE=64` produces an actual incoming stream minibatch of **32**, matching the paper. In buffer mode, the remaining 32 slots are assigned to `memory_batchsize`, so an optimization step can combine 32 current + 32 replay examples while preserving the 32-example incoming minibatch convention.
