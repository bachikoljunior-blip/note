## 3. `--seed 42` is inert in the UC8 entrypoint; the published run loop remains stochastic
The entrypoint parses `args.seed` but never applies it. There is no `np.random.seed(args.seed)`, `torch.manual_seed(args.seed)`, Python `random.seed`, or generator passed to the window/threshold routines in the inspected script.

This matters because the exact execution path uses NumPy global RNG repeatedly:
- comparison reference subsampling uses `np.random.choice`;
- `WindowsGenerator.balanced_without_drift_windows_generation` shuffles source arrays with `np.random.permutation`, samples each class with `np.random.choice`, and shuffles each sampled window again;
- DriftLens random threshold estimation samples windows and shuffles them using NumPy global RNG.

Thus `--number_of_runs 5 --seed 42` does **not** mean five reproducible runs under a fixed seed. The five runs are successive draws from the process-global RNG state (plus any detector-library randomness), and exact outputs are not replayable from the CLI seed alone.

## 4. Window construction semantics are exact enough to reconstruct
For UC8, `training_label_list = drift_label_list = [0..9]`. Each evaluation window calls `balanced_without_drift_windows_generation(window_size=250, n_windows=1, flag_shuffle=True, flag_replacement=True)` on either the non-drift new-unseen embedding pool or one precomputed drift-percentage embedding pool.

Inside `_balanced_sampling`:
- `250 // 10 = 25` examples are drawn for each label;
- there is no residual because `250 % 10 = 0`;
- the class draw itself hard-codes `replace=False` even when `flag_replacement=True`;
- `flag_replacement=True` only prevents deletion from the temporary class pools, so samples may be reused across separately generated windows, but there are no duplicate indices for a label within one 25-example class draw;
- source arrays are shuffled first and each final window is shuffled again.

Because the entrypoint instantiates a fresh `WindowsGenerator` for every single window, replacement semantics are effectively: balanced sampling without duplicate indices within each label/window, but unconstrained reuse across windows.

Ground truth is not temporal: all 100 windows are labeled no-drift for `0%`, and all 100 are labeled drift for each nonzero blur-percentage pool. This is a repeated independent-window classification experiment, not a stable→shift change-point sequence. It cannot by itself yield detection delay/NDT or event-level false-alarm behavior.

## 5. DriftLens baseline/PCA and threshold estimator are now explicit
If `--run_driftlens` is added manually:
- baseline is estimated from the full train embedding using predicted labels and PCA dimensions `batch_n_pc=150`, `per_label_n_pc=25`;
- threshold windows are sampled from the test embedding with `window_size=250`, `n_samples=10000`, balanced labels, and cross-window reuse enabled;
- the random-threshold estimator samples without duplicate indices within each label/window, then shuffles each window;
- the returned per-batch Frechet distances are sorted, but the UC8 entrypoint then ignores the CLI `threshold_sensitivity` value.

The actual threshold calculation is:
1. convert the 10,000 per-batch distances to an array;
2. keep values strictly greater than the empirical 1% quantile and strictly less than the empirical 99% quantile;
3. set threshold to the maximum remaining value.

Therefore `--threshold_sensitivity 99` is **inert in this UC8 entrypoint**. The effective threshold is approximately the largest observed threshold-sampling distance below the empirical 99th percentile after also trimming the bottom 1%, not a generic configurable sensitivity parameter.

The estimator's `flag_shuffle` argument is also not used to condition the RandomSampling estimator's behavior: its sampled windows are explicitly shuffled regardless. This is a code-contract detail, not a method-level claim.

## 6. Comparator reference-window semantics
The official wrapper sets MMD reference subsample target 8,500 and LSDD 14,000; if the target is at least the train-set length the full train set is used. CVM and KS pass `-1`, which routes to the full train set. When subsampling is active, the entrypoint draws an equal target count per label using NumPy global RNG, without replacement within each class. These reference subsamples are redrawn once per outer run, before evaluating all drift percentages in that run.

Detector initialization is then:
- KS: `p_val=.05`
- MMD: `p_val=.05`, 100 permutations, PyTorch backend
- LSDD: `p_val=.05`, PyTorch backend
- CVM: `p_val=.05`.

The run's reported metric is window-level accuracy for each separately generated 0/5/10/15/20% condition, followed by a harmonic mean combining 0%-condition mean accuracy with the mean of the nonzero-condition mean accuracies. This metric can hide alarm multiplicity and timing because there is no temporal event structure.
