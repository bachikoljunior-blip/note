## New source-level result: public CPO retains dense masks after their values become semantically dead

Public anchor remains `MaolinLuo/CPO@9429452cb536a9e713b73b91c0011b96df44962c`.

In `src/trainer/grpo_trainer_cl.py`, the release does the following at trainer construction:

1. loads `importance_mask` as dense bool tensors and `ref_weights` as float32 tensors;
2. immediately derives `_mask_flat_idx[name] = mask.nonzero()` as int64 indices;
3. keeps the full dense `importance_mask` dictionary resident for the trainer lifetime.

After `_mask_flat_idx` is built, the bool **values** are not used again. Later code uses `importance_mask` only for key membership (`name in self.importance_mask`) and `len(self.importance_mask)` logging. The actual regularizer uses `_mask_flat_idx` plus `ref_weights`.

Therefore a conservative semantics-preserving repair is available before changing the on-disk format:

- derive `_mask_flat_idx` exactly as today;
- retain a small key set / use `_mask_flat_idx` membership;
- release each dense bool mask after its indices are materialized;
- preserve `ref_weights` and the current int64 indices unchanged.

This is distinct from the earlier canonical trainer-namespace repair. Canonical filtering removes dead state-dict aliases/buffers; mask-drop removes the dense bool copy for every *valid* protected tensor after index derivation.

1. **Canonical trainer-namespace filter**: build masks only for names that the trainer can actually consume, eliminating tied aliases/dead state safely without storage-identity dedup.
