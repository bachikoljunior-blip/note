## 2. New candidate CLG1-CL-019 — CLDD provides an event-level temporal benchmark for continual-learning boundary detection
Primary public artifact: Anton Lee, `Continual Learners as a Drift Detection dataset` (CLDD), Zenodo DOI `10.5281/zenodo.21232615`, published 2026-07-07, with reproducible source at `tachyonicClock/cldd`.

CLDD is a collection of per-instance error streams generated by online continual learners specifically for drift-detector development. This materially fills a gap in the current frontier: DriftLens UC8 evaluates independent drift/no-drift windows, whereas CLDD stores temporal event positions (`trues`), detector alarm positions (`preds`), and explicit acceptable early/delay windows.

### Dataset structure
- CLDD-A uses an oracle boundary detector and is a full factorial of 3 boundary types × 6 continual-learning strategies × 1 detector × 20 seeds = 360 configurations. The documented standard split is 10 training seeds and 10 test seeds.
- CLDD-B uses imperfect detectors and is 3 boundaries × 5 strategies × 5 detectors × 10 seeds = 750 configurations.
- Boundary regimes are abrupt (`w=0`), gradual (`w=0.1`) and slow (`w=0.2`).
- Strategies in the public workflow are EWC, FT, LWF, MAS, RWalk and SI; FT is detector-agnostic and therefore omitted from CLDD-B. Imperfect detectors are ADWIN, DDM, Page-Hinkley, SEED and STEPD.
- Each exported row carries an `error_stream` of roughly 300k per-instance booleans, `trues`, `preds`, `max_delay`, and `max_early`.

### Strong evaluation-design feature: open-loop detector quality can be separated from closed-loop learner impact
The public workflow is explicitly three-phase: tune continual-learning strategy hyperparameters with oracle boundaries; generate oracle-controlled error streams and tune detector hyperparameters; evaluate final configurations on held-out random seeds. `dodo.py` creates ten error-stream seeds from `random.Random(0)` and a disjoint set of ten evaluation seeds from `random.Random(1)`.

Crucially, the `dd_run` path replays tuned drift detectors on oracle evaluation error streams. This provides an **open-loop** comparison: every detector sees a fixed learner-generated temporal signal, so detector alarms cannot change the future learner/error stream during the comparison. Separately, CLDD-B/full `evaluate` runs are **closed-loop**: detected boundaries are emitted back to the continual learner, so detector behavior can alter the learner and therefore its future error stream.

This separation is a useful general evaluation contract for continual/adaptive systems:
1. first measure boundary/alarm quality on a fixed stream;
2. then measure closed-loop downstream utility after the alarm is allowed to change the learner;
3. do not collapse the two into one score because a detector can be temporally accurate yet harmful to the learner, or imperfect as an event detector yet still improve downstream continual-learning utility.

### Event scoring details
The public experiment constructs `EvaluateDriftDetector` with symmetric acceptable early/delay width
`int(mean_task_length * scenario.gradual + mb_train * 10)` and `rate_period=int(mean_task_length)`. Therefore timing tolerance intentionally grows from abrupt to gradual/slow transitions. Raw detector F1/MDT/FAR across boundary types should not be compared as if all regimes used an identical timing window.

The source also exports standard drift-detection metrics (`precision`, `recall`, `f1`, `mdt`, `far`) and continual-learning metrics (`accuracy_final`, `accuracy_seen_avg`, forward transfer, backward transfer). This supports the desired two-axis evaluation: event quality plus learner utility.

### Scope limitation
CLDD's detector signal is current-label-dependent: the public implementation feeds per-instance cross-entropy loss or misclassification error into the detector. It is therefore **not** evidence for label-free, unsupervised same-label visual change-point detection at deployment time. It complements rather than replaces the planned DriftLens/LargeMonitor-style representation-score temporal benchmark.

Status: strong evaluation artifact / medium mechanism relevance. It is most valuable as a clean benchmark and causal evaluation design, not as a new continual-learning algorithm by itself.

## 3. CLDD reproducibility/metric issues that must be scoped narrowly
### 3.1 CLDD-B seed-count documentation is internally inconsistent
The Zenodo text says `Only 5 seeds exists for CLDD-B configurations`, but the same record defines the factorial as 3 × 5 × 5 × 10 = 750 and lists count-each = 10. The repository's dataset test likewise asserts 750 rows and explicitly notes this documentation inconsistency. Treat the actual public dataset/factorial as ten seeds per CLDD-B configuration unless direct artifact inspection disproves it.

### 3.2 A raw auxiliary `my_precision` field is assigned incorrectly, but this does not contaminate the standard collected metrics
`src/drift_detector.py` constructs a custom drift confusion object but assigns `metrics["my_precision"] = drift_cm.fn` rather than `drift_cm.precision`. `src/metrics.py` defines the correct `precision` property, so this is a clear bookkeeping bug in the auxiliary raw field.

Scope guard: `collect.py` does not include `my_precision` in the collected metric keys. It uses the evaluator's standard `precision`, `recall`, `f1`, `mdt`, `far`, plus `my_f1`, `my_fp`, `my_tp`, and `my_fn`. Therefore this bug should not be claimed to invalidate CLDD parquet data or the standard collected detector metrics. It matters only to consumers who directly trust the raw `dd_metrics.pkl["my_precision"]` field.

### 3.3 Error-stream docstring polarity is stale, but implementation/dataset semantics are clear
The `ERROR` enum docstring says 1 means correct and 0 incorrect, whereas implementation appends `(y != y_pred).bool()`, so True/1 means error. Zenodo describes the column as per-instance errors. Treat implementation + dataset definition as authoritative and the enum prose as a documentation defect.

### 3.4 Reproducible dataset source generation exists, but the generated `.pt` is not tracked in the current Git tree
The current scenario loads `data/rotated_fashion_mnist_data.pt`; the checked-in data directory exposes a task PDF but not that `.pt`. `script/rfmnist.py` deterministically regenerates the five-task RotatedFashionMNIST dataset using CapyMOA with default `num_tasks=5`, seed 0 and then `torch.save`. This is a source-generation dependency, not evidence that the published Zenodo parquet files are unavailable—the actual CLDD-A/B parquet artifacts are downloadable from Zenodo.

## 4. Updated synthesis for the task-boundary frontier
The current evidence now supports two complementary benchmark layers rather than trying to force one dataset to answer everything:

**Layer A — event-controller validity on learner-derived temporal signals.** Use CLDD-A oracle-generated fixed error streams and held-out seed calibration to compare ADWIN/Page-Hinkley/CUSUM-like controllers under explicit temporal metrics. This is suitable for open-loop event quality and for studying abrupt/gradual/slow tolerance.

**Layer B — label-free same-label representation drift.** Continue the deterministic DriftLens radius-2 reconstruction or an equivalent fixed representation-score trace, then apply the same alarm controllers under held-out calibration. This tests whether controller rankings transfer when the input signal no longer depends on labels/current model errors.

Only after those open-loop comparisons should controllers be attached to a continual learner and evaluated closed-loop on retention/plasticity metrics. This prevents controller quality, representation quality and learner adaptation from being conflated.

## Scope guards
- CLDD is a benchmark/evaluation artifact, not evidence that error-rate drift detection is universally the best boundary mechanism.
- CLDD error streams use current labels; do not generalize its detector ranking to unlabeled deployment streams without a matched representation-score test.
- CLDD-A open-loop replay is especially valuable for detector causality because it fixes the input stream; CLDD-B is inherently more confounded because alarms alter learner behavior.
- Boundary-specific evaluation windows differ with transition gradualness; do not compare raw F1/MDT across regimes without accounting for tolerance definition.
- The auxiliary `my_precision` bug is narrow and does not invalidate the standard evaluator metrics or parquet event arrays.
- DriftLens public artifact gaps remain reproducibility gaps, not method-failure evidence.
