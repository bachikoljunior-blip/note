## 4. Important scope downgrade: the public 25-vs-paper-75 per-label PCA mismatch does not drive the main per-batch detection metric in the inspected code
The final paper states `d'=150` per-batch and `d'_l=75` per-label (except use case 10). The public STL-blur wrapper uses 150/25. However, direct inspection of the March 2024 DriftLens implementation shows the per-batch and per-label PCA models are fitted separately. `_compute_frechet_distribution_distances` transforms the whole window with the batch PCA for `per-batch`, and separately transforms each label subset with label-specific PCA for `per-label`.

The STL-blur evaluation entrypoint classifies drift using **only** `dl_distance["per-batch"] > per_batch_th`; the threshold used for reported binary window accuracy/HDD is likewise derived from the per-batch distance list. Therefore, conditional on identical embeddings/window RNG and successful baseline construction, changing only `per_label_n_pc` from 25 to 75 should not change the public entrypoint's per-batch binary predictions or HDD. It can change per-label characterization outputs, computational/memory cost, and failure behavior if per-label PCA is infeasible, but it is not a plausible direct explanation for the main UC8 drift-detection table under this code path.

This supersedes the earlier framing that the 25/75 discrepancy necessarily blocks attribution of the published UC8 detection table. The stronger unresolved provenance issue for the table is the actual embedding/model/radius/RNG/execution lineage.
