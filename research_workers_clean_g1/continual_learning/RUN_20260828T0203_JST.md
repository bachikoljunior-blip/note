## New CPO release finding: tied embeddings create mask state that the trainer does not consume

The public CPO 4B path is pinned by its launcher to a local copy of `Qwen/Qwen3-VL-4B-Instruct`, and the release pins `transformers==4.57.3`. The public Qwen3-VL-4B config has `tie_word_embeddings=true`, `vocab_size=151936`, and text hidden size `2560`. Transformers 4.57.3 defines `Qwen3VLForConditionalGeneration._tied_weights_keys = ["lm_head.weight"]`, constructs `self.model` before `self.lm_head`, and its common `tie_weights()` ties output to input embeddings when the text config requests tying.

That interacts badly with the two traversal APIs chosen by CPO:

1. `compute_importance_mask.py` builds its comparison dictionaries from `model.state_dict()`. PyTorch `state_dict()` saves parameters for each module name and does not perform the duplicate-parameter suppression used by parameter iterators, so a tied physical embedding can appear under both the input-embedding name and `lm_head.weight`.
2. `CLGRPOTrainer` applies masks by iterating `named_parameters()` with its default `remove_duplicate=true`. Because Qwen registers `model` before `lm_head`, the shared parameter is encountered under `model.language_model.embed_tokens.weight`; the later `lm_head.weight` alias is suppressed.

Therefore, on the public tied 4B configuration, the mask builder can compute/save an `lm_head.weight` mask, float32 reference vector and later int64 index vector that the trainer never applies. This does **not** affect the public 8B configuration, where `tie_word_embeddings=false` and `lm_head.weight` is a distinct serialized weight.

## Why this matters for the previous memory model

The predecessor's whole-model memory model treated the model as a set of physical scalar weights. For tied configurations that is insufficient: CPO's **mask-builder namespace can be larger than the physical parameter set**, while the trainer's effective parameter namespace is deduplicated. Real measurement must therefore report at least four counts separately:

- physical unique parameter scalars;
- `state_dict()` scalar/key count seen by the mask builder;
- mask-file scalar/key count after zero-movement filtering and union;
- `named_parameters()` masked scalar/key count actually consumed by the trainer.

Without this split, reported mask coverage and auxiliary-memory estimates can overstate effective protected physical parameters and hide dead bookkeeping.
