## New finding: “shared vs routed” is not one design axis
The current LLM continual-adaptation literature separates into at least three independent questions that are often conflated:
1. **Where persistent knowledge lives:** one sequential/shared adapter or subspace versus multiple task blocks/experts.
2. **Whether persistent task-specific state grows with task count:** e.g. task-specific coefficient sets, LoRA blocks, or mixing matrices.
3. **Whether inference requires a router/task selector:** explicit task ID, semantic key, merged all-task modules, or no routing.
A fourth orthogonal condition is whether **training itself assumes task boundaries**, even if inference is task-ID-free.

### CLG1-CL-NEW-A — SLoRA: one sequential LoRA plus subspace denoising is a strong non-routed LLM control, but training remains boundary-aware
Primary source: ACL 2026, *SLoRA: Scalable Continual Learning of Large Language Models via Subspace-Adaptive Low-Rank Adaptation*. Official public code pinned this run to `alina1031/SLoRA@0faf15fd6562ed3e146e8733205f59ef9742ba0f`.

Mechanism/scope: SLoRA uses standard LoRA training and removes task-irrelevant / interference components via task-vector subspace structure, without storing replay data or historical gradients. `SLoRA-Pre` performs the denoising after each task, so it is online in the sequential-task sense but still assumes task boundaries. `SLoRA-Post` denoises after the full sequence and is not strict online continual learning.

TRACE Table 1:
- Llama3.1-8B: Seq-LoRA 52.81 average; RCL 53.73; O-LoRA 49.31; SLoRA-Post 54.68; **SLoRA-Pre 60.19**.
- Qwen2.5-7B: Seq-LoRA 51.54; RCL 57.97; O-LoRA 46.47; SLoRA-Post 58.13; **SLoRA-Pre 59.20**.

For the first four TRACE tasks on Llama3-8B, reported ACC/average forgetting rate are Seq-LoRA **50.03 / 9.31**, O-LoRA **45.86 / 11.14**, SD-LoRA **43.24 / -0.14**, SLoRA-Pre **52.95 / 4.78**, and SLoRA-Post **49.29 / 5.09**. The negative forgetting of SD-LoRA comes with much lower accuracy, so forgetting alone is not an adequate objective.

On a 15-task sequence, reported average scores are Seq-LoRA 70.91, O-LoRA 71.50, SD-LoRA 74.37, SLoRA-Pre 72.15, SLoRA-Post 75.35.

Interpretation: this is strong evidence that a **non-routed, selective subspace cleanup/interference-control mechanism** can beat plain sequential LoRA on LLM continual learning. It is not evidence that task boundaries are unnecessary.

### CLG1-CL-NEW-B — Share: a shared basis can be extremely parameter-efficient, but the near-non-CL score is a relaxed variant and task-specific coefficient state remains
Primary/public source: *Shared LoRA Subspaces for Almost Strict Continual Learning* project/paper, accepted ECCV 2026 according to the authors' project page. Official public code pinned to `ankit-vaidya19/Share@ed4bc9c261f4389b1c2abd639e4f55ae81a1028b`.

The public NLU pipeline is explicitly sequential: `COLA → MRPC → RTE → STSB → QNLI → SST-2`.

Key NLU table:
- Upper Bound: average 83.90, 125M parameters / 500MB.
- non-CL LoRA: average 83.43, `1.2M × 6` / 81.6MB.
- **strict Share (CL): average 78.69**, only 0.012M / 0.29MB.
- **Share-full: average 83.44**, same tiny reported adapter storage.

Critical scope correction: `Share-full` optionally fine-tunes task-specific coefficients when previous-task data is available. Therefore the headline near-non-CL result cannot be attributed to the strict replay-free continual setting. Strict Share is roughly 4.7 average points below the non-CL LoRA row in this table.

Also, Share does not mean a single universal coefficient vector: the shared basis is accompanied by `t` sets of lightweight task-specific coefficients. The paper discusses dynamically switching those lightweight coefficient parameters for multi-user serving. Thus Share compresses task adapters into a common subspace but does **not yet establish task-agnostic coefficient selection** in the strict continual NLU evaluation.

Interpretation: strong evidence for **shared-factor storage efficiency**, weaker evidence for fully task-agnostic continual inference, and a clear warning to separate strict Share from Share-full.

### CLG1-CL-NEW-C — ASO-LoRA: task-specific blocks can avoid inference-time routing by merging all learned blocks, at linear persistent growth
Primary source: ACL 2026, *ASO-LoRA*. The method creates a separate LoRA block for each new task, freezes historical blocks, and applies attribution-guided soft orthogonality. At inference, all learned LoRA updates are summed/merged into the base, so explicit task labels are not required. This buys task-ID-free inference at the cost of persistent module growth.

Reported T5 table:
- standard 4-task: SeqLoRA 64.5, MoELoRA 54.1, O-LoRA 75.3, **ASO-LoRA 77.0**.
- long 15-task: SeqLoRA 41.8, MoELoRA 27.6, O-LoRA 72.2, **ASO-LoRA 72.8**.

Each single LoRA is reported at about 0.4% of the model, so four tasks use about 1.6% total trainable LoRA state. The paper notes that many baseline values are referred from prior papers rather than necessarily rerun in the same codebase; preserve that comparison caveat. On LLaMA2-7B, SeqLoRA 77.2 exceeds ASO-LoRA 76.0, so the method is not uniformly dominant.

Interpretation: useful control showing that **routing-free inference does not imply shared persistent parameters**; one can instead grow task blocks and compose all of them.

### CLG1-CL-NEW-D — MoBLoRA scope correction: shared bases still retain task-specific mixing matrices and semantic routing
Primary source: ACL 2026, *From Experts to Bases: Redefining Mixture of Experts for Efficient Continual Learning*. On CoIN / LLaVA-1.5-7B, reported Table 1 values include:
- MoBLoRA: **65.34 Avg.ACC / 0.00 Forgetting / 65.34 New.ACC**.
- ProgLoRA: 59.09 / 7.53 / 65.68.
- PCLR: 62.19 / 3.39 / 65.16.
- MoELoRA: 35.86 / 25.71 / 58.36.

The method uses globally shared orthonormal basis pools plus task-specific mixing matrices. At inference it performs task-agnostic dynamic routing with semantic task keys / nearest-neighbor selection of a historical mixing matrix. Therefore the title's move “from experts to bases” does **not** eliminate routing; it replaces full expert routing with cheaper shared bases plus task-specific coefficients and a semantic selector.

Reported efficiency discussion gives MoELoRA about 327.16M trainable parameters versus MoBLoRA around 20M with marginal growth, and a 26-basis pool after 8 tasks. This is strong evidence that routing can be made much cheaper, not evidence that routing is unnecessary.

## Synthesis with prior SinglePrompt / PASs-MoE evidence
Prior role-local evidence showed SinglePrompt's learned prompt selector was almost unnecessary on CIFAR100, while minibatch label masking had a massive effect. Separately, PASs-MoE showed a large benefit from soft/pathway-aware expert routing on heterogeneous multimodal continual instruction tuning.

The new LLM evidence reconciles the apparent conflict: **the important comparison is not “router vs no router” in isolation**. Current methods jointly vary persistent parameter growth, shared-factorization, task-specific state, training boundary assumptions, and inference selection. A fair causal test must factor these apart.

Provisional matched-budget comparison design:
- A: one persistent shared adapter with SLoRA-like selective subspace denoising; no router.
- B: one shared basis plus lightweight task-specific coefficients; oracle task selection only as a diagnostic control.
- C: same shared basis/coefficients plus a cheap semantic router, MoBLoRA-style.
- D: routed task experts / MoE, PASs-style.
- E: growing task-specific LoRA blocks merged at inference, ASO-style.

Hold fixed: backbone, exact task/data stream, replay=0, trainable-rank budget, **total persistent parameter budget**, active parameter budget, optimizer/training FLOPs, number of update steps, and evaluation budget. Report both task-sequence training and a genuinely boundary-free/smooth-shift stream separately. Explicitly record train-time task-boundary availability and inference task-ID/router dependence.
