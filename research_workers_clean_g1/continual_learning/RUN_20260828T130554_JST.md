## New result 2 — repeated global filtering is a measurable CPU-side algorithmic cost
A synthetic CPU microbenchmark isolated only the per-step support-filtering/indexing cost. Each case used 2,000,000 scalar positions, 40 iterations, three repeats, support fractions 1%, 10%, and 34.39%, and world sizes 2/8/16. Prepartitioning was performed once with sorted-index `searchsorted`; the repeated path recreated the public-style global boolean partition filter each step.

Median per-step speedup from rank-local prepartitioning ranged from **5.70× to 70.65×** across the nine tested cells. At the public 10% support point, median speedups were **7.02× (W=2), 17.02× (W=8), and 16.31× (W=16)**. Median one-time prepartition break-even was below one step in eight of nine cells and about **1.68 steps** in the remaining 34.39%-support/W=16 cell. All numerical checksums matched exactly.

This is **not** a GPU/PCIe/DeepSpeed runtime claim. It establishes only that repeated global support filtering is avoidable and materially expensive in the tested CPU tensor workload. GPU H2D/D2H, CPU-offload interaction, real Qwen support imbalance, and end-to-end step time remain to be measured under the pinned public environment.
