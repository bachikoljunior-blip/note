## 2. The use-case-8 same-label substrate is source-described, but not self-contained by released embeddings
The use-case-8 accuracy script references `static/saved_embeddings/vit/*.hdf5`, but the public use-case-8 directory currently exposes only the accuracy Python file and `model_training_and_embedding_extraction/`; the referenced saved-embedding directory is not present at that path.

The released notebook can in principle regenerate ViT embeddings, but it begins by loading local files `stl_test.pickle`, `stl_train.pickle`, `stl_val.pickle`, and `stl_deg.pickle`; those pickle inputs are not adjacent artifacts in the use-case-8 directory. The notebook then reintegrates the held-out truck class, applies the same-label central Gaussian-blur transformation, and trains/extracts a `google/vit-base-patch16-224-in21k` representation.

A separate public script located under `experiments/use_case_6_intel_image_sea_drift/model_training_and_embedding_extraction/stl_to_pickle.py` generates files with exactly those pickle names from a local `Stl-10/` folder and uses `random_state=42` for stratified train/test/validation splitting. This is useful provenance, but the dependency is cross-located rather than declared by use case 8.

Important reproducibility risk in that converter: class labels are assigned by incrementing an integer over unsorted `os.listdir(data_path)` directory order. The `truck` folder is split into a special `drift` collection, but its numeric label is whatever position it receives in that filesystem iteration. Directory enumeration order is not guaranteed. For use case 8, which eventually uses all ten labels, a permutation may mostly preserve same-label distribution-shift semantics if kept internally consistent. For use case 7, however, the Python experiment hard-codes training labels `[0..8]` and drift label `[9]`, so exact regeneration can silently mismatch the intended `truck == 9` assumption unless the folder order happens to place `truck` last. This is a **potential regeneration nondeterminism**, not an observed method failure.

Consequence for the planned chronological alarm comparison: calling the released use-case-8 experiment a fully runnable fixed trace substrate was too strong. The scoring logic is public, but exact precomputed embeddings are not shipped at the referenced path, and source regeneration has a cross-directory data-preparation dependency plus label-order ambiguity. Any regenerated chronological trace must record the dataset folder ordering, class-to-label map, split hashes, model checkpoint/hash, and embedding hashes; otherwise it is an adaptation/reconstruction rather than exact artifact replay.
