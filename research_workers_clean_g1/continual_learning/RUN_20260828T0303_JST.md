## New result: tied-alias dead bookkeeping is now measured in an executable source-equivalent CPO harness

The public CPO release is pinned at `MaolinLuo/CPO@9429452cb536a9e713b73b91c0011b96df44962c`. Its `src/compute_importance_mask.py` iterates every floating `state_dict()` key and builds a separate dense bool mask plus cloned float32 references for each key. `src/trainer/grpo_trainer_cl.py` later iterates `named_parameters()` and only consumes mask names present in that deduplicated iterator. The release README specifies training with PyTorch `2.8.0`; PyTorch 2.8 documentation states that `state_dict()` is a shallow mapping of parameter/buffer names while `named_parameters(..., remove_duplicate=True)` removes duplicate parameters by default.

To move beyond source algebra, I ran a deterministic minimal tied-embedding model with the same namespace shape that matters here: `model.embed_tokens.weight` is physically tied to `lm_head.weight`, plus one untied `model.proj.weight`. The mask loop is source-equivalent to the public release: per-tensor `floor(n * top_percent / 100)`, `torch.topk`, drop zero-difference selections, dense bool mask, cloned float32 references, and trainer flat int64 indices. Execution used local PyTorch `2.10.0+cpu`; therefore this is not a full Qwen/DeepSpeed/PyTorch-2.8 reproduction, but it directly exercises the same public API semantics also documented for PyTorch 2.8.

### Exact-storage dedup control

I added a control that skips only later `state_dict` keys that are the exact same storage/view (`storage, offset, shape, stride, dtype`), preserving all distinct tensors/views. It keeps the first encountered physical embedding name, which is the same name the trainer consumes.

- Builder-visible scalars fall to **1,064,960**.
- Mask keys become exactly `model.embed_tokens.weight`, `model.proj.weight`.
- Saved mask file falls to **1,493,411 bytes**, saving **1,468,522 bytes** in this tiny run.
- Logical persistent trainer auxiliary payload falls to **2,342,900 bytes**, saving **2,306,860 bytes**.
- Baseline vs dedup masks and reference values for every trainer-consumed key are bitwise equal in this deterministic run.
- Single-run wall time changed `0.2008s -> 0.1688s`; max RSS changed `343,204 -> 336,948 KiB`. These one-shot timing/RSS deltas are supportive only, not stable performance estimates.

This establishes the previously inferred alias issue as an executed bookkeeping defect in the relevant source pattern: duplicate state-dict aliases can create saved mask/ref/index state that the trainer never consumes, and exact-storage deduplication can remove it without changing the trainer-effective protected set.
