## 2. Important CLDD protocol correction — public source tunes each detector on 10 error streams, not 5
The Zenodo/DATASHEET prose says the standard CLDD-A split uses 10 training seeds and 10 test seeds, then says: `Using five training error-streams, each detector is tuned for a specific strategy-boundary pair.`

The public source at `tachyonicClock/cldd` commit `7b0a474ae171388eb0a666c9b1e1431d2450b73d` does something different:
- `N_TRIALS = 10`.
- `ERROR_STREAM_SEEDS` contains ten seeds from `random.Random(0)`.
- `task_tune_hp_detector()` builds `error_streams` by iterating **all** `ERROR_STREAM_SEEDS` and passes all ten paths to the detector tuner.
- `DDHPSearch._objective()` loops over every supplied error stream, evaluates the proposed detector configuration on each, averages the metrics across all streams, and optimizes `config/hp/detector.yml` metric `my_f1` over 30 trials.

Therefore the current public reproduction workflow uses **10 training error streams per strategy-boundary detector tuning problem**, not five. The five-stream sentence in the dataset documentation is inconsistent with the current public source.

Scope guard: this establishes source-vs-documentation inconsistency at the inspected public commit. It does not prove that an older/private dataset-generation run used ten rather than five unless the Zenodo generation commit is separately pinned. For any fresh reproduction of the current repository, ten is the operative behavior.

## 6. CLDD's custom event matcher is independently reproducible and penalizes duplicate alarms explicitly
`src/metrics.py::drift_confusion` sorts true/predicted alarms, partitions the timeline at midpoints between consecutive true drifts, and for each true drift accepts predictions only inside `[true-max_early, true+max_delay]` within that partition. One in-window alarm yields one TP; extra in-window alarms count as FP; all out-of-window alarms count as FP; a true drift with no in-window alarm is FN.

This is a useful event-level evaluation contract because duplicate alarm bursts cannot inflate recall without cost. It can be reimplemented directly from the parquet event arrays and does not depend on the `my_precision` bookkeeping bug in `src/drift_detector.py`.
