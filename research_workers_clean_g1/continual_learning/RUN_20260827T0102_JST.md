## Branch J — Data Mixing Agent: adaptive replay/data-mixture control is a distinct knob from parameter-write protection

Primary source: Kailai Yang et al., `Data Mixing Agent: Learning to Re-weight Domains for Continual Pre-training`, ACL 2026 main / arXiv:2507.15640v2 (`https://arxiv.org/html/2507.15640v2`).

Mechanism: instead of fixing a source/target replay ratio or hand-coding a domain schedule, the method learns a policy over domain-mixture distributions. It samples 384 data-mixing trajectories, trains small proxy models along them, evaluates each checkpoint with lightweight validation feedback, then trains a 2-layer Transformer policy with 2.1M parameters using SFT warm-up plus offline Conservative Q-Learning. At target continual-pretraining time the policy chooses the next domain distribution online from prior mixture states and environment feedback.

The paper reports the agent is trained in a 52-dimensional domain space formed from DCLM source data and Dolmino math target data, though one method sentence says `26+26` domains lead to `54-dimensional`; this is an internal reproducibility ambiguity because 26+26=52. Do not silently normalize the discrepancy until source/code clarification exists.

Representative LLaMA-DCLM math-target results (overall average across 8 general + 4 math benchmarks):
- Naive target-only training: `38.51`, 874.88 GPU h.
- RegMix: `44.01`, 1987.84 GPU h.
- DBL: `43.50`, 1906.8 GPU h.
- DataAgent-SFT: `44.95`, 1880.32 GPU h.
- DataAgent-RL: `47.03`, 1891.84 GPU h.
DataAgent-RL therefore beats RegMix by `+3.02` absolute points on the reported balanced average under this setup, while using slightly fewer main-run GPU hours. The method also reports transfer without agent retraining to unseen source fields/models/domain spaces and partial transfer from math to code; code-domain transfer is weaker, with the paper explicitly observing a 3.18-point general-benchmark drop relative to the math application, so the heuristic is not fully target-domain invariant.

Data-efficiency evidence is more concrete than the abstract wording: with a nominal 21B-token training budget, DataAgent-RL stops at 19.92B tokens and DataAgent-SFT at 18.86B when target data are exhausted. The paper states superior balanced performance versus RegMix while using `2.14B` fewer source-field tokens. It also reports average main-run savings of 106.33 GPU h versus RegMix in math and 264.29 GPU h in code.

Critical total-cost correction: the lightweight policy itself is cheap to run and its SFT+CQL training is reported under 10 minutes, but collecting the 384 proxy trajectories plus evaluations costs `1996.08 GPU h`. This cost is amortized only if the learned controller genuinely transfers across later scenarios. Therefore do not describe Data Mixing Agent as end-to-end compute-cheap without including trajectory-collection cost, environment-evaluation cost, source-data storage/access, and the number of future adaptations across which the controller is amortized.

Critical scope guards:
- This is not replay-free or source-data-free continual learning. It explicitly controls mixtures containing source-field data; synthetic source data can be used in one tested setting when original source data are unavailable, but general-capability preservation degrades there.
- It is not evidence that hidden task/domain boundaries are solved. The experiment assumes organized source/target fields, domain definitions, and a feedback environment. Treat it as an adaptive data/replay scheduling controller, not as an unsupervised task-discovery mechanism.
- The feedback environment uses validation MMLU and a MATH subset through per-token log probability. Any autonomous deployment needs an equally trustworthy online evaluation signal and must account for possible benchmark-overfitting/evaluation leakage.
- No public implementation repository was found in fresh exact-title/GitHub searches in this invocation; this is an artifact-availability limitation, not evidence that no code exists anywhere.
