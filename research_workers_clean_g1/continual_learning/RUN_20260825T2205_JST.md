## CLG1-CL-015 — ODDL: discrepancy-triggered expansion works as task-free adaptation, but its own plots show substantial over-expansion and no standardized false-alarm/delay evidence
Primary source: Ye & Bors, Knowledge-Based Systems 2025, `Online task-free continual learning via discrepancy mechanism`.

### Mechanism
ODDL uses a discrepancy criterion between incoming information and existing components to decide when to expand a dynamic model without explicit task IDs/boundaries. It therefore belongs to the explicit boundary/expansion family rather than boundary-free continual adaptation.

### Exact final-accuracy evidence
Table 6 reports:
- ODDL-Random: Split MNIST `95.12±0.13`, Split CIFAR10 `51.68±0.18`, Split CIFAR100 `20.23±0.65`.
- ODDL-S: `95.75±0.05 / 52.69±0.11 / 27.21±0.87`.
- ODDL: `94.85±0.02 / 51.48±0.12 / 26.20±0.72`.
The reported setup uses ResNet-18 for Split CIFAR10/100, recent-memory maxima 1000/5000 respectively, and batch size 10.

### Boundary/capacity evidence and scope correction
Figure 7 plots the true task count against the number of created components. On five-task Split MNIST, the component curve ends at roughly 9; on five-task Split CIFAR10 it ends at roughly 8. These are visual plot reads, not exact table entries, but they demonstrate that the expansion process is not one-component-per-true-task and materially over-expands relative to task count.

The threshold ablation on Split MNIST is also strongly capacity-sensitive. In the published plot, increasing ODDL threshold `lambda` from roughly 0.1 to 0.8 reduces component count from about 11 to about 3, while accuracy collapses to around 40% at the highest threshold. ODDL-S is less brittle in that plotted range, with component count falling roughly 11→7 while accuracy remains in the high 90s. Again, these are plot-read approximations.

The paper itself notes that continually novel input can keep creating components and may become impractical. It does not report a standardized detection-delay, false-positive-rate, average-run-length, or precision/recall metric for change detection.

### Updated interpretation
ODDL is useful evidence that task-free discrepancy expansion can support continual classification, but it is **not** evidence for a low-false-alarm calibrated boundary detector. For the present frontier it is more valuable as negative/diagnostic evidence: threshold-based dynamic expansion can trade accuracy against capacity sharply and can create substantially more components than true task boundaries.

## DEMD scope update — unsupervised expansion/reduction improves memory modeling, but does not close the same-label boundary-detection gap
Primary source: Ye & Bors, CVPR 2025, `Online Task-Free Continual Learning via Dynamic Expansionable Memory Distribution`.

DEMD uses discrepancy-based sample-distribution memory expansion plus memory reduction/merging, without task or class labels for memory management. On the paper's class-incremental benchmarks with maximum memory 2000, Table 1 reports FID:
- Split MNIST `23.62`
- Split Fashion `40.16`
- Split SVHN `59.42`
- Split CIFAR10 `73.27`
- average `49.11`

Its Split-MNIST diagnostic figure shows memory-component count and true distribution/task count tracking broadly but not coinciding exactly; expansion and reduction intentionally permit an overcomplete/merged memory representation. The paper does not expose standardized boundary delay or false-alarm metrics.

Most importantly, the strongest expansion diagnostics are category/class-incremental. The cross-domain experiments use distinct domain pairs, but they still do not provide a clean same-label abrupt-shift detector benchmark with detection latency/FPR. Therefore DEMD is retained as a dynamic memory-distribution candidate, not as a resolution of the current same-label detector frontier.

## CLG1-CL-016 provisional — LargeMonitor supplies a genuine same-label domain-shift stream and frozen-feature monitoring, but exact alarm quality is still unverified
Primary source/artifact: Yuan et al., `LargeMonitor: Monitoring Online Task-Free Continual Learning via Large Pretrained Models`, arXiv `2606.09430`, and public repository `Agentic-Intelligence-Lab/LargeMonitor`.

### Why it materially advances the open frontier
The released `imagenet_hs.py` defines a heterogeneous 10-step ImageNet-HS stream over 50 WordNet synsets shared by Tiny ImageNet and ImageNet-R. The classes are partitioned into five groups of ten. Within a group, the source task and shifted task use the **same label set**:
- T1 group A: Tiny ImageNet source; T2 group A: ImageNet-R `domain_shift`.
- T3 group B: Tiny source/new classes; T4 group B: Tiny corruption with the same B labels.
- T5 group C: Tiny source; T6 group C: ImageNet-R domain shift with the same C labels.
- T7 group D: Tiny source; T8 group D: corruption with the same D labels.
- T9 group E: Tiny source; T10 group E: ImageNet-R domain shift with the same E labels.
This is the first modern source reached in this clean branch whose public artifact explicitly contains repeated **same-label domain shifts** alongside new-class and corruption events in one stream.

The released `disjoint_dino_cka_hs.py` computes frozen DINO features for each incoming batch, compares them with a rolling feature buffer by linear CKA, and records CKA per batch with source/change-type metadata. Defaults are batch size 64 and feature-buffer size 10000. Thus the public artifact verifies a task-free representation-monitoring pathway without requiring model retraining merely to generate the drift signal.

### Important current limitation
The inspected public scripts expose the heterogeneous stream and per-batch CKA monitor, but not yet an exact table of alarm precision/recall, false-positive rate, average detection delay, or capacity growth. Fresh searches also did not surface those exact primary-paper metrics. Therefore LargeMonitor is **provisional** evidence for the right benchmark/mechanism family, not yet evidence that the detector is well calibrated.

## Cross-method inference from this branch
Across ODDL, DEMD, LEViT/EEM from earlier clean checkpoints, and the newly inspected LargeMonitor stream, a useful evaluation distinction is becoming sharper:
1. **Representation/drift signal quality** — can an unlabeled signal distinguish same-label domain drift from ordinary within-domain variation?
2. **Alarm calibration** — delay, false alarms, missed shifts, and threshold sensitivity.
3. **Structural response policy** — expansion, routing, replay, or continuous adaptation after an alarm.
4. **Capacity/runtime cost** — new experts/components, stored examples/features, and compute.
Final accuracy alone conflates all four. ODDL's over-expansion is a concrete example: high task-free accuracy does not imply accurate boundary calibration.
