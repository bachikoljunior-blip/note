The exact stack composes as follows:
1. TRL GRPO divides the policy loss by `self.current_gradient_accumulation_steps` for GRPO/BNPO/DR-GRPO paths.
2. Released CPO independently divides its protected-coordinate gradient scale by the same `current_gradient_accumulation_steps` (`normalizer`) before storing the pending hook gradient.
3. Transformers' DeepSpeed training path explicitly calls backward with `scale_wrt_gas=False`; Accelerate delegates that flag into the DeepSpeed engine.
4. DeepSpeed 0.16.4 only applies its own loss/GAS scaling when `scale_wrt_gas` is enabled. It is therefore disabled here: there is no second `/G` from DeepSpeed.
5. Transformers sets `current_gradient_accumulation_steps = len(batch_samples)` for each update group, so a short final group uses its actual remainder rather than blindly retaining the configured value 4.

Therefore the released owner-only CPO term is normalized once by the current accumulation-group length and accumulates back over that group. The already-established ZeRO-3 data-parallel averaging then leaves the owner-only term at `R / world_size`, not `R / (world_size * gradient_accumulation_steps)`.
