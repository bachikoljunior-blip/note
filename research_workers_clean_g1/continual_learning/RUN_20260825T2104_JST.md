## CLG1-CL-012 update — ARROW mechanism is a bundle; public code does not causally isolate “world-model consolidation”
The public ARROW artifact materially sharpens the mechanism scope.

### What the released code actually does
- Every incoming trajectory is added to both ARROW sub-buffers. World-model updates draw a minibatch from `MultiTypeReplay` and optimize `wm.compute_loss` on that replay.
- `MultiTypeReplay.minibatch()` first chooses one whole sub-buffer with `random.choices` and then draws the entire minibatch from that selected buffer. It does not mix FIFO and long-term examples sample-by-sample inside a minibatch.
- `FifoReplay` is an ordinary ring FIFO.
- `LongTermReplay` assigns every incoming trajectory an iid Gaussian random priority and retains the trajectories with the highest priorities. Because priorities are iid continuous and independent of trajectory content, the released implementation is effectively maintaining an approximately uniform random subset over the history by random rank; it is not explicitly optimizing semantic/task distribution matching.
- Actor/critic updates are performed on imagined world-model rollouts, but `dream_rollout()` first samples replay trajectories as context and passes those observations/actions through the RSSM to initialize latent state. Thus FIFO/LTDM composition also affects policy learning through the replay-conditioned latent seed states, even though actor/critic gradients are computed from imagination rather than directly from logged transitions.
- The ARROW ratio controls both capacity split and the probability that a minibatch comes from FIFO vs LTDM. Therefore the published 25/75, 50/50, 75/25 ablation jointly changes storage allocation and replay sampling frequency; it is not a pure capacity-only ablation.
- The public SAC path does not use the same `MultiTypeReplay` dual-buffer mechanism. Therefore there is no matched model-free `same dual buffer + same memory + same sampling ratio` control in the released artifact that would isolate whether the gain specifically requires a world model.

### Updated interpretation
The defensible claim is: a fixed-budget short-term + long-term random-retention replay mixture, used to train a predictive world model and to seed imagined actor/critic rollouts, yields strong continual-RL retention in the reported experiments. The stronger causal claim “the gain is specifically because replay is consolidated only into a world model rather than a policy” is not isolated by current public controls.

Targeted public searches did not surface an independent ARROW reproduction/failure report. Treat the original TMLR paper + released code as strong primary evidence but keep independent replication as open.

## HESTIA artifact audit — released training path is not density-only boundary creation
The UAI 2026 paper/repository describes HESTIA as order-invariant linearized adaptation plus density-guided adapter routing. The released implementation reveals an important scope restriction.

### Training-time boundary logic
- `OnlineDiagonalGMM.score()` provides a minimum Mahalanobis-plus-prior score over clusters.
- `detect_convergence_stationary_streaming()` detects a stable period in the sequence of those scores; it is a stationarity/convergence detector, not by itself a new-distribution trigger.
- In released `main.py`, the actual branch that saves the current adapter and starts a new distribution is entered only after convergence **and** when the ground-truth labels of the current batch contain a class not already in `within_seen_classes`:
  `is_converged and not target_classes.issubset(within_seen_classes)`.
- The code comment explicitly says that after convergence, “if new classes come” the system marks a new incoming distribution.

Therefore the released main training path does **not** demonstrate label-independent density-only change-point creation for same-label covariate/domain shifts. Density controls stationarity and later routing; unseen target-class labels trigger structural boundary creation.

### Inference routing
At evaluation, adapter selection is density-based: validation batches are scored against each stored GMM key and the minimum-distance adapter is selected. However, classification then also applies an adapter-specific `class_mask` that was created from supervised training labels, masking other logits to `-inf`. This is not test-time task-ID supervision, but it is label-derived metadata and should be included in scope comparisons.

## CLG1-CL-013 — LEViT: genuinely label/task-agnostic expansion with useful cross-domain accuracy, but threshold-sensitive and still capacity-growing
Primary source: Ye & Bors, Pattern Recognition 169 (2026), `Online Task-Free Continual Learning via Expansible Vision Transformer`.

### Mechanism
LEViT maintains an ensemble of ViT components. When its recent-memory buffer is full, it compares the probabilistic latent representation of incoming memory against the joint knowledge represented by existing components. If the distribution-distance criterion exceeds threshold `gamma`, it creates a new expert; previous experts are frozen. No task IDs or task-boundary labels are required for this expansion trigger. Dynamic Knowledge Fusion (DKF) gates prior attention representations into new components.

### Exact accuracy evidence (five runs)
Split MNIST / Split CIFAR10 / Split CIFAR100:
- ER: 92.16±0.75 / 42.48±3.04 / 19.57±1.79.
- CNDPM: 93.23±0.09 / 45.21±0.18 / 20.10±0.12.
- Dynamic-CAA: 95.23±0.05 / 50.28±1.16 / **23.58±0.57**.
- LEViT-DKF: **96.81±1.37 / 51.74±1.23 / 23.03±1.32**.
- LEViT without DKF: 96.11±1.22 / 48.93±1.16 / 20.08±1.38.
Thus DKF contributes materially on these streams, but LEViT-DKF is not universally best: on Split CIFAR100, Dynamic-CAA 23.58 exceeds LEViT-DKF 23.03.

MiniImageNet:
- ER+GMED 27.27±1.8, MIR+GMED 26.50±1.3, CNDPM 27.97±2.3, LEViT-DKF **29.27±1.5**.

Cross-domain accuracy / final component count:
- Permuted MNIST: CNDPM 69.87 / 18 components; LEViT-DKF **72.24 / 10**.
- Split MNIST-Fashion: CNDPM 75.28 / 21; LEViT-DKF **76.89 / 12**.
- Split MNIST-SVHN: CNDPM 53.87 / 28; LEViT-DKF **58.93 / 22**.

### Parameter/capacity evidence
- Split MNIST: LEViT-DKF 8 components / ~11M parameters.
- Split CIFAR10: 6 / ~65M.
- Split CIFAR100: 9 / ~97M.
The authors explicitly note accumulated parameters as a limitation for resource-constrained deployment. This is more compact than EEM’s extreme CIFAR10 expansion in the clean state, but it is not fixed-capacity continual learning.

### Expansion-threshold sensitivity
The paper explicitly states that smaller `gamma` creates more components and larger `gamma` produces a more compact model but degrades performance. Figure 7 on Split MNIST visually shows component count falling roughly from ~31 at `gamma=9.7` to ~6 at `10.3`; accuracy stays near the mid-90s through about 10.2 and then drops sharply to roughly 80 at 10.3. These are plot-read approximations, not exact table values. Figure 8 shows substantially different expansion trajectories across nearby thresholds. The paper also notes that useful threshold ranges differ across datasets because latent dimensions differ.

### Important text/figure inconsistency
The paragraph around Figure 7 says the threshold experiment is trained on CIFAR10, while Figure 7’s caption says Split MNIST and the surrounding threshold values/latent-dimension discussion distinguish Split MNIST from CIFAR10. Treat the figure/caption as the visual evidence and do not infer a universal calibrated threshold.

### Scope
LEViT provides a cleaner label-independent expansion comparator than the released HESTIA boundary path and a more modern comparison to EEM. It still relies on a recent sample buffer, grows parameters, and reports accuracy/component count rather than standardized change-point delay and false-expansion rates. Same-label abrupt domain-shift boundary calibration therefore remains unresolved.

## CLG1-CL-014 — EG-CNN: boundary-free, single-head, no-image-replay structural adaptation is viable, but its strongest same-label Domain-IL test is mild
Primary source: Leite, Neurocomputing 671 (2026), `Task-free continual learning with expansion-based granular CNN`.

Mechanism: an extractor + online refiner + evolving granular single-head classifier incrementally creates/merges/prunes class-linked granules. It uses no task IDs/boundaries and stores no images for replay; supervised class labels arrive after prediction. The system therefore avoids explicit boundary detection and adapts continuously at the classifier-structure level.

Quantitative evidence:
- CIFAR-10 Domain-IL, strict single pass: EfficientNetV2Large+iLDA+EGNN reaches **85.52%** vs **86.51%** for a dense black-box multi-epoch reference; MobileNet+iLDA+EGNN reaches **80.27%** vs **79.88%** for its dense reference.
- Intel-6 class-emergence stream: with no omitted class, standalone MobileNet is **88.07%** vs EGNN **86.93%**; with one omitted class EGNN gains 3.5 percentage points; with two omitted classes standalone falls to **61.87%** while EGNN reaches **70.97%**.
- SUN-397 compounded Class-IL + Domain-IL: best EG-CNN reaches **82.27%**, versus **80.74%** without dynamic deferral and **60.12%** for the standalone offline multi-epoch EfficientNet_B0 reference. It uses 2261 active granules (~5.7/class), 39-dimensional latent space, and 443,156 granular-classifier parameters versus 508,557 for the minimal dense softmax head. Dynamic deferral occurs on 2133 samples (10.75%).

Scope: the CIFAR-10 Domain-IL stream has all classes present and relatively mild nonstationarity; it is not a calibrated abrupt same-label shift benchmark with boundary-delay/false-positive metrics. EG-CNN is therefore useful as evidence for **boundary-free continuous adaptation**, not as evidence that a shift detector solves the open same-label boundary problem.
