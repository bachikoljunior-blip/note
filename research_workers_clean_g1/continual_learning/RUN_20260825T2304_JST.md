## 1. LargeMonitor: stronger mechanism evidence, but alarm-calibration evidence remains incomplete

Primary paper: Mingqi Yuan, Xiaoquan Sun, Shihao Luo, Jiayu Chen, *LargeMonitor: Monitoring Online Task-Free Continual Learning via Large Pretrained Models*, arXiv:2606.09430v1, 2026-06-08. HTML: https://arxiv.org/html/2606.09430v1

The paper's detector is more specific than the previously inspected raw-CKA script suggested. Incoming batches and a FIFO representation memory are embedded with a frozen LVM; linear CKA gives monitoring statistic C_t; a one-sided CUSUM accumulates sustained downward deviations. A shift is declared when S_t exceeds a dynamic MAD-scaled threshold h_t. This is label-independent at detection time and O(1) per batch after feature extraction.

The paper includes genuine same-label domain changes. Its HS-Incremental sequence contains A: labels 0-9 Tiny-ImageNet -> the same labels 0-9 ImageNet-R, then analogous same-label domain changes for groups C and E. It also separately evaluates a domain-incremental setting where class semantics are preserved.

Important limitation: the paper's stated detection evaluation is not a full alarm-quality evaluation. A detection is counted correct when a peak lies inside a tolerance window around the true boundary; the text says all domain-setting boundaries were detected, and figures use cumulative regret to compare buffer/model choices. However, the surfaced paper text does not report the standard tuple needed to separate detector quality: false positives/FAR, episode recall or missed-event rate, and normalized detection delay. This matters because a detector can hit every boundary yet still alarm excessively or late.

Concrete downstream gains show that boundary information can help, but they do not isolate alarm quality. In the Si-Blurry table at buffer 2,000, ImageNet-R MVP-R improves from A_AUC 48.11±0.27 / A_Last 47.29±2.51 to MVP-R+LargeMonitor 51.86±0.50 / 49.28±1.73. On ImageNet-HS, MVP-R 80.51±0.11 / 82.06±0.15 becomes 82.14±0.24 / 82.24±0.26 with LargeMonitor-guided shift-aware adaptation. Scope: this supports useful monitoring/adaptation, not calibrated low-FAR detection by itself.

Artifact check: public `Agentic-Intelligence-Lab/LargeMonitor` main, inspected file `disjoint_dino_cka_hs.py` at blob `6521e9ddf8f8434994e8b1df74291c7e9668d82e`, computes frozen-DINO features, rolling-buffer linear CKA, and writes per-batch CKA/change metadata. That inspected HS script does not implement the paper's CUSUM alarm/threshold stage. Repository search for `CUSUM` returned no indexed match, but code-search incompleteness prevents concluding that no implementation exists anywhere. Therefore exact paper-alarm reproduction from the released HS script remains unresolved.

## 2. HESTIA scope correction is now exact from released final code

Primary publication: Hang Thi-Thuy Le et al., *Task-Free Continual Learning via Order-Invariant Linearized Adaptation and Density-Guided Adapter Routing*, UAI 2026, PMLR 337:3274-3297. https://proceedings.mlr.press/v337/le26a.html
Released code: https://github.com/Alisia0303/HESTIA

The publication describes order-invariant linearized adaptation plus density-guided adapter routing, and says density signals support lightweight change-point detection. But released `main.py` at blob `8f0a17cd6103f275768a35c778985912a1827670` makes the structural boundary condition explicit: after the Mahalanobis-score history has converged, a new distribution/checkpoint is created only when `not target_classes.issubset(within_seen_classes)`. In other words, the released training loop requires an unseen ground-truth class to trigger a new distribution after convergence.

Therefore this released implementation is task-ID-free but is NOT evidence that density alone can create a new adapter for a same-label domain shift. Density is used for scoring/stationarity and later routing, while structural creation is class-gated. The ImageNet-R config uses 200 classes and 20 tasks, consistent with a class-incremental benchmark rather than a controlled same-label domain-switch creation test. Preserve this distinction when interpreting the final paper.

## 3. A stronger evaluation protocol for the boundary-detection branch

Primary paper: Vitor Cerqueira et al., *A Framework for Evaluating and Benchmarking Concept Drift Detection Methods*, KDD 2026, DOI 10.1145/3770855.3819070, arXiv:2606.07789. https://arxiv.org/abs/2606.07789

This work directly addresses the metric gap above. It defines an acceptable detection window around each drift and recommends reporting precision, recall, Episode Recall, F1 detection score, Normalized Detection Time (NDT), Alarm Rate, and False Alarm Rate. It also recommends leave-one-dataset-out hyperparameter selection so detector thresholds are not tuned on the evaluation stream. The benchmark covers 14 detectors, 7 real-world datasets, four drift types, abrupt and gradual transitions.

For continual-learning boundary mechanisms, this suggests a stricter evaluation contract: do not accept final continual-learning accuracy, visual boundary alignment, or 'all boundaries detected' as detector validation. Require at least Episode Recall + FAR + NDT under held-out threshold calibration, then separately score the adaptation policy and capacity/runtime cost.
