## New high-value comparison source: DeMix (ICML 2026)

Primary source: Li et al., `Decouple Searching from Training: Scaling Data Mixing via Model Merging for Large Language Model Pre-training`, accepted ICML 2026, arXiv:2602.00747v3 (29 May 2026), https://arxiv.org/html/2602.00747 . Official code/artifacts: https://github.com/Lucius-lsr/DeMix and https://huggingface.co/datasets/lucius1022/DeMix_Corpora .

DeMix is the closest currently located external control for the missing OptiMer comparison. It also decouples mixture search from expensive mixture training, but uses weighted component-model merging only as a **proxy for data-mixture performance**, then trains the final model on the selected real data mixture. This is distinct from OptiMer, which deploys the post-hoc merged model itself and only uses retraining at the OptiMer-derived ratio as a secondary baseline.

### Quantitative evidence against weak proxy-based mixture search

DeMix trains seven component models and synthesizes many merged proxy models. With 30B-token component models, 112 merged proxies yield macro Spearman rank correlation `rho=0.81`, top-25% `rho=0.59`, and capability recovery up to `0.85`, at about `212B` total token budget. Training-based proxies at comparable budget reach only `rho=0.53` and top-25% `0.20`; matching the proxy accuracy requires about `1344B` tokens, reported as roughly `6.4x` the computation.

For final mixture quality on Qwen3-1.7B, the model trained on the DeMix-selected mixture from 224 merged proxies has macro rank `24.00` (general/code/math ranks `46/12/14`) at about `212B` search-side training budget. The paper reports that 112x2B and 28x8B RegMix/CLIMB configurations at comparable `224B` budget do not match it; even 56x8B baselines at `448B` remain worse. DeMix's own proxy count improves `29.33 -> 25.67 -> 24.00` for 56/112/224 proxies, then worsens to `27.67` at 448 proxies, showing that cheap proxy generation does not remove predictor overfitting/noise.

### Critical scope guard: merge fidelity degrades as the parameter update grows

DeMix directly compares weighted merged proxies with models trained on the corresponding real Math/Code data mixtures at four update scales. Reported consistency (merged score / real-mixture score) degrades as update magnitude grows:
- 2B-token components, update magnitude `delta=3.10%`: Math `1.04`, Code `0.97`.
- 10B, `delta=6.90%`: Math `0.96`, Code `0.81`.
- 30B, `delta=10.10%`: Math `0.82`, Code `0.75`.
- 50B, `delta=10.50%`: Math `0.79`, Code `0.75`.

This is important for OptiMer interpretation. OptiMer's main evidence uses Gemma 3 27B distribution vectors produced by only 1B-token CPT runs and reports near-linear trajectories. DeMix independently shows that model-merging proxies become less faithful as the update grows. Therefore **OptiMer should not be generalized to longer CPT or larger parameter displacement without a matched test**. This is a scope constraint, not negative evidence against the 1B-token Gemma result.

DeMix has materially stronger public reproduction artifacts than the current OptiMer surface. Its official README states that the Hugging Face release includes all seven trained component models at 2B/10B/30B/50B token budgets and 16 sampled-mixture reference models; the Hugging Face dataset currently reports about `6.1 TB` total file size, and the 16 reference-model directory alone is about `552 GB`.
