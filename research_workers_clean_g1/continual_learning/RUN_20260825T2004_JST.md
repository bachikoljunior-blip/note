### CLG1-CL-009 — HESTIA implementation audit sharply narrows the current evidence for “task-free” change-point discovery
Primary publication: Le et al., UAI/PMLR 2026.
Official artifact: `Alisia0303/HESTIA`.

Published mechanism claim:
- HESTIA couples order-invariant linearized adaptation with density-guided adapter routing.
- A diagonal-GMM task key over adapter-induced embeddings is described as supporting both streaming change-point detection and likelihood-based inference-time adapter retrieval.
- The paper reports higher accuracy/lower forgetting than TFCL baselines in standard and realistic streaming settings, but the exact primary quantitative tables could not be extracted in this environment because the PMLR PDF is served through a binary endpoint that the available text connector cannot decode. The official repository contains code/configs but no result logs or machine-readable paper tables, so exact values are intentionally not invented.

New implementation-level evidence from the official code:
1. The training loop computes a GMM score (`mean_ood`) over current embeddings and applies a stationarity detector to decide when the current distribution has *converged*.
2. After convergence, however, creation of a new distribution/adapter is triggered by supervised label novelty: the code checks whether the current minibatch's ground-truth target classes are a subset of the previously seen class set. If not, it declares a new distribution, saves the current adapter/signature, resets the IA3/GMM/head optimizer, and starts the next adapter.
3. Therefore the released implementation does not demonstrate a density-score-only boundary trigger. Density score gates convergence; unseen target classes supply the actual new-distribution trigger in the main training path.
4. This is not automatically invalid in supervised class-incremental/task-free learning—training labels may be available even when task IDs/boundaries are not—but it materially narrows transfer scope. Current artifact evidence does **not** establish unlabeled change-point discovery, same-label covariate/domain-shift detection, or a boundary detector driven solely by density deviation.

Inference-routing audit:
- For each validation batch and each stored adapter, the code embeds the batch with that adapter, computes diagonal Mahalanobis distances to that adapter's GMM clusters, averages the minimum distance over the whole batch, and selects the single adapter with the smallest batch-level score.
- Classification logits are then masked to the set of classes recorded for the predicted adapter during supervised training.
- Thus released routing is **batch-level**, not per-sample: every item in a validation batch shares one predicted adapter. This assumes sufficiently homogeneous evaluation batches and is a distinct scope limitation from change-point detection.
- The class mask itself is learned from labels observed during training; the true task ID is used to score matching accuracy but not directly to choose the adapter in this evaluation function.

Artifact/protocol notes:
- The released Split-CIFAR100 config uses a pretrained ViT-B/16, 20 class-incremental tasks, batch size 16, 8 GMM clusters, cooldown 50, stationarity window 10, and k=1.3.
- A `dataset_gradual.py` helper constructs gradually expanding class mixtures, but the default `main.py` imports `data.dataset`, and the README reproduction commands point to the standard configs. No result logs were found in the public tree. Therefore realistic-streaming reproducibility should be graded separately from standard-code availability until the exact paper protocol/results are extracted.

Status: promising mechanism family, but quantitative strength remains provisional and the released boundary-routing implementation has important label/batch-homogeneity assumptions that must be tested explicitly before generalizing to open-ended task-free streams.

### CLG1-CL-006 delta — FOREVER “model time” is LoRA-parameter movement with replay movement censored, plus an unconditional final replay
Primary publication: Feng et al., ACL 2026.
Official artifact: `WoodScene/FOREVER`.

New implementation-level details:
1. `tau` is the cumulative L2 norm of the change in the concatenated **trainable parameter vector only**. In the released Qwen/LLaMA experiments, training uses LoRA on `q_proj`/`v_proj` (default rank 8, alpha 16), so model-time is not full-model or function-space drift.
2. Each task normally gets a new output directory, loads the previous LoRA adapter, and recalibrates `model_day` from the first `steps_per_day` current-task steps. The released Qwen script uses `steps_per_day=24`, memory ratio 2%, memory epochs 2, current-task epochs 10, first-task epochs 60, batch size 32.
3. Memory-replay phases intentionally do **not** attach the drift recorder. Replay updates therefore do not increment `tau`; after replay, the code resets the drift reference point to the post-replay parameters. Future replay timing reacts to current-task movement while censoring movement caused by replay itself.
4. The scheduler uses trigger days `[1,2,4,7,15,30,60,90,120]` multiplied by the calibrated model-day, so the published “forgetting-curve time” is concretely a threshold schedule over per-task LoRA-space movement.
5. Regardless of threshold-triggered replay, the implementation performs one **unconditional final memory replay after all current-task steps**. Therefore comparisons of replay timing are not “scheduled replay versus no final replay”; the released method always includes end-of-task replay when memory exists.
6. Intensity-aware replay regularization snapshots trainable parameters at the start of the task; the released implementation initializes all parameter-importance weights to 1.0 and scales a quadratic penalty by an EMA of current-task update magnitude, clipped to a finite range.

Interpretation / scope:
- The paper's quantitative ablations remain strong evidence that this specific scheduler helps under the tested LoRA regimes.
- But “model time” should not yet be generalized as an architecture/parameterization-invariant clock: raw Euclidean LoRA movement can change with LoRA rank/scaling, optimizer, PEFT parameterization, or full-parameter fine-tuning.
- Because replay-induced movement is censored from tau, an important unresolved causal test is whether performance changes if model-time counts replay updates too.
- Fresh searches still found no direct independent replication/failure of FOREVER/model-time scheduling, especially under full-parameter fine-tuning, alternative PEFT geometry, or task-free streams. Keep this as an external-validation gap, not negative evidence.

### New provisional curriculum branch — task order is itself a controllable continual-learning variable
Primary source: Li & Hiratani, ICML/PMLR 2025, `Optimal Task Order for Continual Learning of Multiple Tasks`.

Mechanism/theory:
- In a linear teacher-student model with latent task factors, the authors derive how task similarity and order affect final continual-learning error.
- Two broad ordering rules emerge: place less-representative/peripheral tasks before more-typical/core tasks, and make adjacent tasks dissimilar (a longest-path-like ordering over task dissimilarity).
- The primary PMLR paper reports validation on Fashion-MNIST, CIFAR-10, and CIFAR-100 with MLP/CNN models and consistent gains over poorer/random orderings.

Scope:
- This is task-incremental curriculum optimization, not a solution for an uncontrollable real-world stream where future tasks are unknown and cannot be reordered.
- It is nevertheless relevant where an autonomous learner can choose experiments, data domains, skills, or self-generated curricula. In that setting, “what to learn next” becomes another control axis alongside what samples to update, when to replay, update geometry, LR trajectory, and boundary routing.
- Exact quantitative table extraction remains pending; do not promote this provisional branch above candidates with already verified matched numbers until those tables/ablations are checked.

## Matched-budget synthesis after this continuation
The current mechanisms act on distinct control axes and should not be compared as if they consumed the same resource:
- **What to update:** OASIS-like online sample selection; selection itself needs last-layer gradients and leaves a substantial gap to full-data training.
- **Which old examples/directions to protect:** replay selection, gradient alignment, OCAR curvature/preconditioning.
- **When/how strongly to replay:** FOREVER; tested with LoRA-space movement, replay-movement censoring, and unconditional final replay.
- **Global optimizer trajectory:** Infinite-LR; low structural complexity but published protocols reset optimizer state between domains, unlike Abbes et al.
- **Where a distribution starts/which specialist to route:** HESTIA; official implementation currently couples density stationarity with supervised unseen-class triggering and batch-level inference routing.
- **Which task/domain to expose next:** Li–Hiratani task-order optimization; only applicable when sequence is controllable.
- **Move task adaptation out of parameter rewriting:** online-world-model planning; strongest result remains under shared dynamics and changing rewards.

This decomposition suggests that a fair future experiment must cross at least memory %, extra training FLOPs, trainable-parameter count/PEFT geometry, optimizer-state reset policy, task-boundary information, and whether sequence order is controllable. Final accuracy alone is insufficient; BWT/forgetting, online/anytime performance, current-task plasticity, and routing/boundary errors need separate measurement.
