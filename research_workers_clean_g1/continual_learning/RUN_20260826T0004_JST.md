## 1. LargeMonitor artifact audit: current release does not expose the paper CUSUM detector end-to-end

Paper: Mingqi Yuan et al., *LargeMonitor: Monitoring Online Task-Free Continual Learning via Large Pretrained Models*, arXiv:2606.09430v1 (2026-06-08), https://arxiv.org/abs/2606.09430 .
Current public code snapshot: `Agentic-Intelligence-Lab/LargeMonitor` main `bf0b22909333b986336912e8acda86644034f594`, latest commit `fix_hs` dated 2026-06-29.

The paper defines the detector as frozen-LVM features -> linear CKA -> one-sided downward CUSUM. With rolling median/MAD `(mu_tilde, sigma_tilde)`, it specifies `S_t=max(0,S_{t-1}+(mu_tilde-C_t)-kappa_d*sigma_tilde)` and declares a shift when `S_t > kappa_h*sigma_tilde`, resetting statistic/baseline after an alarm. The experimental text reports `kappa_D=0.5` for a detection setting, but the surfaced paper text does not provide a numeric `kappa_h`, so exact alarm reproduction already has an underspecified threshold parameter.

The complete current Git tree was inspected. It contains the raw-monitor scripts under `lvmonitor/` and the HS root script, but no file/path named for CUSUM/alarm logic; repository code search for `CUSUM` also returned no indexed match. Direct inspection of:
- `lvmonitor/disjoint_dino_cka.py` blob `1cb7470aa6d2aec5b1e3fc1086f3d0c3f6fa9dcb`,
- `lvmonitor/sib_dino_cka.py` blob `a2f172838fae2b54ee43cf990d8833202e0c8fe6`,
- `lvmonitor/disjoint_dino_cka_core50.py` blob `165084b2b0848019ecaeadd044ddbd0dc783c867`,
- `lvmonitor/imagenet_r_stream_dino.py` blob `b425bedbcf65d2ce6add6d5243f8ddcb9943d9c4`, and the previously inspected root HS CKA script
shows feature extraction + rolling feature buffer + similarity/CKA logging to CSV, but no CUSUM state, MAD threshold, alarm/reset, or detector-to-adaptation interface.

Conclusion: preserve the paper mechanism as a plausible detector, but downgrade released-artifact reproducibility. The current public repository reproduces the monitoring statistic streams, not the surfaced paper's complete CUSUM alarm stage.

## 2. Stronger scope correction: released diagnosis-guided adaptation is an oracle control, not end-to-end LargeMonitor wiring

The paper itself states that `MVP-Shift (oracle)` outperforms vanilla MVP/uniform-response baselines on HS-Incremental, so Q4 supports the value of shift-type-specific adaptation when the shift type is available; it does not by itself validate the detector->LMM diagnosis->policy chain.

The released implementation makes this exact:
- `configuration/config.py` blob `ed3ed2707c2a54f3848319e4e6f7953cbc2a76a9` exposes `--shift_policy_mode` with **only** the choice `oracle`.
- `methods/mvp_shift.py` blob `f26ac6ecbcb4690fb02e7fe7b8263655d70027ed` resolves change type from `train_sampler.change_type_for_task(task_id)` in oracle mode; there is no LargeMonitor alarm/diagnosis input path.
- `scripts/mvp_shift_hs.sh` blob `f1f29a44b2c20f6af86db7bd0e46d684d328fcdc` explicitly runs `--shift_policy_mode oracle`.

Therefore the released code currently provides (a) raw frozen-representation monitoring traces and (b) an oracle shift-aware adaptation control, but not a runnable end-to-end bridge between them. This is a more material reproducibility gap than the earlier observation that the HS signal script lacked CUSUM.

## 3. Detection-evidence scope remains incomplete

The paper counts a detection as correct when a peak falls inside a tolerance window and says all task boundaries were detected in the Domain setting. It does not report a separated false-alarm rate, episode recall/miss rate, and normalized detection time. A targeted fresh search found the original paper/code and secondary summaries but no independent/follow-up reproduction publishing alarm traces with FAR + Episode Recall + NDT. Absence of a found replication is not negative evidence; independent validation remains unobserved.

## Updated candidate interpretation
- `LargeMonitor@arXiv:2606.09430`: **mechanism promising, artifact incomplete**. Strong evidence for frozen-LVM CKA as a useful drift signal and for same-label domain-shift benchmarks; paper CUSUM stage is not currently exposed in the released code and `kappa_h` is not numerically surfaced in the paper text inspected.
- `MVP-Shift-oracle@LargeMonitor-main:bf0b229`: **oracle adaptation ablation**, not end-to-end LargeMonitor. Use it to support heterogeneous shift-specific policies, not to claim automatic diagnosis-to-policy execution.
- Detector evaluation contract remains: require Episode Recall + FAR + NDT under held-out threshold calibration, separately from downstream CL accuracy/regret.
