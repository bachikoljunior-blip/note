## New scope correction — Share public strict NLU driver does not expose a historical-coefficient router
Source-qualified code anchor: `ankit-vaidya19/Share@ed4bc9c261f4389b1c2abd639e4f55ae81a1028b`.

The released strict continual GLUE pipeline is more task-agnostic at the adapter-selection level than the previous checkpoint implied:
- `NLU/scripts/run_share_continual.sh` trains `cola -> mrpc -> rte -> stsb -> qnli -> sst2` sequentially. Each new task loads the immediately previous task's trained EigenFlux state and saves one new current state.
- After each task, `evaluate_previous_tasks()` evaluates every prior GLUE dataset using the **same current adapter path**. It passes the evaluation task name to select the dataset / classification setting and also uses that string as an adapter namespace, but it does not search or route among a bank of historical coefficient states.
- `NLU/run_glue.py` instantiates the current EigenFlux adapter, loads the supplied current path under that name, and sets that one adapter active.
- The custom `EigenFluxLayer` keeps shared/frozen basis `components` and trainable `loadings` plus temporary rank-update vectors for the active adapter. The main continuation pointer remains the current state; post-hoc `update_previous_weights()` copies are not the state used for the next task.

The released strict GLUE driver, however, does **not expose an inference-time selector over those historical coefficient sets** in its main evaluation path. Thus the earlier characterization "strict Share requires oracle selection among task coefficients" is too strong for the public NLU implementation. A narrower remaining oracle condition is that evaluation is task-by-task with known `--task_name`, which selects the GLUE dataset/head semantics.

Interpretation: strict Share is a stronger control for a **single evolving shared subspace/current adapter state without inference routing** than previously recorded. ## New lifecycle result — SLoRA has constant active routing state but linear archival/reconstruction state unless compacted
Source-qualified code anchor: `alina1031/SLoRA@0faf15fd6562ed3e146e8733205f59ef9742ba0f`.

`src/train/cl_train_slora.py` and `src/model/builder.py` clarify the lifecycle:
- Before training task `t`, the script iterates all prior task directories, loads each denoised `max.safetensors`, creates a temporary LoRA, and immediately `merge_and_unload()`s that delta into the base model.
- After all past denoised deltas are merged, it creates **one fresh LoRA** for the current task, trains it, denoises it, and saves the current task's `max.safetensors`.
- Evaluation reconstructs the continual model similarly by iterating task directories and merging each denoised delta; no inference router or active adapter bank is needed.

Accounting consequence:
1. **Deployed active inference parameters:** can remain constant-size once prior deltas are merged into backbone weights; no router/task selector.
2. **Active trainable adapter during a task:** approximately constant with task count (one current LoRA).
3. **Reproducibility/checkpoint archive:** grows approximately linearly with task count if each task directory is retained.
4. **Released reconstruction/startup work:** grows with the number of prior task deltas because the script replays merges from all previous directories.

This changes the fair-comparison matrix: "persistent growth" must be split into deployed-model state, retained archival state, and reconstruction cost. Counting only active adapter parameters makes SLoRA look constant; counting the experiment's retained continual history makes storage/reconstruction grow with T.

## Fresh routing stress test — FLEX shows short MCIT benchmarks can hide routing difficulty
Primary source: Yi et al., arXiv:2608.01437, submitted 2026-08-02, `Beyond Routing Saturation: A Long-Horizon Class-Incremental Perspective on Expert Routing in Multimodal Continual Instruction Tuning`.

FLEX introduces a 34-task, fingerprint-reduced long-horizon MCIT benchmark. The paper argues that common 4–10 task benchmarks leak task identity through textual fingerprints and keep the historical expert pool too small, making routing look nearly saturated. Plug-in class-incremental routers improve strict LoRA matching by up to **16.3 percentage points** and MacroScore by up to **4.6 points**.

Scope guard: the public FLEX workflow still uses an explicit progressive task order. It is therefore a high-value **inference-routing stress test**, not evidence that train-time task boundaries have been removed. This also adds three confounds to every routing comparison: benchmark fingerprint leakage, sequence horizon, and expert-pool size.
