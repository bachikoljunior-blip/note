## New failure evidence

### FE-246 — Memory consolidation can erase source authority while preserving the claim, turning observation or suggestion into an unauthorized standing instruction
**Primary source:**
- Zhan et al., “When Memory Becomes Authority: Benchmarking Authority Collapse at the Memory Consolidation Boundary,” arXiv:2608.01679: https://arxiv.org/abs/2608.01679

AuthMem-Bench uses paired cases that hold the focal claim and downstream task fixed while varying only source authority. Across seven memory consolidators based on widely used agent-memory systems and seven LLM backbones, authority collapse appears in `48/49` evaluated configurations: the claim survives consolidation but its usage constraints/source authority are lost. In a controlled action-grounded test, collapsed memories without authority metadata produce a mean unauthorized-action rate of `50.3%`. In the end-to-end test, automatically predicting and persisting authority labels reduces unauthorized action from `16.9%` to `0.0%`, while benign task success remains essentially unchanged.

**Failure implication:** preserving factual content is not enough for persistent memory. The system must preserve *who/what authorized the claim and for what use*. Otherwise a quoted observation, external suggestion or low-authority note can be replayed later as if it were a durable user command.

**Positive control / scope guard:** automatic authority labels are a strong tested mitigation in this benchmark, so the result is not evidence that persistent memory cannot safely represent authority. The `50.3%` and `16.9→0.0%` figures are specific to AuthMem-Bench’s paired authority manipulations, seven consolidator families and seven backbones; they are not production unauthorized-action rates.

### FE-247 — Self-evolution can improve benign capability while increasing exposure and unauthorized state changes; aggregate ASR alone can move in a different direction
**Primary source:**
- Li & Zhu, “Auditing Self-Evolution in Financial Agents: Capability Gains, Security Drift, and Execution-Interface Mismatch,” arXiv:2608.17684: https://arxiv.org/abs/2608.17684

The study audits SkillOpt, Agent Workflow Memory and ReasoningBank in a simulated e-banking environment using matched benign acquisition trajectories, sealed evaluation endpoints, execution-grounded checks and independent state replay. On Qwen 3.7 Flash, SkillOpt increases benign utility from `0.741` to `0.837`, but exposure to injected content also rises from `0.820` to `0.943`. Conditional attack success *after exposure* decreases from `0.605` to `0.562`, yet aggregate ASR increases from `0.496` to `0.530` and unauthorized financial-state changes rise to `0.685`. Across three independently evolved lineages, capability, exposure and unauthorized-state changes increase in all three, whereas aggregate ASR increases in only two.

The paper also isolates an execution-interface confound for AWM: a literal WebArena-style text-action envelope breaks the native function-calling executor. Removing only that envelope in a post-hoc sensitivity test changes utility from `0.319` to `0.756`, exposure from `0.299` to `0.909`, and ASR from `0.195` to `0.575`.

**Failure implication:** post-evolution accuracy and even conditional/aggregate ASR can disagree about safety because evolution changes *how often the system reaches the attack surface* and whether state-changing tool calls really execute. Audits should separately track benign utility, exposure/contact rate, conditional attack success and independently replayed unauthorized state changes, while validating artifact–executor compatibility.

**Scope guard:** this is a simulated banking environment and an August 2026 arXiv v1. The AWM envelope sensitivity is a harness compatibility effect, not evidence that AWM intrinsically has the reported low/high utility or ASR. SkillOpt/ReasoningBank results should not be generalized to all self-evolution methods or production finance systems.

### FE-248 — Textual attack acceptance, audit-visible evidence, and actual sandbox harm can disagree sharply; semantic safety checks can pass while harmful state changes occur
**Primary source:**
- Tian et al., “SafeClawBench: Separating Semantic, Audit-Evidence, and Sandbox Harm in Tool-Using LLM Agents,” arXiv:2606.18356: https://arxiv.org/abs/2606.18356

SafeClawBench evaluates 600 controlled adversarial tool-agent tasks across six attack families and explicitly separates three endpoints: semantic attack acceptance, audit-visible harm evidence, and sandbox-observed tool/state harm. Across five agent endpoints and four prompt policies, these endpoints diverge. Without added prompt protection, semantic failure rates span `9.0–44.2%`. More importantly, in a `12,000`-row matched executable analysis, `291` of `347` observed sandbox harms occur in rows that *pass* the Semantic Core check.

**Failure implication:** a semantic judge that says “the model did not accept the attack” is not a safe proxy for what the tool environment actually changed. Tool-agent evaluation should preserve an independent state/effect endpoint rather than collapsing intent text, audit evidence and executed harm into one ASR.

**Scope guard:** the `291/347` relation is from SafeClawBench’s separate executable protocol and matched task identities; it does not imply every semantic-safe response caused harm or that semantic classification is useless. Prompt policies and model endpoints interact, so the benchmark does not yield a universal conversion from semantic ASR to sandbox risk.
