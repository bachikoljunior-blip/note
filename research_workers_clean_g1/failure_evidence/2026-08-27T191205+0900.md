## New failure evidence

### FE-240 — A targeted long-horizon fix can reverse sign across model generations, so bottleneck interventions must be re-diagnosed rather than inherited from the previous model
**Primary source:**
- Shao et al., “Beyond End-to-End Success: Diagnosing Failures in Long-Horizon Security LLM Agents,” arXiv:2608.20563: https://arxiv.org/abs/2608.20563

The paper instruments long-horizon security tasks with intermediate checkpoints so it can distinguish failures that occur before versus after the capability of interest becomes available. In a pre-specified `92`-seed observed-state-reuse experiment, targeted protocol-disambiguation guidance raises the probability that Gemini 2.5 Flash actually observes the state it will later need from `65.5%` under a matched non-guidance control message to `95.4%`. Repeating the same experimental design with Gemini 3.7 Flash produces the opposite effect, and state observation itself no longer reliably predicts final task completion.

**Failure implication:** a controller that carries forward the last model generation’s diagnosed bottleneck and remediation can actively make the next generation worse. Long-horizon evaluation should localize where failure occurs under the *current* model/harness, then test the intervention against a matched control; aggregate end-to-end success is too coarse to tell whether an upstream fix still targets the dominant failure mechanism.

**Scope guard:** this is a security-agent diagnostic methodology over four task families and the reported Gemini checkpoints. The sign reversal does not imply protocol guidance is generally harmful or that model upgrades always change bottlenecks; it shows that the tested intervention is model-generation-dependent and that state observation ceased to be a sufficient predictor of task completion in the newer setting.
