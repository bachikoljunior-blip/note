## Source-qualified negative finding

Public repository issue `cfg-is/cfgms#3095` describes a real three-controller same-LAN partition test using an actual host firewall/iptables partition rather than the Docker baseline. Its acceptance criterion requires concurrent polling from both sides and no instant where two nodes both report leadership.

A repository comment dated 2026-08-16 reports that `TestRealClusterPartition_NoDualLeader` failed reproducibly on the real cluster with measured dual-leader overlaps of **2.0 s** and **5.5 s**. The same report traces `POST /api/v1/config/push` past an `IsLeader()` gate into desired-state writes and command fan-out to stewards **without a Raft commit in that path**. The reporter therefore distinguishes `CheckQuorum`'s replicated-log write-safety from authority over external side effects: during the overlap window, two nodes can both admit config pushes and deliver them to real endpoints. The repository issue is now closed with state_reason=`completed` (closed 2026-08-26), but this slice does not inspect or infer the status of the separate repair story referenced by the comment.

## Falsifying trace / tested scope

Tested/reported scope only: cfg-is/cfgms real 3-node controller cluster, same-LAN 2-vs-1 partition, `TestRealClusterPartition_NoDualLeader`, and the cited config-push path. Observed trace: real partition -> temporary simultaneous leadership reports (2.0 s / 5.5 s) -> both leaders may pass `IsLeader()` -> external config-push effects are not fenced by a Raft-log commit.

This falsifies the narrow assumption that **Raft leadership plus CheckQuorum alone is sufficient authority for all externally visible side effects** in this tested path. It does **not** establish that every Raft system has this bug, that every cfgms endpoint is unsafe, or that the referenced later fencing design is merged/effective.

## Phase-1 relevance

For scheduled-Chat parity designs, a local/replicated leadership witness is not automatically an effect-fencing witness. If a stale or concurrent actor can still pass a local authority predicate while emitting effects outside the protected commit path, duplicate or conflicting effects can escape. Acceptance therefore needs the authoritative business-effect boundary itself to reject stale generations/terms, not merely a controller-side liveness/leadership signal.
