## New failure evidence

### FE-334 — Harness context reconstruction can turn low-privilege attacker content into actual user/system privilege, bypassing both model hierarchy and automatic permission review
**Primary source:** “When Context Gets Root: Privilege Escalation in LLM Harnesses,” arXiv:2608.27299v1, 27 Aug 2026, https://arxiv.org/abs/2608.27299

The paper evaluates 13 confidentiality/integrity/availability/RCE objectives across six coding-agent harnesses. Under unrestricted execution, instruction-privilege-escalation attacks achieve all 13 objectives on all six harnesses. Under automatic permission review, they still achieve all 13 objectives on all three harnesses that provide that mode. The root cause is not merely model-side role confusion: delegation, persistent goals, scheduled tasks, and custom subagents can reconstruct context so tool-level content is inserted as an actual user message or system-effective instruction. The authors also report that role labels are then consumed by both the working agent and permission reviewer as if they faithfully reflected provenance.

A concrete matched mechanism matters: the same malicious request can be refused when received as low-privilege tool content, then followed after the harness reintroduces it to a subagent under a user role. Thus an instruction hierarchy can be locally correct while the harness invalidates its provenance premise between invocations.

**Failure implication:** model-side instruction hierarchy and permission review are not sufficient if the harness can relabel or reconstruct provenance. Persistent/delegated/scheduled state needs origin-preserving labels that cannot gain authority merely because it crossed an agent or session boundary.

**Scope guard:** six evaluated coding-agent harnesses, 13 chosen objectives, and the tested context-reconstruction mechanisms. This does not establish that every harness or every permission reviewer is vulnerable.

### FE-335 — Safety can fail to compose across loop iterations when risk state decays or resets even though every local trajectory appears acceptable
**Primary source:** “Safety Does Not Compose: Non-Decaying Loop State for Autonomous LLM Agents,” arXiv:2608.27141v1, 27 Aug 2026, https://arxiv.org/abs/2608.27141

On the paper’s outer-loop Track-B benchmark (200 attack episodes per family, 1,000 per configuration), the single-trajectory/outer-reset baselines B0/B1/B1.5 have **97.6% overall ASR** with about **97.3–97.4% clean completion**. A naive final-response arbiter B2 still has **88.4% ASR** and only **87.8% CleanGC**. The full five-component loop-state system B4 reduces overall ASR to **0.1%** while retaining **96.9% CleanGC**. Matched one-component removals restore the intended family almost completely: overall ASR becomes **19.3–19.6%** when one of four mechanisms is removed and **38.8%** when governance is removed.

The matched risk-retention test is especially sharp. With identical episodes and all other modules fixed, a decaying retained-risk state blocks A14 at one evidence-free iteration (**0.0% ASR**) but falls below threshold after two iterations and reopens to **97.0% ASR**; after four iterations ASR is **97.5%**. A non-decaying latch remains at **0.0% ASR** over the same intervals. The paper separately reports compounding cASR for B1/B1.5 rising from **2.9% at N=5** to **6.2% at N=10/20**, while B4 stays at 0%.

**Failure implication:** a defense that is sound within one trajectory can become unsafe when autonomous loops reset, decay, or summarize away cross-iteration evidence. “Cooling off” is not itself authenticated clearance. Long-running automation should preserve structural risk/authorization evidence until an explicit scoped clearance event occurs.

**Scope guard:** the paper’s LoopHarness / Agent-SafetyBench-derived A6–A15 suites and frozen model-role assignment. The authors explicitly state each reported matrix uses one execution seed and does not include multi-seed/multi-model replication; the result should not be generalized to all persistent-agent designs.

### FE-336 — Execution guardrails can over-refuse authorized actions because a resource name sounds dangerous, even when authorization is held fixed
**Primary source:** “The Guard That Cried Wolf: How Scary Names Make Agent Guardrails Refuse Legitimate Actions,” arXiv:2608.27009v1, 27 Aug 2026, https://arxiv.org/abs/2608.27009

Cautious Bench constructs 756 decidable benign cells with authorized actions and renders each under innocent/as-authored/scary resource-name grades while holding every authorization-bearing field, action, policy, and gate fixed. On the full Decidable set, ToolEmu false positives rise **32%→36%→45%** as names become scarier; the paper reports the same direction across the execution-safety guards. The effect survives a nearly length-matched subset of 356 cells: TS-Guard refusal rises **32%→62%** when only the name changes.

Authorized removal actions provide another matched check: AgentDoG-Llama refusal rises **25%→56%**, R-Judge **54%→76%**, and TS-Guard **29%→40%** from innocent to scary names. ToolEmu reverses on this removal subset (**38%→29%**), which is important negative scope evidence: there is no universal monotonic rule that every guard reacts identically.

**Failure implication:** a guardrail can use semantic “scariness” as a shortcut instead of the actual authorization contract, producing high false refusals while seeming cautious. Safety evaluation should pair authorized and unauthorized twins and include surface counterfactuals that preserve policy state.

**Scope guard:** the Cautious Bench Decidable segment, tested guardrails, and disclosed refusal predicates. Exact false-positive rates are not universal, and the ToolEmu removal reversal prevents broad claims about monotonicity across all guards/subsets.
