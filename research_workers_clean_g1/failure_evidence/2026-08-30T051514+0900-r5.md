## FE-472 — A remote transport/handle failure can be observationally identical to an empty process inspection and therefore trigger a false clean-completion signal
**Sources:** stablyai/orca issue #9151 and merged PR #9263.
- https://github.com/stablyai/orca/issues/9151
- https://github.com/stablyai/orca/pull/9263

In Orca v1.4.143's paired remote-runtime path, `no_connected_pty`, stale-handle, and gone-handle inspection failures were collapsed to the same `{ foregroundProcess: null, hasChildProcesses: false }` shape used by a successful authoritative inspection that found no agent process. The completion coordinator required two consecutive empty samples, so two transport/handle failures could satisfy the normal clean-exit detector and emit `agent-task-complete` / completion attention even though the remote agent turn had not been proven finished.

The issue's reproduction is deliberately remote-specific: start a long-running remote agent, interrupt the paired runtime so inspection returns `no_connected_pty` or equivalent stale/gone-handle evidence, restore connectivity, and let the inspection cadence run twice. The observed failure is a completion notification caused by connection loss rather than a confirmed agent exit.

Merged PR #9263 on 2026-07-23 makes process inspection an atomic discriminated result. Transport/routing uncertainty, stale handles, explicit stops, real process exits, and genuine idle completion remain distinct. Unknown/unavailable results clear any armed idle sample; after recovery the coordinator requires two fresh authoritative idle samples before completion. The PR reports a deterministic authority oracle where the candidate passes all four scenarios and reverting the fix reproduces three false-completion failures, plus focused regressions and a headed macOS paired-client disconnect/reconnect exercise.

**Trigger:** a non-authoritative remote inspection error is normalized into the same value as authoritative proof of process absence.

**Detectable signal:** completion/attention is emitted after two stale/unavailable inspection outcomes without any successful remote inspection or authoritative exit event.

**Fail-closed response:** preserve an explicit `unknown/unavailable` liveness state; do not accumulate it toward completion evidence; after recovery require fresh authoritative samples before declaring clean exit.

**Recovery witness:** merged PR #9263 with revert-sensitive deterministic oracle and paired remote disconnect/reconnect exercise.

**Scope:** Orca paired/SSH remote-runtime process inspection and agent-completion coordination in the tested release/main path. This does not prove that every local process loss or every remote disconnect is a false completion, and it is not evidence that arbitrary remote work continues successfully after disconnect.
