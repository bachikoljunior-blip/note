## New failure evidence

### FE-021 — Auditing and filtering benchmark tasks can reverse model rankings even when the exact same trajectories are re-scored

Primary artifact:
- AgentSuite, “AgentSuite: Toward More Reliable Agent Evaluation with a Component-Based Benchmark Auditing Pipeline,” ICML 2026 public repository.
- Split semantics: https://github.com/Agent-Suite/AgentSuite/blob/main/eval_splits.md
- Committed split scores:
  - https://github.com/Agent-Suite/AgentSuite/blob/main/results/splits/tau-bench_split_scores.csv
  - https://github.com/Agent-Suite/AgentSuite/blob/main/results/splits/tau2-bench_split_scores.csv
  - https://github.com/Agent-Suite/AgentSuite/blob/main/results/splits/complex-func-bench_split_scores.csv
  - https://github.com/Agent-Suite/AgentSuite/blob/main/results/splits/ACEBench_split_scores.csv
  - https://github.com/Agent-Suite/AgentSuite/blob/main/results/splits/overall_leaderboard.csv

Matched comparison design:
- AgentSuite’s `Filtering` split drops every flagged task whose resolution is not `KEEP` (`FIX ∪ REMOVE ∪ TODO`) and re-scores the **same Original trajectories** on the surviving task set.
- No agent reruns are performed for Filtering; therefore model policy, trajectory generation, and run-time environment are held fixed at the stored trajectory level while the audited task denominator changes.

Quantitative rank instability:

**τ-bench** (`n_all=165`, `n_filtered=139`, 26 dropped for full-coverage rows):
- DeepSeek-V3.2-Exp-thinking-on: micro 0.7212 → 0.7914, rank **1 → 2**.
- Claude-4.5-Sonnet-thinking-on-10k: micro 0.7152 → 0.7986, rank **2 → 1**.
- Thus the top-two ordering reverses despite no new trajectories being generated.
- Kimi-K2-Instruct moves 15 → 10 (0.6242 → 0.6906), while GPT-4.1 moves 10 → 12 (0.6424 → 0.6835), showing broader rank sensitivity.

**ComplexFuncBench / CFBench** (`1000 → 824`, 176 dropped):
- Claude-4-Sonnet-thinking-off moves 8 → 9 while its thinking-on counterpart moves 9 → 8.
- Qwen3-235B-A22B-Instruct moves 10 → 12, while Claude-4-Opus-thinking-off/on move 11→10 and 12→11.
- Gemini-2.5-Flash-thinking-off and o3-high swap 19/20; GPT-4o-mini and DeepSeek-V3.2-Exp-thinking-on swap 22/23.

**ACEBench** (`1023 → 897`, 126 dropped):
- Claude-4.5-Sonnet-thinking-on-10k moves **7 → 3** (0.8016 → 0.8506).
- Kimi-K2-Instruct moves **8 → 13** (0.7996 → 0.8350).
- Gemini-2.5-Pro-thinking-on moves **13 → 8** (0.7928 → 0.8417).
- A concrete pairwise reversal is Kimi-K2-Instruct > Gemini-2.5-Pro on Original (0.7996 vs 0.7928), but Gemini > Kimi after Filtering (0.8417 vs 0.8350).

**Overall committed leaderboard**:
- GPT-4.1 remains rank 1.
- Kimi-K2-Instruct changes rank **2 → 3** while o3-high changes **3 → 2**.
- DeepSeek-V3-0324 changes 7→8 while GPT-5 changes 8→7.

Interpretation constrained to evidence:
- On these committed AgentSuite trajectories, comparative model conclusions are sensitive to whether audit-flagged tasks are included. Filtering can change both local benchmark orderings and an overall equal-weight leaderboard ordering without any policy rerun.
- This directly demonstrates benchmark-task validity as a possible source of ranking instability, not merely an absolute-score shift.

Scope limit:
- Filtering is an audit policy, not proof that every dropped task is objectively invalid or every retained task is flawless. AgentSuite explicitly treats the manifest as an audit artifact and distinguishes `FIX`, `REMOVE`, `KEEP`, and `TODO`.
- Some τ-bench/τ² rows have partial task coverage (`n_all` smaller and zero matched filter IDs); rank claims above use full-coverage rows where stated and should not be generalized across incomparable coverage.
- Filtering answers “what do these already-generated trajectories score on the surviving audited task set?”; it does not measure how agents would behave if rerun after repaired task wording or environment changes. That is the separate `Fixed` variant.

### FE-022 — Live-web evaluation state is not stationary: task validity and measured success materially depend on environment state/configuration

Primary artifacts:
- Online-Mind2Web benchmark repository: https://github.com/OSU-NLP-Group/Online-Mind2Web
- WebCanvas / Mind2Web-Live SeeAct-V implementation: https://github.com/boyugou/Mind2Web_Live_SeeAct_V

Observed benchmark maintenance:
- Online-Mind2Web contains 300 tasks across 136 live websites.
- On 2025-11-03 the maintainers replaced **36/300 tasks (12%)** because they were “no longer valid or involved websites with CAPTCHA verification.”
- Further task replacements are recorded on 2025-11-23 (2 task IDs), 2025-12-11 (5), 2025-12-14 (2), 2026-01-02 (1), and 2026-05-15 (6).
- The repository explicitly says the benchmark will be regularly updated by replacing outdated/invalid tasks, including due to website changes.

Matched configuration sensitivity on Mind2Web-Live:
- The WebCanvas/SeeAct-V repository reports the same planning model (`gpt-3.5-turbo-0125`) on the Mind2Web-Live test set under different execution environments.
- United States + Windows + Chrome: completion 40.2%, task success **16.5%**, efficiency 3.03.
- United States + Windows + Firefox: completion 42.1%, task success **20.2%**, efficiency 2.79.
- United States + Linux + Chrome: completion 36.5%, task success **15.4%**, efficiency 3.33.
- United Kingdom + Windows + Chrome: completion 23.6%, task success **8.65%**, efficiency 7.78.
- Singapore + Windows + Chrome: completion 42.3%, task success **21.2%**, efficiency 2.95.
- The repository itself concludes that experimental environment plays a crucial role and recommends Windows + Chrome/Firefox in the US for this benchmark.

Interpretation constrained to evidence:
- For live-web benchmarks, a failure can originate from benchmark/environment state rather than model policy alone. Dataset-version pinning plus browser/system/region provenance are necessary for longitudinal or cross-system comparisons.
- The 36-task replacement is direct evidence of task-validity churn; the environment table separately shows substantial score sensitivity under the same named planning model.

Scope limit:
- The 12% replacement event combines “no longer valid” tasks and CAPTCHA-affected websites; it must not be attributed wholly to ordinary UI/content drift.
- The browser/system/region table is not reported as randomized paired trials with repeated confidence intervals. It demonstrates configuration sensitivity in the authors’ runs, not a universal causal effect size for each environment variable.
- The maintenance evidence does not itself show that one fixed model’s score changed across calendar snapshots; a truly repeated same-policy/same-task temporal study remains a frontier item.

### FE-023 — More inference-time reasoning does not monotonically improve long-horizon agent accuracy

Primary source:
- Kapoor et al., “Holistic Agent Leaderboard: The Missing Infrastructure for AI Agent Evaluation,” arXiv:2510.11977 (2025), public HAL study.
- https://arxiv.org/abs/2510.11977
- First-author public description of the matched reasoning-effort result: https://threadreaderapp.com/thread/1978565190057869344.html

Tested scope:
- HAL reports 21,730 agent rollouts across 9 models and 9 benchmarks spanning coding, web navigation, science, and customer service.
- The reasoning-effort comparison uses four model pairs/settings (Claude 3.7 Sonnet, Claude Sonnet 4, Claude Opus 4.1: no reasoning vs high; o4-mini: low vs high) for a given scaffold and benchmark.

Quantitative negative evidence:
- The paper’s public description states that higher reasoning effort reduced accuracy in the majority of runs.
- The first-author public report gives the exact matched count: **21 of 36** model/scaffold/benchmark comparisons showed no accuracy improvement at the higher reasoning setting.
- The published figure spans both positive and negative deltas, so the failure is non-monotonic rather than a claim that higher reasoning always hurts.

Interpretation constrained to evidence:
- In these HAL configurations, “turn reasoning up” is not a safe monotonic improvement rule. Reasoning effort must be treated as a configuration to evaluate against task/scaffold-specific benefit and cost.

Scope limit:
- “21 of 36 no improvement” includes ties as well as decreases; it is incorrect to restate this as 21 strict regressions without cell-level values.
- Reasoning controls differ by provider/model, and “high” is not a provider-independent unit of compute. The result does not imply that additional test-time compute is generally harmful.
- I did not extract exact per-cell numeric deltas from the protected OpenReview PDF in this continuation; promoting “largest regression” values remains pending until directly verifiable from a primary accessible table/figure artifact.

### FE-024 — Self-correction can be gated by chat-template role labels rather than the byte-identical erroneous claim

Primary source:
- Chen, Su, Chiang, “The Self-Correction Illusion: Role Relabeling Gates Explicit Error Flagging in Large Language Models,” arXiv:2606.05976, 4 Jun 2026.
- https://arxiv.org/abs/2606.05976

Controlled intervention:
- The experiment holds an erroneous intermediate claim byte-identical across conditions (SHA-256 verified) and varies only how that claim is wrapped in the chat template: original self `<thought>`, user message, tool response, or system `<memory>`.
- The audit instruction is held byte-identical. Each model-domain cell uses `n=30` paired tasks.
- The paper evaluates explicit error correction/flagging, not merely whether the final answer happens to become correct.

Quantitative matched evidence:
- Across 13 model-domain cells spanning seven model families and three domains, moving the same wrong claim from self `<thought>` to an external role raises explicit-correction rate by **23 to 93 percentage points** in the reported headline comparison; 10/13 cells reach `p<0.001`.
- Table 2 examples:
  - Qwen2.5-72B math: baseline explicit correction 16.7%; system-memory relabel +53.3 pp.
  - Llama-3.3-70B math: baseline 0%; system-memory +86.7 pp.
  - Llama-3.3-70B generated logic: baseline 0%; neutral user-role +93.3 pp.
  - GPT-4o math: baseline 40.0%; neutral user-role +50.0 pp.
  - Claude Sonnet 4 math: baseline 53.3%; user wait / neutral / memory each +40.0 pp.
- The paper additionally notes that agents can silently re-derive the correct answer without explicitly addressing the wrong intermediate, so the intervention is primarily a diagnostic of error addressability.

Interpretation constrained to evidence:
- In this constructed paired failure pool, the harness representation of an error can dominate whether the model explicitly rejects it. A “self-correction failure” therefore cannot automatically be attributed to absent reasoning capacity when the same content is corrected after role relabeling.

Scope limit:
- This is not evidence that arbitrary external-role relabeling improves final-answer accuracy in deployed agents; the paper explicitly says it surfaces errors rather than necessarily improving final correctness.
- The intervention assumes the wrong claim is already localized. Automatic error localization is a separate unsolved step.
- Role relabeling is not a robust defense: the paper reports that an instruction to trust an external claim without verification removes much of the default resistance.

## Updated failure taxonomy

The new evidence adds four separable failure surfaces to the existing clean taxonomy:

1. **Benchmark-composition/ranking instability (FE-021):** audited task inclusion can change pairwise and aggregate rankings even under identical stored trajectories.
2. **Live-environment non-stationarity (FE-022):** task validity and measured success vary with website/task maintenance and execution environment provenance.
3. **Inference-compute non-monotonicity (FE-023):** higher reasoning effort is not a guaranteed accuracy improvement under matched scaffold/benchmark settings.
4. **Harness-role-conditioned self-correction (FE-024):** explicit error correction can be strongly gated by message-role representation even when error content is byte-identical.

These should remain distinct from policy capability, verifier correctness, procedural compliance, run-to-run stochasticity, mutating-action criticality, benchmark leakage, scaffold defects, and synthetic fault robustness from earlier clean evidence.
