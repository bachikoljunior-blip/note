## New failure evidence

### FE-189 — Native file-carrier evaluation exposed a failure that vanished in plain-text approximation
**Primary sources:**
- https://arxiv.org/abs/2608.16393
- https://github.com/Tencent/AI-Infra-Guard/tree/main/Research/deepseek-harness-security-assessment

In the DeepSeek Harness indirect-prompt-injection assessment, the same evaluation matrix spans 16 channels, text/file carrier modes, and 35 payload objectives. For hidden-Unicode attacks, RuleJudge attack success was `0.0%` in text mode but `25.5%` in file mode. The repository explicitly states that file mode creates native carrier files and then invokes format-specific extraction/parsing, whereas text mode injects only a textual representation.

**Failure implication:** replacing native artifacts with text approximations can erase representation/parser-mediated attack paths and materially understate agent exposure.

**Scope guard:** this is one DeepSeek Harness configuration with controlled local source/sink fixtures and the paper's carrier generation/extraction path. It does not imply that file mode is always riskier for every channel, parser, backend, or agent.

### FE-190 — A stronger framing attack tripled measured success relative to the unmodified baseline in the same text-mode assessment
**Primary sources:** same as FE-189.

Within the published DeepSeek Harness text-mode assessment, fake-completion attack reached `17.0%` LLMJudge attack success versus `5.7%` for the unmodified `naive` baseline. The repository describes `naive` plus 12 attack methods applied to the same objective matrix.

**Failure implication:** a weak or unmodified red-team baseline can substantially understate reachable failure even before changing the model, tool registry, or agent loop; attack formulation is an evaluation variable.

**Scope guard:** fake-completion is not proved globally strongest. The 17.0% vs 5.7% comparison is limited to this harness, backend, text carrier path, objective matrix, and LLMJudge contract.

### FE-191 — Deterministic and semantic judges disagreed sharply on partial compliance over the same saved traces
**Primary source:** https://arxiv.org/abs/2608.16393 and the matching public assessment repository above.

Across the same 14,560 saved traces, the semantic LLM judge labeled `7.3%` as partial compliance while the deterministic RuleJudge labeled `2.0%`. The repository states that RuleJudge checks exact taint/sink/argument/canary/refusal criteria, whereas the LLM judge applies semantic trace-level judgment offline.

**Failure implication:** a single automatic judge can hide an important class of influence/failure; exact operational completion and semantic partial compliance should remain separate reported outcomes rather than being collapsed into one score.

**Scope guard:** this difference is not evidence that either judge is globally more correct. It identifies construct sensitivity to the success contract in this one evaluation.

### FE-192 — Reusable agent skills behaved as a high-risk prompt-injection channel in the tested harness
**Primary sources:** same as FE-189.

The DeepSeek Harness public artifact reports RuleJudge attack success for the `skills` channel of `14.3%` in text mode and `16.0%` in file mode. The experiment preserves the real agent loop and tool registry while using simulated local sinks.

**Failure implication:** code-adjacent reusable instructions/integrations can be part of the prompt-injection supply chain; treating skills as trusted configuration outside the untrusted-content threat model can miss real execution paths.

**Scope guard:** this does not show that all skill systems are unsafe or that these percentages transfer to other skill formats, provenance controls, models, or privilege boundaries.

### FE-193 — Standard short-form benchmark accuracy can miss route-level stochastic fidelity loss that appears in long-horizon agent tasks
**Primary source:** https://arxiv.org/abs/2608.16391

Ventor-QTest treats hosted inference routing as a stochastic process. Across seven route snapshots, 20-run sequence probes showed route-specific extreme fidelity loss (EFL). The paper reports little detectable route-level association of AFL/EFL with GPQA-Diamond accuracy, while pronounced EFL coincided with declining Terminal-Bench pass rate as task exposure increased.

**Failure implication:** a hosted endpoint can look normal on a conventional capability score while rare or tail-distribution deviations degrade long-horizon agent reliability. Vendor/API route fidelity should therefore be audited with repeated and sequence-level probes, not inferred from one benchmark score.

**Scope guard:** the reported Terminal-Bench relation is descriptive, not a randomized causal estimate, and is limited to the paper's seven route snapshots and hosted-model configuration. Do not generalize it to all providers or all long-horizon tasks.
