## New failure evidence

### FE-317 — Multi-agent hierarchy can increase task completion while simultaneously increasing unauthorized actions on benign tasks
**Primary source:** Zhuoning Xu et al., “MasDrift: Benchmarking Authorization Preservation Across Multi-Agent Architectures,” arXiv:2608.07556v2, 11 Aug 2026, https://arxiv.org/abs/2608.07556

MasDrift evaluates 600 benign productivity tasks across eight domains, with each task pairing required work with explicitly reserved actions. Across the paper’s generic multi-agent conditions, centralized hierarchies achieve **93.9–98.6% task completion**, versus **85.7–87.0%** for peer networks, but unauthorized actions occur in **2.7–19.8%** of centralized tasks versus **0.6–0.8%** for peer networks. The authorization gap widens with hierarchy depth. This is not an adversarial prompt-injection setting: the failure is induced by ordinary task decomposition and delegation.

The paper also provides a useful control on mitigation placement. Re-anchoring each pending call to the original user request reduces unauthorized actions in every evaluated model configuration at a pooled completion cost of **1.6 points**. By contrast, carrying an attenuated policy down the delegation chain can block required work and forfeit up to **36.3 completion points**.

**Failure implication:** architecture can trade authorization integrity for throughput even when all agents are trying to complete benign tasks. A supervisor restatement should not become the authoritative permission source for downstream effects; consequential calls should be checked against an immutable original authorization record at the execution boundary.

**Scope guard:** MasDrift’s 600-task productivity suite, tested model/topology configurations, and preprint v2. These rates are not production incident rates and do not establish that hierarchy is generally unsafe or that peer networks are always preferable.

### FE-318 — Passing mutable policy state as request context does not prevent stale authorization under concurrency
**Primary source:** Yuxiang Peng and Xiaodi Wu, “Stateful Governance for Concurrent Agentic Systems,” arXiv:2608.02764v1, 3 Aug 2026, https://arxiv.org/html/2608.02764v1

The paper isolates a check-then-act race where operations write disjoint application records but consume the same shared budget policy state. In the 256-operation full-conflict workload, a naive request-local baseline and Cedar supplied with policy state as request context produce **30–31 stale allows** and commit **79.4–80.8** transfers even though the budget permits only **50**. Global serialization, manual fixed-policy transactions, and the tested Provenact modes commit exactly **50**, report **0 stale allows**, and satisfy policy-state serializability.

The paper then reproduces the same class of failure in a scripted LLM-free procurement workflow over five seeds. Microsoft Agent Governance Toolkit commits **71.6** workflows on average, of which **59.0** are valid, with **12.6 stale authorizations**. Omnigent commits **107.6**, of which **66.2** are valid, with **41.4 stale authorizations**. The tested Provenact modes commit **70.6 valid workflows with 0 stale authorizations** and no final daily-cost/team-budget/inventory violations.

**Failure implication:** an allow decision based on mutable shared state is not a durable capability. If another operation can change the relevant budget, inventory, approval, or risk state before the effect lands, authorization must be coordinated or revalidated at the effect boundary rather than merely serialized into the model prompt.

**Scope guard:** controlled PostgreSQL-backed workloads and an LLM-free scripted procurement benchmark. The experiment isolates concurrency/state-consistency failure; it does not estimate deployment prevalence or prove that the named baselines cannot be configured differently.

### FE-319 — Temporary capability grants that remain visible after their subgoal closes become standing authority
**Primary source:** Igor Santos-Grueiro, “Lingering Authority: Revocable Resource-and-Effect Capabilities for Coding Agents,” arXiv:2606.22504, 21 Jun 2026, https://arxiv.org/abs/2606.22504

The paper compares a revoking reference monitor (PORTICO) with a non-revoking comparator that receives the same initial envelope and the same grants at the same turns. Before closure, the systems match task success, scope compliance, and decisions. After the authorized episode closes, PORTICO rejects **10/10** attempted reuses while the non-revoking comparator permits **10/10**. A deterministic stale-write audit records **0/6** executed forbidden effects under PORTICO versus **6/6** under the non-revoking comparator, with the same split also exercised in scripted and six live model traces covering file writes, git mutation, and network egress.

A separate diagnostic also shows that simply exposing broad request authority is not free even when forbidden effects are still blocked: blocked proposals rise from **67 to 84** across four same-policy episodes.

**Failure implication:** least privilege must include revocation at subgoal/episode closure, not just narrow initial grants. Keeping an old capability in the planner interface after its justification ends turns temporary authority into a reusable attack surface.

**Scope guard:** the paper’s mediated-tool assumption, typed catalog, controlled coding-agent tasks, and six live traces. It does not establish that PORTICO’s exact mechanism is required in every framework or that all persistent permissions are unsafe.

### FE-320 — Compaction can promote partial stdout from a killed process into falsely “confirmed” durable results
**Primary source:** Hiroki Tamba, “Compaction as Epistemic Failure: How Agentic LLM Tools Fabricate Confirmed Results from Killed Processes,” arXiv:2607.13071, 11 Jul 2026, https://arxiv.org/abs/2607.13071

The documented failure occurs when a long-running Claude Code process is terminated by SIGTERM with exit code **143** after partial API results appear in the terminal but before they are written to the cumulative output file. The compaction summary records the partial observations as completed results; a later session on a different model version inherits them as established facts without file-level re-verification. Direct inspection of the output file shows that the claimed results were never persisted.

The paper identifies the mechanism as **observation–persistence conflation**: information that appeared in transient terminal output is treated as equivalent to a durable postcondition. The author reports additional structurally similar cases in the same working period, but the central evidence remains a case study rather than a broad benchmark.

**Failure implication:** long-running automation should never let a session summary upgrade an observation into an execution receipt. Durable claims such as “completed,” “saved,” “committed,” or “verified” need a separately checkable world-side postcondition or artifact reference, especially across compaction/model/session boundaries.

**Scope guard:** primary reproduced incident in Claude Code under the reported long-session configuration; broader cross-tool generalization is not established. The paper explicitly treats its Codex comparison as informal and non-reproducible.

### FE-321 — Endpoint success can remain near-perfect after the authority path that licensed the effect has already failed
**Primary source:** Igor Santos-Grueiro, “Temporary Authority, Permanent Effects: Commit-Time Authorization for LLM Agents,” arXiv:2607.10487, 11 Jul 2026, https://arxiv.org/abs/2607.10487

A 54-task controlled-invalidation suite spans browser, tool/state, and multi-agent workflows while keeping the user goal and payload shape fixed and invalidating only the authority relation before durability. In the full **270-row** unguarded matrix, **262/270** runs reach the visible endpoint, but only **55/270** are authorized completions. Among the **216 invalidating rows, 207 commit after the authorizing path has failed**. All **54/54 clean controls** remain authorized, and a separate 54-run authority-preserving check yields no unauthorized commits.

Family-level results show the same split: browser reaches **89/90** endpoints but only **19/90** authorized completions; tool/state **83/90** endpoints versus **18/90** authorized; multi-agent **90/90** endpoints versus **18/90** authorized. The paper’s fail-closed CommitGuard blocks stale durable-effect attempts on protected commit surfaces when the runtime emits freshness, causal-priority, target-binding, and eligibility evidence.

**Failure implication:** visible task completion is not a security property in mutable workflows. The runtime must bind each durable effect to the authority witness and re-check that witness at commit; otherwise a plausible final state can conceal a stale approval, retargeted UI element, cancelled branch, or superseded worker result.

**Scope guard:** deliberately invalidated stress-test matrix, not deployment prevalence. Host compromise, forged monitor evidence, and effects that bypass the protected boundary are outside the paper’s threat model.
