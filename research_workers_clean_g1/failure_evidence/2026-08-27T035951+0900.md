### FE-146 — ToolHazard shows that a single prompt-injection wrapper can drastically understate benchmark-level agent vulnerability
**Status:** primary arXiv v1 + official code release; ToolHazard-Bench exact tested setup only.

Primary sources:
- Paper: https://arxiv.org/abs/2608.11878
- PDF: https://arxiv.org/pdf/2608.11878
- Official code: https://github.com/MurrayTom/ToolHazard

Evidence from Table 2:
- GPT-5 ASR ranges from `1.18%` under Basic Combined to `59.14%` under Tool Selection.
- GPT-4.1 ranges from `1.18%` Basic Combined to `75.57%` Tool Selection.
- DeepSeek-V3.2 ranges from `1.18%` Basic Combined to `75.00%` Decision Hijacking and `73.33%` on several other wrappers.
- Gemini-3.1-Pro ranges from `23.06%` Important Template to `63.20%` Reasoning Criteria.
- The six attack categories contain slightly different counts of valid cases, so these are benchmark-level strategy comparisons rather than a perfectly paired per-task single-factor causal estimate.

Failure implication: reporting one canonical environment-side injection wrapper can materially understate worst-case vulnerability and can distort model comparisons. Attack-family coverage is part of the evaluation protocol.

Scope guard: this does not establish that Tool Selection, Decision Hijacking, or Reasoning Criteria are universally strongest; the result is specific to ToolHazard-Bench, its stateful synthesized environments, ReAct-style agent harness, model versions, and released wrappers.

### FE-147 — Tool-output serialization alone can change indirect prompt-injection ASR by tens of percentage points
**Status:** primary matched format analysis in ToolHazard Figure 4; exact tested conditions only.

Evidence:
- The paper explicitly compares free-form string versus JSON/YAML tool outputs under identical settings.
- For GPT-4.1 with Basic Combined, ASR is approximately `1.2%` with YAML, `12.9%` with JSON, and `52.6%` with free-form string.
- For Gemini-3.1-Pro with Tool Selection, ASR is `32.6%` with YAML, `40.5%` with JSON, and `77.7%` with free-form string.
- Free-form is therefore +51.4pp versus YAML in the first cell and +45.1pp versus YAML in the second cell.

Failure implication: agent safety measured with one tool-output format cannot be assumed to transfer to another. A benchmark that serializes observations as structured JSON/YAML may substantially overestimate safety for deployments that expose free-form text, and vice versa.

Scope guard: JSON is not uniformly safer than YAML in every plotted cell, and this does not prove that structured output alone is a sufficient defense. The claim is about large format sensitivity under the tested ToolHazard conditions.

### FE-148 — Clean-trajectory SFT / clean-environment SFT+RL can improve benign utility while worsening security on one model size, while the same recipes improve security on a larger model
**Status:** primary Table 4 + Appendix H labeling; Qwen3-4B/8B only.

Evidence from Table 4:
- Qwen3-4B base on ToolHazard-Bench: BR `38.19`, ASR `25.05`.
- `+ SFT`: BR improves to `67.29` but ASR worsens to `29.88` (+4.83pp).
- `+ SFT+RL`: BR improves to `68.87` but ASR worsens further to `32.41` (+7.36pp versus base).
- On AgentDojo, the same 4B SFT row also slightly worsens ASR `14.23→14.65`, while SFT+RL improves it to `13.07`.
- By contrast, Qwen3-8B SFT improves ToolHazard ASR `36.10→22.53`, and SFT+RL improves it to `19.27`; the sign is opposite to the 4B ToolHazard case.
- Full adversarial ToolHazard-Align is a positive control: Qwen3-4B reaches BR `70.68`, ASR `22.76` on ToolHazard and BR `41.73`, ASR `7.17` on AgentDojo; Qwen3-8B reaches `75.94/18.06` and `52.08/18.34` respectively.
- Appendix H explicitly calls the non-adversarial comparator a `clean-environment SFT+RL` baseline.

Failure implication: benign-task/capability fine-tuning gains are not reliable proxies for injection robustness, and even the sign of the security effect can depend on model size and benchmark. Safety evaluation must accompany each training recipe and target model rather than being inherited from a nearby scale.

Scope guard: this does not establish that SFT or RL generally worsen security. The negative sign is specific to Qwen3-4B under the released ToolHazard-Bench configuration; Qwen3-8B and full adversarial alignment provide explicit counterexamples.

### FE-149 — Injection timing and field placement are evaluation variables: fixed/random placement can miss a stronger reachable attack point
**Status:** primary matched ToolHazard Figure 3; tool-selection wrapper fixed.

Evidence:
- Timing experiment fixes Tool Selection and compares earliest accessible (`top-1`), second earliest (`top-2`), and random injection points.
- GPT-5 ASR: `67.2%` top-1, `52.1%` top-2, `57.5%` random; earliest exceeds random by 9.7pp.
- Gemini-3.1-Pro ASR: `45.7%` top-1, `30.4%` top-2, `34.3%` random; earliest exceeds random by 11.4pp.
- Placement experiment inserts into the last writable field (`top-1`), second-last (`top-2`), or random field. GPT-5 is `67.4/53.5/57.6%`; Gemini-3.1-Pro is `44.2/41.5/43.5%`.

Failure implication: a fixed or random injection location can underestimate worst-case exploitability if an attacker can choose among reachable early or tail-end locations. Placement search belongs in the threat model.

Scope guard: the three-point results are not strictly monotone (`random` can exceed `top-2`), so the claim is not a universal law that every earlier/later position is stronger. It is a tested worst-position sensitivity under ToolHazard's reachable-point definitions.
