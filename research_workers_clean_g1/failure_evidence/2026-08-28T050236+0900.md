## New failure evidence

### FE-300 — Lossy context compaction can erase binding governance while preserving task continuity, causing prohibited tool actions without any model or request change
**Primary source:** Shiyang Chen, “Governance Decay: How Context Compaction Silently Erases Safety Constraints in Long-Horizon LLM Agents,” arXiv:2606.22528, 21 Jun 2026, https://arxiv.org/abs/2606.22528

ConstraintRot holds the later prohibited request fixed and varies whether a previously obeyed governance constraint remains in the agent context. Across 1,323 episodes, every model is at **0% violation with the policy still in full context**, while one compaction step raises pooled violation to **30%**, reaching **59%** for DeepSeek-V4 and Kimi-K2.5 and **41%** for GPT-5.4-mini. A higher-powered 1,080-episode grid reports pooled decay **+37pp, bootstrap 95% CI [31,43]**. Mechanism evidence is unusually clean: when the compacted summary still preserves the constraint, violation is **0% (n=90)**; when it drops the constraint, violation is **38% (n=315)**. A counterfactual GLM ablation keeps violation at 0% in a 5.9k-token uncompressed context, raises it to 60% when the summary omits the policy, and returns it to 0% when the same summary has the policy restored.

The compactor×agent crossing further shows that apparent model robustness can actually belong to the summarizer: a GLM-written summary yields only **7–13%** violation across three agents, whereas a DeepSeek-written summary yields **33–93%**; GLM as the downstream agent still violates **53%** when handed the DeepSeek summary. Tightening the summary budget from 300 to 15 words reduces constraint survival **88%→23%** and raises pooled violation **7%→28%**. Optimized compaction-eviction injections break every evaluated model along at least one tested axis. A positive control, Constraint Pinning, quarantines the governance text from lossy compaction and restores **0% violation** with and without the tested attack.

**Failure implication:** preserving topical/task information is not enough for long-running automation. Binding constraints must be carried as protected operational state outside lossy summarization and reintroduced or independently enforced at decision/commit time. A model that is safe before compaction cannot be assumed safe after a task-focused summary, even if the summary is otherwise accurate.

**Scope guard:** seven tested model families, nine ConstraintRot tasks, the paper’s compaction strategies and non-system governance channels. System/developer instructions that the framework guarantees to preserve are outside this failure mode. Constraint Pinning’s 0% is limited to the tested benchmark/attack surface, not a universal safety guarantee.

### FE-301 — Many real agent failures live at the model–harness interaction boundary and can be silent, so live reruns may fail to reproduce the triggering condition
**Primary source:** Jingyi Chen et al., “Understanding Agent-Reactive Bugs at the Model-Harness Boundary: An Empirical Study of LLM Agent Issue Reports,” arXiv:2607.15684, 17 Jul 2026, https://arxiv.org/abs/2607.15684
**Detailed public extraction used for category counts:** AgentPatterns summary of the paper, https://agentpatterns.ai/observability/agent-reactive-bugs/

The study manually analyzes **255 confirmed agent-reactive bug reports** from Codex, Gemini-CLI, LangChain and CrewAI: failures that occur only when a particular LLM output elicits an abnormal harness reaction, so inspecting the model response or harness code alone is insufficient. The public detailed extraction reports **108/255 (42%) silent errors**, **71 (28%) crashes**, **34 raw-error outputs**, **33 retry loops**, and **9 hangs**. Common triggering behaviors include task-instruction non-compliance (67 cases), unexpected tool arguments (62), and message-template conflicts (49). The primary paper emphasizes that stochastic model outputs complicate reproduction; a fresh live rerun may not regenerate the output that exposed the harness defect.

**Failure implication:** automation observability should preserve the paired model-output + harness-reaction trace and replay the triggering output as a fixed mock when debugging. Final narration and exception logs are insufficient because a large fraction of boundary failures are fluent silent errors. Repeated non-reproduction is not evidence that the defect is gone.

**Scope guard:** empirical issue reports from the four studied projects, not a random sample of all agent executions; issue-report frequencies are not production incident rates. The exact symptom counts above come from a detailed public extraction of the paper rather than a directly accessible primary table in this run, so they should be treated as secondary-extracted until independently re-read from the paper PDF/artifact.

### FE-302 — Optimizer quality can be misread if the load harness is wrong or if only the single best trial is scored; budget consistency can improve while peak value is statistically tied
**Primary source:** Christian Lysenstøen, “SLO-Guard: Crash-Aware, Budget-Consistent Autotuning for SLO-Constrained LLM Serving,” arXiv:2604.17627, Apr 2026, https://arxiv.org/abs/2604.17627

The paper explicitly reports and corrects an earlier measurement defect in the load-dispatch harness, moving from sequential to truly concurrent request dispatch. Under the corrected concurrent harness and a pre-specified **five-seed** study, SLO-Guard and uniform random search are both **75/75 feasible with zero crashes** and are statistically tied on best-achieved latency (**Mann–Whitney two-sided p=0.84**). The useful difference appears in how the fixed 15-trial budget is spent: SLO-Guard places **10.20 vs 7.40** trials in the fast-serving regime (one-sided **p=0.014**), has post-handoff consistency **0.876 vs 0.539 (p=0.010)**, and its cross-seed SD on best latency is **2.26 ms vs 10.00 ms**, a **4.4×** reduction. A separate sequential-dispatch replication preserves the consistency conclusion.

**Failure implication:** a recursive optimizer should not claim superiority from a best-of-run metric or a faulty execution harness. It should treat feasibility/crash outcomes as first-class observations, repeat across seeds, separately score budget allocation/stability, and re-run key conclusions under an independent or corrected harness. A configuration search can be operationally much more predictable without producing a statistically better single terminal metric.

**Scope guard:** Qwen2-1.5B on vLLM 0.19, A100 40GB, the paper’s 15-trial SLO-constrained search space and workload. This does not establish SLO-Guard as a generally superior optimizer; the authors explicitly limit the primary claim to budget consistency.

### FE-303 — The same explicit reasoning/testing scaffold can help weaker models by >20pp while degrading stronger models under a clean prompt-only ablation
**Primary source:** Lucas Jing et al., “PBT-Bench: Benchmarking AI Agents on Property-Based Testing,” arXiv:2605.15229, 13 May 2026, https://arxiv.org/abs/2605.15229

PBT-Bench evaluates eight contemporary LLMs on 100 property-based-testing problems (365 injected semantic bugs) using the same OpenHands scaffold. Each model is run under an open-ended baseline prompt and an explicit Hypothesis/PBT scaffold, with **three independent runs per configuration**. The prompt-only scaffold produces strongly model-dependent effects: the weakest baselines gain **+24.5pp, +22.9pp, and +20.3pp** bug recall, while Claude Sonnet 4.6 gains only **+6.7pp**, DeepSeek V3.2 **regresses −3.2pp**, and Grok 4.1 Fast **regresses −8.0pp**. The benchmark’s reliable union across all sixteen model-mode cells reaches **99.5%**, **12.7pp above** the best single cell, showing that different model/prompt regimes expose different bugs rather than one scaffold dominating everywhere.

**Failure implication:** a repository optimizer should not globally propagate one “helpful” scaffold or policy change to all models/roles merely because it substantially helps weaker configurations. Interventions can substitute for a missing capability in one model while interfering with an already-internalized strategy in another. Acceptance should therefore be role/model-conditional and protected by matched held-out evaluation and rollback.

**Scope guard:** PBT-Bench’s 100 problems, eight model endpoints, OpenHands v1.11.5, and the exact two prompt regimes. The scaffold also changes Hypothesis availability/timeouts as defined by the benchmark, so the result supports deployment-conditional evaluation rather than a pure linguistic-prompt causal claim beyond this harness.
