## New failure evidence

### FE-270 — Wording-based memory defenses can look perfect on basic forgeries and collapse under adaptive rephrasing; memory claims need proof of execution, not textual plausibility
**Primary source:** Rahman & Kim, “Proof-of-Execution Memory: Defending LLM Agents Against Forged-Reasoning Attacks by Verifying What Actually Happened,” arXiv:2608.16032v1, 17 Aug 2026, https://arxiv.org/abs/2608.16032

The FARMA threat writes a fabricated memory claim that a required safety step already happened. The SENTINEL defense scores memory text against suspicious wording. The paper reports that a simple automated rephrasing attacker evades SENTINEL on its first try, reducing its protection to zero on every tested model; adaptive attack success is 98–100% on GPT-4o/GPT-4o-mini and 44% on Llama-3.1-8B. PoEM instead checks a separate HMAC-chained ledger writable only by the trusted action layer and allows a skip only when the required execution is recorded. Across three models and three scenarios, PoEM reports 0% attack success, with 0% false positives in eight of nine benign cells and 1.7% in the ninth; SENTINEL wrongly blocks 33–50% of legitimate operations.

**Failure implication:** a persistent memory entry saying “verified/completed/authorized” is not evidence that the world-side event occurred. Textual anomaly detection can be defeated by semantic paraphrase; safety-critical continuation should bind claims to trusted execution receipts/state.

**Scope guard:** this is a preprint over the stated models/scenarios and assumes a trusted runtime/key/ledger. PoEM protects only decisions explicitly gated against that ledger; it does not establish general immunity to arbitrary memory poisoning or runtime compromise.

### FE-271 — “Single-use” tokens can still spend one human authorization multiple times when retries/replanning mint fresh identifiers
**Primary source:** Xu et al., “Beyond Single-Use Tokens: Durable Authorization State for Replay-Resistant LLM Agent Actions,” arXiv:2608.01710v1, 3 Aug 2026, https://arxiv.org/abs/2608.01710

Across 10,152 valid agent trajectories, uncertain outcomes induce 4,036 semantically equivalent reproposals (39.8% overall): lost acknowledgements 58.0%, timeouts 46.0%, ambiguous results 31.0%, delegation/restart 24.0%, with 36–44% aggregate rates across three model families. In 282 matched workflows, identifier-/grant-local controls can reject reuse of the old artifact while still permitting a fresh authorization artifact for the same user decision. SUDP blocks same-artifact duplicate redemption but permits fresh reissuance (fresh-reissuance rate 1.000); Authority+CapLease and a matched Server Ledger both reduce fresh reissuance and same-artifact duplicate admission to 0. The transactional tests include 28,200 two-thread races; 12,000 process-kill/restart schedules report no resurrection, excess admission, or duplicate effect when an idempotent sink is present.

**Failure implication:** idempotency must be defined over the semantic authorization instance/action budget, not merely a token/grant ID. Retry, recovery, delegation and replanning can otherwise rematerialize the same approval under a new identifier.

**Scope guard:** the zero-counterexample result depends on the stated trusted, non-rollback/linearizable durable state and, for exactly-once physical effects, an idempotent sink. The paper’s negative control explicitly shows the ledger alone cannot guarantee exactly-once external effects without sink idempotency.

### FE-272 — Durable authorization state cannot repair a wrong trusted contract: metadata/provenance errors bypass the gate at very high rates
**Primary source:** Xu et al., arXiv:2608.01710v1, same source as FE-271.

The paper isolates failures of the trusted contract boundary over 9,584 security cases. With honest schema/provenance, unsafe execution is 0/9,584. If a side-effecting operation is incorrectly marked read-only, unsafe execution is 9,302/9,584 (97.1%); if external provenance is promoted to user authority it is 9,020/9,584 (94.1%); omitting organization policy yields 141/9,584 (1.5%). Authentication protects the contract from tampering but cannot make false trusted metadata true.

**Failure implication:** a perfectly transactional authorization ledger can faithfully enforce the wrong policy. Safety evidence must include machine-checked capability classification/provenance at the trusted-input boundary, not only replay/consumption correctness downstream.

**Scope guard:** these are deliberate trusted-input fault injections in the paper’s AgentDojo-derived schema set, not prevalence estimates for real production metadata defects.

### FE-273 — Red-team memory can materially strengthen held-out attacks; per-sample “fresh start” search can underestimate adversarial pressure
**Primary source:** Wang et al., “Agent Against Agent: An Agentic System for Automatic Prompt Injection Red Teaming,” arXiv:2608.05108v1, 5 Aug 2026, https://arxiv.org/abs/2608.05108

PIMiner accumulates a long-term strategy library plus intra-dataset and intra-sample memory. On held-out target LLMs, the memory ablation reports average ASR for a vanilla PAIR-style per-sample iterative attacker of 13.1% on Haiku-4.5 and 50.6% on Sonnet-4.6; full PIMiner reaches 32.9% and 68.4%, gains of 19.8 and 17.8 points. Either long-term or intra-dataset memory alone also improves over the vanilla attacker. The learned strategy library transfers across attacker LLMs: with Gemini-2.5-Flash attacking GPT-4o-mini at the same Nmax=10 setting, PAIR rises from 0.14 ASR to 0.52 when the strategy library is supplied.

**Failure implication:** a red-team process that resets attack knowledge every sample/run may systematically understate the threat from an adversary that accumulates reusable failure knowledge over time. Attacker persistence/memory is itself an evaluation variable.

**Scope guard:** this is a preprint in prompt-injection benchmarks. Training uses grey-box intermediate target trajectories while testing is black-box, and the result does not imply that every form of attacker memory improves every target or that memory cannot overfit.

### FE-274 — A late warning after a malicious skill is admitted is much weaker than an admission-time hard boundary
**Primary source:** Wang et al., “ClawSentry: A Progressive Multi-Tier Security Monitor for Safeguarding Autonomous LLM Agents,” arXiv:2608.21101v1, 21 Aug 2026, https://arxiv.org/abs/2608.21101

In a controlled 60-case SkillsSafety subset with Work Agent and reviewer fixed, only the response to a flagged package changes. Hard block yields ASR 8.47 / TSR 18.64, a document-level warning 24.56 / 21.05, and runtime feedback 10.53 / 17.54. Thus warning costs +16.09 points of ASR for +2.41 points of TSR versus hard block; even runtime feedback remains 2.06 ASR points worse while also having lower TSR. A separate component ablation with Codex/GPT-5.4 reports full ASR 12.73, removing first-use package review 23.73 (+11.00), and removing session anti-bypass state 19.30 (+6.57).

**Failure implication:** once untrusted instructions/package content have entered the model context, a later caution competes inside an attacker-shaped channel. For high-risk package/tool admission, boundary placement can dominate warning wording; cross-attempt state is independently useful after a denial.

**Scope guard:** each controlled block is its own fixed 60-case subset and values should be compared only within a block. The result is specific to the tested SkillsSafety/agent configurations and does not prove hard-block is optimal for every skill distribution or user-interactive setting.

### FE-275 — Framework “pause/cancel/timeout” controls can fail to fence real side effects; named control primitives are not enforcement contracts
**Primary source:** Khan, “Stop Means Stop: Measuring and Repairing the Enforcement Gap in Agent-Framework Control Primitives,” arXiv:2607.14166, 15 Jul 2026, https://arxiv.org/abs/2607.14166

Across six widely used open-source agent frameworks, the paper finds the implied barrier contract holds on none. Every framework with a pre-execution approval gate (5/6) exhibits a sibling leak in which the gated branch pauses but a sibling side effect executes before the later rejection; additional measured failures include replay double-execution, cancellation orphans and timeout zombies. Under a fixed live-agent protocol, 215/1,200 runs execute an effect during an approval pause across three schedulers and two runtimes. The external SOUNDGATE complete-mediation effect gate blocks every measured violation on all six frameworks while releasing legitimate effects, at about 1 ms admission/write and 12k–26k durable admissions/s.

**Failure implication:** “paused”, “cancelled”, or “timed out” in orchestration state is not proof that world-side effects are fenced. High-risk automation needs an external complete-mediation effect gate with explicit hold/reject/dedup/fence semantics and real concurrency/cancellation tests.

**Scope guard:** the result concerns the six tested framework versions/configurations and the paper’s complete-mediation contract. It does not establish that every framework or later release has the same defects.

### FE-276 — Recursive harness optimization can improve one safety metric while regressing utility or clean safety unless candidate selection is explicitly multi-objective
**Primary source:** Qu et al., “SHE: Trajectory-driven Safety Harness Evolution for LLM Agents,” arXiv:2608.09885v1, 10 Aug 2026, https://arxiv.org/abs/2608.09885

The authors report that evolution of coupled safety frameworks can reduce ASR while introducing regressions in clean safety behavior or utility under attack. SHE therefore accepts a candidate only if safety strictly improves and normal-task utility does not decrease, restores the previous best harness otherwise, and records rejected edits. Its evolution history explicitly contains plateaus where candidates improve an individual metric but fail the joint criterion and are rejected. In the tested decoupled setup, seed→evolved changes average ASR 8.6→5.5, clean UBR 25.7→19.8, and utility-under-attack 33.5→47.6; held-out AgentHarm Harm Score improves 19.8→9.8 with Harm Refusal 78.4→86.4.

**Failure implication:** an optimizer that immediately applies whichever edit makes its currently targeted metric look better can select regressions or metric-specific shortcuts. Durable best-so-far state, explicit rollback, validity checks, and safety+utility acceptance gates are control-plane primitives rather than reporting niceties.

**Scope guard:** the positive results are from Agent-SafetyBench/AgentHarm under the paper’s 20-round, temperature-0 protocol and two rollout replications per task-condition; they do not prove this specific selection rule is sufficient against evaluator overfitting or all optimizer-induced regressions.
