## New failure evidence

### FE-286 — A screenshot can be correct when observed and wrong by execution time; commit-time revalidation must cover the state layer that can actually change
**Primary source:** Wenpeng Xu, “Temporal UI State Inconsistency in Desktop GUI Agents: Formalizing and Defending Against TOCTOU Attacks on Computer-Use Agents,” arXiv:2604.18860v1, 20 Apr 2026, https://arxiv.org/abs/2604.18860

The paper measures a mean 6.51-second observation-to-action gap on real OSWorld workloads. Its Window Focus Manipulation primitive achieves 100% action-redirection success with zero visual evidence at the original observation time. A pre-execution UI-state verifier (PUSV) that rechecks masked target pixels, global screenshot state, and the X Window snapshot immediately before dispatch intercepts 100% of 180 tested adversarial trials for the notification-overlay and window-focus primitives (135 + 45), with zero false positives and under 0.1 s overhead. But the same defense has a structural blind spot against zero-visual-footprint Web DOM injection, with approximately 0% Action Interception Rate.

**Failure implication:** binding authorization to the screen state the agent saw several seconds earlier is a TOCTOU bug even when the perception itself was accurate. Commit-time world-state verification is a materially stronger boundary, but it must verify the semantic layer capable of changing the effect: pixel/window checks do not protect a DOM mutation that preserves the same visible evidence. “Re-check before click” is therefore a family of controls, not a single sufficient check.

**Scope guard:** this is an arXiv v1 desktop/GUI study with three concrete primitives and the stated OS/X11-style verification layers. The 100% interception result applies only to the 180 Primitive-A/B trials; the paper itself demonstrates failure on Primitive C, so it is not evidence that PUSV or visual revalidation universally secures browser/GUI agents.

### FE-287 — Faithfully stored and relevant memory can still reduce current-task performance; memory correctness is not memory usefulness
**Primary source:** Mengru Wang et al., “MemTrapBench: Benchmarking Cognitive Traps in LLM Memory Use,” arXiv:2608.20202v1, 20 Aug 2026, https://arxiv.org/abs/2608.20202

MemTrapBench targets two memory-induced cognitive traps, Reasoning Fixation and Belief Distortion. Across two model families and five representative memory frameworks, every evaluated memory strategy underperforms the no-memory setting on this benchmark; even the strongest memory methods lose more than 10 percentage points. The paper’s positive control, AdaptiveMem, is an inference-time instruction that asks the model to avoid memory traps and improves MemTrapBench while preserving or improving performance on standard memory benchmarks.

**Failure implication:** admission integrity, retrieval relevance, and factual faithfulness do not establish that a retrieved memory should influence the current decision. Long-running agents need an applicability/conflict gate that can decide when a valid prior is out of scope or actively harmful, and evaluations need a no-memory or trap-free counterfactual rather than treating “more accurate retrieval” as monotonic progress.

**Scope guard:** this is an arXiv v1 diagnostic benchmark deliberately constructed to expose cognitive traps, not an estimate that memory lowers average production performance by >10 points. The result is evidence that valid/relevant memory can be causally harmful in the tested contexts, not that persistent memory should generally be disabled.

### FE-288 — Cryptographic writer authenticity can launder untrusted ancestry: a correctly signed agent-written summary may still be unsafe authority
**Primary source:** Ciyan Ouyang and Rui Hou, “MemLineage: Lineage-Guided Enforcement for LLM Agent Memory,” arXiv:2605.14421v1, 14 May 2026, https://arxiv.org/abs/2605.14421

MemLineage isolates a sleeper-via-derivation attack where attacker-controlled external content is retrieved, summarized or rephrased by the LLM, and committed as a fresh entry signed by the legitimate agent principal. In the deterministic mechanism-isolation harness, the signature-only baseline closes the direct AgentPoison-style column but still fails MemoryGraft-style and sleeper-via-derivation attacks; the lineage-aware configuration drives all three tested columns to zero ASR. In the intentionally vulnerable AgentDojo banking profile, no-defense and signature-only baselines fail all six banking pairs, while all MemLineage rows reduce strict ASR to 0/6. The paper also shows that attribution thresholds cannot be calibrated at one derivation depth and assumed safe at another: under its degrading-judge schedule w0=0.9, d=0.7, a K=5 chain needs tau<=0.10 whereas K=1 would appear safe up to tau<=0.30.

**Failure implication:** provenance that records only “who wrote this entry” is insufficient once agents derive new memories from old ones. Authenticity can certify the laundering step rather than the underlying authority. Durable memory therefore needs derivation lineage/chain of custody through summarization and cross-session reuse, and any lineage threshold must be stress-tested across the maximum derivation depth rather than calibrated on one hop.

**Scope guard:** MemLineage’s deterministic harness uses fixed non-adaptive payload sequences and assumes host-process integrity, principal-key secrecy, and trusted inference code; adaptive threshold probing is explicitly deferred. The 0-ASR cells are therefore mechanism evidence under those trust assumptions, not a universal production guarantee.
