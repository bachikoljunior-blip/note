### FE-036 — Hardening can displace or enlarge a known exploit surface when the in-loop attacker does not cover that exploit class
**Status:** primary arXiv preprint + released implementation/artifact; matched ablation inside the same Terminal Bench hardening study; not an independent replication.

Primary sources:
- Zhong et al., *Hardening Agent Benchmarks with Adversarial Hacker-Fixer Loops*, arXiv:2606.08960 (2026-06-08), https://arxiv.org/abs/2606.08960
- Implementation: https://github.com/few-sh/harden-v0

Matched Terminal Bench evidence (77 tasks):
- The study compares a pooled original baseline against three hardening ablations under the same stronger evaluator corpus: full verifier-aware hacker + shared defense pool; verifier-aware only; blind hacker + shared defense pool.
- Raw trajectory ASR, pooled original → blind+pool:
  - **hinted: 51.6% → 56.2% (+4.6 pp)**,
  - **unhinted: 42.3% → 22.3% (−20.0 pp)**,
  - benign solver pass **79.2% → 77.0%**.
- With the paper's judge filtering, pooled original → blind+pool:
  - **hinted ASR: 42.9% → 50.7% (+7.8 pp, reported p<0.01)**,
  - unhinted ASR **35.7% → 17.1%**,
  - benign solver pass **77.5% → 78.4%**.
- In contrast, full verifier-aware+pool lowers judge-filtered hinted ASR to **35.1%** and unhinted ASR to **12.9%**, at the cost of lower benign solver pass (**64.3%**).
- The authors' mechanism analysis states that the blind in-loop hacker never exhibits the wrap-style attacks present in the hint corpus, so those paths remain uncovered while newly introduced shell-side defense machinery can itself become substrate for those attacks.

Failure implication, limited to tested scope:
- Security hardening is not necessarily monotone across exploit classes. A defense loop can improve the attack distribution it actively sees while making a known, under-covered class easier.
- Aggregate ASR therefore hides exploit displacement. Hardening evaluation should preserve per-class before/after attack rates and explicitly test classes absent from the in-loop attacker.
- Attacker coverage is part of the defense configuration; a result from verifier-aware hardening must not be transferred to a blind-attacker regime, or vice versa.

Scope/caveat:
- Same study and benchmark family as FE-033/034, not an independent replication.
- The stronger post-hardening evaluation is a fixed attack/evaluator corpus rather than an attacker that re-optimizes online against every hardened snapshot. This still leaves the prior frontier for true per-snapshot adaptive re-attack unresolved.
- The +7.8 pp increase is specific to the blind+pool ablation and hinted Terminal Bench attacks; it is not evidence that hardening generally worsens security.

### FE-037 — Defense-aware adaptive indirect-prompt-injection attacks can reverse large apparent gains from static defense evaluation
**Status:** peer-reviewed Findings of NAACL 2025 paper + primary paper artifact; white-box defense-aware adaptive attacks; normal-case utility not evaluated by this study.

Primary source:
- Zhan et al., *Adaptive Attacks Break Defenses Against Indirect Prompt Injection Attacks on LLM Agents*, Findings of NAACL 2025, https://aclanthology.org/2025.findings-naacl.250/ ; arXiv version: https://arxiv.org/abs/2503.00061

Design:
- Eight defenses are evaluated on Vicuna-7B and Llama3-8B agent setups.
- The adaptive attacker is assumed to know the target agent/defense and optimizes attack strings specifically against it; this is a deliberately strong white-box threat model.
- The same defended systems are compared under non-adaptive/original attacks and defense-aware adaptive attacks.

Matched results:
- Direct-harm aggregate ASR:
  - Vicuna: original **0.62**, defended non-adaptive **0.39±0.19**, adaptive **0.90±0.06**.
  - Llama3: original **0.14**, defended non-adaptive **0.05±0.04**, adaptive **0.87±0.10**.
- Data-stealing aggregate ASR:
  - Vicuna: **0.50 → 0.33±0.18 → 0.68±0.15** (original → defended non-adaptive → adaptive).
  - Llama3: **0.40 → 0.02±0.02 → 0.57±0.17**.
- Two defenses show especially clear reversals when attacked adaptively:
  - perplexity filtering: Vicuna **24% → 76%**, Llama3 **22% → 61%** ASR;
  - paraphrasing: Vicuna **53% → 79%**, Llama3 **8% → 54%** ASR.
- Detector evasion also shifts sharply after adaptation: one fine-tuned detector's detection rate drops **61% → 1%** on Vicuna and **61% → 10%** on Llama3; an LLM detector drops **34% → 0%** and **72% → 0%**, respectively, on the paper's adaptive strings.

Failure implication, limited to tested scope:
- Static attack pools can substantially overstate robustness when a realistic attacker can condition on the defense. A defense that looks strong against an original corpus can become weaker than the undefended baseline under targeted adaptation.
- Defense evaluation should therefore report both fixed-corpus and defense-aware adaptive attack results when the threat model permits attacker knowledge/probing.
- The large reversals are direct evidence against treating non-adaptive ASR reduction as a stable property of the defense.

Scope/caveat:
- This is indirect prompt injection on two open-model agent setups under white-box defense knowledge, not benchmark-verifier reward hacking and not a production compromise rate.
- The paper explicitly does not evaluate normal benign-task utility, so these ASR results alone cannot establish overall defense quality.
- Adaptive optimization is strongest for the first-stage attack objective; later data-stealing steps remain a distinct bottleneck in the paper.

### FE-038 — Some defense-trained agent models fail before tool observations and retries amplify the failure; the same defenses can also lose attack-detection quality
**Status:** primary 2026 arXiv preprint; controlled open-model study; not independently replicated.

Primary source:
- Li & Zhao, *The Autonomy Tax: Defense Training Breaks LLM Agents*, arXiv:2603.19423v2 (submitted 2026-03-19; revised 2026-06-18), https://arxiv.org/abs/2603.19423

Benign agent-execution evidence:
- Before any tool observation is available, the first agent action already changes dramatically under the tested defense-trained models:
  - Llama3 base: normal action **96.9%**, refusal **1.0%**, invalid **2.1%**.
  - StruQ-Llama3: normal **22.7%**, invalid **69.1%**.
  - SecAlign-Llama3: normal **52.6%**, refusal **47.4%**.
  - Mistral base: normal **97.9%**, invalid **2.1%**.
  - StruQ-Mistral: normal **23.7%**, invalid **71.1%**.
  - SecAlign-Mistral: normal **53.6%**, refusal **46.4%**.
- On the paper's 97-task multi-step agent set, systematic failures are retried as if recoverable and propagate down the trajectory:
  - Llama3 cascade-failure rate: base **13.4%**, StruQ **19.6%**, SecAlign **36.1%**; SecAlign mean retry depth reported as **7.78**.
  - Mistral: base **49.5%**, StruQ **85.6%**, SecAlign **99.0%**; SecAlign mean retry depth **9.94** and only **1.0%** of tasks complete versus **50.5%** for base Mistral in this harness.

Security-side evidence in the same study:
- On a curated set of 350 examples (289 adversarial, 61 benign), the paper reports base Llama3 attack detection at **82.7%**, while the tested defense-trained variants are only **26.7–37.4%**, alongside false-positive rates roughly **25–71%** depending on method/configuration.
- Advanced obfuscation and social-engineering categories remain high-bypass regimes in the reported analysis.

Failure implication, limited to tested scope:
- Safety training can fail as an interface-level agent capability regression rather than only a quality loss after tool use. If the harness blindly retries refusals/invalid structured outputs, a first-step systematic error can become a long cascade and large latency/cost penalty.
- Security and autonomy must be evaluated jointly: a defense can simultaneously reduce benign agent competence and fail to improve, or even worsen, attack discrimination in the tested setup.
- Agent runtimes should distinguish systematic policy/format failures from transient tool failures instead of applying generic retries.

Scope/caveat:
- These results cover specific open models, StruQ/SecAlign-style defenses, and the authors' agent harness. They do not establish an autonomy tax for all defense training.
- StruQ's dominant failure is invalid action/interface output while SecAlign's is refusal, so the evidence does not support one universal causal mechanism.
- Preprint and not independently replicated. Interface adaptation or harness changes could recover some observed capability and should be tested separately.

## Bounded auxiliary evidence — iterative hardening horizon and cost
A separate primary preprint, Huang et al., *RvB: Automating AI System Hardening via Iterative Red-Blue Games* (arXiv:2601.19726, 2026-01-27), reports that its code-hardening Defense Success Rate is initially below a cooperative baseline and only surpasses it after later red-blue iterations, reaching 90% by iteration 5. In a guardrail experiment, the reported adaptive-defense metric rises across rounds while cumulative token/cost consumption grows sharply. This is useful as a positive control for a temporal-horizon failure mode—judging an adaptive hardening procedure after one early round can mis-rank it—but it is not promoted to a separate failure claim here because the result is primarily a successful iterative-defense result and uses different domains/objectives from FE-036/037.
