## New claims

### FE-033 — Iterative hacker–fixer hardening can withstand stronger held-out attackers, but robustness is benchmark-dependent and remains incomplete on heterogeneous Terminal Bench
**Status:** primary arXiv preprint + released implementation/artifact verified; adaptive hardening loop, held-out attacker evaluation; not an independent replication.

Primary sources:
- Zhong et al., *Hardening Agent Benchmarks with Adversarial Hacker-Fixer Loops*, arXiv:2606.08960 (2026-06-08), https://arxiv.org/abs/2606.08960
- Implementation: https://github.com/few-sh/harden-v0
- KernelBench traces/artifact: https://github.com/fjzzq2002/harden-kb-traces

Design:
- Audit: 1,968 terminal-agent benchmark tasks; 323 (16%) were hackable by frontier models given only task instructions.
- Hardening loop alternates: hacker finds a verifier exploit; fixer patches the verifier; solver checks that a legitimate solution still passes; then the attacker is run again. Up to 3 hacker retries per iteration and up to 10 hacker–fixer iterations in the reported default configuration.
- Main hardening uses Gemini 3 Flash as hacker/fixer; held-out evaluation includes stronger Gemini 3.1 Pro and Claude Opus 4.7.
- Verifier-aware mode and a cross-task shared defense pool are explicit interventions; the released KernelBench artifact records 100 tasks, four ablations, and a 171-commit defense pool.

Matched/held-out results:
- KernelBench task 001, no defense → hardened + post-loop autopatch:
  - Gemini 3.1 Pro hinted ASR **62% → 0%**; unhinted ASR **76% → 0%**; benign pass **98% → 98%** by iteration 8 and still 0% ASR at iterations 11/13.
  - Claude Opus 4.7 hinted ASR **44% → 0%**; unhinted ASR **61% → 0%**; benign pass **90% → 92%** in the autopatched snapshots.
  - Released held-out artifact reports 0/234 hacks for Gemini 3.1 Pro and 0/232 for Opus 4.7 at each of iterations 8, 11, and 13 against the fixed attack corpus.
- Terminal Bench, 77 tasks, stronger blind Gemini 3.1 Pro:
  - unhinted trajectory ASR **39.2% → 16.7%** (−22.5 pp, reported p≈1e−7), task-level any-of-3 **55.8% → 30.3%**;
  - hinted trajectory ASR **50.4% → 39.4%** (−11.0 pp, reported p=2e−4).

Failure implication, limited to tested scope:
- Static one-shot hardening is not the only relevant defense regime: repeated attack→patch→re-attack can surface successive exploits and materially improve verifier robustness, including against stronger held-out attacker models.
- However, the **0% result is not universal**. It occurs in the homogeneous KernelBench case study under its released attack corpus and verifier structure. On more heterogeneous Terminal Bench tasks, substantial residual attack success remains after hardening (16.7% unhinted trajectory ASR; 39.4% hinted).
- Therefore a benchmark should not be declared reward-hacking-resistant from one patched snapshot or one attack pool; adaptive re-attack and cross-task held-out evaluation are necessary, and residual risk must be reported per benchmark/task regime.

Scope/caveat:
- Preprint; benchmark-specific exploit definitions/verifiers; KernelBench held-out evaluation uses fixed-corpus rescoring for blind attackers, which is justified by hidden verifier logic but does **not** simulate an evaluator-aware attacker probing each hardened snapshot online.
- The stronger-attacker transfer results establish robustness against the tested models/corpora, not all future/adaptive attackers.

### FE-034 — Verifier hardening itself can silently narrow the accepted solution set; a weak solver guard can make “0% attack success” coincide with severe legitimate-solver rejection
**Status:** primary paper + released artifact verified; direct failure mode of the hardening mechanism itself.

Primary sources: same as FE-033.

Reported matched evidence:
- KernelBench raw loop output (no post-loop autopatch) reached **0% held-out ASR by iteration 8**, but over-restrictive defenses rejected legitimate solver implementations.
- The paper reports that raw no-autopatch snapshots at iterations 8–13 had benign pass rates as low as **0–22%** for tested solver styles in some conditions; a single post-loop Flash-fixer autopatch raised benign pass to **92–98%** while leaving held-out ASR unchanged at 0%.
- The root cause is explicitly diagnosed: the in-loop KernelBench solver guard was a deterministic reference solution that did not exercise code paths used by diverse LLM-produced solvers. Two defenses (module/stack-introspection poisoning and per-trial thread isolation) blocked legitimate `load_inline` / cuBLAS-based solution styles even though the reference kept passing.
- On Terminal Bench, where the full loop uses an LLM solver rather than only the deterministic reference, hardening still narrows solutions: benign trajectory pass **76.1% → 65.2%** (−10.9 pp, reported p=0.011); task-level any-of-3 **84.4% → 74.0%** (p=0.112).

Failure implication, limited to tested scope:
- A verifier can look “safer” because it has become **over-restrictive**, not because it cleanly distinguishes hacks from legitimate solutions. Attack success alone is therefore insufficient as a hardening metric.
- Solver validation must cover the diversity of legitimate implementation paths. A single reference/oracle can miss compatibility regressions, especially when defenses alter runtime/import/thread semantics.
- The released autopatch is a positive control showing that at least these over-restrictions were repairable without reopening the tested exploits; it does not prove all over-restriction is cheaply repairable.

Scope/caveat:
- This is one hardening framework and two terminal-agent benchmark families. Do not generalize the exact pass-rate losses to unrelated verifiers.
- The autopatch received one failing legitimate solver example and its test output; that extra evidence is a stronger validation signal than the original reference-only loop.

### FE-035 — First-turn safety evaluation can miss vulnerabilities exposed by response-conditioned adaptive attacks; same battles move from ~0–1% to 5.4–14.0% ASR over 15 rounds
**Status:** primary arXiv preprint verified; matched scoring of the same battle records; separate security setting from FE-033/034.

Primary source: Jain, Hartmann, Li, *Adaptive Adversaries: A Multi-Turn, Multi-LLM Benchmark for LLM Agent Security*, arXiv:2607.18063 (2026-07-20), https://arxiv.org/abs/2607.18063

Design/result:
- 21 held-out scenarios; 3 attacker models × 3 defender models × 5 repeats = **945 battles**.
- Defenders are memoryless across rounds; the attacker observes previous defender responses and adapts/pivots for up to 15 rounds. Each defender response is scored as a fresh structured-output interaction.
- Holding scenarios, attacker/defender identities, and structured success checks fixed, scoring only round 1 yields defender ASR **0–1%**; allowing the full 15-round adaptive sequence yields **5.4–14.0%**.
- Reported defender aggregates: Claude Opus 4.6 **0.0% first-turn → 5.4% adaptive**, GPT-5.4 **0.0% → 5.4%**, Gemini 2.5 Pro **1.0% → 14.0%**.
- Pooling three frontier attacker LLMs finds **1.4–2.2×** as many unique successful attacks as the best single attacker; generated attacks have low cosine similarity (0.02–0.14) to existing attack corpora.
- Aggregate ties hide scenario-specific failures: Opus and GPT-5.4 both aggregate to 5.4%, but one reported scenario reaches **60% ASR** for Opus versus **7%** for GPT-5.4/Gemini; overall defender rankings have low cross-scenario concordance (Kendall W=0.19).

Failure implication, limited to tested scope:
- A one-shot refusal/attack benchmark can materially under-detect failures that appear only after the adversary conditions on prior responses and changes strategy.
- Fixed attack pools and single aggregate rankings can both conceal important vulnerability structure: attacker diversity and scenario diversity materially change what is discovered.

Scope/caveat:
- This is adaptive prompt-injection/security testing against **memoryless** defenders, not a reward-hacking verifier benchmark and not a production compromise probability.
- “15-round ASR” is success at any point in a battle under continued adaptive pressure, not a per-round success frequency.
