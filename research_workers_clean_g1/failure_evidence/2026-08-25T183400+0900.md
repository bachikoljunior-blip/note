### FE-014 — Realistic network/server faults can collapse web-agent success under otherwise matched benchmark runs

Primary source:
- Kara, Faisal, Nath, “WAREX: Web Agent Reliability Evaluation on Existing Benchmarks,” Transactions on Machine Learning Research, April 2026 (arXiv:2510.03285).
- https://arxiv.org/abs/2510.03285
- https://www.microsoft.com/en-us/research/publication/warex-web-agent-reliability-evaluation-on-existing-benchmarks/

Matched setup / tested scope:
- WAREX injects controlled network/server failures into existing web-agent benchmarks and compares the same benchmark setup to a proxy/no-fault condition.
- Evaluated on WebArena, REAL, and WebVoyager.

Quantitative failure evidence from the primary paper’s extended-results table:
- **WebArena:** no-fault success 0.124; network error 0.037 (−70% relative); server error 0.053 (−57%).
- **REAL:** no-fault 0.170; network error 0.045 (−73%); server error 0.071 (−58%).
- **WebVoyager:** no-fault 0.420; network error 0.020 (−95%); server error 0.300 (−28%).
- Prompting the agent to handle the faults partially recovers some settings but does not uniformly restore baseline: WebArena network-error “fixed” = 0.071 (still −45%), server-error “fixed” = 0.090 (−27%); REAL network-error “fixed” = 0.036 (−79%), server-error “fixed” = 0.089 (−47%); WebVoyager fixed conditions recover to 0.410 (−2%) for both tested error types.

Interpretation constrained to evidence:
- A policy that scores acceptably in a stable benchmark can fail sharply under realistic transport/server faults, and a generic recovery prompt is not a universal fix. The effect is strongly benchmark/scaffold dependent.

Scope limit:
- These are the particular fault models, agents/scaffolds, and benchmark configurations tested by WAREX. Do not infer identical relative drops for arbitrary browser agents or production sites.

### FE-015 — An official TAU-bench few-shot scaffold leaked actual test-set examples, invalidating its evaluations

Primary source:
- Kapoor et al., “Holistic Agent Leaderboard: The Missing Infrastructure for AI Agent Evaluation,” ICLR 2026 / arXiv:2510.11977.
- https://arxiv.org/abs/2510.11977

Matched audit / tested scope:
- HAL evaluated the official TAU-bench Few Shot agent from the benchmark repository.
- The scaffold loaded `few_shot_data/MockAirlineDomainEnv-few-shot.jsonl` as demonstrations.
- HAL’s automated log analysis found that this file contained actual examples from the benchmark test set rather than only training demonstrations.

Failure evidence:
- The HAL authors explicitly state that this data leakage **invalidated all evaluation results using this scaffold** and excluded those results.
- The problem was discovered only after approximately **$1,000** had already been spent running those evaluations.

Interpretation constrained to evidence:
- Using an official benchmark scaffold is not sufficient evidence that an evaluation is contamination-free. Execution/log inspection can uncover integrity failures that are invisible in aggregate scores.

Scope limit:
- This finding invalidates results using the affected TAU-bench Few Shot scaffold/file. It does not invalidate every TAU-bench scaffold or every TAU-bench evaluation.

### FE-016 — A large share of failed agent tasks contain scaffold/environment barriers, confounding capability attribution

Primary source:
- Kapoor et al., HAL, ICLR 2026 / arXiv:2510.11977.

Observed scope:
- Docent rubric analysis covered 1,634 transcripts from 36 model-scaffold pairs on AssistantBench, SciCode, and CORE-Bench.

Failure evidence:
- On AssistantBench, CORE-Bench, and SciCode, agents encountered at least one environmental barrier such as a crashing browser, unavailable file, or unavailable coding import in **roughly 40% of failed tasks**.
- HAL also documents a concrete scaffold/benchmark instruction conflict in AssistantBench: the benchmark told the agent to return a blank string when information could not be found, while scaffold instructions told it to return an answer with a dictionary flag, causing some outputs to be scored down for an evaluation-interface conflict rather than a clean capability test.

Interpretation constrained to evidence:
- Some benchmark failures are mixtures of model/agent inability and execution/scaffold defects. Failure attribution should therefore distinguish policy errors from environment/oracle/interface errors before using scores as capability evidence.

Scope limit:
- The ~40% statistic is observational over failed tasks in the three analyzed benchmarks; it is not a causal estimate that 40% of all agent failures are caused by infrastructure, nor a universal benchmark-failure rate.

### FE-017 — Increasing reasoning effort is non-monotonic for agents under matched model/scaffold/benchmark comparisons

Primary source:
- Kapoor et al., HAL, ICLR 2026 / arXiv:2510.11977.

Matched setup / tested scope:
- HAL compares higher versus lower/no reasoning settings for Claude 3.7 Sonnet, Claude Sonnet 4, Claude Opus 4.1, and o4-mini while holding a given scaffold/benchmark comparison cell fixed.

Quantitative failure evidence:
- In **21 of 36** model-agent-benchmark comparisons, increasing reasoning effort produced **equal or lower accuracy**.
- The plotted changes span both positive and negative values, so extra inference-time reasoning is not monotone even within this broad agent evaluation suite.

Interpretation constrained to evidence:
- More test-time reasoning should be treated as a tunable intervention requiring matched measurement, not as an assumed improvement. Equal/lower outcomes could arise from interaction with scaffold, task, context, or model-specific behavior.

Scope limit:
- “21 of 36 equal or lower” does not mean reasoning generally hurts capability; 15 cells improved, and the tested settings cover a finite set of models/scaffolds/benchmarks.

## Updated cross-candidate pattern

The environment/evaluation branch adds three distinct confounders to the prior verifier-failure taxonomy:

1. **Execution robustness:** controlled network/server perturbations can erase most benchmark success (FE-014).
2. **Evaluation contamination:** an official scaffold can directly leak test examples (FE-015).
3. **Attribution confounding:** environment/scaffold faults coexist with task failures at substantial rates (FE-016).
4. **Non-monotonic compute:** more reasoning effort can be neutral or harmful under matched agent configurations (FE-017).

Together with FE-007–FE-013, these results argue for reporting capability only after separating: policy quality, verifier quality, benchmark integrity, environment reliability, and compute/scaffold effects.
