## New failure evidence

### FE-280 — Recognizing that a memory is stale does not imply resisting a stale premise or applying the current state in downstream behavior
**Primary source:** Chao et al., “STALE: Can LLM Agents Know When Their Memories Are No Longer Valid?”, arXiv:2605.06527v1, 7 May 2026, https://arxiv.org/abs/2605.06527

STALE contains 400 expert-validated implicit-conflict scenarios and 1,200 queries across State Resolution (SR), Premise Resistance (PR), and Implicit Policy Adaptation (IPA), with contexts up to 150K tokens. The strongest evaluated plain model, Gemini-3.1-pro, reaches 55.2% overall. More importantly, explicit recognition and operational use separate sharply: Gemini-3.1-pro scores 92.0% on Type-I SR but only 30.0% on Type-I PR and 71.0% on Type-I IPA; Qwen3.5-27B scores 76.0% SR but only 4.0% PR and 39.0% IPA. On the LightMem diagnostic, updated evidence is retrieved in 77.5% of SR/PR cases and 67.8% of IPA cases, yet failures persist despite new evidence in 56.1% / 99.0% / 78.6% respectively. The CUPMem positive control, which explicitly adjudicates active/stale/unknown state at write time and constrains query-time readout to authorized state, raises the same GPT-4o-mini backbone from 8.7% overall to 68.0%, with PR at 78.0%/75.0% for Type I/II.

**Failure implication:** retrieval presence, stale-state recognition, and downstream action are distinct capabilities. A persistent agent can correctly retrieve or even explicitly identify a newer fact yet still execute a request whose premise resurrects an invalid state. Memory evaluation therefore needs state adjudication and action-grounded premise-resistance tests, not recall alone.

**Scope guard:** STALE is an arXiv v1 benchmark over synthetic-but-expert-validated everyday user-assistant state conflicts, judged with an LLM evaluator reporting 95.8% human agreement. It does not establish these exact rates for arbitrary world-state, tool, or safety-critical deployments, and CUPMem is a prototype rather than a universal solution.

### FE-281 — A semantic memory auditor can pass structurally legitimate poison that still hijacks safety-critical tool choice on more than half of tested tasks
**Primary source:** Zhang et al., “MemMorph: Tool Hijacking in LLM Agents via Memory Poisoning,” arXiv:2605.26154v1, 24 May 2026, https://arxiv.org/abs/2605.26154

MemMorph injects only three crafted long-term-memory records and evaluates safety-critical safe-vs-risky tool selection across MetaTool, tau2-Bench, ToolBench, ten backbone LLMs, and multiple memory modules. Against three defenses, MemMorph retains ASR 65.8% under a perplexity filter, 69.8% under a distilled adversarial-text classifier, and 54.9% under a separate GPT-4o-mini semantic Memory Auditor. The corresponding attack-hit rates are 82.1%, 84.5%, and 72.3%. The semantic auditor produces the largest absolute reduction, but the structured poison still succeeds on more than half of the tested tasks.

**Failure implication:** “verified at memory admission” is not an integrity guarantee when an attacker can craft records that look like ordinary technical facts, incident reports, or procedures and survive the same rewrite/summarization path as legitimate experience. Verifier metadata such as FE-277’s MemGuard result is useful only if the verifier itself is trustworthy and resistant to adversarially structured inputs; lifecycle governance cannot repair a systematically fooled admission signal by itself.

**Scope guard:** the threat model assumes white-box access to the memory-rewriter pipeline and targets single-step tool selection; multi-step human oversight is not evaluated. The reported ASRs do not establish equivalent risk for proprietary memory pipelines or all memory verifiers.

### FE-282 — Benign memory growth does not reliably wash out a small, one-time structured poison
**Primary source:** Zhang et al., “MemMorph: Tool Hijacking in LLM Agents via Memory Poisoning,” arXiv:2605.26154v1, 24 May 2026, https://arxiv.org/abs/2605.26154

In the continued-operation experiment, the attacker injects three records once and then the memory grows from 300 to 2,000 benign records (6.7x) with no further attacker intervention. At 2,000 records, MemMorph still achieves 43.1% ASR versus 28.8% for the strongest baseline. The paper attributes the persistence to records that remain structurally legitimate, are not overwritten during routine operation, and reactivate when target-scenario queries retrieve them.

**Failure implication:** elapsed time, benign usage, or a large ratio of good memories to bad memories is not evidence that a poisoned state has decayed away. Long-running systems need provenance/conflict/retirement mechanisms and adversarial replay tests rather than relying on dilution through normal operation.

**Scope guard:** this is the paper’s simulated continued-operation setting with the same attack construction and memory pipeline, not a measurement of arbitrary production-store decay rates.

### FE-283 — Compression can launder harmful state below a detector threshold while preserving downstream behavioral influence
**Primary source:** “State Contamination in Memory-Augmented LLM Agents,” arXiv:2605.16746v1, May 2026, https://arxiv.org/abs/2605.16746

In 200 paired toxic-vs-neutral chain rollouts with no memory sanitization, toxic-condition memory summaries have mean detector toxicity 0.0852 versus 0.0007 neutral; all stored summaries are below the standard threshold tau=0.5, and at least 99% remain classified clean for every tested threshold from 0.03 through 0.5. Despite that, downstream toxicity conditioned on classifier-clean toxic memory is 0.141 versus 0.001 neutral, yielding a safety-propagation gap (SPG) of 0.140; the paired seed-level difference is 0.168 with 95% CI [0.120, 0.226], p=3.75e-8.

**Failure implication:** a compressed memory can become superficially benign to the same classifier used for admission while retaining latent behavioral influence. “Stored state passes the content filter” therefore cannot substitute for downstream counterfactual testing of what that state causes an agent to do.

**Scope guard:** this is a controlled Reddit-style simulation using the paper’s toxicity classifier and graph protocol. It establishes a compression/detection failure mode in that setup, not a universal toxicity or semantic-contamination rate.

### FE-284 — Sanitizing only after memory compression can be too late; intervention placement changes the hidden propagation channel by two orders of magnitude
**Primary source:** “State Contamination in Memory-Augmented LLM Agents,” arXiv:2605.16746v1, May 2026, https://arxiv.org/abs/2605.16746

Under the same 200 paired seeds and tau=0.5, post-compression memory rewriting reduces overt mean toxicity shift but leaves SPG 0.0856; post-compression gating leaves SPG 0.1030. By contrast, applying a write gate to generated transcript content before it is summarized into memory reduces SPG to 0.0004 with redaction and 0.0006 with rewriting, while also lowering upper-tail toxicity. The authors interpret this as evidence that toxic framing can be compressed into a sub-threshold representation before a summary-level monitor sees it.

**Failure implication:** safety controls are not commutative with summarization/compression. A checker placed after an irreversible lossy transformation may receive too little evidence to reconstruct the dangerous provenance. For long-running agent memory, pre-compression admission/declassification and post-compression lifecycle governance are separate controls, not interchangeable placements of the same classifier.

**Scope guard:** the matched placement result is specific to the paper’s chain-memory simulation, threshold/classifier, and paired seeds. It does not prove that every pre-write filter is sufficient or that later-stage checks are useless; the paper’s full system combines multiple pathways.

### FE-285 — For computer-using agents, the agent’s own perceived screen can be an invalid authorization source; channel fusion can also fail catastrophically when the wrong evidence type is required
**Primary source:** Liu et al., “Visual Confused Deputy: Exploiting and Defending Perception Failures in Computer-Using Agents,” arXiv:2603.14707v1, 16 Mar 2026, https://arxiv.org/abs/2603.14707

ScreenSwap demonstrates a compromised runtime swapping two native GUI button pixel regions so that the model clicks coordinates it believes are benign while the actual display executes a privileged action; the proof-of-concept is an eight-line pixel swap and is blocked in all 8 controlled SOC scenarios by an external click verifier. The paper’s wider evaluation shows why one evidence channel is not enough: on 20 neutral-button scenarios, image-only and AND-fusion have F1=0 because visually identical buttons contain no intent signal, while text-only and OR-fusion reach F1=1.0; on 260 ScreenSpot-Pro screenshots, image+text veto reaches F1=0.915 versus 0.779 for “both channels must agree.” Cross-domain contrastive transfer from an InjecAgent-derived knowledge base to OS-Harm fails with 0% specificity.

**Failure implication:** if the runtime/perception path is compromised or simply wrong, asking the same agent to self-police from the same pixels is circular. Authorization for GUI side effects needs independently acquired execution-time evidence. But “add two classifiers” is not enough: fusion logic and deployment-domain coverage are themselves safety-critical and can erase the only informative channel.

**Scope guard:** the external guardrail is narrowly evaluated for pointer-driven GUI clicks and does not cover harmful typed content, multi-step compositional harm, classifier-adaptive evasion, or arbitrary terminal workflows. Its residual false-negative rate is deployment-dependent.
