## New failure evidence

### FE-343 — Harness context reconstruction can turn rejected tool-level content into user-authorized action without a model-side jailbreak
**Primary source:** “When Context Gets Root: Privilege Escalation in LLM Harnesses,” arXiv:2608.27299v1, 27 Aug 2026, https://arxiv.org/abs/2608.27299

The paper isolates a provenance/authority failure in agent harnesses: content that first enters as low-privilege tool output is later reconstructed as a higher-privilege user or system-effective message during delegation, persistent-goal resume, scheduled-task execution, or custom-subagent loading. Across six coding-agent harnesses and 13 confidentiality/integrity/availability/RCE objectives, unrestricted execution achieved all 13 objectives on all six harnesses; the three harnesses offering automatic permission review also allowed all 13 objectives under that mode.

The motivating matched case is especially strong. Codex GPT-5.5 sees the same explicit server-start request and attacker-controlled server code. When the request is still tool-level, the model recognizes the arbitrary-command interface and refuses to start it. When the main agent delegates the request, the harness inserts the delegated text into the subagent context as a user message; the same model then starts the server. With automatic permission review, the reviewer still classifies the command as high-risk yet authorizes it because the reconstructed transcript makes the text look like explicit user approval. The authors therefore attribute the failure to provenance-changing context construction rather than danger-recognition failure.

**Failure implication:** model-side instruction hierarchy and high-risk action classification are insufficient if the harness can upgrade the authority of carried content. Delegation, persistence, scheduling, skill/subagent installation, and permission review need non-upgradable origin authority/provenance that survives reconstruction.

**Scope guard:** six evaluated coding-agent harnesses, 13 objectives, paper-specific versions/settings, attacker-controlled repository artifacts, and an attacker who knows harness construction. This does not establish prevalence in all harnesses or production deployments, and it does not show that every delegation mechanism is exploitable.

### FE-344 — Full-solution communication can erase useful cross-model diversity under matched budgets and flip interaction gains into losses
**Primary source:** “The Interaction Tax: When Communication Erases Diversity in Multi-Agent Teams,” arXiv:2608.23541, ICML 2026 / PMLR 306, https://arxiv.org/abs/2608.23541

The study evaluates 11 deterministic-verifier optimization tasks under a common budget vector and uses five seeds per main cell (ten seeds in a smaller factorial). Same-model interaction has positive mean interaction gain for Chain, MAgICoRe, and Debate: **+0.051, +0.044, +0.012**. With diverse model families, the corresponding gains become **−0.024, −0.035, −0.078**, with bootstrap probabilities that same-model gain exceeds diverse-model gain of **97%, 99%, and 88%**. For MAgICoRe and Debate, the authors state that model assignment is the changed factor across the compared conditions.

A mechanism check shows mean pairwise solution distance falling from **0.315 before interaction to 0.229 after full-solution synthesis**. The paper also reports that visible and hidden configuration rankings diverge on several tasks, reinforcing that interaction selected by the visible scorer can lose robustness offline. Independent proposal generation (MoA before synthesis) and repair-focused critique on locally checkable faults are positive controls: communication is not uniformly harmful.

**Failure implication:** an optimizer should not treat “more inter-agent communication” as a monotonic improvement. Full candidate sharing can collapse the very heterogeneity that motivated multi-model teams; independent proposals plus late/verified selection should remain an explicit baseline, and interaction should be accepted only on held-out outcomes under matched budgets.

**Scope guard:** verifier-scored scientific optimization tasks, three model families, five main seeds per condition, and the paper’s specific protocols. The diversity effect is task-dependent; removing the Erdős task makes the factorial diversity coefficient small with a confidence interval crossing zero. This is not evidence that all multi-agent communication hurts open-ended research or dialogue.

### FE-345 — Correct recovered state and perfectly valid tool syntax can still yield state-inconsistent actions when decision and realization are coupled
**Primary source:** “From State to Action: OODA-Tool for Reliable Multi-Turn Tool Use,” arXiv:2608.24368v2, 27 Aug 2026, https://arxiv.org/abs/2608.24368

On turns where every compared OODA variant has already recovered the correct action-relevant state and the correct readiness/Orient mode, residual State–Action Contradiction Rate is **7.8%** for Joint OODA and **5.6%** for Shared OODA, falls to **3.9%** for Specialized OODA, but rises to **10.7%** when the Decide–Act split is removed. A separate profile comparison keeps schema validity perfect while changing readiness/active-state/argument-grounding targets; the constraint-enriched profile removes stale bindings and restores grounding. Thus schema validity and state reconstruction alone do not certify that the emitted action actually respects the state.

The broader accuracy/cost result supplies a useful positive control and trade-off. Specialized OODA improves ToolDial task success over Direct-LoRA at every Qwen3 size tested (for example **78.67→85.46** at 1.7B), but uses four sequential model calls and **2.36× normalized latency** at 1.7B. Direct self-consistency with four calls remains below OODA, suggesting the gain is structured decomposition rather than sampling count alone.

**Failure implication:** tool agents should distinguish state acquisition, permission/readiness, action selection, and argument realization in evaluation. A valid JSON/tool call can be semantically stale even when the agent “knows” the current state. Optimizer acceptance should also include latency because the stronger structure is not free.

**Scope guard:** Qwen3 0.6B–14B models and the paper’s ToolDial/transfer settings. The contradiction-rate claim is for the filtered turns where correct state and Orient are recovered; it does not establish a universal 6.8-point gain for all tool agents, and parallel-call realization remains a stated limitation.

### FE-346 — A latent safety controller that is strong when backbone-matched can lose both safety and specificity after encoder/base mismatch
**Primary source:** “Reassembling Distributed Risk: Trajectory-Conditioned Action Generation for Multi-Turn Agent Safety,” arXiv:2608.25711v1, 26 Aug 2026, https://arxiv.org/abs/2608.25711

The paper freezes the Qwen3.5-9B base model and offline target source while varying only the safety-encoder backbone/latent budget on selected Filesystem, Terminal, and PostgreSQL tasks (10 benign and 10 harmful tasks per domain). With the backbone-matched 9B encoder at latent budget K=8, the table reports **0.0% ASR / 0.0% FPR** across all three domains. Replacing it with Qwen3.5-4B at the same K=8 raises aggregate results to **16.7% ASR / 5.0% FPR**.

Increasing the mismatched encoder’s latent budget does not monotonically repair the issue: K=16 gives **10.0% ASR / 45.0% FPR**, while K=32 improves to **3.3% / 5.0%** but remains below the matched setting. This is a compact matched example where a safety component is not portable merely because it belongs to the same model family and exposes the same latent interface.

**Failure implication:** when a base model or safety encoder is upgraded/swapped, latent/representation-space controls need requalification against the new pairing. Interface compatibility and nominal latent dimensionality are not sufficient evidence of safety transfer.

**Scope guard:** one Qwen3.5-9B base, a Qwen3.5-4B alternative encoder, three selected tool domains, and small fixed benign/harmful sets. It does not show that all cross-model safety encoders fail or that mismatch always increases ASR.

### FE-347 — Broad fixed-prompt security policy can be materially weaker than narrow policy under the same prompt-space budget, while low refusal does not establish end-to-end utility
**Primary source:** “SkillShield: Prompt-Space Security Skills for LLM Coding Agents,” arXiv:2608.25817v1, 26 Aug 2026, https://arxiv.org/abs/2608.25817

Across six models on RedCode, an all-classes prompt-space security skill reduces execution ASR from **67.4% to 43.6%**, but class-fixed per-class provisioning lowers it to **14.5%** when the threat class is known in advance; per-bundle sits at **36.2%**. The paper attributes the broad-policy gap to loss of class-specific detail when more threats share the same finite prompt budget. Reactive per-class synthesis further lowers mean execution ASR to **10.1%**, showing that prompt-space policy can be useful while still having a coverage/composition limit.

The benign metric must be interpreted narrowly. Proactive SkillShield averages only about **0.11–0.14% safety-grounded refusal** on 731 benign SWE-Bench Pro task descriptions, but the authors explicitly state this single-turn experiment does **not** measure end-to-end task completion. The threat model also excludes direct access to the complete system prompt and white-box optimization against it; the jailbreak tests use fixed, non-adaptive reformulations.

**Failure implication:** one monolithic “all safety rules” prompt should not be assumed equivalent to selectively materialized, threat-specific policy. At the same time, a low single-turn refusal rate should not be promoted to an end-to-end utility guarantee. Policy breadth, selection/routing, adaptive robustness, and real task completion need separate measurements.

**Scope guard:** RedCode, six evaluated LLMs, the paper’s fixed prompt budget and provisioning schemes, and non-adaptive jailbreak families. Per-class performance assumes the threat class is known in advance and therefore is an upper-bound reference, not a deployable apples-to-apples replacement for the all-class mode.
