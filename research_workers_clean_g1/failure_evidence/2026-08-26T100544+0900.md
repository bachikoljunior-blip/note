### FE-075 — A full attacker-checkpoint × defender-checkpoint matrix shows that evaluating a hardened agent with an early attacker can understate vulnerability by an order of magnitude
**Status:** primary ARLAS preprint / ICLR-2026 submission; BrowserGym indirect-prompt-injection setting; 3 random seeds.

Primary sources:
- Wang et al., *Adversarial Reinforcement Learning for Large Language Model Agent Safety* (ARLAS), arXiv:2510.05442: https://arxiv.org/abs/2510.05442
- Project page: https://wangzizhao.github.io/spag_web_agent/

Evidence:
- ARLAS population-based training explicitly trains the agent against all prior attacker checkpoints, then cross-evaluates agent stages {base, SFT, RL iter 5, RL iter 10, RL iter 15} against attacker stages {base, SFT, RL iter 5, RL iter 10, RL iter 15} on unseen BrowserGym tasks.
- For Gemma 3 12B, the final RL-15 defender has attack-success rate (ASR) **3±0%** against the base attacker, **11±1%** against the SFT attacker, **19±2%** against RL-5, **25±2%** against RL-10, and **37±4%** against RL-15.
- Thus, holding the defender fixed while only changing attacker stage changes measured ASR from **3% to 37% (+34 pp)**. A static or weak attacker would make the same frozen defender look dramatically safer.
- Holding the latest attacker fixed also changes the result materially across defender stages: RL-15 attacker ASR is **55±3%** against the base agent and **37±4%** against the RL-15 agent, so attacker strength and defender strength must be disentangled rather than summarized by one same-round score.
- The figure reports mean and standard error across **3 random seeds**.

Failure implication: attack-evaluation strength is a major measurement variable. A single frozen attacker is not a stable estimator of a defender's vulnerability when attacker optimization itself improves over time. This result directly satisfies the prior fallback frontier of a multi-checkpoint cross-evaluation with uncertainty, but it does **not** satisfy the stricter frontier of independently re-optimizing a fresh held-out attacker from scratch against every frozen defender under an exactly matched attack budget.

Positive control / scope guard: ARLAS itself is evidence that population-based co-training can improve both defense and task completion in this exact agent environment. The claim is about evaluation confounding and attacker strength, not that ARLAS or adversarial training fails generally.

### FE-076 — In co-evolution, contemporaneous attacker-vs-defender scores can make an improving attacker look weaker; a cross-stage matrix reverses that interpretation
**Status:** primary MAGIC arXiv v2; multi-turn LLM safety co-evolution; 320 HarmBench test prompts.

Primary source:
- Wen et al., *MAGIC: A Co-Evolving Attacker–Defender Adversarial Game for Robust LLM Safety*, arXiv:2602.01539v2: https://arxiv.org/abs/2602.01539
- Code: https://github.com/BattleWen/MAGIC

Evidence:
- MAGIC cross-evaluates five attacker stages against five defender stages on **320 HarmBench test prompts**.
- Against the fixed initial Instruct defender, attacker effectiveness rises monotonically across the displayed stages: **20.00 → 21.25 → 24.06 → 26.56 → 27.81**.
- Yet along the co-evolving near-diagonal pairings, observed attack success falls sharply as the defender improves: **20.00** (no-revision attacker vs Instruct defender), **16.56** (SFT attacker vs RL-1 defender), **11.56** (RL-1 attacker vs RL-2 defender), **3.43** (RL-2 attacker vs RL-3 defender), **0.31** (RL-3 attacker vs RL-4 defender).
- Therefore a same-round learning curve alone could be misread as attacker degradation, while the fixed-defender column shows the attacker actually became more effective against that frozen target.

Failure implication: in adversarial co-training, a scalar same-round ASR conflates two moving policies. Cross-stage evaluation is necessary to tell whether the attacker weakened, the defender strengthened, or both changed. This is a measurement failure mode, not evidence that MAGIC's defender is ineffective.

Scope guard: these attacker checkpoints were produced sequentially in one co-evolutionary process; they were **not** independently initialized and separately optimized against every frozen defender. No uncertainty bars are reported on this heatmap, so it is a strong matched cross-stage diagnostic but still short of the strict per-defender independent-reoptimization frontier.

### FE-077 — Large safety gains from adversarial co-training can coexist with a 26–30 pp loss in benign compliance even when general knowledge benchmarks remain stable
**Status:** primary AdvGRPO arXiv preprint; Qwen2.5-7B defender; explicit benign-vs-harmful evaluation.

Primary source:
- Bullwinkel et al., *Learning to Attack and Defend: Adaptive Red Teaming of Language Models via GRPO*, arXiv:2606.09701: https://arxiv.org/abs/2606.09701

Evidence:
- Base Qwen2.5-7B has HarmBench ASR **18.8%**. AdvGRPO defenders reduce this to **0.9%** when co-trained with a Qwen2.5-7B attacker and **1.5%** with a Qwen2.5-14B attacker.
- On benign WildJailbreak prompts that resemble harmful requests, non-refusal/compliance falls from **99.2%** for the base model to **72.8%** and **69.6%**, losses of **26.4 pp** and **29.6 pp** respectively.
- XSTest benign compliance falls from **95.6%** to **88.8% / 91.6%**.
- In contrast, broad capability metrics remain close to base: MMLU **73.5 → 73.3 / 73.1**, TruthfulQA **51.5 → 51.6 / 51.2**, ARC-C **89.9 → 90.2 / 90.0**, IFBench **31.3 → 33.3 / 32.3**.
- The authors attribute the benign-compliance problem to using only vanilla benign prompts during co-training, making harm-like benign prompts hard to distinguish.

Failure implication: a defender can look dramatically better on harmful-prompt safety benchmarks while acquiring a large refusal-calibration defect that generic capability benchmarks barely reveal. Safety evaluation should therefore include harm-like benign compliance, not only harmful ASR and broad utility.

Positive control / scope guard: the general capability scores do not collapse, so this is specifically an over-refusal/calibration tradeoff in the tested setup rather than a claim of broad model degradation or a rejection of co-training.

### FE-078 — Token-level entropy can be a misleading proxy for red-team strategy diversity: preventing entropy collapse need not prevent tactic collapse
**Status:** primary AdvGRPO ablation; negative result on diversity control.

Primary source:
- Bullwinkel et al., arXiv:2606.09701, Appendix C: https://arxiv.org/abs/2606.09701

Evidence:
- Without entropy regularization, attacker token entropy steadily collapses during training.
- With adaptive entropy regularization at `β_max=0.1`, token entropy stays at a moderate level, but the authors report that the attacker still converges to narrow strategies; generated attacks vary surface phrasing while repeatedly using the same documentary-style tactic.
- Increasing to `β_max=0.15` makes the entropy bonus dominate the policy gradient, causing entropy to explode and generations to become incoherent.
- The authors conclude that token-level entropy regularization does not necessarily improve strategy-level diversity and suggest explicit strategy-conditioning / latent-variable mechanisms instead.

Failure implication: maintaining high token entropy is not evidence that an automated red team is exploring materially different attack strategies. An evaluator that monitors only token entropy can miss tactic-level mode collapse, while aggressive regularization can destroy coherence.

Scope guard: this is an ablation of one entropy-regularization design in AdvGRPO, not evidence that all diversity regularizers fail.
