## New failure evidence

### FE-243 — One-shot verifier filtering is weaker than carrying verifier uncertainty through the entire memory lifecycle
**Primary source:**
- Wang et al., “MemGuard: Persisting Verifier Signals for LLM-Agent Memory Governance,” arXiv:2608.21867, August 22, 2026: https://arxiv.org/abs/2608.21867

MemGuard targets two specific persistent-memory failures: unreliable admission, where failed trajectories, accidental successes or misleading observations enter memory, and memory drift, where the bank accumulates duplicate, stale and conflicting records that retrieval cannot repair. Instead of using a verifier only as an admission filter, it attaches reward, confidence, label and uncertainty metadata before activation and reuses those signals during retrieval, conflict resolution, summarization and archival. Under matched runtime budgets on Terminal-Bench 2.0, SWE-Bench Verified, WebArena and Mind2Web, across four backbones and five seeds, MemGuard achieves the best reported success metric and lowest average steps in all `16` backbone×benchmark settings. Against ReasoningBank, the strongest prior memory baseline in the study, the largest gains are `+7.9` success-rate points on WebArena, `+5.6` step-success-rate points on Mind2Web and `+2.4–3.5` points on terminal/software-engineering tasks.

**Failure implication:** verifying an experience once and then discarding the verification context is not sufficient evidence that the memory remains trustworthy after retrieval, merging, conflict resolution or archival. Reliability metadata may need to remain attached to the artifact throughout its lifecycle rather than being reduced to a binary accept/reject decision.

**Positive control / scope guard:** this is primarily a positive-control result showing a stronger governance design, not evidence that every one-shot verifier fails. It is a very recent arXiv v1 and the comparison is system-level; the lifecycle metadata, conflict logic and other implementation differences move together. The reported gains are limited to the tested four backbones, four benchmarks, baselines and matched runtime budget.

### FE-244 — Fixed task order can manufacture apparent self-improvement; shuffling the same task set flips the average sign and stateful memory amplifies run variance
**Primary source:**
- Ye et al., “On the Fragility of Self-Improving Agents: Variance, Task Order, and Underspecification,” arXiv:2608.18066: https://arxiv.org/html/2608.18066

The authors re-evaluate Agent Workflow Memory (AWM) and ReasoningBank (RBank) with three identical runs per setting and two shuffled task orders on WebArena, VisualWebArena and SCUBA. Across `24` method-domain comparisons, self-improvement increases run-to-run variance in `17/24` cases (`≈71%`), and in `11` cases the relative increase exceeds `50%`. On WebArena GitLab, the no-memory best-worst gap is `4.44 pp`, while RBank widens it to `7.78 pp`; on Multisite, the RBank gap reaches `10.42 pp` versus a `2.08 pp` baseline. Under the default order, RBank’s WebArena average is `56.3%`, `+1.5 pp` over the `54.8%` baseline, but the paper reports the apparent average self-improvement changes from `+1.5%` under the default ordering to `−4.5%` under shuffled ordering. In Shuffle-1, AWM drops to `49.1%` and RBank to `49.8%`; overall, performance degrades significantly in `6/8` shuffled cases.

The default ordering is itself an implicit curriculum: early task success is around `75%` and can fall below `40%` later in the sequence. The authors identify underspecified environment/task information as one mechanism by which early stochastic failures generate unusable memories (e.g. advising API use in a browser-only environment). Supplying rubrics, environment feedback and stricter memory prompts closes only about `31%` of the shuffled-order degradation.

**Failure implication:** a stateful self-improvement loop cannot be credibly evaluated by one run over one fixed sequence. Early random outcomes become persistent state, and an easy-to-hard benchmark order can act as hidden training curriculum. Report multiple independent runs and perturb task order/distribution before attributing gain to the self-improvement mechanism.

**Positive control / scope guard:** this study uses three runs per condition, GPT-5-mini as the agent/memory backbone unless otherwise specified, and web-browsing benchmarks. The fixed-order `+1.5 pp` RBank gain itself has `p=0.23` over three runs, so it should not be treated as established positive effect. Shuffling is a stress test, not a claim that all real user streams are uniformly random.

### FE-245 — Continuous LLM rewriting can corrupt even ground-truth experience; retaining raw episodes is a strong control against abstraction drift
**Primary sources:**
- Zhang et al., “Useful Memories Become Faulty When Continuously Updated by LLMs,” arXiv:2605.12978: https://arxiv.org/abs/2605.12978
- Author project page: https://dylanzsz.github.io/faulty-memory/

Across five agent benchmarks and a controlled ARC-AGI Stream, the authors find that memory utility often rises and then degrades as an LLM repeatedly rewrites prior experience into consolidated textual lessons, sometimes falling below the no-memory baseline. The cleanest test removes bad-data explanations: they choose `19` ARC-AGI problems that GPT-5.4 solves at `100%` with no memory and provide ground-truth solutions during consolidation. After repeated consolidation, accuracy on those same problems falls to `54%`—a `46 pp` regression caused despite correct source experience. The authors trace the degradation to consolidation/update scheduling: the same raw trajectories produce different abstractions under different rewrite schedules, while episodic-only retention remains competitive. In a controlled Retain/Delete/Consolidate environment, the agent tends to preserve raw episodes, and an episodic-management-only policy matches the automatic regime while forced consolidation performs substantially worse.

**Failure implication:** “derived from correct trajectories” does not imply “correct persistent lesson.” Repeated generative summarization can overwrite applicability conditions and introduce drift even when the underlying experience is clean. Raw immutable episodes/provenance should remain recoverable, and abstraction should be gated as a lossy hypothesis rather than treated as replacement ground truth.

**Positive control / scope guard:** this is evidence against the tested continuous textual consolidation mechanisms, not memory abstraction in general. ARC-AGI Stream is a controlled diagnostic and the `54%` post-consolidation accuracy is on 19 selected problems the model originally solved; it is not an estimate of general GPT-5.4 memory reliability. Episodic-only storage has its own context/storage costs and does not establish that abstraction can be eliminated indefinitely.
