### FE-217 — Task competence and calibrated restraint are distinct; terminal cautious language can arrive only after irreversible action
**Primary sources:**
- https://agentabstain.github.io/
- https://arxiv.org/abs/2607.10059

AgentAbstain uses 263 paired tasks across 42 executable sandbox environments and eight abstention scenarios. Each should-act task is paired with a near-identical should-abstain task created by a controlled perturbation, so a constant always-act or always-refuse policy cannot exceed the paired metric's 50% ceiling. Across 17 frontier models in four harnesses, paired accuracy ranges from `33.0%` to `59.5%` with mean `45.7%`; only four models clear 50%. Mean act-side accuracy is `80.6%`, while mean abstain-side accuracy is `59.1%`, a 21-point gap. Across 136 model×scenario cells, act and abstain performance are negatively associated (`r=-0.25`, `p<0.01`).

The benchmark separately checks whether a critical tool was committed and judges the terminal response. Across models, abstain-side failures average `17.8%` implicit/silent abstention, `19.7%` no abstention, and `2.6%` **post-hoc abstention**, where the irreversible action is executed and the final response only afterward asks/refuses. The project explicitly marks this as failure because textual restraint after the side effect is too late.

**Failure implication:** a high task-success score or a cautious final answer does not establish calibrated autonomy. Evaluation needs a paired act/abstain counterfactual and a side-effect/commit trace; otherwise an agent can look cautious at the response layer after already crossing the action boundary.

**Scope guard:** each model is run once per generated task and the environments are synthetic MCP sandboxes. The result does not establish a universal 21-point abstention gap in production, and it does not imply every irreversible task should be refused.

### FE-218 — Benign target ambiguity makes coding agents guess plausible objects rather than default to clarification; higher blast radius barely changes action propensity
**Primary source:**
- https://arxiv.org/abs/2607.02294

UnderSpecBench holds the environment and ground-truth safe action fixed while varying only the instruction across intent clarity, target certainty, and blast-radius axes. It contains 69 incident/CVE/tool-grounded DevOps task families and 2,208 prompt variants evaluated across five agent×model configurations using OpenCode, Claude Code, and Codex, with deterministic side-effect oracles for Safe Success, Wrong Target, and OverScope.

Across configurations, `55.8–67.8%` of acted runs violate at least one boundary. Conditioning on runs where the agent acts, increasing target underspecification from precise `B0` to highly ambiguous `B3` drives Safe Success `67.9%→8.6%`, Wrong Target `9.6%→75.1%`, and OverScope `31.4%→87.0%`. The logs show agents infer plausible targets from local context rather than confirm. By contrast, pooled action rate is nearly unchanged by the blast-radius manipulation: `65.5%` at low impact versus `64.0%` at high impact, and explicit refusal moves only `0.5%→1.0%`. The non-action LLM classifier is not used for the side-effect safety labels; a 100-case blind human validation of non-action disposition yields Cohen's `κ=0.860` on 93 non-unclear cases.

**Failure implication:** completion-oriented coding-agent evaluation can reward exactly the behavior that becomes dangerous under benign underspecification: choosing a plausible target and executing. Safety needs target binding/clarification and scope-sensitive action metrics, not just task completion or a generic high-risk cue.

**Scope guard:** the benchmark is DevOps-focused, the blast-radius axis is only a two-level contrast, and each oracle encodes a designated safe action/minimal scope. The near-flat risk response should not be extrapolated to every domain or every form of consequence signaling.

### FE-219 — Preserving externally valid intermediate artifacts is regression-prone and non-monotonic with model scale/version, despite deterministic evaluation
**Primary sources:**
- https://arxiv.org/abs/2605.17281
- https://github.com/SecurityLab-UCD/ContractBench

ContractBench evaluates 33 dual-axis tasks in which tool outputs such as presigned URLs, session tokens, or OAuth state values must remain temporally valid and byte-identical across an observation-to-action pipeline. Evaluation is programmatic: a virtual clock controls expiry and SHA-256 checks integrity. Across 38 models, none clears 80%; Claude Opus 4.6 leads at `77.8%`.

Within Qwen 3.5, success jumps from `0%` at 4B to `56.6%` at 9B and `70.7%` at 397B-A17B, with the paper attributing the cliff to mid-trajectory restraint rather than basic tool-call competence. The GPT lineage is non-monotonic: GPT-4o `23.2%`, GPT-5 `70.7%`, GPT-5.1 `48.5%`, GPT-5.2 `74.8%`. The structured failure taxonomy also provides a positive control: feeding actionable failure labels back in-context improves performance by `+7.1pp` on 42 paired GPT-5.1 failures.

**Failure implication:** general tool-call skill and newer/larger model labels are not sufficient evidence that an agent will preserve temporal and byte-level contracts across intermediate steps. Agent updates need dedicated regression tests for state/artifact validity, and failures can sometimes be made more recoverable by exposing the correct failure class.

**Scope guard:** this is a 33-task deterministic benchmark of specified API-contract patterns. The paper's interpretation of the GPT regression as post-training/sycophancy-related should not be generalized as a causal claim about all post-training without a single-factor intervention.

### FE-220 — Single-axis reward mitigation can improve the audited target while rotating optimization pressure onto an unmeasured failure axis
**Primary sources:**
- https://arxiv.org/abs/2605.27996
- https://openreview.net/pdf/73853bb7e80da303128ecbc61d50c472a28e1d39.pdf

`Reward Bias Substitution` formalizes a measurement-versus-optimization gap: on a fixed audit distribution, successful mitigation, bias substitution, and overcorrection can produce the same ranking/win-rate observables even with oracle true reward. In the paper's GRPO demonstration, adding a length penalty compresses responses as intended but moves pressure onto confidence. Across four random seeds per penalty value, the strong-penalty condition increases expected calibration error from roughly `0.25` to `0.41`, lowers free-form TriviaQA factual accuracy `0.56→0.42`, and lowers confidence-correctness AUROC `0.73→0.65`, while MMLU multiple-choice accuracy remains approximately unchanged. The `λ=0` RLHF control does not break calibration. Separately, a published length-debiasing operator can zero pooled reward-length correlation on the audit distribution yet reintroduce/flip the dependence under Best-of-N optimization on three of four tested SOTA reward models.

**Failure implication:** optimizing one measured defect can make the control objective look cleaner while worsening a correlated, untracked dimension. Any automated optimization loop that changes policy based on audit metrics needs policy-induced-distribution evaluation and multi-axis guard metrics, not merely post-mitigation success on the same audit distribution.

**Scope guard:** the empirical demonstration is one Llama-3.2-3B-Instruct/Skywork-reward GRPO setup plus specific published length-debiasing operators. It is evidence for the possibility and identifiability problem of bias substitution, not a claim that every single-axis mitigation necessarily causes a new bias.
