## New failure evidence

### FE-265 — Closing a self-play loop against the attacker set used to train the defender can demonstrate patching without demonstrating post-patch exploitability
**Primary source:** Dharna, Lu & Clune, “Foundation Model Self-Play: Open-Ended Strategy Innovation via Foundation Models,” Reinforcement Learning Journal 2025 / arXiv:2507.06466, https://arxiv.org/abs/2507.06466 ; RLC/OpenReview full paper https://openreview.net/pdf/40a68e2620dedfe26c6cc04f5fc0029d911e2f3c.pdf

In the Gandalf safety simulation, the authors first select 18 high-performing attacker policies that collectively bypass defenses 1–6, explicitly using redundancy because specialists can fail on slightly new settings. Those selected attackers are then used as seeds/targets for the defender-evolution half of the loop. The subsequent defender result shows newly generated defenders stopping those attacker variants while passing six benign questions. The paper separately reports four seeds for attacker-side QD coverage/QD-score statistics, but this defender-closing demonstration is not an independent per-defender fresh-best-response evaluation.

**Failure implication:** a “patched all discovered vulnerabilities” result can be in-sample with respect to the exploit population that drove the patch. A safety optimizer should not treat patching the training attack set as evidence of low exploitability; after each frozen defense it should train/search a fresh attacker and measure transfer against all other defenses.

**Scope guard:** this is a methodological limitation of the tested Gandalf closing-the-loop evaluation, not evidence that FMSP defenses are ineffective. The paper’s positive result—automatic discovery and patching of known attack variants—remains valid within that tested set.

### FE-266 — One-shot skill testing misses most exploitable paths; feedback-driven multi-round probing changes ASR by an order of magnitude on real skills
**Primary source:** Duan et al., “SkillAttack: Automated Red Teaming of Agent Skills through Attack Path Refinement,” arXiv:2604.04989, https://arxiv.org/abs/2604.04989 ; public full text mirrored at https://www.researchgate.net/publication/403605216_SkillAttack_Automated_Red_Teaming_of_Agent_Skills_through_Attack_Path_Refinement

Across 10 LLMs, 71 adversarial skills and 100 real-world Hot100 skills, the feedback-driven attack substantially outperforms one-shot Direct Attack. On Hot100, GPT-5.4 moves from Direct ASR 0.02 to SkillAttack 0.23; GLM-5 from 0.03 to 0.26; Hunyuan from 0.04 to 0.23. Among all successful pairs, the first success occurs in rounds 1/2/3/4/5 at 12.8% / 11.6% / 36.0% / 28.8% / 10.8%; on Hot100 specifically, 39.5% first succeed in round 3 and 30.2% in round 4. The case study also shows a round-2 hallucinated tool execution that is rejected because trajectory/artifact evidence is absent, followed by a real exploit in round 3.

**Failure implication:** a skill can look safe under source review and early prompts yet expose a reachable unsafe execution path once the attacker conditions on actual tool/trajectory feedback. Security testing needs path-level, multi-round execution evidence rather than one prompt or final-answer semantics alone.

**Scope guard:** the study uses one judge model (Gemini 3.0 Pro Preview), only prompt-level attacks, and 171 skills across two benchmark sources; it does not establish the same ASR for all registries, models, or environment-level attackers.

### FE-267 — A configured LLM API router is an active trust boundary; real routers have modified tool traffic, stolen canary secrets, and delayed activation to evade smoke tests
**Primary source:** Liu et al., “Your Agent Is Mine: Measuring Malicious Intermediary Attacks on the LLM Supply Chain,” arXiv:2604.08407, https://arxiv.org/abs/2604.08407

The study measures 28 paid and 400 free commodity LLM API routers. It finds 1 paid and 8 free routers actively injecting malicious code, 2 routers using adaptive evasion triggers, 17 touching researcher-owned AWS canary credentials, and one draining ETH from a researcher-owned private key. The paper’s threat model is structural: routers terminate TLS and see plaintext JSON, while no provider-enforced end-to-end integrity binds the client’s received tool call to what the upstream model actually emitted. One observed malicious router stayed benign through a warm-up period and began injection only after the 50th request.

**Failure implication:** “the model generated this tool call” is not established if an untrusted intermediary can alter the response after inference. Short pre-deployment smoke tests can also be specifically evaded by delayed activation. Long-running agents should minimize intermediary trust, keep high-risk execution gates client-side, avoid exposing secrets in routed model traffic, and retain provenance/integrity evidence independent of the router.

**Scope guard:** the empirical prevalence is specific to the sampled router markets and collection period. It does not imply every third-party router is malicious or that the observed rate generalizes to first-party/enterprise gateways.

### FE-268 — High clean utility can coexist with a highly reliable dormant multi-skill backdoor
**Primary source:** Feng et al., “SkillTrojan: Backdoor Attacks on Skill-Based Agent Systems,” arXiv:2604.06811v2, https://arxiv.org/abs/2604.06811

SkillTrojan hides encrypted payload fragments across otherwise plausible skill invocations and reconstructs/executes the payload only under a predefined trigger. The authors release 3,000+ curated backdoored skill variants. On the EHR SQL setting, GPT-5.2-1211-Global reaches up to 97.2% attack success rate while maintaining 89.3% clean accuracy. The payload is intentionally dormant outside the trigger path, so ordinary clean-task evaluation can remain strong while triggered behavior is malicious.

**Failure implication:** clean-task pass rates and ordinary behavioral canaries are weak evidence against conditional skill backdoors. Skill supply-chain evaluation needs provenance, composition-aware execution auditing, trigger-oriented tests, and side-effect controls in addition to benign utility.

**Scope guard:** this is a representative code-based agent evaluation plus additional reported tasks; the exact 97.2%/89.3% pair is tied to the EHR SQL/GPT-5.2 condition and does not generalize to all skill systems.

### FE-269 — Auditing skill source code is insufficient when executable skill behavior depends on a bundled learned model artifact
**Primary source:** Tie et al., “BadSkill: Backdoor Attacks on Agent Skills via Model-in-Skill Poisoning,” arXiv:2604.09378, https://arxiv.org/abs/2604.09378

BadSkill places a conditional backdoor in a learned model bundled inside an installable skill rather than in the host LLM or visible prompt logic. The benchmark covers 13 skills (8 triggered, 5 controls), 571 negative-class queries and 396 trigger-aligned queries, across eight architectures from five model families (494M–7.1B parameters). Average ASR across triggered skills reaches up to 99.5% while benign-side accuracy remains strong; in the poison-rate sweep, only 3% poisoned data already yields 91.7% ASR.

**Failure implication:** “reviewed the skill code/instructions” is not a complete supply-chain control if a skill can load learned artifacts. Provenance/signature checks and adversarial behavioral tests must cover bundled models, checkpoints and other opaque executable artifacts too.

**Scope guard:** the evaluation is an OpenClaw-inspired simulation over the stated skill/model set. It does not establish prevalence of poisoned model-bearing skills in real marketplaces or imply every bundled model is unsafe.
