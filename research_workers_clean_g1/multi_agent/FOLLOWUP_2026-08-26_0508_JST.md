## C43 — A real LLM MAP-Elites loop already exhibits strongly asymmetric judge error, but does not inject it experimentally

Primary source: Subhadip Mitra, *Quality-Diversity Evolution for Discovering Diverse Vulnerabilities in LLM Safety*, ICLR 2026 Workshop on Agents in the Wild, OpenReview PDF `c77a41ed92010ddba9a1e71cfb63d5ab2020054f`.

The system uses MAP-Elites with a heuristic refusal/compliance judge. Manual inspection of a random sample of 50 responses found an estimated misclassification rate of about **12%**, described as primarily ambiguous redirections scored as refusals (**false negatives**), with **no false positives observed** in that sample. The experiment used population 30, 30 generations, mutation rate 0.3, and a 6×6×6 archive; reported occupancy was 36/216 cells (16.7%).

This is useful class-conditional evidence because the measurement error is visibly asymmetric in an actual LLM-driven MAP-Elites loop. It supports separating false-admit and false-reject channels instead of collapsing them into one scalar judge error rate. It does **not** establish the effect of those errors on final archive quality: the paper does not run a controlled corruption sweep, and `n=50` is too small to infer a precise false-positive rate or a universal asymmetry.

Public source: https://openreview.net/pdf/c77a41ed92010ddba9a1e71cfb63d5ab2020054f.pdf

## C44 — Loreley's released record is sufficient for an exact, non-Monte-Carlo false-admit/false-reject selection replay

Primary public artifacts: NeapolitanIcecream/loreley, commit `d05392a4950fddee7a5719fa30f0a8db71e8fd4f` (`paper: add preprint source and public evidence`), especially:

- `paper/evidence/build_zstd_formal_records.py`
- `paper/evidence/zstd_formal_records.json`

The public builder explicitly states that the sanitized record retains enough structure to replay finalist selection. Its published `validation_eligible()` rule is:

- root: always eligible with score 1.0;
- non-root: `passed == true`;
- `compression_lower_95 > 1.0`;
- `decompression_geomean >= 0.995`;
- `worst_cell_speedup >= 0.98`.

Eligible candidates are ordered by highest selection score, then root preference, smaller diff, commit, and identity. The builder asserts **126** selection groups and **21** endpoint groups at checkpoint 48, and publishes `validation_evaluations`, `selection_groups`, official `holdout_evaluations`, plus extra fixed-candidate holdout measurements used for Top-5 sensitivity.

### Implemented exact replay tool

A new role-local tool is now persisted at:

`research_workers_clean_g1/multi_agent/tools/loreley_selection_corruption_replay.py`

Creation commit: `437e3d9ce6328d0d9dc9f7e3935bc5439d3bfdc2`; readback blob: `7444275595d271f70b8507e515131c97b58639ac`.

The tool intentionally operates **after clean metric computation at the released eligibility boundary**. It defines:

- `q_fp`: clean-ineligible non-root finalist becomes eligible;
- `q_fn`: clean-eligible non-root finalist becomes ineligible;
- root fixed eligible by default, matching the published unconditional fallback; `--corrupt-root` is a separate sensitivity mode;
- default sweep grid `0, .05, .10, .20, .30, .40, .50` for false-admit-only, false-reject-only, and symmetric corruption.

No Monte Carlo is needed. For a deterministic priority order, the exact probability candidate `i` wins is

`P(i wins) = P(i eligible) × product(P(each higher-priority candidate is ineligible))`.

This reduces the replay to a closed-form calculation and avoids seed variance. Before any corruption result is emitted, the tool replays all 126 clean winners and requires exact identity equality with the public `top10_winner_identity`; it also requires exactly 21 checkpoint-48 groups. Therefore a schema/rule mismatch fails closed rather than silently producing a sweep.

The output separates:

- winner-identity error;
- selected clean-ineligible probability (selected false admission);
- clean-winner false-reject event probability;
- higher-priority false-admit preemption probability;
- root-selection/no-selection probability;
- selected-winner holdout-observable probability;
- fraction of groups whose clean winner has a released holdout measurement;
- paired holdout-regret observable probability;
- conditional signed and absolute paired holdout regret.

This makes **censoring explicit**: when a corrupted winner lacks released holdout data, the tool records unobservable probability mass rather than imputing a result.

### Local logic validation

The implementation was syntax-checked and run against a synthetic three-candidate fixture reproducing Loreley's priority semantics. The fixture had a higher-scoring clean-ineligible candidate `A`, clean winner `B`, and root fallback `R`; at `q_fp=0.10`, `q_fn=0.20`, exact probabilities were `A=0.10`, `B=0.72`, `R=0.18`. Thus clean-winner error was exactly `0.28 = 1 - (1-0.10)(1-0.20)`, selected-clean-ineligible probability 0.10, and root-selection probability 0.18. The tool's error-decomposition invariant matched these values.

### Scope limits

- This is a fixed-finalist **selection-layer** replay, not a full online QD replay.
- It does not reconstruct hidden candidate generation, archive insertion/eviction, parent selection, or downstream feedback from a corrupted earlier winner.
- Eligibility flips are synthetic class-conditional decision errors; they do not model metric-level correlated hallucination unless an additional error model is supplied.
- Independent per-finalist flips are the default; correlated block-level corruption remains a separate planned sensitivity.
- Root-fixed mode is the closest match to the released selection code; corrupting root is deliberately labeled sensitivity, not primary analysis.

## C45 — New 2026 online-FDR work broadens dependence robustness, but adaptive archive validity still requires valid per-candidate evidence

Primary source: Ziyu Xu, Lasse Fischer, Aaditya Ramdas, *Improving online FDR procedures via online analogs of e-closure and compound e-values*, UAI 2026 / PMLR 337:7552–7561.

The paper's published abstract explicitly treats hypotheses that are generated and tested continuously in a stream and gives FDR-control constructions under **arbitrary dependence**, using online e-closure and compound e-values; it also reports `O(log t)` rejection-decision computation. This weakens one concern from the prior checkpoint: cross-hypothesis dependence by itself need not force independence-only procedures.

However, this does not remove the archive-controller proof obligation. An adaptively generated candidate can only enter such a framework if the e-value/test supplied for that candidate is itself valid under the information used to generate and evaluate it. The abstract does not establish that arbitrary search-generated candidates automatically satisfy that condition. Therefore `arbitrary dependence` must not be misread as `arbitrary adaptive data reuse is safe`.

Public source: https://proceedings.mlr.press/v337/xu26a.html

## Updated synthesis

1. The public Loreley artifact is sufficient to turn the previously verbal corruption proposal into an auditable executable experiment with exact probabilities, exact clean-replay validation, and explicit holdout censoring.
2. For post-eligibility independent corruption, clean-winner error has a simple decomposition: false-reject of the clean winner and false-admit of any higher-priority clean-ineligible finalist. The replay can therefore distinguish *mechanism error* from endpoint performance rather than reporting a single noisy score.
3. Fixing root eligibility is the correct primary model for Loreley's released selector; otherwise the corruption experiment changes the fallback semantics as well as the evaluator.
4. Real LLM MAP-Elites evaluation error can be strongly asymmetric (C43), reinforcing the need for separate `q_fp` and `q_fn` sweeps.
5. Online FDR under arbitrary dependence is increasingly practical, but the validity of each candidate-local e-value under adaptive generation/data reuse remains the gating proof condition.

## Rejected / downgraded hypotheses

- `The Loreley replay requires Monte Carlo over 2^N eligibility masks` — rejected. Deterministic selection order gives a closed-form exact winner distribution.
- `Root should be corrupted in the primary eligibility-noise model` — downgraded. The published selector makes root unconditionally eligible; corrupt-root belongs in a sensitivity analysis.
- `No real LLM MAP-Elites system reports class-asymmetric judge error` — rejected by the ICLR 2026 workshop paper, within its small manual-audit scope.
- `Online FDR arbitrary-dependence results make adaptive archive writes automatically valid` — rejected. Dependence control does not by itself prove validity of adaptively generated candidate evidence.
