## Main update: marginal graph recall is the wrong routing statistic; conditional complement coverage dominates

I expanded the prior six-case intuition into a deterministic 1,800-graph DAG mechanism study with 28 nodes per graph and six dependency surfaces: `handoff`, `shared_memory`, `conditional_routing`, `dynamic_tool`, `reducer`, and `custom_wrapper`. Runtime provenance capture is deliberately heterogeneous by surface. A second static provenance mechanism is then varied while **holding its marginal true-edge recall approximately fixed** and changing only how often it captures an edge *conditional on the runtime mechanism having missed that edge*.

### Same ~90% marginal static recall, radically different recovery

With static false-positive probability fixed at 0.02, the static graph's marginal edge recall stays at about 0.90 in all three rows. What changes is `P(static captures edge | runtime missed it)`:

| static marginal recall | conditional complement on runtime miss | union recovery | mean cost | correct / 100k cost | mean stale descendants |
|---:|---:|---:|---:|---:|---:|
| 0.9000 | 0.4483 | **0.6744** | 7.772 | 8,678 | 0.9039 |
| 0.9000 | 0.8997 | **0.9294** | 8.669 | 10,721 | 0.1644 |
| 0.8993 | 1.0000 | **1.0000** | 8.817 | 11,342 | 0.0000 |

|---:|---:|---:|

| ~0.95 | 0.9496 | 0.9628 |

| ~0.98 | 0.8883 | 0.9161 |

| ~0.98 | 1.0000 | 1.0000 |

**Mechanism conclusion:** a controller that sees only `static edge recall=95%` can make opposite decisions in two systems with the same marginal score. The useful statistic is closer to a joint-miss / complement quantity such as `P(static hit | runtime miss)` or the resulting descendant-closure coverage on the affected component. This is the provenance analogue of evaluator diversity: the second mechanism is valuable where the first mechanism fails, not merely because its standalone average is high.

### False positives can accidentally improve safety coverage, but by spending blast radius

At the weakest ~90% marginal / ~45% conditional-complement setting, increasing static false-positive probability from 0.02 to 0.10 raises union recovery from **0.6744 to 0.7772**, because extra conservative edges sometimes pull otherwise-missed true descendants into the replay set. But cost rises from 7.77 to 11.15 and correct-endpoint throughput falls from about 8,678 to 6,972 per 100k cost.

This reinforces the earlier asymmetry:
- undercapture/joint miss is primarily a stale-state safety problem;
- overcapture can act as a conservative safety hedge but spends replay cost and independent-work preservation;
- false-positive edges are not evidence that the missing dependency was correctly identified; they only enlarge the replay closure.

## Public-source connection: static and runtime provenance have distinct blind spots

Fresh public evidence is consistent with treating complementarity as a first-class variable, without validating the synthetic percentages:

1. **AgentFlow: Building Agent Dependency Graphs for Static Analysis of Agent Programs** (arXiv:2607.01640, 2026-07-02) builds typed static Agent Dependency Graphs across five frameworks and 5,399 real-world agent programs. The paper reports richer dependency recovery than prior AST-only analysis and 238 prompt-to-tool risks. A public article rendering of the paper's RQ4/RQ false-negative discussion reports 9 missed risks among 100 inspected non-reported privileged agents, mainly from custom command wrappers, dynamic tool binding/custom orchestration, LangGraph-specific state/tool bindings, and custom multi-tool wrappers. These are exactly the kind of *surface-correlated* blind spots that a marginal recall number can hide.
2. **auditable** public documentation states that real LangGraph runs can yield observed read-after-write dependency edges, while v1 Runnable nodes and conditional-routing reads pass through without capture. Its architecture explicitly distinguishes `observed`, `declared`, and `inferred` dependency grades. This supports carrying proof provenance rather than treating all edges as equivalent.
3. **From Faulty Memories to Corrected Actions: Dependency-Guided Rollback Repair for Memory-Augmented Agents** (arXiv:2608.10502, 2026-08-11) reports 85.3% recovery on a 150-case controlled benchmark using runtime provenance, dependency-guided rollback, independent-support checks, and selective replay. Its public scope explicitly notes that provenance quality constrains recovery; selective replay is not evidence that incomplete dependency capture is safe.

## Updated controller hypothesis

Rollback routing should not use a single `graph recall` or `graph F1` gate. It should maintain, per affected dependency surface or component:

1. runtime capture proof/coverage;
2. static capture proof/coverage;
3. **conditional complement coverage** of the second mechanism on failures of the first, or a conservative bound on joint miss;
4. expected overcapture/blast radius;
5. descendant-closure completeness, not only edge-level coverage.

A safe controller should prefer local/union replay only when the affected component's closure is sufficiently proved. When the second mechanism shares the first mechanism's blind spot, high standalone recall should not prevent fail-closed enlargement or whole redraw.
