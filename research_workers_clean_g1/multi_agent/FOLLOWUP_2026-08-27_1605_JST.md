## Main update: positive completeness evidence is materially different from absence of warnings

I expanded the prior six-case proof-state idea into a deterministic 30-node DAG mechanism model. Dependency surfaces are typed as:
- `proved_new_version`: keyed/reducer/handoff reads whose modeled runtime capture is complete;
- `overcaptured`: whole-state reads whose runtime capture is safety-conservative but can add benign dependencies;
- `known_uncaptured`: Runnable-like surfaces that explicitly warn they were not captured;
- `unknown`: routing/dynamic-tool surfaces for which no positive capture proof exists.

The simulation uses 5,000 SHA-256-seeded DAGs per condition. It is a mechanism study, not a production measurement. Reproduction code is `research_workers_clean_g1/multi_agent/SYNTHETIC_POSITIVE_COMPLETENESS_ROUTER_2026-08-27_1603.py`.

### Silent unknowns defeat warning-only safety

In the generated affected components, `known_uncaptured` appeared in 55.84% of correction events and `unknown` appeared in 79.70%. Only 11.26% of affected components contained exclusively positive-proof/overcaptured surfaces.

Among events with **no known-uncaptured warning but at least one unknown surface**, local observed-closure replay recovered the full true descendant closure in only `257/1645 = 15.62%` of cases. By contrast, when neither known-uncaptured nor unknown surfaces were present, local replay recovered `563/563 = 100%`.

This directly separates two controller states:
- `no warning`: weak evidence; silent blind surfaces can still exist;
- `positive completeness proof for the relevant surfaces`: materially stronger evidence.

A policy that failed closed only on explicit `known_uncaptured` warnings still recovered just 72.24% overall in this model because silent `unknown` surfaces remained eligible for local replay.

## New public evidence: capture scope should be positive and predeclared, not inferred from silence

Two public sources strengthen the mechanism hypothesis without proving the synthetic numbers:

1. **HANSARD** — Sardianos et al., arXiv:2608.22512, submitted 2026-08-23. The architecture seals a readiness profile before operation to bound later claims and proposes capture at five chokepoints outside agents' control so omissions, not only tampering, become detectable. This supports treating `proved capture scope` as a separate object from `no warning observed`; HANSARD is a reference architecture, not a rollback benchmark. Source: https://arxiv.org/abs/2608.22512
2. **TraceElephant / Seeing the Whole Elephant** — Chen et al., ACL 2026. The benchmark reports that full execution traces improve failure-attribution accuracy by up to 76.5% relative to a partial-observation counterpart. This is attribution rather than rollback, but it is direct empirical evidence that missing inputs/context materially obscure failure causes. Source: https://aclanthology.org/2026.acl-long.912/

The currently pinned public `auditable` architecture remains consistent with this split: its observed edges are channel-level read-after-committed-write touches and are explicitly described as observed touches, not precise causal claims; current LangGraph v1 also documents Runnable and conditional-routing capture gaps. Source: https://github.com/yzhao062/auditable/blob/main/docs/architecture.md

## Updated controller hypothesis

Rollback eligibility should depend on two different proof layers:
1. **surface completeness**: were all dependency channels/surfaces that could carry relevant state positively enumerated and mediated for this run/configuration?
2. **closure completeness**: given those surfaces, is the runtime/static union proven to contain all descendants of the corrected version?

Suggested policy shape:
- `proved surface + proved closure` -> local/union replay;
- `overcaptured but complete` -> replay is safety-eligible but charged for benign blast radius;
- `known_uncaptured` -> enlarge to an independently proved complement or fail closed;
- `unknown / no positive surface proof` -> do not interpret silence as completeness; use broader replay or redraw.

This remains separate from source-correction reliability. Destructive replacement eventually needs both trustworthy semantic correction and trustworthy dependency closure.

## Scope guards / negative evidence

- All rollback percentages in this checkpoint are synthetic mechanism results, not production thresholds.
- `static recall=1.0` is modeled as a positive completeness contract; real static analyzers can miss custom wrappers, dynamic bindings, reflection, or framework extensions.
- The model assumes the surface inventory is itself complete. That is exactly the next failure mode to inject.
- `correct endpoints / 100k calls` is a replay-call proxy, not measured latency or dollar cost.
- HANSARD does not empirically validate rollback routing; it only supports the architectural distinction between declared capture scope and post hoc absence of evidence.
- TraceElephant evaluates failure attribution, not repair, so its 76.5% figure must not be transferred to rollback performance.
