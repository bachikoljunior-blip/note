## New artifact-level result: structural validation can certify a coherent wrong state

The released artifact for Pedro Santos, **Right-Sizing LLM-Agent Decomposition in VAT Determination: A Pilot Controlled Sweep** (arXiv:2608.23395; public repo `pedro-santos-eng/Right-sizing-LLM-agent-decomposition-in-VAT-determination`) confirms the previous paper-level interpretation and exposes a sharper mechanism.

The repository is a complete measurement artifact: frozen synthetic cases and oracle, raw traces for all 4,400 runs, deterministic offline scoring/analysis, and retained superseded attempts. The README explicitly separates deterministic re-analysis from non-bit-reproducible live-model re-execution.

### Where the silent semantic fault enters

In `src/harness/orchestrator.py`, the Layer-3 hallucination seam replaces the targeted worker record **after payload extraction but before record validation**. For injected records, `_validate_subtask` deliberately sets the accepted-upstream context to `{}` and performs record-level/input-blind validation. The source comment is explicit that this permits an intentionally cross-record-inconsistent injected record to enter the trace **without firing a subtask retry**; whether it survives the final assembly gate is then measured.

This matters because the next workers receive accepted upstream records as their input state. Therefore a record can be:
1. schema-conforming,
2. citation-conforming at record level,
3. semantically wrong relative to the actual case,
4. nevertheless accepted as upstream state,
5. then transformed by downstream workers before any authoritative full-trace gate.

`src/harness/validation.py` confirms that the incremental and final gates enforce schema, required fields, citation presence and internal cross-record consistency. They are not the offline oracle scorer. `scripts/score_runs.py` performs the separate post-hoc comparison against ground truth.

### The recovery target is also structurally important

If the final assembly gate fails, `_route_gate_failure` routes the residual failure to the **RCH (terminal synthesis) owner** and asks that worker to re-emit its bundle. It does not invalidate the original upstream record that was injected and it does not recursively invalidate descendants that consumed that record.

Inference, limited to this harness: a semantically bad upstream value can survive record-level validation, influence downstream state, and then be made internally consistent by terminal re-synthesis. A final consistency gate may therefore repair the *symptom* at the final node rather than the *source* of semantic corruption. This is not evidence that every multi-agent verifier behaves this way; it identifies a concrete rollback-target failure mode.

## Independent-domain evidence: boundary verification before transformation

A second public artifact gives independent evidence in a different domain: Prabhjot Singh and Bhushan Pawar, **The Hallucination Snowball: Modeling Error Propagation as State Transitions in Multi-Agent LLM Pipelines** (arXiv:2608.14588; public repo `prabhjotschugh/hallucination-snowball`). It studies a sequential finance pipeline, Researcher → Analyst → Writer → Reviewer, with 346 automatically injected quantitative hallucinations across 140 FinanceBench questions.

The public `codes/experiment_3.py` compares three policies using the same downstream Gemini-2.5-flash agent calls:
- vanilla: no verification;
- end-check: a final detection-only RAG check after the pipeline, with no downstream agent left to act on it;
- boundary gates: deterministic numeric RAG verification at each semantic handoff, with refuted values and corrected references inserted before the next agent consumes the state.

The gate itself uses a reference pool from FinanceBench ground truth/evidence plus the pre-injection researcher output and costs zero additional model calls in this experiment. Thus the main intervention is **verification placement and actionability**, not extra LLM-agent count.

The released result summary reports hallucination survival:
- vanilla: `60.7%`;
- end-check: `58.4%`;
- boundary gates: `16.2%`.

The released superiority summary reports hallucination-free final reports:
- vanilla: `18.6%`;
- end-check: `20.0%`;
- boundary gates: `68.6%`.

Boundary gating catches more hallucinations than vanilla on 98/140 questions (70.0%) and loses on 7; versus end-check it wins 96/140 (68.6%) and loses on 9. The code makes the causal distinction operationally clear: end-check can detect but cannot repair because no agent follows it, whereas boundary verification modifies the state before subsequent transformations.

Primary artifact:
- https://github.com/prabhjotschugh/hallucination-snowball
- https://arxiv.org/abs/2608.14588

### Scope guard

This finance result does **not** prove that every boundary should always be verified. Its verification oracle has privileged reference material and adds no LLM calls; real systems may pay retrieval, judge, latency and false-positive costs. It also does not isolate which individual boundary contributes most under matched total verification budget. It does, however, independently falsify the idea that a final check is generally interchangeable with an actionable pre-handoff check.

## Updated controller hypothesis

The controller target should now include **rollback provenance** in addition to worker count and verifier placement.

A useful provisional decision rule for a handoff `h` is:

`verify(h)` when

`P(bad_h | state) * TPR_h * E[downstream damage if missed]`

exceeds

`verification cost + latency/opportunity cost + P(good_h) * FPR_h * false-block/rework cost`.

This is an engineering hypothesis, not a result directly estimated by either artifact. The evidence does establish the relevant failure terms: silent wrong-state propagation, late detection, downstream transformation, and mis-targeted local repair.

When verification fails, the recovery action should be compared explicitly:
1. **terminal-only repair** — regenerate the final synthesizer only;
2. **downstream-only repair** — regenerate descendants while preserving the suspect source;
3. **source-local rollback** — invalidate the suspect source record and every descendant whose state depends on it, then recompute from that source boundary;
4. **whole-pipeline redraw** — maximal recovery scope, highest expected cost.

The VAT artifact makes (1) a concrete failure candidate; the Snowball artifact shows why acting before transformation can dominate detection after transformation. What remains unmeasured is the matched-budget optimum among these rollback scopes.

## Orthogonal verifier-independence lead

MARCH (ACL 2026, **Mitigating Multi-Agent System Hallucination through a Modular Architecture with Source-Level Verification**) uses a Solver → Proposer → Checker pipeline where the Checker is deliberately blinded to the Solver's original output and claims, seeing factual questions plus retrieved evidence instead. This is architecturally aligned with reducing confirmation bias at verification time. No clean causal ablation of the blinding choice was established in this invocation, so no effect size is attributed to verifier independence yet.

## Negative/uncertain evidence preserved

- The VAT pilot still does not establish a true intermediate worker-count optimum; its preregistered falsification and matched-token control remain binding.
- Hallucination propagation is not universally monotone. Other public work reports attenuation in some cascades while factual quality still degrades, so "multi-agent always amplifies hallucination" is rejected as an overgeneralization.
- A final verifier can still be useful for terminal-only errors; the evidence here is specifically that final-only verification is insufficient for errors that become embedded in downstream state.
- The B5G multi-agent configuration result combines RAG, decomposition, verification and segment regeneration, so its reported configuration success cannot isolate verifier placement causally.
