## New primary evidence — controlled worker-granularity sweep
Primary source: Pedro Santos, **Right-Sizing LLM-Agent Decomposition in VAT Determination: A Pilot Controlled Sweep**, arXiv:2608.23395, submitted 2026-08-24. The paper reports 4,400 valid runs on a bounded VAT workflow with a deterministic oracle and independently scorable intermediate steps.

The key methodological advantage is that the orchestrated variants hold the activity surface fixed while changing worker scope. Across C1–C4 the paper reports the same subtasks, tools, I/O schemas, validation checks, orchestrator, base-model family, merge policy, decoding and logging/timeout setup. The fixed dependency graph spans CLS, JUR, RAT, EXM and RCH. C4 assigns one worker per subtask; C3 merges RAT+EXM+RCH while keeping CLS and JUR separate; C2 merges CLS+JUR and separately merges RAT+EXM+RCH; C1 uses one broad orchestrated worker for all subtasks. A tuned no-orchestrator single-agent ReAct/function-calling comparator, S0, is reported separately from C1.

### Main pilot sweep
Reported means over 40 cases with five repeats per condition:

| Condition | Accuracy | Mean tokens | Mean latency |
| --- | ---: | ---: | ---: |
| S0 | 0.755 | 11,899 | 11.8 s |
| C1 | 0.720 | 11,317 | 12.1 s |
| C2 | 0.830 | 14,590 | 15.8 s |
| C3 | 0.830 | 13,591 | 16.7 s |
| C4 | 0.770 | 15,845 | 18.4 s |

Descriptively, C2/C3 lead and C3 reaches the same reported accuracy as C2 with about 7% fewer tokens because the only structural difference is whether JUR is split from CLS. However, the paper's preregistered inference correctly prevents a stronger claim:
- S0 vs C1: difference `+0.035`, CI `[-0.035,+0.110]`.
- C1 vs C4: `-0.050`, CI `[-0.160,+0.050]`.
- C2 vs C1: `+0.110`, CI `[+0.010,+0.210]`, raw `p=.043`, but Holm-adjusted `p=.172`.
- Matched-token S0-prime vs C2: `-0.065`, CI `[-0.165,+0.025]`; the interval includes zero.

The preregistered "intermediate optimum" criterion therefore **does not establish** that C2/C3 is the true optimal granularity at this pilot scale. C2/C3's descriptive advantage is real enough to motivate follow-up, but not enough to attribute causally to worker count or decomposition independent of prompt/compute budget. The authors estimate roughly 90 cases would be needed for the planned fuller study around the observed effect scale.

### Failure-type interaction is more informative than the raw accuracy ranking
The paper injects availability failures and a schema-valid content error separately.

For transient timeout perturbations, localized recovery usually works. C2 changes by about `-0.020`, C3 `+0.005`, C4 `+0.005`. C1 is unusual: it restarts the broad pipeline and reports accuracy `0.880`, `+0.160` above its clean condition, but at roughly `+21,793` tokens. This is consistent with a validation-filtered redraw/restart effect, not evidence that timeouts are beneficial in general.

For a **schema-conforming but oracle-wrong record**, the ordering changes sharply:
- S0: accuracy `0.560`, delta `-0.195`.
- C1: `0.405`, delta `-0.315`.
- C2: `0.345`, delta `-0.485`.
- C3: `0.345`, delta `-0.485`.
- C4: `0.310`, delta `-0.460`.

All reported intervals for these content-fault deltas exclude zero. The more fragmented orchestrated configurations are hit hardest. The reason is mechanistically important: schema validation accepts the bad record, and downstream workers can consume it before later replacement. The orchestrated conditions reportedly replace the poisoned record in roughly 77.5–78% of cases, yet still suffer large endpoint loss because replacement is not equivalent to correction of already-propagated state.

### Controller implication
This narrows the design target from **"choose the right number of agents"** to **"choose where to place semantic boundaries, and what evidence is required before information crosses them."**

A seam can have opposite effects by fault type:
- narrow seams/local retry boundaries help contain visible availability faults;
- the same clean, typed seam can become an efficient propagation channel for a semantically wrong but schema-valid record.

Therefore a future adaptive decomposition controller should treat at least these as separate control variables:
1. worker count / scope;
2. dependency-boundary placement;
3. retry/restart locality;
4. semantic verification before downstream consumption;
5. cost of verification versus cost of redoing downstream work after silent corruption.

This is stronger than a generic "more/fewer agents" rule. It also qualifies the previous MANTA/AgentConductor evidence: topology repair and bounded decomposition may help, but a controller that optimizes only throughput/availability without content-validity checks can create cleaner channels for silent semantic failure.

## Orthogonal evidence — constrained joint orchestration
Primary source inspected before the freeze event: **INFRAMIND: Infrastructure-Aware Multi-Agent Orchestration**, arXiv:2606.11440, Ahasan Kabir et al.

INFRAMIND uses a hierarchical constrained controller in which a planner chooses topology, agent count and roles from query semantics plus an infrastructure/budget summary, while an executor chooses model and reasoning depth per step from remaining budget, queue depth, latency and KV-cache state; scheduling is deadline-aware. Reported ablations show that replacing infrastructure-aware routing with quality-only routing raises step latency by roughly `2.3–3.6x`, replacing deadline-aware scheduling with FCFS raises mean latency from about `68` to `134` seconds in the reported setting, and removing adaptive reasoning depth by using the fast model only lowers reported MMLU-Pro accuracy from `59.5` to `50.0`.

This is useful architectural evidence that **agent count/topology and per-step compute can live inside one constrained objective**, but it does not directly optimize semantic-verifier placement or topology-mutation depth. It is therefore a partial match, not a solution to the current frontier.

## Updated synthesis
The best-supported controller hypothesis is now:

1. Optimize **boundary placement and residual value**, not raw agent count.
2. Use task-conditioned decomposition before execution, but keep topology/role growth bounded.
3. During execution, repair locally when traces show availability/coordination failure.
4. Treat semantic handoffs as risk-bearing decisions: typed/schema-valid does not mean content-valid.
5. Insert independent semantic verification where the expected downstream propagation cost of a wrong handoff exceeds verifier cost.
6. Account for retry scope: whole-pipeline redraw can sometimes recover quality but can be extremely expensive; local retry is cheaper but may preserve silent contamination.
7. Compare every added worker/verifier/mutation against the same marginal compute budget, rather than granting extra calls for free.

The newest VAT sweep is especially useful because its preregistered falsification prevents overclaiming: the descriptive middle-granularity peak is **not yet established as a true optimum**, and the matched-token arm prevents attributing C2's result solely to multi-agent structure.
