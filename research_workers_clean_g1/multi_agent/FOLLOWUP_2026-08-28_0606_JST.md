## Main update: semantic correction quality is a separate gate from repair admissibility

The previous checkpoint made provenance/authorization/effect/KV repair admissibility concrete, but still assumed that the *correction itself* was semantically right. This run inserts an explicit noisy correction stage **before** an otherwise provenance-safe replay.

The deterministic synthetic model separates:
- whether the current datum is actually wrong (`src_err`);
- first-verifier diagnosis (`TPR=0.82`, `FPR=0.12`);
- whether a proposed correction is actually correct (`0.88` when the source is wrong and detected; a false alarm on an already-correct datum is harmful);
- same-verifier confirmation, with a tunable self-copy/dependence channel;
- second-verifier confirmation, with a tunable cross-verifier dependence mixture `rho_cross`;
- repair replay cost, which is charged only after a correction is promoted.

Policies compared:
1. `destructive_single`: one diagnosis immediately replaces canonical state and triggers admissible replay.
2. `provisional_same_repeat`: hold the candidate provisionally, ask the same verifier once more, promote only on confirmation.
3. `abstain`: never perform semantic replacement from this signal.
4. `independent_escalation`: ask a second verifier and promote only on confirmation.

## Strongest result: perfect repair provenance cannot rescue a wrong semantic correction

At low source-error prevalence (`src_err=0.10`), a single destructive correction is worse than doing nothing:
- `destructive_single`: endpoint accuracy **0.86375**, harmful replacement **0.11829**
- `abstain`: endpoint accuracy **0.90001**, harmful replacement **0**

So a provenance-perfect replay can still make the system worse if the diagnosis/correction gate has enough false positives. Repair admissibility and semantic correction validity must remain separate certificate axes.

A same-verifier provisional confirmation with high self-dependence (`same_copy=0.8`) only partly helps:
- endpoint accuracy **0.87785**
- harmful replacement **0.10168**

It is still worse than abstention in this low-error regime.

## Independent escalation helps only when it is actually independent

With `src_err=0.10` and low cross-verifier dependence (`rho_cross=0`):
- `independent_escalation` endpoint accuracy: **0.95536**
- harmful replacement: **0.01187**
- paired accuracy gain vs abstain: **+0.05535**, Monte Carlo 95% interval `[+0.05466,+0.05604]`
- correct endpoints / 100k modeled cost: **8194.3**, essentially tied with abstain's **8181.9** while giving higher endpoint accuracy.

With the same marginals but `rho_cross=0.9`:
- endpoint accuracy falls to **0.88558**
- harmful replacement rises to **0.09273**
- paired accuracy difference vs abstain becomes **-0.01503**, interval `[-0.01602,-0.01403]`
- correct endpoints / 100k modeled cost falls to **7278.8** versus abstain **8187.3**.

Thus “use a second verifier” is not a safe rule. The useful variable is the second verifier's **conditional residual error** relative to the first, not its label/model identity.

At higher source-error prevalence (`src_err=0.25`), low-correlation escalation is strongly useful:
- destructive: accuracy **0.83992**, harmful replacement **0.11531**
- abstain: accuracy **0.74959**
- independent escalation (`rho=0`): accuracy **0.90693**, harmful replacement **0.01167**, paired gain vs abstain **+0.15734**.

Even at `rho=0.9`, endpoint accuracy remains above destructive/abstain (**0.85570**), but the cost-efficiency proxy is below abstain (**6637.1** vs **6819.7** correct / 100k modeled cost). In a dense synthetic sweep at `src_err=0.25`, the independent-escalation vs abstain cost-efficiency sign changed between `rho_cross=0.65` and `0.675` under this particular cost model. This is **not** a real-world threshold; it is a counterexample showing that endpoint quality and compute-adjusted utility can favor different routes.

## Same-verifier repetition is not independent evidence

Holding all else fixed and sweeping the probability that the same verifier simply repeats its own approval:
- `src_err=0.10`, `same_copy=0`: provisional endpoint accuracy **0.9346**, harmful replacement **0.0352**
- `same_copy=0.50`: accuracy **~0.900**
- `same_copy=1`: accuracy **~0.864**, harmful replacement **~0.118**

So once the repeat is strongly coupled to the original diagnosis/candidate, “confirm twice” collapses toward one-shot destructive replacement. The key quantity is effective independent evidence, not confirmation count.

## Fresh public evidence

Three public sources independently support pieces of this separation, with bounded scope:

1. **The Self-Correction Illusion: Role Relabeling Gates Explicit Error Flagging in Large Language Models** (arXiv:2606.05976, 2026-06-04): holding an erroneous claim byte-identical and changing only its chat-template role increased explicit correction by **23–93 percentage points** across reported model/domain cells. The paper explicitly frames role relabeling as a diagnostic rather than a robust defense and notes that explicit correction is not identical to final-answer accuracy. This strengthens the need to separate “a model says this is wrong” from “a destructive state replacement is justified.”
   - https://arxiv.org/abs/2606.05976

2. **Judge, Retrieve, or Abstain: Uncertainty-Guarded LLM Judging with Provable Risk Guarantees** (arXiv:2608.17994, submitted 2026-08-18, accepted at COLM 2026): uses calibrated uncertainty thresholds, routes uncertain cases to a second retrieval-augmented mode, and abstains if uncertainty remains. Its formal target is FDR among accepted verdicts, not repair correctness, but the architectural implication is aligned: **uncertain judgments should route or abstain rather than be forced into irreversible action**. Reported experiments use four open-domain QA benchmarks with repeated calibration/test splits.
   - https://arxiv.org/abs/2608.17994

3. **Delayed Verification Destabilizes Multi-Agent LLM Belief: Instability Thresholds and Optimal Corrector Placement** (arXiv:2606.27409, 2026-06-25): models verifier delay and placement in multi-agent belief dynamics and reports that too-strong or too-delayed signed correction can destabilize consensus, while grounded factual correction is stabilizing in its tested setting. This is a consensus model, not state-repair evidence, but it reinforces that **verification timing/placement and grounding are control variables**, not afterthoughts.
   - https://arxiv.org/abs/2606.27409
   - public code/data: https://github.com/YehudaItkin/delayed-verification-llm

## Candidate controller refinement

The repair certificate should now be explicitly two-stage:

```text
A. semantic-correction gate
  diagnosis evidence
  candidate correction identity
  source-error prior / consequence of false replacement
  verifier calibration
  verifier-to-generator and verifier-to-verifier error dependence
  if risk low and evidence conditionally independent enough -> PROMOTE
  if candidate plausible but evidence correlated/insufficient -> PROVISIONAL/STANDBY
  if second mode has positive conditional residual value -> ESCALATE
  if uncertainty remains -> ABSTAIN

B. repair-admissibility gate
  history / identity / capture / dependency closure
  action binding / authority / effect state
  recorded-result replay vs provider redispatch
  attended serving/KV state
  -> LOCAL / ENLARGED / WHOLE_REDRAW / BLOCK
```

A pass at B must never upgrade a failed/uncertain A. Provenance proves what was changed and how to replay safely; it does not prove the replacement datum is true.

## Scope / negative evidence

- Every quantitative controller result in this checkpoint is synthetic.
- `rho_cross` is a deliberately simple mixture that copies the first confirmation verdict; it is **not** a measured correlation coefficient for any real model pair.
- The source-error prevalence, verifier rates, and replay cost are chosen mechanism parameters, not estimates from production.
- The same-verifier model intentionally represents self-confirmation dependence; it does not claim all repeated calls behave this way.
- The public papers above support externalization, abstention/routing, and timing/placement only in their own tested scopes. None validates this exact synthetic repair controller.
- “Independent verifier” must not be inferred from different model names. Conditional residual error must be measured.
- High endpoint accuracy does not imply best cost-adjusted utility, and vice versa.
