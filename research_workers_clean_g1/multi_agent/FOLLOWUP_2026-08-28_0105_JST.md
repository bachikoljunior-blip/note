## Main update — corrected explicit-channel witness constructor

The rejected singleton-transparency assumption from the predecessor is removed. I built and executed a deterministic event-level mechanism model with actual hash-linked receipt objects and separate evidence channels for:

1. **transaction-local trusted head** — a directly authenticated receiver/controller head for one live transaction;
2. **checkpoint-relative tail answer** — an authenticated, identity-bound checkpoint whose asserted head appears at its original sequence in the presented chain; an older checkpoint followed by a longer consistent chain is accepted as an extension rather than mislabeled truncation;
3. **anti-equivocation support** — transparency inclusion **plus** consistency proof **plus** current monitoring, with a detected conflicting head failing the axis; one inclusion receipt alone is insufficient;
4. **capture scope** — signed manifest, current capture epoch, topology digest, positive surface inventory, receiver/registry-chain completeness and explicit unregistered activity;
5. **dependency scope** — exact runtime read-version proof versus conservative static over-approximation;
6. **obligations/effects** — still-required results, prior authorization, in-flight progress, committed-effect receipts and external-effect ambiguity;
7. **attended state** — committed state digest plus fresh serving-session/cache rebind or equivalent epoch proof.

## New design boundary: whole redraw is not a universal fallback

The predecessor still allowed a coarse intuition that uncertain capture might fall back to whole redraw. This invocation makes the external-effect caveat explicit:

- if capture is incomplete/unknown but the uncovered surface is positively known to be effectless, whole redraw can remain a conservative visible-workflow recovery;
- if an unregistered/unknown surface **may carry external effects**, the router returns `BLOCK`, not whole redraw, because redrawing the visible workflow does not prove that an unseen external effect or consumed authority can be undone.

This is a design inference supported by claim separation, not a direct theorem of the receipt draft.

## Public-source sharpening

### SCITT AI-Agent Action Receipt draft-01 — 2026-08-15

Primary source:
`https://mirrors.aliyun.com/ietf/draft-noa-scitt-ai-agent-receipt-01.html`

The current draft explicitly states:
- tail truncation is detectable only **relative to an authenticated checkpoint**, never from the presented set alone;
- an older checkpoint whose head occurs at its original sequence in a longer presented chain is a consistent extension, not a conflict;
- a foreign/re-headed checkpoint requires identity-manifest binding to reject reliably;
- one Transparency Service inclusion proof establishes membership in one served log view, **not** offline non-equivocation; consistency proofs and monitoring are additionally required;
- a receipt does not prove capture completeness, pre-execution authorization, downstream success, or any physical effect.

This supports keeping `presented_chain_integrity`, `checkpoint-relative tail`, `anti-equivocation`, `authorization`, `effect observation`, and `capture completeness` as distinct axes.

### Exact execution-edit checking — arXiv:2608.22928, 2026-08-24

Primary source:
`https://arxiv.org/abs/2608.22928`

The exact execution-edit model reinforces that a safe Restore/Fork/Merge decision needs more than a syntactically valid history. The trusted runtime record must preserve still-required results, prior authorizations, which workflow calls/actions/authorization records correspond, and execution/call progress; an edit verdict can change after relevant progress even without a new authorization. This is why missing in-flight/effect/required-result evidence remains a `BLOCK` axis in the candidate witness rather than something a workflow redraw can silently erase.

## Scope / negative evidence

- The three-axis split policy is evaluated against labels defined by the same explicit safety model; it is a consistency/counterexample check, not an independent empirical validation.
- The live transaction-local trusted-head mode is a design hypothesis for a directly trusted receiver/controller boundary; SCITT does not define this recovery protocol and it does not establish global non-equivocation.
