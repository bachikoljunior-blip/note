## Updated controller hypothesis

A rollback controller should carry explicit proof state per dependency surface:
1. `proved_new_version`: runtime capture is known to cover the relevant read/version semantics; local closure is eligible.
2. `known_uncaptured`: a supported runtime warns that some node/surface was not captured; local closure is not sufficient and should fail closed to a larger scope unless another independent provenance source proves the missing closure.
3. `unknown`: control-flow or other semantics may matter but no capture proof exists; require conservative static/runtime complement or whole redraw rather than silently accepting the observed graph.
4. `overcaptured`: this can remain safety-eligible but should be charged for expected benign replay and may trigger a narrower validated complement if available.

Source-correction reliability remains a separate gate. This run intentionally did not combine verifier uncertainty with provenance uncertainty; destructive replacement should eventually require both a trustworthy correction and a sufficiently proved dependency closure.
