### Checkpoint corpus

The checkpoint corpus exercised 12 cases:

- no checkpoint -> `unanswered`;
- malformed / wrong-chain / unauthenticated checkpoint -> `unusable`;

- older checkpoint with a longer consistent chain -> `consistent-extension`;

- no identity manifest -> authenticated checkpoint is only `key-level`;

## New update — external-effect reconciliation prevents both unsafe redraw and unnecessary permanent blocking

The predecessor made `unknown effect-capable surface -> BLOCK` explicit. This invocation split that case further.

Seven deterministic effect-reconciliation cases compared a conservative repair policy with a naive `visible workflow can be redrawn -> WHOLE_REDRAW` fallback.

The conservative model permits a redraw only when an independent reconciliation path closes the external-effect ambiguity, for example:

- **replay recorded result**: same stable effect identity **and** same action binding;
- **explicit fork**: source is fenced and delegated/consumed authority is partitioned rather than duplicated;
- **compensation-proved**: compensation is both authorized and externally observed.

It blocks when:

- an unknown effect-capable surface has no reconciliation evidence;
- the same effect identifier is rebound to a different action;
- a fork does not partition authority;
- compensation is merely claimed without an observation.

Observed: **7/7 expected conservative routes matched**. The naive redraw policy was unsafe in **4/7** of these deliberately adversarial mechanism cases.

These counts are not empirical probabilities. The useful result is the contract distinction: `redraw local workflow` does not itself reconcile an already-possible external effect.

Public evidence supporting the decomposition, without proving this exact router:

- *When Can Agents Safely Checkpoint, Fork, Restore, and Merge?* (2026-08-24, arXiv:2608.22928) requires exact edit decisions to preserve still-required results, prior authorization/action linkage and call progress; an edit cannot undo a request already sent.
- *Cordon: Semantic Transactions for Tool-Using LLM Agents* (arXiv:2606.17573) binds result lineage, reversible local state, staged external effects and delegated authority inside a transaction boundary.
- *Robust Agent Compensation (RAC)* (arXiv:2605.03409) provides log-based deterministic compensation as a recovery path, but compensation is a forward recovery action rather than proof that history was literally undone.

## Public-source sharpening

SCITT draft-01 says:

- the six chain conditions are all properties of the presented set;
- the checkpoint question is exactly one of `answered / unanswered / unusable`;
- an older authenticated checkpoint can be consistently extended by a longer chain;
- unauthenticated or wrong-chain checkpoints are unusable and cannot create a chain failure;
- an identity manifest is needed to bind checkpoint authority to the genesis agent rather than merely to some trusted key;
- a single Transparency Service inclusion proof does not establish non-equivocation to an offline holder; consistency proofs and monitoring are additionally required;
- receipts do not prove capture completeness, prior authorization, downstream success or physical completion.

Primary source:
`https://mirrors.aliyun.com/ietf/draft-noa-scitt-ai-agent-receipt-01.html`

The current draft is an Internet-Draft, not a final RFC.
