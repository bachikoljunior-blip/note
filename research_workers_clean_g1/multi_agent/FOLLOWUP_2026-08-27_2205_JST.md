## Main update: explicit witness construction replaces the trusted completeness flag

The prior checkpoint still treated `positive_capture_completeness(module)` as a trusted premise. This run replaced that oracle-like flag with a finite, executable witness constructor over explicit observable axes:

```text
capture witness inputs
  capture_epoch_matches
  topology_digest_matches
  surface positively registered in current epoch
  receiver/transparency chain complete vs explicit gap
  runtime read-version capture = observed | known_uncaptured | unknown
  static potential dependency = complete_overapprox | partial | absent

capture witness output
  proved
  known_uncaptured
  unknown
```

The router then combines that dependency witness with separate obligation/effect/serving-state axes:

```text
required results known?
committed effect receipt present?
action equivalence known?
prior authorization safe?
in-flight call state safe?
serving attended state exact-rebind | cold-rebuild-available | unknown?
```

Routing is deliberately monotone in missing proof:
- precise runtime proof -> `local`;
- runtime gap/unknown but positively complete static over-approximation -> `enlarged`;
- stale epoch/topology or incomplete dependency scope with safe cold reconstruction -> `whole`;
- receiver/transparency omission, required-result ambiguity, committed-effect identity/authorization/in-flight ambiguity, missing effect receipt, or no attended-state repair witness -> `block`.

A receiver/transparency sequence gap is **not** treated as merely another missing dependency edge: it may hide an already-issued external action, so a static program graph cannot establish effect absence.

## New evidence boundary: integrity receipts still do not prove capture completeness

The current IETF draft `draft-noa-scitt-ai-agent-receipt-01` (published 2026-08-15) is useful because it states its claim narrowly: a receipt authenticates/tamper-protects what the issuer recorded at the governed boundary, but does **not** establish that recorded inputs were true or complete, that a downstream controller succeeded, or that a physical effect occurred. Registration in a Transparency Service also does not by itself provide offline non-equivocation without consistency monitoring.

Source: `https://www.ietf.org/archive/id/draft-noa-scitt-ai-agent-receipt-01.html`.

`Notarized Agents` moves receipt issuance to the receiver and a transparency log, which strengthens evidence against self-log tampering, but explicitly retains suppression and service-collusion limitations. Therefore a missing receiver receipt cannot be interpreted as proof that no action occurred.

Source: `https://arxiv.org/abs/2606.04193`.

This is why the witness constructor treats `receiver_chain_complete=false` as a blocking effect-uncertainty condition rather than allowing static dependency analysis to repair it.

The paper's 25/63 is not used as a general failure probability in the finite model.

## Static dependency evidence remains complementary, not a completeness oracle

`AgentFlow` statically reconstructs typed agent dependencies across five frameworks and 5,399 real-world agent programs. It is useful as a conservative potential-dependency source, but static analysis represents program-permitted architecture rather than a proof that every runtime dependency/effect was observed. Therefore the script gives `Static.COMPLETE` meaning only when a **positive over-approximation contract** is already established; high estimated recall is not silently upgraded to this state.

Source: `https://arxiv.org/abs/2607.01640`.

## Scope / negative evidence

- The 27,648-state enumeration is a finite logic/mechanism model, not a deployment distribution or empirical safety rate.
- `Static.COMPLETE` is still a strong premise: this run makes its role explicit but does not yet build a real static analyzer that proves completeness for dynamic wrappers/reflection.
- Receiver/transparency gap -> `block` is conservative; a production runtime could first reconcile/query the receiver/provider and then construct a new proof.
- The three public fixture ports preserve selected upstream assertions but do not execute the upstream checker. No claim of oracle equivalence is made.
- The serving/cache axis models `EXACT / COLD / UNKNOWN`; it does not prove that a hosted provider exposes cache/session epochs.
- The public SCITT and Notarized Agents sources are evidence-integrity protocols, not rollback correctness proofs.
