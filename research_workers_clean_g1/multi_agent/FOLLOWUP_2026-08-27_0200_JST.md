### Derived coverage bounds

Gate 1 alone hits `261/346 = 75.43%` of the seeded hallucination IDs. All three gates together hit `266/346 = 76.88%`. Therefore Gates 2 and 3 together add only **5 unique seeded IDs**, or **+1.45 percentage points** of seeded-ID discovery beyond Gate 1.

Because Gate 2 fires 179 times but at most 5 of those detections can be outside Gate 1's 261-ID set, at least `174/179 = 97.21%` of Gate-2 interventions are re-detections of IDs Gate 1 had already flagged. Likewise, at least `32/37 = 86.49%` of Gate-3 interventions overlap the Gate-1-detected set. Also, at least `174/261 = 66.67%` of Gate-1-detected seeded IDs are seen again one stage later at Gate 2.

These are lower bounds derived from the public aggregate counts, not a claim that every later-gate event is redundant. The later gates may also protect against endogenous downstream hallucinations not represented by the seeded-ID metric.

### Why repeated enforcement is needed in this implementation

The public code shows that the gate does not replace the pipeline state with a clean typed record. `rag_verify` appends a textual verification report to the same text: the wrong value remains present, followed by a `REFUTED` annotation, the correct value, and an instruction not to use the wrong value. The downstream Gemini agent then consumes that annotated text. Gate 2 and Gate 3 repeat the same reference-based check on the downstream outputs.

The artifact rows confirm the operational consequence: there are many cases where `g1_det=True` and `g2_det=True`. So the next agent can re-emit or re-derive a value that was already explicitly marked wrong at the previous boundary. In this benchmark, the downstream gates' dominant measured role is therefore **correction enforcement against reappearance**, not fresh seeded-error discovery.

This sharpens the previous rollback finding from the VAT artifact: verifier placement and rollback scope are not enough. The controller must also decide **how corrected state is represented at the handoff**.

## Updated controller hypothesis: canonicalization before repetition

The next matched-budget comparison should separate four mechanisms that are conflated by ordinary "verify at every boundary" language:

1. **Annotation-only repeated gates** — current Snowball mechanism: preserve bad text, append refutation/correction, rely on downstream compliance, and re-check later.
2. **Hard canonicalization** — when a source field is refuted, remove/invalidate the bad field and hand the next agent a clean canonical field/value plus provenance, rather than the bad value plus an instruction.
3. **Source-local invalidation + descendant recomputation** — invalidate the causal source record and every descendant that consumed it, then recompute from that boundary.
4. **Terminal-only repair** — preserve upstream state and regenerate only the final synthesizer/output.

At matched model-call/retrieval budget, score:
- endpoint accuracy / task reward;
- seeded-error survival;
- correct-source restoration rate;
- **unique-new-catch rate** versus **repeat-enforcement rate**;
- validated-wrong rate;
- extra tokens, latency and verifier cost;
- false-positive / unnecessary-rewrite rate;
- source-correction rate and recomputation scope.

Provisional controller rule: a downstream gate should not be valued only by unique new catches. Its value is `new-discovery value + enforcement value against prior-correction noncompliance + endogenous-error value - verification/rewrite/opportunity cost`. If hard canonicalization materially lowers repeat-enforcement demand, later gates can become selective rather than universal without sacrificing robustness.

## Scope guard

- This does **not** show later gates are generally useless. Here they mostly enforce earlier corrections, and they may also catch endogenous errors that the seeded-ID audit does not count.
- The `+1.45 pp` figure is only additional coverage of the seeded hallucination IDs in this FinanceBench artifact.
- The low false-positive count is specific to the privileged deterministic numeric gate and should not be transferred to open-domain semantic verification.
- The public experiment uses the same three downstream Gemini-2.5-flash calls for vanilla, end-check and boundary-gated methods; the RAG gate itself is zero API calls. This makes placement unusually cheap compared with systems that use an LLM verifier.
- Suppression without restoration is evidence against using "hallucination removed" as the sole success metric, not proof that the final answer is wrong in every such case.
