## Updated mechanism conclusion

The earlier lower bound can now be replaced by an exact statement for this released artifact: **later boundary gates mostly pay to re-detect a known source error because the error remains materially present in state.** Gate3 contributes no new injected-hallucination coverage at all in this run, although it can still block a downstream agent from reusing a known bad value.

This sharpens the candidate controller design:
1. verify at a boundary;
2. if evidence is sufficiently reliable, mutate a canonical typed datum rather than retain `bad value + warning` in the semantic payload;
3. preserve the original/refutation as provenance outside the active value field;
4. invalidate only descendants that actually consumed the superseded datum;
5. re-execute that dependency closure;
6. reserve later repeated verification for newly derived facts or uncertain replacements, not for repeatedly policing a datum already known to be bad.

The central unresolved risk remains verifier error: hard canonical replacement can be worse than annotation-only correction if the verifier is correlated with the source or falsely refutes a correct value. Replacement therefore needs confidence/independence calibration and reversible provenance.
