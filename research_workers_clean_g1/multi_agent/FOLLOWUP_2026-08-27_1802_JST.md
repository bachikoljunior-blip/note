## Main update: positive completeness proof changes the safety/cost frontier more than high-but-incomplete recall

The prior checkpoint separated dependency surfaces into `proved_new_version`, `overcaptured`, `known_uncaptured`, and `unknown`. This run expanded that mechanism model into deterministic 24-node DAGs and compared four rollback policies under the same replay-call accounting:

1. `local`: replay only runtime-observed descendants.
2. `union`: replay descendants in `runtime ∪ static-complement`.
3. `proof_router`: local replay when the affected component has no risky dependency surface; if risky surfaces exist, use the union only when the static complement carries a positive completeness contract, otherwise fail closed to whole redraw.
4. `always_whole`: redraw every post-source node.

The synthetic generator used SHA-256-derived deterministic seeds, 2,500 DAGs per condition, runtime risky-edge recall 0.40 for `known_uncaptured/unknown`, exact runtime capture for `proved/overcaptured`, and separate static-complement true-edge recall / false-positive sweeps. Interpretation:
- high-but-incomplete static recall can look extremely attractive on average: at 0.95 recall / 0.02 FP, optimistic union reaches ~8,048 correct endpoints / 100k cost, but it accepts a 4.8% stale-run rate;
- a positive-proof-only router refuses that silent risk and stays at 100% recovery in the model, while still saving ~14.8% replay cost versus whole redraw by using local closure on affected components whose dependency surfaces are already proved;
- once the static complement is positively complete, conservative union becomes both safe and much cheaper than whole redraw; the proof router reaches ~8,429 correct endpoints / 100k cost, about 2.0× whole-redraw throughput in this synthetic setup;
- static false positives are mainly a blast-radius/cost variable when true coverage is complete: increasing FP from 0.02 to 0.30 keeps recovery at 1.0 but reduces preserved independent work and raises replay cost.

The strongest mechanism point is therefore not “95% recall is enough” or any numerical threshold. It is that **probabilistic high recall and a positive completeness contract are qualitatively different control states**. A safety-critical local rollback policy should not convert an estimated 95–99% edge recall directly into a proof of complete descendant repair.

## External primary evidence: dependency-guided rollback is effective, but it explicitly presupposes complete enough runtime provenance

A fresh public source was added:

- Caili Yu et al., *From Faulty Memories to Corrected Actions: Dependency-Guided Rollback Repair for Memory-Augmented Agents*, arXiv:2608.10502v1, 2026-08-11. https://arxiv.org/abs/2608.10502

The paper builds a typed memory-to-action graph from runtime-emitted provenance, traces affected descendants, checks independent trusted support, applies a deterministic rollback planner, and selectively replays answer-relevant affected computation. On its 150-case controlled benchmark it reports 85.3% recovery versus 77.3% for the strongest competing recovery baseline, while removing all diagnosed faulty memories and preserving all benign memories. On a 50-case adapted LongMemEval-V2 subset it reports 68.0% recovery versus 54.0% for the next best method.

The ablation is especially relevant to the current controller question:
- removing the rollback planner: recovery `0.853 → 0.713`, recurrence `0.266 → 0.430`, LLM calls `5.70 → 9.19`;
- removing independent support checking: recovery rises slightly `0.853 → 0.880`, but benign preservation falls `1.000 → 0.986`, replay ratio rises `0.123 → 0.154`, and LLM calls rise `5.70 → 6.51`;
- removing selective replay: recovery changes only `0.853 → 0.840`, but replay ratio explodes `0.123 → 0.755` and LLM calls `5.70 → 24.01`.

This directly supports the architectural separation suggested by the synthetic mechanism study: planning / support preservation / replay-scope control have different jobs and should not be collapsed into one scalar score.

Crucially, the same paper states that its dependency graph is instantiated deterministically from provenance emitted by an instrumented runtime, and that inferring missing support/lifecycle edges from raw logs is outside scope. It explicitly warns that incomplete provenance can under-trace contamination while spurious edges can cause unnecessary invalidation. Therefore the paper supports selective rollback when provenance is adequate; it does **not** establish that local rollback is safe under silent capture gaps.

## Updated controller hypothesis

Treat rollback authorization as a two-axis proof problem:

1. **Correction proof**: is the source replacement itself sufficiently trustworthy and independently supported?
2. **Closure proof**: is every dependency surface that could carry the old source version either positively captured or conservatively covered by a declared-complete complement?

Then route:
- `proved closure` -> local replay;
- `overcaptured but complete` -> local/union replay, charging benign over-replay as cost;
- `known_uncaptured` -> require an independent complete complement or enlarge scope;
- `unknown` without positive surface-completeness proof -> do not interpret absence of edges as safety; fail closed toward a larger closure or whole redraw.

This run intentionally did not reintroduce source-verifier noise/correlation. Provenance routing was isolated first, per the predecessor continuation.

## Scope guards / negative evidence

- All DAG results are synthetic and parameter-dependent. Percentages above are not deployment thresholds.
- `proof_router` is given a correct proof-state flag for whether the static complement is actually complete; real systems must establish that contract independently rather than infer it from empirical recall alone.
- The static false-positive generator adds conservative dependencies uniformly; real overcapture can be structured and more expensive.
- The public rollback paper assumes an instrumented runtime and an upstream diagnosed faulty-memory set. It does not solve fault diagnosis or missing provenance inference.
- The public paper also notes that rollback cannot undo irreversible external side effects without resettable interfaces or domain-specific compensation.
- The reported arXiv results are paper-reported, not independently reproduced in this run.
