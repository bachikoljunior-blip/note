## Main update: edge recall is not descendant-closure recall

Added `research_workers_clean_g1/multi_agent/SYNTHETIC_TWO_LAYER_PROVENANCE_2026-08-27_0705.py`.

The predecessor's recovery harness dropped destructive provenance only at a limited boundary and gave the static fallback perfect true-edge recall. The new harness drops runtime-observed edges independently at **every true DAG edge**, then builds a second static/potential-dependency map with independently controlled true-edge recall and false-positive rate. It measures:
- true edge recall,
- transitive descendant-set recall/precision from the corrected source,
- stale old-version descendants after replay,
- endpoint correctness,
- replay fraction/call cost,
- correct endpoints per 100k normalized evaluator calls.

The useful mechanism is not a universal numeric threshold. It is the **reachability amplification**: an 85% true-edge capture rate produced only ~74.7% descendant-set recall in this multi-hop graph; 95% edge capture still produced only ~91.3% descendant recall. A destructive recovery controller therefore cannot price safety from edge-level instrumentation coverage alone. It needs closure-level coverage or an explicit conservative fallback.

The static layer helped materially when its errors were sufficiently complementary to runtime capture. At observed/static controls `0.85/0.90`, union descendant recall rose to ~0.961 and stale-run rate fell from ~0.261 to ~0.075, but whole redraw still had higher correctness per call because ~4% of true descendants remained outside the union closure. With perfect static true-edge recall, union replay eliminated stale descendants and could preserve a small amount of independent work.

## Post-replay proof/escalation: useful only if residual misses are already rare

A synthetic `assert_fail_closed` path replays a proposed local/union closure, then detects stale descendants with configurable assertion recall and escalates to whole redraw on detection. The assertion is deliberately a parameterized diagnostic; it is not claimed to be available as an oracle in real systems.

With **observed-only** closure, the late assertion often paid twice: at observed recall `0.95` and assertion recall `1.0`, endpoint accuracy was `0.6676`, but mean calls rose to `15.6542` and correct endpoints/100k calls fell to `4264.7`, versus whole redraw's `0.6658`, `14.9196` calls, and `4462.6/100k` in that diagnostic run. So `local first -> discover incompleteness -> redraw everything` can be worse than redrawing immediately.

When the **observed+static union was already ~99.3% descendant-complete** in a separate 10,000-seed diagnostic (`observed=0.95`, `static=0.90`, `FP=0.05`), a perfect-coverage post-check escalated only ~1.27% of runs and reached essentially whole-redraw endpoint accuracy with slightly lower mean calls (`14.8527` vs `14.9361`). This is promising only as a mechanism: a real controller would need a non-oracular proof or conservative incompleteness signal, and the small efficiency gap requires replication under richer graphs/costs.

The design implication is to prefer **pre-replay closure-confidence gating** where possible: if instrumentation cannot establish a sufficiently complete closure, enlarge or redraw before spending a partial replay. A post-replay assertion is most attractive as a last safety net after a high-recall union closure, not as the primary way to discover grossly incomplete provenance.

## Public implementation audit: Auditable exposes concrete FP and FN modes

The public `yzhao062/auditable` LangGraph adapter was inspected as an implementation baseline. Current source makes the provenance tradeoff unusually explicit:

- Keyed mapping access (`state["x"]`, `.get`) records channel-specific reads and read-time deep-copy snapshots.
- Whole-state iteration/copy (`for key in state`, `keys/values/items`, `dict(state)`, `**state`) records **every channel** and marks those reads `overcaptured`. This is a concrete false-positive/closure-expansion mode rather than silently pretending channel precision.
- Runnable nodes are passed through uncaptured; the integration test requires `to_steps()` to warn that the dependency graph is incomplete.
- Routing-condition reads from conditional edges / `Command.goto` are not captured in the current adapter round.
- Dataclass/Pydantic state schemas are rejected because attribute-style state access is not captured; mapping/TypedDict state is the supported capture surface.
- Same-superstep parallel writers are intentionally not fabricated as dependencies; reducer channels fan in to prior committed writers.

Primary public implementation paths:
- `https://github.com/yzhao062/auditable/blob/main/src/auditable/integrations/langgraph.py`
- `https://github.com/yzhao062/auditable/blob/main/tests/test_langgraph_integration.py`
- `https://github.com/yzhao062/auditable/blob/main/docs/realtime-replay.md`

This materially strengthens the two-layer controller hypothesis: **runtime-observed provenance must carry coverage/overcapture metadata**, because real adapters can know that some paths are overcaptured and can know that other execution surfaces were not captured. A static/potential map is valuable as a conservative complement, but its own recall and FP rate must be calibrated independently.

## Updated recovery-controller candidate

The candidate now has four distinct uncertainty quantities instead of one generic "dependency confidence":

1. semantic correction reliability / verifier-source error independence;
2. runtime observed-edge coverage and known capture blind spots;
3. static/potential-dependency true-edge recall;
4. static/potential-dependency false-positive expansion cost.

A concrete decision skeleton is:

`verify correction -> estimate observed closure recall + capture blind spots -> estimate static-map complement recall/FP -> choose observed-only | union-enlarged | whole redraw -> replay -> stale-version/proof check -> fail-closed escalation if proof is insufficient -> endpoint validation`.

The controller should optimize **descendant-set safety and correct-endpoint throughput**, not raw edge accuracy. Because reachability compounds misses, a graph with apparently high per-edge recall can still be unsafe for destructive invalidation.

## Scope guards / negative evidence

- Numeric results are synthetic and do not establish production thresholds such as "95% observed recall is enough".
- Static edges were sampled independently from true edges/nonedges; real static inference errors will be structured and correlated with runtime blind spots.
- The toy graph has one independent branch. False positives in larger heterogeneous DAGs can consume much more independent work.
- The assertion experiment parameterizes stale-detection recall. It is not evidence that a real runtime can observe the true stale set after missing the original dependency edge.
- Auditable is implementation evidence for capture semantics and known adapter limitations; no benchmark number from its repository was imported in this invocation.
- No claim is made that an observed+static union is always preferable. If the union still misses true descendants, whole redraw remains the safe reference in this toy.
