## New recovery-semantics distinction from current provider/runtime documentation
The public evidence supports separating at least four mechanisms rather than labeling them all `idempotent` or `replay-safe`:

1. **Recorded-result replay**: reconstructs an observation without necessarily reproducing the physical effect.
2. **At-least-once retry**: can re-execute a side effect; safe use therefore depends on an idempotency/fencing contract.
3. **At-most-once retry**: refuses ambiguous re-execution and surfaces interruption/unknown state instead of creating a second attempt.
4. **Compensation**: application-specific semantic undo; it can fail and may not restore the exact original state.

Azure's Compensating Transaction pattern explicitly says compensation is application-specific, may fail, should itself be resumable/idempotent where possible, and cannot always restore the world exactly. AWS Durable Execution documentation distinguishes default at-least-once retry from an at-most-once mode that waits for a durable start checkpoint and surfaces interruption rather than re-executing an ambiguous step.

Stripe also makes the idempotency contract provider/API-version specific rather than timeless. Its API v1 documentation preserves and replays the first result for a key and permits pruning after at least 24 hours; a reused key after pruning can become a new request. API v2 documents a different scope/window, including API/account or sandbox binding and a 30-day window. The IETF HTTPAPI Idempotency-Key draft describes a generic key/fingerprint/expiry contract but is currently expired, so it is not a universal active standard that can substitute for provider-specific evidence.

## New exhaustive two-provider mechanism lattice
A reproducible finite lattice was constructed for two effect-capable providers. Each provider exposes four observable dimensions:
- current live effect evidence: `PRESENT / ABSENT / UNKNOWN`
- recorded historical result: `SUCCESS / NO_EFFECT / UNKNOWN`
- same-intent retry fence available: boolean
- compensation available: boolean

This gives 36 observable states per provider and 1,296 two-provider observable combinations. Hidden worlds additionally vary actual effect presence whenever the live state is `UNKNOWN` and whether an attempted compensation succeeds, yielding 9,216 compatible latent worlds under the deliberately balanced lattice.

Four policy mechanisms were compared:
- `proof_gated`: terminal forward only when both current effects are proven present; terminal rollback only when both are proven absent. Partial/unknown vectors remain pending/reconcile/block until post-action proof.
- `trust_record`: substitutes a recorded success for unknown current physical effect state and terminalizes from that inference.
- `blind_retry`: retries every provider not currently proven present, assuming the retry will complete the forward vector; unfenced hidden prior success can duplicate an effect.
- `blind_compensate`: attempts rollback from recorded/current evidence and compensation capability, then terminalizes even though compensation success is hidden.

Results across the finite lattice:
- `proof_gated`: 1,152 terminal admissions; **0 unsafe terminal worlds**.
- `trust_record`: 4,736 terminal admissions; 2,112 unsafe (`44.59%` of its terminal admissions in this lattice).
- `blind_retry`: 9,216 terminal admissions; 2,160 unsafe (`23.44%`).
- `blind_compensate`: 5,776 terminal admissions; 3,072 unsafe (`53.19%`).

These percentages are **not** real-world incident rates or provider reliability estimates. They are deterministic proportions under a deliberately balanced mechanism grid whose purpose is to expose failure modes.

A separate terminal-admission monotonicity check removed one live-state proof or one retry/compensation capability at a time. Across 4,320 one-step evidence/capability removals, the proof-gated policy had **0 cases where weaker evidence created a new terminal admission**. This is a narrowly defined terminal-admission property, not a proof that every nonterminal routing choice is globally monotone.

## Controller refinement
The external-effect portion of repair admissibility should preserve separate evidence objects for each provider/action:
- `observation_replayability`: can a prior response be returned without dispatch?
- `physical_effect_currentness`: is the intended external mutation currently present, absent, or unknown?
- `retry_fence`: if dispatch is repeated, what exact provider contract prevents a second effect?
- `retry_fence_scope`: provider, API surface/version, account/sandbox, idempotency key, request fingerprint, and retention/expiry window.
- `compensation_state`: available / attempted / proven-success / failed / unknown.
- `irreversibility`: whether semantic undo is available at all.

These fields are non-substitutable. In particular, a recorded success is not current-effect proof; compensation capability is not compensation success; and an idempotency key is not a timeless fence after its provider-defined scope/window expires.

For a multi-provider workflow, terminal forward should require a consistent vector of proven-present intended effects. Terminal rollback should require a consistent vector of proven-absent or proven-compensated effects. Mixed or unknown vectors stay `PENDING_RECONCILE`, `PENDING_COMPENSATE`, `BLOCK`, or manual escalation depending on available contracts and impact. This is a mechanism-level controller hypothesis, not a deployment-complete protocol.

## Scope discipline
- The 1,296/9,216 lattice is synthetic and deliberately balanced; it cannot estimate production failure prevalence.
- Only two providers and binary effect presence are modeled. Amounts, partial writes, causally dependent effects, asynchronous settlement, duplicate-but-equivalent objects, provider outages, and compensation ordering are not yet modeled.
- `fenced=true` is an abstract contract in this experiment. The public docs show that real fences have provider/API/account/payload/time scope, which must be modeled explicitly next.
- Compensation is represented by a hidden success bit, not by a realistic saga dependency graph.
- The proof-gated 0 unsafe result is exact only for the enumerated safety predicate and state lattice.
- The SymFail external-state observation is a scope limitation on replay guarantees, not a claim that its published native metric is invalid.
