## Strongest empirical result: model-name diversity did not create residual evidence on the base-judge failures

Across all 100 items:
- GPT-4o-mini r1 close accuracy: **0.57**, MAE **5.94**
- GPT-4.1-mini r1 close accuracy: **0.52**, MAE **7.05**
- error-indicator correlation between GPT-4o-mini r1 and GPT-4.1-mini r1: **phi = 0.9040**
- GPT-4o-mini r1 was wrong on **43/100** items under the <=5 definition
- among those 43 base-judge failures, GPT-4.1-mini was correct on **0/43**: `P(B correct | A wrong) = 0`
- when GPT-4o-mini r1 was correct, GPT-4.1-mini was also correct with probability **0.9123**

So in this corpus, a different model identity is not an independent correction channel for the failure class that matters. The relevant quantity is empirically measured conditional residual value, not heterogeneous model count.

Ground-truth stratification explains the shared failure mode:
- expert score 90, n=52: both models have close accuracy **1.00**
- expert score 80, n=47: GPT-4o-mini close accuracy **0.1064**, GPT-4.1-mini **0.00**; MAE **10.32** vs **12.55**
- expert score 70, n=1: both are wrong by 20 points

This is a strong class-conditional systematic bias in this narrow corpus, not a claim about the models in general.

## Same-verifier repetition is even more dependent

Five GPT-4o-mini runs give close accuracies `[0.57, 0.57, 0.56, 0.58, 0.56]`.

Across the ten run-pairs, error-indicator phi is:
- mean **0.9473**
- min **0.9192**
- max **0.9799**

Conditioned on GPT-4o-mini r1 being wrong:
- r2 is correct only **2.33%** of the time
- all four later repeats are also wrong in **93.02%** of cases
- at least one later repeat becomes correct in only **6.98%**

There are **72/100** items where all five GPT-4o-mini scores are identical. **31/72 (43.06%)** of those perfectly stable items are still wrong under the <=5 criterion. This directly rejects `stable == trustworthy` for this dataset.

Aggregation did not rescue the judge:
- A1 alone: MAE **5.94**, close accuracy **0.57**
- mean of five A runs: MAE **6.074**, close accuracy **0.54**
- median of five A runs: MAE **5.99**, close accuracy **0.57**

- A2 minus A1 MAE delta: **+0.11**, 95% interval `[-0.16, +0.40]`
- B1 minus A1 MAE delta: **+1.11**, 95% interval `[+0.42, +1.80]`

## Held-out calibration pilot: the correct action can be “do not spend the extra judge call”

I used a deterministic split based only on `SHA256('multi_agent_laj_v1:'+jira_id)`:
- calibration: **61** items
- held out: **39** items

Candidate one-step actions were:
1. keep GPT-4o-mini r1;
2. spend one same-verifier call and average A1+A2;
3. spend one heterogeneous call and replace with GPT-4.1-mini r1.

The only routing feature was the already-observed A1 score bin (`<=85`, `86-90`, `>90`). No held-out expert labels were used to choose the action.

When calibration optimized the binary close-accuracy objective, every bin chose **keep A1**. On held-out data:
- A1 baseline close accuracy: **0.6154**
- same-repeat mean2: **0.5897**
- switch-all-to-B1: **0.5128**
- calibrated router: **0.6154**, with **0 extra calls**

When calibration optimized MAE instead, it selected B1 for `A1<=85` and `A1>90`, but on held-out data the routed MAE was **5.3846**, exactly the baseline A1 MAE, while spending **12 extra calls**. Thus a calibration objective can preserve endpoint MAE while still wasting compute, and optimizing MAE can disagree with thresholded correctness.

## Controller refinement

The semantic-correction gate should estimate a class-conditional joint error object rather than a scalar correlation:

```text
for candidate verifier B given current verifier A:
  estimate P(B wrong | A wrong, observable slice)
  estimate P(B helpful | A wrong, observable slice)
  estimate P(B harmful | A correct, observable slice)
  estimate same-verifier repeat residual value separately
  keep endpoint objective and extra-call cost explicit

if calibrated residual value <= opportunity cost:
  ABSTAIN / KEEP CURRENT
elif residual value is positive but evidence is weak:
  PROVISIONAL / targeted escalation
else:
  ESCALATE to B
```

Different model names, repeated calls, and raw agreement counts are not substitutes for those conditional quantities.

## Scope / negative evidence

- GPT-4.1-mini run 1 is used as the heterogeneous comparator in this checkpoint; this does not characterize every possible model pair or prompting scheme.
- The <=5 threshold is a local analysis convention. MAE and close accuracy give different routing preferences.

- Same-verifier repeat dependence here is empirical for these published five runs, not a universal repeat-correlation constant.
- No O, other worker, downstream, legacy/pre-independence state, or shared aggregate ledger was used.
