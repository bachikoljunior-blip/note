## Public evidence update: static and runtime provenance fail differently

Two public results sharpen the proof-contract model.

1. **AgentFlow: Building Agent Dependency Graphs for Static Analysis of Agent Programs** (arXiv:2607.01640, 2026-07-02) explicitly treats agent static analysis as an **over-approximation** of execution permitted by program architecture because LLM-dependent execution is probabilistic. It models explicit handoffs, messages/shared state, tool calls and dynamic routing constructs that enumerate possible next agents. In a manual audit, 9 of 100 non-reported privileged-capability agents contained missed risks, mainly from custom command wrappers, dynamic tool binding/custom orchestration, LangGraph-specific state/tool bindings and custom multi-tool wrappers. Among 27 sampled reported false positives, 25 still had valid taint-propagation paths; the error was mainly sink semantics rather than nonexistent dependency paths. The paper itself recommends hybrid static/dynamic analysis.
   - Primary: https://arxiv.org/abs/2607.01640
   - Readable full text used for the manual-audit/limitation details: https://academ.us/article/2607.01640/

2. **From Faulty Memories to Corrected Actions: Dependency-Guided Rollback Repair for Memory-Augmented Agents** (arXiv:2608.10502, 2026-08-11) builds its rollback graph deterministically from runtime-emitted provenance and explicitly states that incomplete provenance can under-trace contamination while spurious edges cause unnecessary invalidation. On its 150-case controlled benchmark the full method reports 85.3% recovery. Removing the rollback planner drops recovery to 71.3%; removing selective replay expands replay ratio from 12.3% to 75.5% and LLM calls from 5.70 to 24.01 while recovery is 84.0%.
   - Primary: https://arxiv.org/abs/2608.10502

These sources support a division of labor rather than a single dependency score: runtime provenance is the best concrete-execution evidence when captured; static analysis is useful as a conservative architecture-level complement, but can overcapture and can still miss custom/dynamic framework escape hatches.

## New deterministic mechanism study: class-specific proof contracts beat one global recall threshold

I expanded the prior six-case proof-state idea into 3,000 deterministic mixed DAGs per condition. Each DAG contains a faulty-source component plus independent work. SHA-256 controls every pseudo-random choice. The affected component mixes five dependency surfaces:

- `handoff`
- `reducer`
- `shared_memory`
- `conditional_routing`
- `dynamic_tool`

This is a **synthetic mechanism study**, not an estimate of any real framework's capture rates. By construction, handoff/reducer/shared-memory true edges are runtime-complete; shared memory can overcapture independent work. Runtime capture of risky synthetic edges is set to 0.55 for conditional routing and 0.65 for dynamic tool edges. Static false-positive edges are added only as conservative extra dependencies to independent work.

Three static-complement profiles were compared:

- `uniform_97`: conditional-routing and dynamic-tool true edges each captured with probability 0.97.
- `enumerated_route_dynamic_gap`: conditional routing is complete (1.0) while dynamic tool/custom-style edges are incomplete (0.75).
- `complete`: both risky classes are complete (1.0).

Policies:

- `local`: runtime-observed closure only.
- `union`: runtime ∪ static closure.
- `scalar97`: trust the union when the global average risky-class static recall is at least 0.97.
- `global_strict`: any risky graph goes broad unless *all risky classes globally* have complete static coverage.
- `classaware_strict`: only the risky classes actually present in the affected program component must have complete static coverage; otherwise fail closed to whole redraw.
- `whole`: replay all materialized work.

Reproducible script: `research_workers_clean_g1/multi_agent/SYNTHETIC_CLASS_PROOF_ROUTER_2026-08-27_1304.py`.

The key result is not the synthetic numeric threshold. It is the structural separation:

- trusting a high **global average recall** (`uniform_97`) buys throughput by silently accepting about 3.1% unrecovered cases in this model;
- a globally strict rule is safe but can redraw work even when the actual affected component only uses a class with a complete proof contract;
- a **class-aware strict rule** can preserve 100% synthetic recovery while avoiding some broad redraw when the present dependency class is individually proved complete.

Under the `enumerated_route_dynamic_gap` profile, conditional-routing-only cases are the clean example: class-aware strict achieves 100% recovery with mean cost 20.23 and about 4,944 correct endpoints/100k cost, versus global strict whole-style replay at mean cost 24.65 and about 4,056/100k. Cases containing `dynamic_tool` correctly fall back broad because that class is not complete in the synthetic contract.

## Updated controller hypothesis

Do not compress rollback provenance to one F1, one average recall, or even one “static quality” scalar. Carry a **proof contract per dependency surface**:

1. `proved_new_version`: exact runtime version/read capture is complete for that surface; local closure is eligible.
2. `overcaptured`: safety-complete but broad; local/union remains eligible while charging benign replay.
3. `known_uncaptured`: runtime explicitly says capture is incomplete; require a separate dependency source with a completeness contract for this surface or fail closed broader.
4. `unknown`: no completeness claim is available; high empirical average recall is not enough for destructive local replay.
5. `static_complete(surface)`: static complement has a complete contract for this specific framework construct. This can safely enlarge runtime closure for that class even if other classes remain unproved.

The resulting router should choose rollback scope from the **set of dependency surfaces actually reachable in the affected program component**, not from a global average graph metric. A high-recall but incomplete surface should remain a measured-risk optimization, not be mislabeled as proved safe.

## Scope guards / negative evidence

- All capture probabilities in the synthetic DAG study are invented mechanism parameters. They are **not** measured AgentFlow, LangGraph, or production rates.
- The study assumes the program can inventory which dependency-surface classes may occur in the affected component. That assumption itself can fail under reflection, custom wrappers, runtime-generated tools, or unmodeled orchestration; AgentFlow's manual misses make this an important next target.
- `correct endpoint` here means the replay set contains all ground-truth synthetic descendants. It does not model stochastic semantic regeneration quality.
- No source-verifier diagnosis error or replacement-value error is included.
- No irreversible external side effects are modeled; real rollback requires resettable/compensating interfaces.
- A scalar-97 rule is intentionally an unsafe empirical-threshold comparator, not a recommended policy.
- The public rollback paper assumes instrumented runtime provenance and explicitly does not infer missing support/lifecycle edges from raw logs.
