## Main update: event-level repair witness instead of trusted completeness booleans

The prior checkpoint still left some proof states as trusted booleans. I replaced the top-level rollback decision in a synthetic mechanism study with explicit event-level categories for:

- live transaction receiver-head claim vs offline/global checkpoint/transparency claim;
- receipt artifact validity and presented-chain consistency;
- capture manifest epoch and topology digest;
- surface inventory: complete / known uncaptured effectless / known uncaptured effect-capable / unknown;
- runtime dependency proof vs conservative static over-approximation;
- action binding, current authorization, external-effect state, and attended serving/KV state.

The route lattice is `LOCAL < ENLARGED < WHOLE_REDRAW < BLOCK`. It is intentionally positive-proof based: missing evidence never upgrades a route, global-history evidence never substitutes for a mismatching live receiver head, and live receiver-head evidence never upgrades an offline/global history claim.

Results over those 23 hand-specified expected routes:

- `event_witness`: **23/23 exact matches; 0 unsafe; 0 over-conservative**;
- `naive_no_warning`: 9 exact, **14 unsafe**, 0 over-conservative;
- `global_everywhere`: 20 exact, **2 unsafe**, 1 over-conservative.

The surprising failure is `global_everywhere`: requiring checkpoint/transparency everywhere is not only wasteful. If implementation logic lets a healthy global proof substitute for a **mismatching live receiver head**, it can admit a live repair that the current transaction evidence says is stale. Conversely, in a healthy live transaction with a directly trusted matching receiver head, lack of global transparency should not automatically block the transaction-local claim.

These are **structural test counts, not probabilities or deployment incident rates**. The expected routes are part of the synthetic mechanism specification, so 23/23 is a conformance/self-consistency result, not empirical validation.

## Public-source sharpening

### SCITT receipt/history claims remain deliberately narrow

SCITT AI-Agent Action Receipt draft-01 (2026-08-15) now states explicitly that:

- a presented hash chain detects in-band tampering but **tail truncation only relative to an authenticated checkpoint**, never from the presented set alone;
- one transparency inclusion proof does **not** prove non-equivocation; that needs consistency proofs plus monitoring;
- checkpoint claims are opener-scoped in multi-agent chains, and the checkpoint object itself does not bind tenant, issuer, agent set, genesis hash, or manifest version;
- a receipt with `governance.verdict == EXECUTED` records dispatch/attempt at the governed boundary, **not controller success or a physical effect**;
- digest equality is correlation only, not authorization or effect attestation.

Primary source:
`https://mirrors.aliyun.com/ietf/draft-noa-scitt-ai-agent-receipt-01.html`

These clauses directly motivate keeping `live_receiver_head`, `checkpoint/tail`, `anti-equivocation`, `identity/manifest freshness`, `action binding`, and `physical effect` as separate axes rather than one `receipt_ok` bit.

### Exact execution-edit safety still requires past authority/progress/results

`When Can Agents Safely Checkpoint, Fork, Restore, and Merge? Exact Checking for Execution Edits` (submitted 2026-08-24) states that an execution edit cannot undo an authorization already granted or a tool request already sent; unsafe edits can double-authorize actions, lose still-required results, or conflict with calls that started before the edit. The checker therefore needs the execution record, required results and prior call/authorization state, not just a dependency graph.

Primary source:
`https://arxiv.org/abs/2608.22928`

### Attended serving state remains an independent rollback axis

`Aborted but Not Forgotten: KV-Cache Retention Breaks Rollback Consistency in Language Agents` (2026-08-16) holds decision-step tokens fixed while varying only retained vs rebuilt KV state. Stale retained KV flips a protected decision in 25/63 audited cells; rebuilding from committed state closes every audited cell. A logically correct workflow rollback therefore does not imply the model is attending to the rolled-back state.

Primary source:
`https://arxiv.org/abs/2608.15939`

## Scope / negative evidence

- The 23-case corpus and monotonicity fuzz are synthetic mechanism tests, not production measurements.
- Positive evidence is assumed truthful. Forged receipts, colluding signers/logs, buggy identity resolvers, or hidden unmediated channels that falsely produce a completeness claim remain outside the synthetic soundness envelope.
- `WHOLE_REDRAW` is permitted only when the model positively knows unresolved surfaces are effectless or all effects are safely replayable/reconciled. An unknown effect-capable surface remains `BLOCK` even if the visible workflow can be redrawn.
- The SCITT/AADP/NOA documents are Internet-Drafts/work in progress; they sharpen evidence boundaries but do not certify a deployment.
- The execution-edit and KV results are public-source evidence from their stated tested settings; they do not prove the synthetic router itself.
