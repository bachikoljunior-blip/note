## Main update: semantic-correction evidence should scale with blast radius, not use a fixed support threshold

The previous checkpoint established that construct applicability/identity must precede residual-value calibration. This run adds a conservative decision rule that connects same-construct verifier evidence to the harm of a wrong destructive correction.

For a calibration slice define:
- `p_help = P(B helpful | A wrong, same construct, slice)`
- `p_harm = P(B harmful | A correct, same construct, slice)`
- `pi = P(A wrong | slice)`
- `H = normalized harm multiplier for a wrong destructive promotion` (descendant blast radius / irreversibility / external-effect exposure proxy)
- `c = normalized extra-call or promotion cost`

The expected utility model is:

`U = pi*p_help - (1-pi)*H*p_harm - c`.

Using independent Jeffreys `Beta(0.5,0.5)` posteriors, the conservative destructive-promotion rule is:

`U_LB = pi*LCB95(p_help) - (1-pi)*H*UCB95(p_harm) - c > 0`.

This is intentionally asymmetric: uncertainty about helpfulness reduces the claimed benefit, while uncertainty about harmful correction increases the claimed downside.

### Support requirement explodes near the harm boundary

In the concrete synthetic mechanism example `pi=0.25`, `p_help=0.65`, `p_harm=0.03`, `c=0.01`, with integer observations rounded to those rates, the first equal-support sample size that makes `U_LB>0` is:

- `H=0.25`: `n=7` (`5` helpful, `0` harmful)
- `H=1`: `n=30` (`20` helpful, `1` harmful)
- `H=2`: `n=75` (`49` helpful, `2` harmful)
- `H=4`: `n=480` (`312` helpful, `14` harmful)
- `H=6`: `n=10,347` (`6,726` helpful, `310` harmful)
- `H=10`: never certifies asymptotically because the assumed true utility is negative (`-0.0725`)

This is not a proposed production sample-size table. It is mechanism evidence that a universal rule such as “30 examples are enough” is structurally wrong: evidence demand should rise sharply as an incorrect canonical replacement becomes more destructive or irreversible.

## External evidence: no universal fixed support count, and judge value is state-dependent

### Calibrate, Don't Curate — same-construct panels still require calibrated support

`Calibrate, Don't Curate: Label-Efficient Estimation from Noisy LLM Judges` (arXiv:2605.09702) evaluates same-prompt pairwise panels across JudgeBench, RewardBench, RewardBench2 and LLMBar. Full-panel calibration can beat accuracy-ranked top-k panels, and on RewardBench reaches NLL about `0.01` with roughly 75 labels while top-5 remains above that level past 300 labels. A sharp beta-calibrator transition near about 30 labels is explicitly a calibrator-identifiability phenomenon, not a universal epistemic threshold. The paper also reports asymmetric transfer across difficulty slices and recommends calibration support spanning the relevant difficulty distribution.

Source: https://arxiv.org/abs/2605.09702

This directly argues against transplanting a fixed `n≈30` rule into semantic repair. Support has to be conditional on construct, slice, calibration model, and — per the synthetic result above — the downstream harm of a false promotion.

### Construct sensitivity is a separate qualification axis

`A Judge Should Know What Changed: Construct Validity for LLM-as-a-Judge Evaluation` (arXiv:2608.24419) separates invariance under construct-preserving edits (`S`) from sensitivity to minimal construct-changing edits (`R`). At matched `S>=0.90`, average `S=0.945` but average `R=0.319`; sensitivity is higher for scope changes (`0.383`) than strength changes (`0.262`). A judge can therefore be stable without detecting the semantic changes the correction gate actually cares about.

Source: https://arxiv.org/abs/2608.24419

So a candidate verifier should not receive destructive-promotion authority solely because it agrees with a human aggregate or with another judge. It should have evidence that it detects the relevant change type.

### Very recent MAS evidence: separate candidate supply, recognition, and terminal selection

`Candidate supply and answer selection shape the value of LLM judging in multi-agent systems` (arXiv:2608.25937, submitted 2026-08-26) analyzes 15,336 questions for judge reliability and replays 81,390 fixed candidate pools. It finds that correct answers are often present but are outnumbered or poorly recognized; changing only terminal selection to combine answer frequency with judge signal raises reported accuracy from `63.82%` to `70.82–70.95%` in the tested setup. Judge reliability varies with task, generator, and rarity of the correct answer rather than acting as a fixed model trait.

Source: https://arxiv.org/abs/2608.25937

This strengthens the residual-value formulation: `P(B helpful | A wrong, slice)` should include observable candidate-supply state such as rarity/frequency, rather than treating B's global accuracy or model family as enough.

### Very recent repair evidence: symptom/anchor intervention beats blind rerun

`Repair or Resample? Rethinking Failure Debugging in LLM Multi-Agent Systems` (arXiv:2608.25920, submitted 2026-08-26) reports on 536 human-annotated failure trajectories across three MAS frameworks. In the reported experiments, unguided rerun repairs only `6.90%` of failures while reproducing failure `67.97%`; symptom-driven intervention repairs `20.15%`.

Source: https://arxiv.org/abs/2608.25920

This supports retaining the existing separation between semantic truth and repair admissibility: first establish what correction is justified, then intervene at an evidence-backed anchor and recompute the affected suffix/closure rather than relying on a stochastic whole rerun.
