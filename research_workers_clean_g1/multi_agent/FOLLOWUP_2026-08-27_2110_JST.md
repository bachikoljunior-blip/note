## Main update: replace the oracle-like closure flag with an explicit repair-specific certificate

The prior checkpoint used a truthful synthetic `descendant_closure_complete` oracle-like bit to ask how much cheaper repair-specific proof could be than global graph-completeness proof. This run replaces that bit with a more concrete machine-checkable mechanism study.

The deterministic simulator generates 20–45-node DAGs across 3–7 modules and assigns dependency surfaces from `handoff`, `shared_memory`, `conditional_routing`, `dynamic_tool`, and `custom_wrapper`. For each module it separately models:
- whether all true outgoing dependency surfaces are actually mediated/covered;
- whether a **positive completeness proof** for that module is available;
- runtime read/version capture;
- conservative static potential dependencies with false positives;
- current capture epoch/topology state;
- committed external effects with effect-log and semantic-equivalence evidence.

A positive module proof is issued only when that module's true outgoing dependencies are actually covered. The repair-specific certificate therefore uses explicit positive premises rather than checking the hidden true descendant set:

```text
repair_admissibility(source_version)
  capture_epoch_current
  affected_candidate = closure(runtime_reads ∪ static_potential, source_version)
  for every module touched by affected_candidate:
      positive_capture_completeness(module, current_epoch)
  for every committed effect in affected_candidate:
      effect_record_present
      semantic_action_equivalence_or_consumed_authority_state_proved
  else: fail closed to wider replay / whole redraw / block
```

The global certificate uses the same premise type but requires positive capture completeness and effect safety for the **entire task graph**, including unrelated modules/effects.

Reproducibility artifact: `research_workers_clean_g1/multi_agent/SYNTHETIC_REPAIR_ADMISSIBILITY_2026-08-27_2109.py`.

| **repair-specific positive certificate** | **89.965%** | **0%** | **10.035%** | **22.000** | **4,089** |

Within this model, the repair-specific certificate preserved the same zero-unsafe-admission property as the global proof while:
- increasing successful recovery by **4.045 percentage points**;
- reducing blocked cases by **4.045 points**;

The unproved runtime∪static union remains much cheaper and has higher raw successful-endpoint throughput, but it silently admits 3.595% stale/effect-unsafe cases here. Therefore `high empirical recall` and `machine-checkable admissibility` remain distinct targets.

## New public evidence: the certificate needs more than dependency closure

### Exact execution-edit checking — 2026-08-24

`When Can Agents Safely Checkpoint, Fork, Restore, and Merge? Exact Checking for Execution Edits` derives edit safety from a trusted execution record rather than agent text. It identifies four information classes that can change the safe answer: task structure/required results, which calls refer to the same underlying action, prior authorizations and call progress, and which rules govern calls overlapping the edit. Its checker returns all safe continuations or a checkable proof that none exists, and applies accepted rules atomically.

Primary source: `https://arxiv.org/abs/2608.22928`

This sharpens the certificate: dependency closure is necessary for stale-state repair but not enough to preserve still-required results, one-time authorizations, in-flight calls, or policy/action identity.

### DART semantic recoverability

DART independently formalizes the same boundary from a checkpoint-recovery perspective: a mechanically legal local restore can be semantically invalid after downstream commitment, so it certifies admissible restore points under dependency **and effect constraints**, or blocks when none is admissible.

Primary source: `https://arxiv.org/abs/2605.23311`

### ACRFence effect replay/fork semantics

ACRFence records irreversible tool effects and, after restore, distinguishes semantic action equivalence from a genuinely new action. Equivalent calls can return the recorded result without re-execution; semantically different calls require an explicit fork, and consumed authority must stay consumed.

Primary source: `https://arxiv.org/abs/2603.20625`

This makes `effect_record_present + action_equivalence/authority_state` a stronger candidate premise than a generic `effect_safe` boolean.

## New cross-layer failure: logical rollback can still leave the model's attended state stale

`Aborted but Not Forgotten: KV-Cache Retention Breaks Rollback Consistency in Language Agents` (submitted 2026-08-16) isolates a serving-layer rollback failure that the dependency/effect certificate above does not cover. With decision-step tokens held identical, retained stale KV flips the protected decision in **25/63** audited cells; rebuilding the cache from committed bytes or a cold restart yields **0/63** flips. The paper also reproduces the issue through LangGraph time-travel, where persisted logical graph state is restored but the serving-layer KV handle can remain stale.

Primary source: `https://arxiv.org/abs/2608.15939`

A small synthetic cross-layer extension therefore injected an arbitrary 8% stale-attended-state event (explicitly **not calibrated** to the paper's 25/63 result). The logical repair certificate alone then had 7.11% unsafe admissions despite zero dependency/effect-proof violations. Adding an `attended_state_consistent(committed_state_digest)` premise and using transaction-local cache rebind when observable, otherwise a conservative cold rebind, restored zero unsafe admissions in that synthetic extension with a small modeled cost increase (`22.000 → 22.055`). The exact percentage/cost are synthetic; the mechanism lesson is that a rollback certificate must bind **served attended state**, not only transcript/workflow state.

The key design change is that **global graph completeness is no longer the proof target**. The certificate must instead prove that this particular repair preserves every dependency, requirement, authorization/effect, and attended-state condition that can make this local edit unsafe.

## Scope / negative evidence

- All DAG/cost/proof-availability/cache-injection values are synthetic. They are not thresholds for a deployed agent system.
- Positive module completeness is trusted by construction here. The hard real problem is producing that witness without circularly assuming the capture system is complete.
- The public exact-checker/DART/ACRFence papers operate on their own task/effect models; this checkpoint does not claim their guarantees compose automatically.
- The KV-cache paper demonstrates a cross-layer rollback-consistency channel, not that every hosted model/session exposes a verifiable cache digest or that 25/63 is a general failure rate.
- `repair-specific > global` is supported only for the tested synthetic family and modeled validation costs; it does not prove global certificates are always wasteful.
