## C84 — GPT-4.1 Mini independently replicates stable-wrong behavior; same-judge repetition still has no established endpoint gain

Across the same 100 expert-scored items, the five public GPT-4.1 Mini runs have single-run MAEs `7.05, 6.95, 6.80, 6.80, 7.00`, exactly averaging to the repository's published MAAE `6.92`.

| 1 | 100 | 7.050 | 9.260 | 0.00 | 100/100 |

Paired item bootstrap intervals condition on these fixed public traces. K4−K1 MAE is `−0.150`, with 95% bootstrap interval about `[-0.363,+0.063]`; K5−K1 is `−0.130`, about `[-0.350,+0.090]`. Thus the narrow conclusion is again **no established accuracy gain from repeated identical-judge averaging**, not that every repetition is harmful.

Stable wrongness is strong and independently replicates the GPT-4o Mini finding from C81:
- 71/100 items return exactly the same GPT-4.1 Mini score on all five runs;
- 43/71 perfectly stable items are nevertheless not exact expert matches;
- 35/71 perfectly stable items have absolute error >5 points;
- maximum perfectly stable error is 15 points; many expert-80 items are scored 95 on all five runs.

An early-disagreement policy also fails here: evaluate r1+r2 for all items, and only for the 12 disagreements buy r3..r5 and use the five-run median. It consumes 236 evaluations and has MAE `7.10`, versus K1 `7.05`; the fixed-trace paired bootstrap interval for adaptive−K1 spans roughly `[-0.20,+0.30]`.

The public summary reports GPT-4.1 Mini retry-adjusted cost `$3.077078917/1K evaluations`, about 3.05× GPT-4o Mini's `$1.008010180/1K`. Paying several times more for repeated same-model evaluations is therefore not supported by endpoint MAE on this trace.

## C85 — heterogeneous routing can beat equally priced same-judge repetition even when the routed model is globally worse

A useful surprise is that GPT-4.1 Mini is **globally worse** than GPT-4o Mini on this benchmark (r1 MAE `7.05` vs `5.94`) and their one-shot absolute-error correlation is high (`r≈0.815`; signed-error correlation `r≈0.890`). A naive equal-weight one-shot ensemble is also worse than the cheap base (MAE `6.445`). So “different model” or “more expensive model” is not by itself useful.

However, there is conditional complementarity. A deliberately tiny router class was evaluated by five-fold cross-fitting over item index modulo five. Inside each training fold, for each *observable GPT-4o Mini r1 score category*, route the held-out category to GPT-4.1 Mini iff that category's training MAE is lower for GPT-4.1 Mini than for GPT-4o Mini; otherwise keep GPT-4o Mini. Across held-out predictions, the learned rule routes 30/100 items: all 18 base-score-85 cases and all 12 base-score-95 cases; the singleton base-score-86 case is not routed out-of-fold.

Matched-cost comparison:
- GPT-4o Mini r1 for all 100: MAE `5.94`, approximate adjusted cost `$0.1008`.
- Cross-fitted heterogeneous route: 100 GPT-4o Mini base calls + 30 GPT-4.1 Mini calls; MAE `5.44`, approximate adjusted cost `$0.19311`.
- Same routed 30 items, but spend the nearly identical budget on three additional GPT-4o Mini calls (r2-r4) and average all four cheap outputs for those items: MAE `5.89`, approximate adjusted cost `$0.19152`.

Thus the heterogeneous policy is about 0.8% more expensive than the matched cheap-repeat policy yet improves MAE by `0.45` points on the fixed out-of-fold predictions. A paired item bootstrap on those fixed predictions gives heterogeneous−cheap-repeat `−0.45`, 95% interval about `[-0.85,-0.05]`; heterogeneous−base is `−0.50`, about `[-0.95,-0.10]`. These intervals **do not include router-selection uncertainty** and this is still one 100-item corpus, so treat them as exploratory external validation, not a production guarantee.

The mechanism is slice complementarity, not global superiority. On the GPT-4o Mini r1 score-90 slice (69 items), GPT-4o Mini MAE is about `5.22` while GPT-4.1 Mini is about `7.61`, so routing those items is clearly harmful. On base-score-85 items (18 items), GPT-4o Mini MAE is `5.00` while GPT-4.1 Mini is about `3.33`. The one-shot oracle that chooses the lower-error model per item would reach MAE `5.15`, showing some complementarity remains, but that oracle uses expert labels and is not deployable.

**Controller implication:** maximize conditional residual value per call, not model count, price, or global judge rank. Repeated calls to the same correlated judge can spend nearly the same budget while preserving systematic error; a globally weaker heterogeneous judge can still be worth routing to a narrow observable slice where its residual errors differ.

## Scope and limitations

- One domain-specific scalar-assessment benchmark, 100 items, fixed public traces; not a QD archive or pairwise preference task.
- The heterogeneous router uses expert labels on training folds and only a single coarse observable feature (base score category). Held-out fold predictions are out-of-fold, but the policy class and analysis were chosen on this corpus; independent-corpus validation is still required.
- Bootstrap intervals condition on the realized out-of-fold predictions and do not propagate router-training/policy-class selection uncertainty.
- Public prices are repository-reported average token/retry economics, not per-item counterfactual invoices. Heterogeneous cost is about 0.8% above the cheap-repeat comparator.
- Fixed traces allow selecting recorded outputs but cannot generate counterfactual calls under a different online routing history.
- GPT-4.1 Mini is not claimed to be a “stronger” verifier; it is globally worse here. The positive result is specifically about conditional complementarity.
- Error correlations are descriptive for this corpus and not claims about general model-family independence.
