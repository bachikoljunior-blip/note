## Main update: edge-level complement recall is not a rollback safety proof

I expanded the prior six-case mechanism study into a deterministic 1,200-DAG synthetic router harness. The script is persisted at `research_workers_clean_g1/multi_agent/SYNTHETIC_PROOF_STATE_DAG_ROUTER_2026-08-27_1205.py`.

Synthetic scope:
- 1,200 SHA-256-seeded DAGs, 16–34 nodes (mean 24.94).
- Each graph contains a guaranteed source-to-sink backbone plus extra forward edges.
- A correction source is selected from nodes that can reach the sink; the mean true affected descendant closure is 5.58 nodes.
- Incoming dependency surfaces are synthetically assigned `proved_new_version` 58%, `overcaptured` 16%, `known_uncaptured` 13%, `unknown` 13%. These are mechanism-study priors, not measured production rates.
- Runtime capture keeps true edges targeting `proved_new_version`/`overcaptured` surfaces and misses true edges targeting `known_uncaptured`/`unknown` surfaces; `overcaptured` surfaces may add benign extra edges.
- A static complement recovers each missing true edge with calibrated recall `srec` and may add extra edges controlled by `sfp`.
- `local` replays runtime-observed descendants only; `union` replays descendants in runtime ∪ static; `whole` redraws every node except the corrected source.
- Recovery is strict: every true descendant of the corrected source must be replayed. Cost is one correction/diagnosis unit plus one unit per replayed node. `correct_per_100k` is therefore a fixed-call throughput proxy, not measured LLM latency or dollars.

`local` is cheap but unsafe in this synthetic mixture; its recovery is 30.33%. `whole` is safe but discards all independent materialized work by construction. A complete static complement makes `union` both safe and much more call-efficient in this model.

Even 99.5% edge-level complement recall left stale descendant state in about 0.83% of correction events. One missed dependency can hide an entire downstream chain, so an edge-recall number cannot itself justify destructive local rollback. The controller should gate on a closure/proof guarantee or fail closed to a broader redraw when such a guarantee is absent.

This strengthens the prior conclusion that graph F1 is the wrong rollback-controller objective: false negatives and false positives have qualitatively different costs.

## Fresh public evidence: static agent graphs are deliberately over-approximating

A fresh primary-source read of **AgentFlow: Building Agent Dependency Graphs for Static Analysis of Agent Programs** (arXiv:2607.01640, 2026-07-02) adds an important static-analysis constraint. AgentFlow models agent, prompt, model, tool/capability, memory-state, control-policy, control-flow and data-flow dependencies across five agent frameworks and evaluates on 5,399 real-world agent programs. The paper explicitly states that concrete agent behavior depends on runtime model outputs, so static analysis cannot predict a single deterministic execution trace and instead must **over-approximate the execution behavior permitted by the program architecture**. Its ADG therefore over-approximates possible dependencies rather than reproducing one runtime trace.

This supports using static analysis as a conservative complement to runtime provenance, but it does **not** provide a measured guarantee that every rollback-relevant runtime dependency is recovered. It therefore supports the cost side of conservative union enlargement, not a blanket safety claim for selective rollback.

Primary source: `https://arxiv.org/abs/2607.01640`.

## Updated controller hypothesis

The rollback controller should separate three questions:
1. **Correction reliability:** is the replacement datum itself trustworthy enough to invalidate old state?
2. **Closure reliability:** do runtime + static provenance provide a proof/sufficient guarantee that every affected descendant is included?
3. **Blast radius:** how much benign work will the conservative closure replay?

A practical fail-closed policy candidate is:
- use local observed closure only where the relevant dependency surface is positively proved complete;
- use runtime ∪ static conservative closure only where the static complement has a closure-level completeness proof or equivalent contract for the relevant framework construct;
- if `known_uncaptured`/`unknown` surfaces remain without such proof, broaden to a larger reset/whole redraw rather than converting a high but imperfect edge-recall estimate into a safety guarantee;
- charge overcapture separately as replay cost, rather than weakening the safety gate to optimize a single graph-accuracy score.

## Scope guards / negative evidence

- The 1,200-DAG result is a synthetic mechanism study. The proof-state mix, graph sizes, static recall, static FP process, unit costs and reported numerical cliffs are not deployment thresholds.
- `correct_per_100k` is a normalized replay-call proxy, not a token, wall-clock, dollar or user-utility measurement.
- False-positive static edges can occasionally connect to an otherwise missed descendant in a synthetic graph; no safety benefit is inferred from that accidental effect. The clean interpretation of the FP sweep is the srec=1.0 case, where true coverage is already complete.
- AgentFlow is a static-analysis paper and intentionally over-approximates possible execution. It does not establish completeness for all runtime rollback dependencies or validate this synthetic router.
- No source-verifier uncertainty/correlation was reintroduced in this run.
- Irreversible external side effects still require compensation/resettable interfaces; graph replay alone cannot undo them.
