## Main update: explicit evidence-monotone repair witness router

I replaced the previous trusted `positive_capture_completeness(module)` style premise with a small explicit finite witness model whose positive inputs are separately named:
- receipt artifact validity;
- authenticated checkpoint and transparency-consistency evidence;
- current capture epoch and matching topology digest;
- positive surface-inventory attestation and receiver-chain completeness;
- runtime read-version dependency proof;
- conservative static over-approximation proof;
- still-required-result / obligation proof;
- committed-effect proof;
- attended-state consistency proof.

The router has four ordered outcomes: `BLOCK < WHOLE_REDRAW < ENLARGED < LOCAL`. It is intentionally fail-closed:
- invalid/ambiguous receipt, obligation or effect evidence -> `BLOCK`;
- capture-scope or attended-state proof missing -> `WHOLE_REDRAW`;
- exact runtime dependency proof -> `LOCAL`;
- runtime proof missing but conservative static over-approximation proved -> `ENLARGED`;
- otherwise -> `WHOLE_REDRAW`.

## Public-source sharpening: receipt integrity, tail completeness, and equivocation are distinct axes

The 2026-08-15 SCITT AI-Agent Action Receipt draft-01 explicitly separates these:
- a receipt proves issuance/integrity of the record, not that the action was correct, authorized, successful, or physically effected;
- a presented hash chain detects in-band modification;
- **tail truncation is detectable only against an authenticated checkpoint**, never from the presented set alone;
- issuer **equivocation requires a Transparency Service or equivalent external witness**.

Primary source:
`https://mirrors.aliyun.com/ietf/draft-noa-scitt-ai-agent-receipt-01.html`

This means a repair certificate should not collapse `artifact_valid`, `presented_chain_complete`, `checkpoint_authenticated`, `transparency_consistent`, `authorization`, and `effect_observed` into one generic `receipt_ok` bit.

My finite router currently requires checkpoint+transparency proof for every effect-bearing repair. That is deliberately conservative and is **not implied as necessary for every local transaction by SCITT**. A narrower next step is to distinguish a directly trusted transaction-local receiver head from cases that require global anti-equivocation evidence.

## Candidate witness constructor v3

```text
repair_witness(source_version)
  record_integrity
    artifact_signature_valid
    presented_chain_complete
    checkpoint_authenticated_if_tail_claimed
    transparency_consistent_if_anti_equivocation_claimed

  capture_scope
    capture_epoch_current
    topology_digest_match
    positive_surface_inventory
    receiver_chain_complete
    -> proved | known_uncaptured | unknown

  dependency_scope
    runtime_read_version_receipts
    conservative_static_overapproximation
    -> exact_local | conservative_enlarged | unknown

  obligations_and_effects
    still_required_results
    action_equivalence
    prior_authorizations
    in_flight_progress
    committed_effect_receipts
    -> replay_recorded_result | explicit_fork | safe | conflict | unknown

  attended_state
    committed_state_digest
    serving_session_or_cache_epoch
    fresh_rebind_receipt
    -> proved | unknown

  verdict
    LOCAL only on positive local proof
    ENLARGED only on positive conservative closure proof
    WHOLE_REDRAW when dependency/capture/attended state is unknown but effects/obligations are safe
    BLOCK when external effect/authority/required-result state is ambiguous or conflicting
```
