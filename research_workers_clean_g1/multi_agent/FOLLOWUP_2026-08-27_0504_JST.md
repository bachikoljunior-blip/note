## Runnable matched-budget recovery harness

Added `research_workers_clean_g1/multi_agent/SYNTHETIC_DEPENDENCY_ROLLBACK_2026-08-27_0503.py`.

The harness has two roots: source datum `S` and independent root `U`. Observed dependencies are `S -> A -> B -> D` and `U -> C -> D`. `A` and `C` materialize before a boundary verifier checks `S`, creating a concrete stale-descendant problem if `S` is replaced. Model calls are stochastic so replay can itself repair or introduce errors. A second source verifier runs after the endpoint to measure repeated interventions and validated-wrong cases. Model calls cost 1000 token units; verifier calls cost 250. A fixed-total-budget comparison is reported as correct endpoints per 100k calls / 1M token units, so cheaper policies process more tasks rather than receiving free extra compute.

Compared policies:
1. `annotation`: retain the active datum and attach a proposed correction; downstream `B` heeds the annotation probabilistically.
2. `hard_no_replay`: replace the canonical source but retain already-materialized `A`; this deliberately tests stale descendants.
3. `local_replay`: replace the source and replay only the observed dependency closure (`A`, then downstream work).
4. `whole_redraw`: replace the source and redraw both affected and independent materialized branches.
5. `local_inferred_dense`: diagnostic in which a full-history inferred dependency graph marks independent `C` as affected, making local replay degenerate toward whole redraw.

Base parameters: source corruption 0.35, model-step correctness 0.97, verifier TPR 0.88, FPR 0.05, correction accuracy conditional on a true detection 0.94, same-version repeat correlation 0.60, annotation-heed probability 0.75. These are synthetic controls, not estimates of any production model.

Mechanism conclusions inside this synthetic scope:
- Canonical replacement **without descendant replay is unsafe**: source restoration can be high while stale descendants make endpoint accuracy much worse. Here 33.742% of runs contain a stale descendant after replacement, and validated-wrong rises to 37.216%.
- Observed dependency-closed replay dominates whole redraw on efficiency in this graph: nearly identical endpoint accuracy, but mean calls are `6.337` vs `6.675` (about 5.3% fewer) and correct endpoints per 100k calls are `12,799` vs `12,143` (about 5.4% more).
- Treating full-history inferred dependencies as destructive rollback dependencies collapses local replay to whole redraw in this graph. That is a direct harness-level example of why inferred dense dependencies should not be used as if they were observed read provenance.
- Annotation-only can remain competitive per unit compute because it is cheaper, despite lower per-task accuracy. Therefore hard replacement + replay should be gated by verifier reliability and the cost/value of replay rather than made unconditional.

## Verifier reliability is a first-class routing variable

A correction-accuracy sweep held `TPR=0.85`, `FPR=0.08` and other controls fixed. Local replay had higher per-task endpoint accuracy throughout `q_correct=0.50..0.98`, but its fixed-call-budget throughput crossed annotation-only only around **q_correct ≈ 0.87** in this harness. Below that, the extra replay call costs more throughput than it recovers; above it, source-local replay wins.

A false-positive sweep with correction accuracy 0.94 showed the same tradeoff. Local replay had better per-task accuracy across the tested range, but its throughput advantage was approximately gone by `FPR≈0.10` and reversed at `FPR=0.15/0.20`. This reinforces the previous frontier: destructive replacement should require sufficiently low false-refutation risk or an abstain/provisional path.

These thresholds are properties of this synthetic parameterization, not universal constants.

## Public-source alignment and a provenance warning

GRADE's public implementation explicitly separates `dependency="explicit"` (logged/observed dependencies) from `dependency="full_context"` (the assumption that every step depends on all earlier steps). Its own gating experiment says the full-context inferred layer saturates at `rho=1.0`, while observed dependencies are sparse, and uses this distinction as a gate on whether dependency shape is informative. This directly supports using observed read/touch provenance for destructive rollback closure rather than dense inferred history.

Primary public source:
- https://github.com/yzhao062/grade/blob/main/experiment/agent_failure_gating.py
- https://arxiv.org/abs/2606.22741

Cordon's public paper formalizes a lineage graph `G` over semantic result objects, where an edge records that one result was derived from another, and combines that lineage with shadow state / staged effects. I did not locate a public implementation repository for the semantic-transaction paper in this run, so no claim is made about an exact Cordon manifest schema. The minimum metadata implied by the paper plus the runnable harness is: stable artifact/version id, producing step, **observed read parents**, touched/written state/effect ids, validity/retraction state, and enough version provenance to identify descendants of a superseded datum.

Primary public source:
- https://arxiv.org/abs/2606.17573

PatchBoard independently replaces conversation-as-state with validated transactional JSON Patch mutations over a typed shared state; its 630 matched ALFWorld episodes report 84.6% success vs 30.8% LangGraph and 61.6% Flock, with 45.5k tokens per successful task vs 368.3k and 64.2k respectively. This supports explicit canonical structured state, but it does not by itself prove descendant rollback correctness.

Primary public source:
- https://arxiv.org/abs/2605.29313

MemTX is even closer to the current recovery question: retracting a belief triggers typed cascading repair of derived records/effects; the paper reports machine-checked cascade-repair completeness over 5.5 million bounded protocol states with zero violations, and zero realized downstream harm across all five tested backbones. Its negative result is crucial: if an agent transcribes content **without declaring the parent**, a declarative lineage check has nothing to inspect. Therefore destructive invalidation should prefer runtime-observed reads over agent-declared provenance whenever possible.

Primary public source:
- https://arxiv.org/abs/2607.23929

## Updated controller candidate

The stronger candidate is now:
1. keep a typed/versioned canonical datum separate from provenance/audit text;
2. record actual reads from datum-version to consuming step/result;
3. verifier may `confirm`, `refute+replace`, or `abstain/provisional`;
4. only sufficiently reliable replacement mutates the active value;
5. compute the transitive closure over **observed** read dependencies from the superseded version;
6. invalidate and replay only that closure; unrelated branches remain materialized;
7. final validation checks both active canonical values and absence of stale descendant versions;
8. inferred/declared dependencies may enlarge a safety fallback closure, but should not silently be treated as precise observed provenance.

## Scope guards

- All recovery-policy numbers above are from a deliberately small synthetic graph. They demonstrate mechanisms and cost tradeoffs, not expected production accuracy.
- The verifier thresholds/crossover values are not universal; they depend on source-error rate, model-step noise, annotation behavior, graph fan-out, verifier cost and replacement quality.
- `local_inferred_dense == whole_redraw` is exact only for this graph and the chosen full-history assumption. Larger graphs can have different redundancy/cost patterns.
- Cordon implementation-schema claims were intentionally not made because a public code repository for arXiv:2606.17573 was not located in this run.
- GRADE shows that observed-vs-inferred dependency structure matters for prediction/representation; it does not experimentally validate destructive rollback itself.
- MemTX's strongest cascade guarantees depend on provenance being present; its source-scope failure is direct evidence against relying only on declared lineage.
