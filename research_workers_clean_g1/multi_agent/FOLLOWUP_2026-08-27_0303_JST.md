## New mechanism result: boundary verification without canonical state replacement spends most later interventions re-catching an already-known error

The public Hallucination Snowball artifact (`prabhjotschugh/hallucination-snowball`, arXiv:2608.14588) exposes the exact gate implementation and a false-positive/intervention summary.

`codes/experiment_3.py::rag_verify` does not replace or remove a refuted numeric value from the handed-off text. It appends a verification report saying the value is incorrect and provides a corrected reference, then passes the original wrong value plus annotation to the next agent. The Analyst and Writer prompts are instructed not to use refuted values, but the bad value remains materially present in state.

The released `fp_summary.json` reports, across 346 injected hallucinations:
- Gate 1 interventions: 261 (`75.43%`)
- Gate 2 interventions: 179
- Gate 3 interventions: 37
- any gate intervention: 266 (`76.88%`)
- false positives: Gate1 `0`, Gate2 `1`, Gate3 `0`, any `1`
- `suppressed_no_restore`: 87 (`25.14%`)

Because Gate 1 already catches 261 of the 266 hallucinations caught anywhere, only **5 / 346 = 1.45%** of injected hallucinations are newly brought into the caught set after the first boundary. Yet Gate 2+3 emit 216 intervention events. Without the per-injection intersection table, an exact downstream re-catch count is not identifiable from the summary alone, but hard lower bounds are available:
- Gate 2: at least `174 / 179 = 97.21%` of its interventions concern hallucinations that could already have been caught at Gate 1;
- Gate 3: at least `32 / 37 = 86.49%`;
- combined downstream events: even allowing all 5 non-Gate1 hallucinations to be caught once at both downstream gates, at least `206 / 216 = 95.37%` of downstream intervention events are re-catches of Gate1-caught injections.

This is not proof that later gates are useless. They can prevent a downstream agent from reusing or re-expressing a still-present wrong value, and they may catch newly derived wrong numbers. It does show that the current annotation-only state representation makes repeated verification structurally necessary: correction is represented as advice alongside the bad datum rather than as a canonical state mutation.

The `suppressed_no_restore=87` field further separates three outcomes that should not be conflated: removing the injected wrong value, restoring the original correct value, and achieving endpoint correctness. A lower final survival rate can therefore coexist with incomplete factual restoration.

## Independent systems evidence: dependency lineage is the missing primitive for bounded rollback

Two independent 2026 systems papers support a sharper recovery design, while remaining outside the Hallucination Snowball domain.

### Cordon — semantic transactions and lineage-scoped rollback

`Cordon: Semantic Transactions for Tool-Using LLM Agents` (arXiv:2606.17573) tracks result-object lineage, stages reversible mutations/effects, and validates the composed task before commit. On 45 risk-bearing multi-tool workflows, plain execution committed policy-violating effects in `45/45`; strategy adapters derived from existing defense boundaries intercepted only `14/45` before commit, while Cordon intercepted `45/45` before commit.

Its deterministic rollback table is directly relevant to rollback scope:
- Cordon: rollback median `4.17 ms`, `0` residual deltas, resume `15/15`;
- Git restore: `10.99 ms`, median `73` residual deltas, resume `0/15`;
- Git reset: `12.27 ms`, median `73` residual deltas, resume `0/15`;
- reset+clean: `21.74 ms`, `0` residual deltas, resume `12/15`.

The paper attributes the difference to transaction-scoped manifests/lineage rather than broad workspace reconstruction. This does **not** establish that the same numbers transfer to semantic multi-agent handoffs, but it does falsify the idea that broad snapshot/restore is automatically equivalent to lineage-aware rollback once hidden or untracked dependent state exists.

Primary source: https://arxiv.org/abs/2606.17573

### GRADE — explicit dependency structure helps identify blast radius and fault origin

`GRADE: Graph Representation of LLM Agent Dependency and Execution` (arXiv:2606.22741) separates execution edges from dependency edges. Public benchmark summaries report:
- SWE-Gym run-failure ROC-AUC `0.805` with dependency structure versus `0.663` for the run-length baseline;
- leave-one-corpus-out dependency signal stays above chance across all six held-out agent corpora while run-size falls below chance on tau-bench (`0.468`) and SWE-Gym (`0.350`);
- on 126 failed Who&When runs, execution-structure fault localization reaches Top-3 `0.614`, MRR `0.454`, Top-1 `0.211`, versus an early-position prior `0.516 / 0.407 / 0.159`.

GRADE does not itself benchmark rollback. Its contribution here is narrower: dependency edges carry actionable information about what downstream state relies on a suspect step, so descendant invalidation need not be guessed from execution order alone.

Primary source: https://arxiv.org/abs/2606.22741
Public artifact: https://github.com/yzhao062/grade

## Updated controller hypothesis

The rollback controller should treat state correction as a provenance operation, not only a verifier-message operation. A stronger candidate architecture is:

1. verifier identifies a suspect source record/value;
2. canonical state **removes or replaces** the bad datum rather than retaining it beside a warning;
3. a dependency graph identifies every descendant that consumed that datum;
4. only those descendants are invalidated/recomputed;
5. irreversible external effects remain staged until the corrected dependency closure passes verification.

This yields a falsifiable comparison among four recovery policies:
- annotation-only + downstream re-verification;
- hard canonicalization at the caught boundary, without descendant replay;
- source-local invalidation + dependency-closed descendant recomputation;
- whole-pipeline redraw.

Primary metrics should be endpoint accuracy, correct-value restoration rate, validated-wrong rate, downstream re-intervention count, model calls/tokens, latency, and residual dependent-state deltas. A successful source-local policy must beat terminal/annotation repair on correctness **without** approaching whole-redraw cost.

## Scope guards and negative evidence

- Hallucination Snowball uses privileged deterministic numeric references and zero additional LLM calls for gates; intervention-count savings do not directly imply token/cost savings in arbitrary verifier systems.
- The downstream re-catch percentages above are lower bounds from aggregate counts, not exact per-injection intersections.
- Cordon studies tool effects and filesystem/workflow rollback, not semantic financial records; its rollback numbers support lineage-scoped recovery as a systems primitive, not a transferred effect size for multi-agent reasoning.
- GRADE predicts/localizes failure but does not establish that its inferred dependency edges are sufficiently accurate for safe automatic invalidation in every domain.
- Hard canonicalization can itself be harmful when the verifier is wrong. Any source replacement policy therefore needs calibrated verifier confidence, reversible provisional state, or an independent confirmation path for high-impact edits.
