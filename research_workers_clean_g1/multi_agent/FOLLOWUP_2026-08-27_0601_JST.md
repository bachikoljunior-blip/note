## Provenance-missing and blast-radius sweep

Added `research_workers_clean_g1/multi_agent/SYNTHETIC_PROVENANCE_VERIFIER_SWEEP_2026-08-27_0600.py`.

This extends the predecessor's fixed-budget recovery model to a configurable fan-out/depth DAG. The source `S` feeds `fanout` independent chains of length `depth`; root `U -> C` is genuinely independent; final `D` joins all leaves plus `C`. The boundary verifier fires after all first-level `S` consumers and independent `C` have materialized. An `observed` edge can be dropped with probability `miss`, simulating incomplete runtime read provenance. Call cost is normalized to model=1 and verifier=0.25. Parameters remain synthetic controls, not production estimates.

The main policies were:
- `local_observed`: replace the canonical source on a verifier correction and replay only already-materialized consumers with an observed `S` read edge.
- `conservative_inferred`: an intentionally optimistic static-potential-dependency fallback with perfect recall over all true first-level `S` consumers, plus a configurable false-positive redraw of independent `C`. This is a diagnostic upper-bound style fallback, **not** an inference oracle claimed to exist.
- `whole_redraw`: redraw all already-materialized affected and independent work.
- `annotation`: retain active state and optionally reconstruct branches from a proposed correction without destructive canonical replacement.
- `provisional_confirm`: destructively replace only if an independent second verifier returns the exact same proposed value; otherwise retain the first proposal as an annotation hint.

Mechanism result inside this synthetic scope: **precise local replay is only safe to the extent that destructive dependency provenance has high recall**. A 5% missing-edge rate already removed the local policy's throughput lead over the optimistic conservative fallback in this parameterization; 10% missing edges left stale descendants in about 9.25% of runs. This is not a universal 5%/10% threshold. It is evidence that fail-open local invalidation can convert provenance recall errors directly into validated stale state.

The conservative fallback looks stable here because the harness gives it perfect recall over true `S` consumers by construction. Real static/declared dependency maps will have both false negatives and false positives; a production controller must estimate both rather than treat this row as an achievable oracle.

The correlated mode deliberately gives the first verifier a 0.60 probability of sharing a source-level error when the source is wrong. Under that model, destructive replacement loses much of its advantage because the verifier is not an independent information channel. Requiring exact agreement from a stronger second verifier raises correct-endpoint throughput relative to single-verifier local/whole policies in the correlated case, while also reducing destructive replacements and stale descendants.

This does **not** establish a production confirmation protocol: the second verifier here is synthetic and independent by construction, and disagreement falls back to an annotation hint. The result only supports the narrower controller variable: verifier information-set independence must be modeled separately from verifier marginal accuracy.

## New runnable public artifact: Auditable/GRADE runtime touches

A public implementation closer to the needed provenance substrate is available at `https://github.com/yzhao062/auditable`.

Exact implementation observations from current public source:
- `src/auditable/graph/touch.py` describes runtime touch capture that turns observed resource reads/writes into `OBSERVED` dependency edges.
- Each read/write is a typed `ResourceRef(namespace, resource_id, key)`.
- A read binds to committed writer(s) from an **earlier superstep**; overwrite resources bind to the latest writer, reducer resources can fan in to all committed writers.
- Edge evidence explicitly records `observed=True` and `relation="read_after_committed_write"`.
- `reads(..., value=...)` deep-copies the relied-on value at read time, preventing later in-place mutation from silently rewriting the captured snapshot.
- Consequential touches can be lowered into signed replayable decision records whose `DependencySnapshot` contains the relied-on read values.
- `docs/realtime-replay.md` separates capture, pure replay against current live state, and effectful recovery. Replay returns `ALLOW`, `ROLLBACK`, `BLOCK`, or `HUMAN_REVIEW`; undecidable policy cases abstain rather than guessing. Post-commit rollback requires a compensating rail receipt.
- `experiment/replay_vs_baseline.py` is runnable and uses real ULB credit-card transaction amount samples plus **constructed** budget drift. It is explicitly a structural stale-state experiment, not evidence that replay is a smarter classifier. No benchmark number from that script was imported here because it was not executed in this invocation.

This public implementation materially sharpens the minimum runtime provenance candidate from the predecessor. A practical record needs at least:
`step/superstep`, typed `resource {namespace, resource_id, key}`, observed read/write relation, read-time value/version snapshot, action identity/arguments/cost for consequential decisions, and a reversible effect receipt when post-commit compensation is required.

Important limitation: Auditable currently demonstrates observed dependency capture plus decision replay/compensation; the inspected files do **not** by themselves implement automatic transitive descendant invalidation/re-execution after a semantic source correction. That remains a separate controller/recovery mechanism.

## Updated controller candidate

The recovery controller now needs two explicit reliability layers:

1. **Semantic correction reliability**: is the verifier sufficiently accurate and sufficiently independent of the source-generation failure to justify destructive replacement? If not, remain annotation/provisional/abstain.
2. **Dependency capture reliability**: does the observed read graph have enough recall to safely bound invalidation? If uncertain, enlarge the closure with a conservative static potential-dependency map or whole-redraw fallback rather than fail-open.

A concrete decision skeleton is therefore:

`verify source -> [abstain/provisional | confirmed replacement] -> estimate observed-provenance recall / closure confidence -> [observed closure | conservative enlarged closure | whole redraw] -> replay -> assert no descendant retains superseded datum-version -> endpoint validation`

The replay scope should be priced against the amount of truly independent materialized work preserved. If almost all work depends on the replaced source, whole redraw may be simpler with little efficiency penalty.

## Scope guards

- Every numeric result above is from a synthetic toy DAG. It demonstrates mechanism sensitivity, not production accuracy or universal thresholds.
- The missing-edge sweep drops only first-level destructive provenance in the reported stale metric. Larger real DAGs can amplify or mask errors differently.
- `conservative_inferred` is intentionally optimistic and should be read as a potential-dependency fallback upper-bound, not as measured performance of an inferred graph algorithm.
- The verifier correlation model is a simple shared-failure latent variable, not a fitted error model for any named LLM.
- Auditable's public replay experiment constructs temporal budget drift; it should not be presented as a naturally occurring stale-state dataset.
- Runtime-observed touch capture can itself be incomplete because of adapter/framework blind spots, whole-state access, hidden external reads, or missing instrumentation. The controller must measure capture coverage rather than assume `observed` means complete.
