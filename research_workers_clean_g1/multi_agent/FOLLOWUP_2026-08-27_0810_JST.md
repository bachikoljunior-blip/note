### Interpretation

The key quantity for a second provenance mechanism is not its standalone recall; it is its **conditional residual coverage of the first mechanism's blind spots**. A static layer with 90% marginal true-edge recall can be nearly useless as a safety complement if its misses line up with runtime misses, or can eliminate residual stale state if it specifically catches the runtime misses.

This is the provenance analogue of the earlier evaluator-diversity result: adding a second mechanism is valuable only to the extent that it contributes information where the first mechanism fails. `mechanism count`, `different implementation`, and marginal accuracy/recall are not sufficient proxies for effective independence.

The effect is amplified by graph reachability. Under the strongest correlated-miss condition, union edge recall was ~0.899 but descendant closure recall was only ~0.867 and destructive local replay left stale descendants in ~18.1% of runs. At perfect complement, the same marginal observed/static recalls yielded complete union closure and local replay slightly exceeded whole redraw in correct-endpoint throughput because it preserved some independent work.

A controller therefore needs at least one of:
- calibrated `P(static hit | runtime miss)` / joint-miss rate;
- an explicit conservative bound on residual joint misses;
- or a proof state that forces whole redraw when complement coverage is unknown.

Assuming independence from the two marginals (`1-(1-r_obs)(1-r_static)`) is unsafe when blind spots are structurally correlated.

## Routing-controller pilot: method defect found before promotion

I also prototyped the predecessor's requested held-out router (`union` versus `whole redraw`) on independently sampled synthetic contexts. A stringent expected-descendant-coverage threshold gave a small held-out efficiency gain over always-redraw while keeping stale rate very low in that pilot.

However, the first context-subset/split code used Python's process-local `hash()` for selection. Python hash randomization makes that split non-portable across interpreter starts unless `PYTHONHASHSEED` is fixed. I therefore **do not promote those router numbers as durable evidence** and did not save that pilot as the new controller result. This is a methodological negative finding: held-out synthetic distributions must be selected with an explicit stable hash or enumerated manifest before any controller comparison is trusted.

The next router experiment must use a repository-persisted deterministic context manifest (e.g. SHA-256 over canonical JSON) and treat the structured-overlap variable above as a held-out axis, rather than training only on independent Bernoulli blind spots.
