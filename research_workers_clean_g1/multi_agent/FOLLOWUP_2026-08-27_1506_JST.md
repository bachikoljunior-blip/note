## Main update: conditional-complement calibration is necessary but still fails on a hidden dependency surface

The 14:06 checkpoint showed that standalone marginal recall can hide whether a second provenance mechanism actually covers the first mechanism's misses. This run adds a harder failure mode: **a whole dependency surface can disappear from both runtime and static observations in the same execution**.

A deterministic 26-node DAG generator uses six surfaces:
`handoff`, `shared_memory`, `conditional_routing`, `dynamic_tool`, `reducer`, `custom_wrapper`.

Two regimes were compared:

1. `independent`: runtime capture varies by surface and static capture is independently 0.90 per true edge.
2. `surface_blind`: in 40% of graphs, one of `conditional_routing`, `dynamic_tool`, or `custom_wrapper` becomes a graph-level blind surface for **both** runtime and static capture. Capture on non-blind surfaces is deliberately increased, so aggregate standalone recall can look as good or better. Half of blind graphs expose an explicit `known_uncaptured` warning; the other half remain silently `unknown`.

All pseudo-randomness is SHA-256-derived; Python process-local `hash()` is not used. Reproduction script:
`research_workers_clean_g1/multi_agent/SYNTHETIC_SURFACE_BLIND_PROVENANCE_ROUTER_2026-08-27_1506_JST.py`.

Scope: synthetic mechanism study only. Capture probabilities are stress-test parameters, not measurements of any public framework.

### Higher marginal recall, worse closure recovery

Across 3,000 held-out graphs per regime:

| regime | runtime edge recall | static edge recall | full union-closure recovery | mean union cost |
|---|---:|---:|---:|---:|
| independent edge misses | 0.8249 | 0.8995 | **0.7647** | 25.503 |
| surface-correlated blind spot | **0.8264** | **0.9239** | **0.6100** | 24.124 |

The surface-blind regime has slightly **higher runtime recall and materially higher static recall**, yet full descendant-closure recovery falls by about 15.5 percentage points. Missing one surface removes a connected set of causal edges rather than iid edges; aggregate edge recall is therefore actively misleading.

This strengthens the earlier controller hypothesis: safety requires evidence about **where misses cluster**, not merely how many edges are recovered on average.

## Held-out routers under matched union capacity

A separate 5,000-graph training set estimates, per visible surface:
- standalone runtime capture `r`,
- standalone static capture `s`,
- conditional complement `c = P(static hit | runtime miss)`,
- independence-composed union probability `1-(1-r)(1-s)`,
- joint union probability `r+(1-r)c`.

Three held-out selectors then rank 5,000 new surface-blind graphs while receiving exactly the same fraction of union/local-replay slots; all remaining cases use whole redraw:

- `marginal`: uses the independence-composed per-surface score.
- `joint`: uses measured conditional complement per visible surface.
- `proof`: uses the joint score **plus an explicit `known_uncaptured` contract**, making a graph ineligible for union replay when that graph announces the blind surface.

Crucially, ordinary `marginal` and `joint` routing see only the surfaces present in captured runtime/static evidence. A fully missed surface is absent from their inventory. Therefore a silent blind graph can look *safer*, not riskier, because the risky surface has vanished from the evidence.

But it still sent 978 of 983 `unknown_blind` cases to union replay because no positive completeness information existed. Union recovery within those unknown-blind cases was only about 8.0%.

### Mechanism conclusion

The 14:06 result remains valid but is now narrowed:

- `P(static hit | runtime miss)` is more informative than standalone recall **when the relevant dependency surface is known to exist**.
- Conditional-complement calibration alone cannot repair a **surface-inventory miss**. If both provenance mechanisms fail to mention a surface, ordinary edgewise calibration has nothing to condition on.
- A `known_uncaptured` warning is highly actionable under matched capacity.
- **Absence of a warning is not a completeness proof.** Silent `unknown` remains unsafe.
- The next proof object must therefore be positive and scope-bearing: e.g. `inventory_complete(surface set, execution boundary)` / `channel_complete` / a conservative closure certificate, not merely `no warning observed`.

This is analogous to the earlier evaluator result: model diversity is useful only when it supplies residual evidence where the first model fails. Here, provenance diversity is useful only if the second mechanism can attest to the *missing surface itself*, not just recover many other edges.

## Fresh public-source connection: HANSARD makes omission detectability an explicit readiness property

A public paper posted 2026-08-23, **HANSARD: A Reference Architecture for Forensic Readiness, Runtime Witnessing, and Graded Attribution in Autonomous Multi-Agent AI Systems** (arXiv:2608.22512), independently emphasizes a closely related distinction:

- before operation, a sealed readiness profile enumerates mediated and known-unmediated channels;
- capture occurs at five out-of-agent choke points: model invocation, tool call, inter-agent message, memory write, and delegation;
- per-channel sequence numbers plus hash chaining are intended to make omissions on mediated channels detectable;
- the guarantee is explicitly **channel-relative**; unmediated channels remain a stated residual assumption.

This is useful architectural evidence for positive capture-scope declarations: integrity of observed records is not the same as completeness of the capture surface. It does **not** validate this run's synthetic rollback percentages, and HANSARD is a reference architecture rather than a matched-budget rollback experiment.

## Updated controller hypothesis

A rollback/provenance controller should separate at least four claims:

1. **edge evidence**: which observed read/write dependencies were captured;
2. **conditional complement**: how often a second mechanism covers failures of the first on a known surface;
3. **surface inventory / capture-scope proof**: which dependency-bearing channels or constructs are guaranteed mediated/covered, which are explicitly `known_uncaptured`, and which remain `unknown`;
4. **descendant-closure completeness**: whether the chosen replay set is sufficient for this corrected datum/version, not merely whether average edge coverage is high.

`known_uncaptured` should fail closed to a larger scope unless an independent complement proves closure. `unknown` should not silently inherit the semantics of `proved complete` merely because no warning fired.

## Scope guards / negative evidence

- The surface-blind experiment is synthetic. Its 40% blind-surface frequency, capture probabilities and router values are not production estimates or thresholds.
- The proof-aware policy is given a synthetic warning for half of blind cases; the experiment tests the *value of a trustworthy warning*, not the feasibility of generating one perfectly.
- `unknown_blind` cases show why warning-based policies are insufficient: no-warning cannot be treated as complete.
- The graph-level blind spot is deliberately harsh and correlated. Real systems can have milder or more complex mixtures of edgewise, surfacewise and trust-domain omissions.
- Costs count one correction plus replayed nodes; they are not token, latency or dollar costs.
- A positive surface-inventory proof by itself would still not prove every edge/descendant is captured; surface completeness and closure completeness remain distinct.
- HANSARD supports explicit capture-scope/readiness declarations and omission detection on mediated channels, but it does not provide empirical evidence that dependency-guided local rollback is safe under incomplete capture.
- Source-verifier diagnosis error remains deliberately excluded in this run.
