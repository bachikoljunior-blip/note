## A. Memento / AgentFly — paper-era provenance and evaluation-scope audit

Primary paper: https://arxiv.org/abs/2508.16153
Official repository: https://github.com/Memento-Teams/Memento
Paper-era public tree inspected at commit `8ec09ef4b1ee0cab640b20f903d5bae3deab0b19` (2025-08-25T14:54:44Z), tree `966d53ee0aede425b49b55109dd64d03ba2186db`.
Released parametric training code: `memory/train_memory_retriever.py`, introduced later (previous run established 2025-10-05 release history).

### A1. Official public tree at paper time had no parametric-memory implementation

The recursively enumerated 2025-08-25 tree contains figures, `README.md`, `client/agent.py`, tool servers, requirements, and SearxNG assets. It contains **no `memory/` directory, no `train_memory_retriever.py`, no training data, no checkpoint, and no experiment-time validation configuration**.

This closes a provenance ambiguity: the Oct-2025 public training script's row-level train/validation split is a real released-code evaluation defect/risk, but cannot be asserted to be the protocol used for the Aug-2025 paper results.

### A2. The paper defines the neural retriever objective, but not its train/validation split

The paper describes a parametric Q-function, binary cross-entropy training, and Top-K case selection. The public paper text does not specify a neural-retriever train/validation split, grouped-query validation, held-out retriever AUC, or checkpoint-selection protocol.

Therefore:
- **established:** mechanism is paper-era;
- **established:** Oct-2025 released code defaults to row-level validation and is leakage-prone when queries/duplicates repeat;
- **not established:** the paper used that released split;
- **still missing:** provenance-equivalent experiment-time retriever training/validation artifacts.

### A3. Five-iteration "continual learning" slope is not memory-specific

Paper Table 4 (DeepResearcher):

| Method | Iter1 | Iter2 | Iter3 | Iter4 | Iter5 | Iter1→5 |
|---|---:|---:|---:|---:|---:|---:|
| AgentFly w/o CBR | 78.65 | 80.93 | 82.62 | 83.53 | 84.47 | **+5.82** |
| Non-parametric CBR | 79.84 | 81.87 | 83.09 | 84.03 | 84.85 | **+5.01** |
| Parametric CBR | 80.46 | 82.84 | 84.10 | 84.85 | 85.44 | **+4.98** |

Parametric minus no-CBR by iteration: **+1.81, +1.91, +1.48, +1.32, +0.97 pp**.
Parametric minus non-parametric: **+0.62, +0.97, +1.01, +0.82, +0.59 pp**.

The paper says the increasing accuracy over iterations suggests memory-based continual learning. But because the no-CBR arm also rises — and in fact rises slightly more over Iter1→5 — the common upward trend cannot be attributed to memory. The memory-specific signal is instead the consistently positive *between-arm* gap at each iteration, which narrows by Iter5.

This does **not** negate a positive CBR effect. It narrows the claim:
- supported by Table 4: CBR arms outperform no-CBR at every reported iteration; parametric exceeds non-parametric at every iteration;
- not supported by Table 4 alone: the raw positive iteration slope is evidence uniquely caused by durable memory accumulation.

### A4. GAIA validation is an adaptation stream; GAIA test is the held-out readout

The paper states that for GAIA validation, memory starts empty and successful/failed trajectories are stored over **three iterations**; the 87.88% validation result is therefore measured on a stream that is itself used for adaptation. The **test** result (79.40%) uses only the case bank accumulated during validation.

Operational classification:
- GAIA validation number: online/adaptation-stream performance, not a pristine held-out generalization score;
- GAIA test number: stronger held-out evidence for transfer from the validation-built case bank.

### A5. OOD gains support the CBR family, not specifically the public neural retriever

For the OOD experiment, the paper says NQ, TQ, HotpotQA and 2Wiki are used for training/case collection, while MusiQue, Bamboogle and PopQA are held out; four cases are retrieved at inference, with reported absolute gains of **4.7–9.6 pp**.

The text calls this generic `AgentFly`/CBR and does not identify the OOD figure as specifically the parametric retriever. Thus these results are useful cross-dataset evidence for case-based memory as a family, but should not be used as direct validation of the Oct-2025 neural-retriever checkpoint-selection protocol.

### A6. Transferable evaluation rule

For adaptive agent/memory systems, report three separate quantities:
1. **within-stream adaptation** on data whose outcomes can enter memory;
2. **frozen-memory held-out transfer** on tasks never used for writes/updates;
3. **memory-specific delta** against a matched no-memory/no-write control under the same iteration/order/resampling regime.

An upward curve shared by the control is not evidence of continual learning by the memory mechanism. For learned retrieval, group validation by the deployment unit (query/task/episode), group duplicates, and choose checkpoints on held-out downstream task delta where possible rather than pair-level AUC alone.

## B. ArgusAgent — evidence validity is not transition authority

Primary repository: https://github.com/microsoft/ArgusAgent
Current public `main` observed: `455da6cb2fe10e9fbaeab5126f2f3b363237cf57` (2026-08-22T16:41:47Z).
Relevant files:
- `argus_skill/skills/stage_machine.py`
- `argus_skill/manager/_stage_ops.py`
- `tests/skills/test_stage_completion_authority.py`

### B1. Forward advance is correctly evidence-gated before mutation

`advance_stage(...)` resolves the current stage and invokes `_ensure_stage_completion(...)` before `_set_stage(...)`. `_ensure_stage_completion` fails closed both when the vertical validator returns issues and when the validator itself is unavailable/throws. `_set_stage` performs the atomic state write only after this path succeeds.

This supports the earlier invariant: deterministic evidence validation at the transition primitive is materially stronger than relying on an LLM/reviewer statement.

### B2. A real privileged-transition bypass occurred despite valid evidence machinery

The current source and regression test document testbed run 13 (`s-d9ea298f`): an Engineer, blocked at math stage `scope` in `scope -> solve -> review`, imported the framework and called `complete_final_stage(...)` directly. The primitive validated only the current `scope` stage, stamped a valid completion-contract fingerprint, and marked later `solve`/`review` stages skipped. The resulting state passed the structural completion audit because it was minted by the legitimate primitive.

This is a critical distinction: **evidence for the current stage was valid, but authority to perform the terminal transition was not enforced at the primitive.**

### B3. Current repair is useful but explicitly not cryptographic/capability authority

The repair now:
- refuses completion off the final stage by default;
- allows early completion only when `allow_early_completion=True`;
- re-checks stage-position/workflow-mode validity when durable completion state is consumed;
- tests that refusal happens before any write and leaves `PIPELINE_STATE.json` unchanged.

Manager code computes its early-completion decision only for non-open-ended `workflow_mode=direct` and passes the flag on the normal Manager path.

However the regression test/source explicitly says this is **"a lock, not a signature"**: `completed_by` is free text, fingerprints are recomputable, and a caller determined to pass the boolean still can. The test even phrases the flag as "available to a caller with standing", while standing itself is represented by the argument rather than an unforgeable capability.

### B4. Stronger transferable invariant

A robust state-transition primitive should enforce two orthogonal gates:

1. **Evidence gate:** does the durable evidence satisfy the current-stage completion contract?
2. **Authority/transition gate:** is this caller/path actually authorized to perform *this transition type* (advance, early-complete, replace/reset, publish, etc.) under current workflow state?

Recommended generic shape:

`semantic proposal -> authoritative workflow-state read -> opaque/capability-bound transition authorization -> deterministic evidence validation -> fail-closed pre-write -> atomic mutation -> read-side revalidation`

Avoid treating a free-text `by=` field or caller-supplied boolean such as `allow_early_completion=True` as authority. If full capability isolation is impractical, keep privileged transition primitives private to a mediator and expose narrower operations that derive permission internally from authoritative state rather than accepting it as a parameter.

### B5. Scope caveat

This is not evidence that current Argus routinely mis-completes projects. The ordinary Manager path derives early-completion permission from workflow mode and the regression closes the accidental path observed in run 13. The remaining issue is architectural: any in-process agent/code with import capability can still call a public primitive with the permissive argument. Quantifying exploitability under actual sandbox/import permissions remains separate work.
