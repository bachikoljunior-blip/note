## Result 1 — Memento Table-4 iteration slope is not identifiable as a memory-learning effect from public artifacts

### New source-level finding

The Memento paper's own ablation definition says the `w/o CBR` arm keeps episodic memory disabled. Yet Table 4 increases across five iterations for all three arms:

- `w/o CBR`: 78.65 → 80.93 → 82.62 → 83.53 → 84.47 (**+5.82 pp**)
- non-parametric CBR: 79.84 → 81.87 → 83.09 → 84.03 → 84.85 (**+5.01 pp**)
- parametric CBR: 80.46 → 82.84 → 84.10 → 84.85 → 85.44 (**+4.98 pp**)

The paper's discussion explains convergence by saying the roughly 3k-case Case Bank saturates, leaving fewer previously unseen/potentially failing cases in later iterations. That explanation can plausibly describe memory-enabled arms, but by itself it does **not** explain why the explicitly memory-disabled `w/o CBR` arm rises by the largest amount.

Therefore the shared upward iteration curve cannot be used as evidence of memory-specific continual learning. The supported memory signal must come from same-iteration arm differences or a frozen held-out transfer comparison under a matched protocol.

### Paper-era repository audit

The last official Memento commit before the paper-v2 submission timestamp is `f1aa7e3b46f7b2e737bb1e8c2d38e97db368972f` (2025-08-25 13:03:21 UTC), tree `e973f65fcec29c4a832ae638ca3511d46f805e56`.

The recursive tree at that commit contains the basic runtime (`client/agent.py`, server tools, figures, README) but not the later memory-retriever training implementation, paper experiment harness, per-iteration manifests, or a released Case-Bank construction/evaluation loop. The paper-date `client/agent.py` is an interactive single-query planner/executor; `process_query()` clears `shared_history` for each query and contains no five-iteration dataset-level control operator.

The repository's later public release timeline also separates the paper from the CBR implementation: no-parametric CBR code was announced after the paper and parametric retriever/inference code later still. Consequently, the later Oct-2025 row-level retriever-validation implementation cannot be assumed to be the Aug-2025 paper protocol.

### Scoped conclusion

`control slope protocol unknown` remains the correct status. Public paper/repository artifacts inspected here do not identify whether the no-CBR arm advances via fresh stochastic reruns, failure-only retry, cumulative-ever-solved/best-of accounting, order/resampling changes, or another operator.

This is an **auditability / ablation-interpretation gap**, not evidence that the reported Table-4 values are false.

## Result 2 — Argus stage-transition primitives still separate evidence validity from transition authority

### New source-level finding

At public Argus commit `455da6cb2fe10e9fbaeab5126f2f3b363237cf57`, the stage-machine source itself explicitly documents that role identity is not authenticated at the mutation primitive.

`advance_stage(...)` correctly calls the active vertical's deterministic completion validator before writing state, but its docstring states that Manager-only use is an intention, not an authenticated property: `advanced_by` is free text and any role able to import the module can call the function. Thus `advance_stage` has a strong **evidence-validity gate**, but not a cryptographic/opaque **transition-authority gate**.

`complete_final_stage(...)` documents the concrete historical consequence: in testbed run 13 an Engineer imported the module, called the primitive at stage 1, and produced a structurally valid completion record that skipped later stages. The current implementation now blocks off-final-stage completion unless `allow_early_completion=True`, but the source explicitly calls this **"a lock, not a signature"** because `completed_by` is free text and a determined caller can still pass the boolean.

`reset_stage_for_replacement_intent(...)` is an even clearer authority surface: it is a thin wrapper around `_set_stage(... direction="reset" ...)`, downgrades downstream state, and does not itself run the normal stage-completion validator. Its intended caller is a Manager-confirmed replacement-intent path, but the low-level primitive receives caller identity as free text rather than an opaque host capability.

### Sandbox audit

The builder sandbox protects file integrity, not transition-capability authenticity:

- Engineer containment is opt-in / default-OFF.
- When enabled, the worktree plus selected caches are writable while package source, `~/.argus-skill`, `~/.codex`, and the active venv are forbidden write roots.
- VCS credentials are stripped and `PYTHONSAFEPATH=1` prevents workdir shadowing of package imports.
- These controls stop source/venv/gate rewriting, but the inspected code does not establish that the installed `argus_skill` package is unreadable/unimportable or that stage-machine calls require a host-held capability.

The sandbox regression tests likewise verify write containment and environment hardening; they do not prove that a sandboxed Engineer cannot import a privileged state-transition function.

### Scoped conclusion

The public source supports this design distinction:

`valid evidence != authority to mutate durable control state`.

A stronger transferable architecture is:

`model/semantic decision → narrow host mediator → opaque/non-forgeable transition capability derived from authoritative state → deterministic evidence validation → fail-closed mutation → read-side authority revalidation`.

File-system immutability remains valuable, but it should not substitute for primitive-level transition authorization. A privileged mutation service/process or an unforgeable capability checked inside every mutator would address the gap more directly.

This run did **not** reproduce a live unauthorized mutation against Argus. The finding is source-level reachability/authentication analysis, strengthened by explicit comments and the repository's documented prior run-13 incident.

## Research implications

Two apparently different branches converge on a common reliability principle:

1. **Adaptive evaluation needs a matched control whose own state-transition/operator is fully specified.** Otherwise common iteration effects can be mislabeled as memory/self-improvement effects.
2. **Agent state mutation needs both evidence admission and caller/path admission.** A deterministic verifier can establish that evidence is valid without establishing that the caller is entitled to cause the transition.

A compact reusable contract is:

`explicit intervention/control operator + immutable per-step provenance + matched no-intervention control + authenticated state-transition capability + deterministic evidence gate + rollback/read-side verification`.
