## Result 1 — Argus' current public sandbox preserves package readability while protecting writes; it therefore does not constitute transition-capability revocation

### Stronger source-level finding

The previous run left an important question open: does the Engineer containment sandbox merely stop framework/source writes, or does it also make privileged stage-machine mutation APIs unreachable from the builder process?

The current public Argus tree answers this more sharply.

At public `main` commit `455da6cb2fe10e9fbaeab5126f2f3b363237cf57` (2026-08-22), `tests/skills/test_stage_completion_authority.py` is not only a regression for the run-13 early-completion incident; its module-level contract explicitly states that the repair is **"a lock, not a signature"**. It records that `completed_by` is free text, the completion fingerprint is recomputable, and **a caller determined to pass the argument still can**. The repaired primitive closes the accidental call shape but intentionally does not authenticate the caller.

The same current `stage_machine.py` says this directly for ordinary forward transitions: `advance_stage` / `rollback_stage` are intended to be Manager-only, but **nothing there authenticates the caller**; `advanced_by` is free text and any role that can import the module can call the function. The deterministic completion validator protects evidence validity, not caller identity.

The containment code then shows why write protection should not be confused with invocation-capability removal:

- `argus_skill/core/sandbox.py` defines the Engineer sandbox as protecting the gate brain, package source, Codex config, active venv and related control roots from **writes**.
- The bubblewrap path starts from a read-only bind of `/` and explicitly re-exposes `sys.prefix` read-only. That preserves executable/runtime access to the installed Python environment rather than making it unreadable.
- `PYTHONSAFEPATH=1` is used to prevent workdir shadowing of the package; that protects import integrity, but it is not a prohibition on importing the genuine package.
- The sandbox invariant intentionally leaves the project workdir writable. The stage machine's durable project state (`.argus/PIPELINE_STATE.json`) is exactly the kind of state its public mutation primitives modify under a supplied project root.

For an installed deployment in which `argus_skill` is available from the active Python environment, these properties are consistent with **read/execute the authentic framework + write project state**, not with revoking the ability to invoke its mutation functions. This run did not execute an unauthorized mutation and does not claim a live exploit; it is a source-level reachability/capability analysis.

### Regression-suite audit

The public sandbox regression suite is strong on filesystem and credential containment. It checks, among other things, forbidden write roots, venv/sitecustomize persistence escapes, symlink attacks on writable caches, rootless workspace-write fallback, VCS credential scrubbing, and read-only worktree metadata.

However, the current public tests do **not** contain an Engineer-subprocess regression that attempts to import `argus_skill.skills.stage_machine` and proves that a privileged project-state transition is rejected due to an unforgeable authority check. The authority regression instead explicitly acknowledges the remaining determined-caller path.

This is stronger than the previous status `package importability not established`: the public design is demonstrably about **write containment**, while the state-machine contract explicitly says caller identity is not authenticated.

### Default/gating scope

The same public test suite also keeps the containment feature opt-in/default-OFF for compatibility, and tests a legacy path that grants full access when safe mode is not enabled. This does not prove how every production deployment configures the environment; it does mean the source-level security property is conditional on deployment configuration rather than unconditional.

### Transferable invariant

`filesystem integrity != semantic transition authority`.

A stronger design is still:

`model/agent decision -> narrow host mediator -> unforgeable transition capability bound to authoritative state + permitted transition kind -> deterministic evidence validation -> fail closed before write -> atomic durable mutation -> read-side authority revalidation`.

The capability should be checked **inside the mutator** (or by a privileged mutation service/process), rather than represented by a free-text role string or a caller-supplied boolean.

## Result 2 — Memento Table-4 control operator remains publicly unidentified; paper text does not resolve the no-memory slope

A fresh primary-source pass over arXiv v2 confirms two facts simultaneously:

1. Section 5.3 defines `Memento (w/o CBR)` as keeping episodic memory disabled so the additional CBR gain can be measured.
2. Section 5.5.3/Table 4 nevertheless reports the no-CBR arm rising from `78.65` to `84.47` over five iterations, while the text explains convergence in terms of the approximately 3k-case Case Bank saturating and later iterations containing fewer unseen/potentially failing cases.

The paper does explicitly describe a three-iteration accumulate-memory protocol for GAIA validation, but it does not state the corresponding inter-iteration operator for the **memory-disabled DeepResearcher Table-4 control**. Searches of the current public repository for the exact Table-4 sequence / a DeepResearcher iteration harness did not surface a primary run manifest or script specifying seeds, order, resampling/retry policy, cumulative accounting, or a no-CBR state transition between iterations.

Therefore `control slope protocol unknown` remains the correct status. The common upward curve cannot be attributed to case-memory learning without identifying what changes in the matched no-memory control. This is an auditability/ablation-interpretation limitation, not evidence that the reported values are false.

## Research implications

The Argus and Memento branches now converge even more tightly on one control principle: **a durable transition needs an explicit operator and an explicit authority boundary**.

- In adaptive evaluation, the intervention/control operator must say exactly what is allowed to persist or change between iterations; otherwise a control can improve for reasons unrelated to the mechanism under study.
- In agent runtime state, a valid evidence bundle should not itself grant the caller authority to perform arbitrary state transitions; caller/path authority must be independently unforgeable.

Reusable contract candidate:

`explicit transition operator + source-qualified immutable provenance + matched no-intervention control + capability-bound mutation authority + deterministic evidence gate + atomic write + rollback/read-side verification`.
