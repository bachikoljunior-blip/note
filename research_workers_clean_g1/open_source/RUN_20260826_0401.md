## Finding A — the non-forward stage mutators are materially less protected than `advance_stage`

### `advance_stage`

`argus_skill/skills/stage_machine.py` explicitly states that caller identity is not authenticated (`advanced_by` is free text), but `advance_stage` does run the active vertical's deterministic completion validator before state mutation. Validator failure or validator unavailability fails closed before `_set_stage` writes.

This gives evidence admission without caller/path admission.

### `rollback_stage`

`rollback_stage` is a thin wrapper around `_set_stage` with:

- no call to `_ensure_stage_completion`;
- free-text `rolled_back_by`;
- `direction="rollback"`;
- `downgrade_downstream=True`;
- legacy rollback-history append.

The primitive can therefore move `current_stage` backward and downgrade downstream `done` / `ready` / `in_progress` / `skipped` records to `pending` without a cryptographic/capability caller check or a deterministic evidence gate at the mutator boundary.

Public production call sites include the Manager-owned planner stage-request helper and the supervisor dynamic-plan guard. These are legitimate host paths, but the low-level function itself does not distinguish them from any other importer.

Primary sources:
- `argus_skill/skills/stage_machine.py`
- `argus_skill/life/supervisor/_planning_cycle_enqueue.py`
- `argus_skill/life/supervisor/_mission_execution_settlement.py`

### `reset_stage_for_replacement_intent`

This wrapper is stronger still as a mutation surface:

- no `_ensure_stage_completion` call;
- free-text `reset_by`;
- calls `_set_stage(... direction="reset", downgrade_downstream=True)`;
- `_set_stage` applies strict index-order checks only for `advance` and `rollback`, so `reset` can target any known stage in the active order, including the current stage, and makes the landing stage actionable.

The public wrapper `vertical_select.reset_stage_for_new_intent(... force_replacement=True)` reaches it without requiring the old pipeline to have reached its terminal stage. The function's stated authority is semantic — "Manager-confirmed replacement objective" — not an unforgeable caller capability.

In the Manager commit path, `force_replacement` is reached not only from the explicit `force_stage_reset` parameter but also when an existing data domain is adapted (`decision.adapted_stages` -> `adapted=True` -> `force_replacement=... or adapted`). The host path is serialized under the Manager pipeline lock and restore-on-error guard, but the low-level transition primitive still authenticates neither caller nor decision provenance.

Primary sources:
- `argus_skill/skills/stage_machine.py`
- `argus_skill/skills/vertical_select.py`
- `argus_skill/manager/_vertical_ops.py`

### `persist_vertical`

`persist_vertical` intentionally does not reset `current_stage`, which is a useful anti-clobber invariant. But it can atomically change the durable semantic route (`vertical`, optional domain, workflow mode, research target/direction, venue) with no caller authentication at this function boundary. Because stage interpretation is vertical-dependent, route authority and stage-transition authority remain distinct surfaces.

## Finding B — Argus already contains a substantially stronger capability pattern in the same codebase

The strongest result of this run is that no external comparison is needed to show a practical capability design: Argus already implements one for restricted validator repair in `argus_skill/manager/control_state.py`.

`CampaignControlStore` uses immutable revision snapshots plus a HEAD commit point. `Authorization` / `RepairCapability` bind operations to:

- campaign id;
- objective SHA-256;
- campaign epoch;
- Manager state revision;
- blocker fingerprint;
- allowed action(s);
- explicit writable paths and their baseline hashes;
- frozen evidence hashes;
- frozen project-tree hash outside allowed writes;
- forbidden mutation paths;
- random nonce generated with `secrets.token_urlsafe`;
- validator id;
- mission id;
- bounded acceptance-retry count;
- expiry/source metadata.

At claim/consume time the store verifies the nonce with `secrets.compare_digest`, campaign identity, exact current HEAD revision, action scope, expiry, frozen evidence, authorized-write baseline, and frozen tree. Validator-repair claims additionally require the latest Reviewer diagnosis to say `failure_source=validator_defect` and to name the same validator id.

The capability is one-shot: claiming consumes the authorization and publishes one current active capability in a new immutable control revision. Acceptance can start once. Closing rechecks frozen evidence and that no writes escaped the authorized validator paths before accepting; interrupted acceptance is recovered as rejected rather than replayed blindly.

The public tests cover concrete adversarial/staleness cases, including:

- one-shot authorization consumption;
- stale authorization after a newer Manager revision;
- campaign mismatch;
- frozen-evidence drift;
- unsafe project-root / directory / symlink write scopes;
- a symlink created after authorization but before claim;
- a directory substituted after authorization;
- observed-wait revision races;
- one-shot repair capability and acceptance retry;
- durable crash/recovery behavior.

Primary sources:
- `argus_skill/manager/control_state.py`
- `tests/manager/test_control_state.py`
- `argus_skill/life/supervisor/_mission_execution_runtime.py`
- `argus_skill/life/supervisor/_mission_execution_settlement.py`

## Candidate refinement — `clean-os-g1-005`

The earlier transferable invariant is now stronger and more concrete:

`filesystem integrity != semantic transition authority`, and Argus itself demonstrates a usable authority mechanism that can be adapted to stage mutation.

A stage-transition capability should be minted/owned by the host Manager control plane, not represented by free-text `*_by` fields. A minimal contract should bind at least:

- campaign/objective/epoch;
- exact control-state revision;
- transition kind (`advance`, `rollback`, `reset`, `complete`);
- `from_stage` and allowed target stage(s);
- workflow mode / relevant route contract;
- decision id or plan id that authorized the transition;
- evidence-contract fingerprint or explicit evidence snapshot where the transition depends on evidence;
- a random one-shot nonce/capability id;
- optional expiry.

The low-level mutator should atomically consume that capability and fail closed on stale revision, transition-kind mismatch, source/target mismatch, route change, evidence drift, or reuse. Read-side completion/authority checks should still remain because write-time capability checks do not repair pre-existing or externally corrupted state.

This is not a speculative mechanism family imported from elsewhere: the repository already has the nonce/revision/evidence/tree/one-shot machinery for validator repair. The implementation hypothesis is therefore narrower: reuse/generalize that proven control-plane pattern for privileged stage-state transitions rather than invent a second authority system.

## Why this matters

Argus currently has an asymmetry:

- restricted validator repair: explicit one-shot capability + revision/evidence/tree guards + negative tests;
- stage rollback/reset/early completion: mostly semantic host ownership, free-text actor fields, and function-level checks that validate evidence/shape but not caller authority.

The run-13 early-completion incident shows that a legitimate framework function invoked from the wrong role/path can mint structurally valid state. The capability subsystem shows the same codebase already knows how to bind dangerous operations to current durable authority.

That makes capability-bound transition admission a higher-confidence engineering candidate than a generic recommendation to "add more review" or "tighten prompts".
