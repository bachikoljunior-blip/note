## Frontier branch executed: Memento vs ReasoningBank retrieval mechanics

### 1. Memento parametric retrieval is still forced top-k

Public `Memento-Teams/Memento/memory/parametric_memory.py` loads a binary `MemoryRetrieverClassifier`, scores every case with `softmax(... )[:,1]`, sorts the full pool, and returns `topk`. There is no probability threshold, compatibility classifier after ranking, or no-memory fallback when the pool is nonempty. `train_memory_retriever.py` uses a 0.5 threshold only for validation metrics; inference `topk_select` ranks and returns the top-k regardless of absolute probability.

This means the earlier observation from Memento's non-parametric cosine-similarity path generalizes to the public parametric path: both rank memories but do not implement a retrieval admission threshold.

The tracked public memory bank consists of concrete prior `case` + `plan` items with a `case_label`; sampled entries are task-specific questions paired with short plans.

Primary artifacts:
- https://github.com/Memento-Teams/Memento/blob/main/memory/parametric_memory.py
- https://github.com/Memento-Teams/Memento/blob/main/memory/train_memory_retriever.py
- https://github.com/Memento-Teams/Memento/blob/main/memory/memory.jsonl

### 2. ReasoningBank also uses forced nearest-memory retrieval, so admission gating is not the differentiator

Public `google-research/reasoning-bank` code shows `select_memory(n=1, ...)` on WebArena. `screening()` embeds the current task, cosine-ranks all cached prior-task embeddings, and returns ordered IDs; `select_memory` takes the first `n` if the bank is nonempty. There is no similarity threshold or retrieval-confidence abstention in this path.

Therefore ReasoningBank's better EvoAgentBench cell cannot be explained by a simple fact such as "ReasoningBank has a confidence gate while Memento blindly retrieves". Public code indicates both can force retrieval.

Primary artifacts:
- https://github.com/google-research/reasoning-bank/blob/main/WebArena/memory_management.py
- https://github.com/google-research/reasoning-bank/blob/main/WebArena/run.py
- https://github.com/google-research/reasoning-bank/blob/main/third_party/src/minisweagent/memory/memory_management.py

### 3. The stronger public distinction is memory abstraction + explicit utilization discretion

ReasoningBank induces up to three generalized memory items from each trajectory. Successful trajectories are distilled into reusable success principles; failed trajectories are explicitly reflected into lessons/avoidance strategies. The induction prompt forbids retaining specific websites, queries, or literal string contents and asks for generalizable reasoning insights.

At WebArena execution time, the retrieved memory text is appended to the system prompt with an instruction that it "may be helpful", can be used when relevant, and should be explicitly considered item by item before action. Thus retrieval is forced but actual utilization is delegated to the model each step.

Memento's public memory artifact, by contrast, exposes concrete task cases and short plans as the retrieval unit. This is an implementation-level qualitative difference, but not yet causal evidence for the EvoAgentBench performance gap.

Primary artifacts:
- https://github.com/google-research/reasoning-bank/blob/main/third_party/src/minisweagent/memory/induce_memory.py
- https://github.com/google-research/reasoning-bank/blob/main/third_party/src/minisweagent/memory/instruction.py
- https://github.com/google-research/reasoning-bank/blob/main/WebArena/agents/legacy/agent.py

### 4. Independent quantitative support for generalized reasoning memory

ReasoningBank is published at ICLR 2026. The primary/public paper reports up to 20% relative effectiveness improvement and up to 16% fewer interaction steps over compared memory baselines. Google Research's public summary gives matched Gemini-2.5-Flash deltas of +8.3 percentage points on WebArena and +4.6 points on SWE-Bench-Verified versus memory-free agents, with almost 3 fewer SWE-Bench execution steps per task. These results are not the EvoAgentBench adapter and therefore cannot explain that exact cell, but they support the mechanism family independently.

Primary report/source:
- https://openreview.net/forum?id=jL7fwchScm
- https://research.google/blog/reasoningbank-enabling-agents-to-learn-from-experience/

## Candidate revision: clean-os-g1-003

Keep the high-confidence observation that skill/memory effects are strongly model × scaffold × domain dependent and can be severely negative. Keep a no-memory fallback as a testable safety mechanism, but **downgrade the claim that missing retrieval admission gating is the likely differentiator between Memento and ReasoningBank**: public ReasoningBank code also performs unconditional nearest-memory retrieval when its bank is nonempty.

Refined hypothesis: negative transfer may depend more on the *retrieval unit and utilization contract* than on retrieval abstention alone. Compare concrete case/plan memories against generalized reasoning/anti-pattern memories; compare automatic prompt injection against explicit model-level relevance consideration; evaluate these components separately from any confidence threshold.

Do not attribute EvoAgentBench's Nanobot/Qwen3.5-27B SWE-Bench Memento 45.8→9.5 regression to any one public Memento retrieval path without the omitted third-party adapter/config or an independent matched reproduction.
