## SA-20260825-09 — Explicit task contracts improve downstream research execution, but the study does not isolate all contract components or matched compute

**Primary source.** Huirui Xu, Runtao Xu, Shuo Ren, Jiajun Zhang, *Project2Task: Graph-Guided Project-Level Planning for Autonomous Research*, arXiv:2608.05225v1, submitted 5 Aug 2026, https://arxiv.org/abs/2608.05225 .

### Setup

- Dataset: **10 project briefs**, created from **7 NanoResearch** samples and **3 ARC-Bench** samples, expanded by LLM-driven augmentation into project-level instances; roughly **30 tasks** total across CV, NLP, tabular ML, time series, graphs, audio, and multimodal ML.
- Planner: parses a project brief/resources/literature; builds an innovation-atom DAG; scores horizontal, vertical, horizontal→vertical, and vertical→horizontal decompositions with a Bernoulli block-model objective; generates bounded task contracts; then runs a validation/repair loop for overlap, missing evaluation fields, dependency feasibility, and sibling boundaries.
- Contract fields include scoped goal, contribution ownership, must-cover/must-not-cover constraints, shared assets, dependencies, expected outputs, evaluation guidance, reporting guidance, and success criteria. The paper emphasizes that the contract stays visible during execution rather than only in the initial prompt.

### Portfolio-quality evaluation

The generated manuscript portfolio is scored on coherence, overlap control, coverage, consistency, and task division by **Qwen3.6-Plus**, 1–10 per dimension, with **five independent judge runs** under identical prompts/settings.

- Brief baseline (macro project directly to AutoResearchClaw): **4.58** average.
- Topic-only setting (planner-produced task titles but structured planning fields removed): **5.31**.
- Full Project2Task contracts: **7.15**.
- Full Project2Task beats the two baselines on all ten project queries in the paper's aggregate table.
- Largest dimension-level gains reported include Coherence **7.28 vs 4.63/4.50**, Coverage **7.50 vs 5.50/5.40**, Overlap Control **8.06**, and Task Division **7.58**.

The Topic-only comparison is useful: it shows that the effect is not explained solely by selecting task titles; structured scope/dependency/evaluation context contributes additional judged portfolio quality.

### Graph-router ablation

All pipeline components were held fixed except the router was forced to use its **second-ranked** decomposition strategy.

- Runner-up routing: **6.48** average portfolio score.
- Selected graph-guided routing: **7.15**.
- Selected routing wins **9/10** queries; query 1 is the exception (**6.68 vs 6.84**).
- Reported dimension deltas include Task Division **+1.04**, Overlap Control **+0.56**, Consistency **+0.62**.

This isolates value in topology-aware decomposition selection, but only relative to the second-ranked strategy—not to random routing or a matched non-graph optimizer.

### Downstream AutoResearchClaw execution

The same 10 project queries were converted to executable tasks with a problem statement, designated datasets, baseline methods, and optimization metrics. Baseline AutoResearchClaw receives a topic description; Project2Task first plans/decomposes and passes structured handoff contracts to AutoResearchClaw.

A 0.000 means **invalid execution/no valid evaluation result**, not measured zero test accuracy. Project2Task is higher on **8/10** tasks. Crucially, the gain persists after excluding baseline invalid executions (**0.830 vs 0.766**), so the average improvement is not only a failure-avoidance artifact. Query 6 degrades materially (**0.747 → 0.542**) and query 8 slightly declines (**0.975 → 0.954**), showing that contracts can over-constrain or misalign with executor strengths.

### Mechanism interpretation

The evidence supports a useful design principle: long-horizon research should have a distinct **project-planning layer** that emits durable task contracts containing contribution ownership, boundaries, evaluation requirements, shared assets, and dependency order. The downstream executor should continuously retain these contracts as context/audit criteria, rather than receiving a vague one-shot task prompt.

The paper does **not** establish which contract fields are individually causal. It also does **not** report a matched-compute baseline that gives vanilla AutoResearchClaw an equal extra planning/token budget without graph contracts. Therefore the causal claim should be narrower than “graphs cause the full 0.223 gain.” The strongest supported claims are:
1. full structured contracts outperform topic-only inputs in their portfolio evaluation;
2. selected graph routing outperforms the runner-up strategy with the rest of the planner fixed;
3. full planning+contracts improve downstream execution on this 10-task set, including when invalid baseline runs are excluded.

### Confidence / scope

- Very recent **preprint**, not peer reviewed.
- Small benchmark: 10 LLM-augmented project briefs / 10 downstream tasks.
- Portfolio quality is an **LLM-judge metric** using Qwen3.6-Plus, averaged over five judge runs; no human portfolio evaluation is reported in the inspected experiment section.
- Downstream accuracy is execution-grounded, but heterogeneous task accuracies are averaged and the planner introduces extra computation/context. Exact magnitudes should be treated as benchmark-local.

## Rejected stronger interpretation

Rejected: “Project2Task proves graph planning itself raises research-agent accuracy from 0.536 to 0.759.” The full downstream comparison changes the entire upstream planning/contract pipeline, not only graph routing, and no equal-compute non-graph contract baseline is reported. The routing-specific causal evidence is instead **6.48 → 7.15** on the manuscript-based portfolio judge when swapping only selected vs runner-up topology.
