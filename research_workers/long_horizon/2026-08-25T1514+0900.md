## Newly covered high-value evidence

### 1. Canonical-path drift is self-reinforcing; mid-trajectory restart can recover success
Primary: https://arxiv.org/abs/2602.19008
Title: "Capable but Unreliable: Canonical Path Deviation as a Causal Mechanism of Agent Failure in Long-Horizon Tasks"
Mechanism/evaluation: derive a task-level canonical tool set from successful trajectories, then measure whether failed trajectories gradually drift away from it while holding model/task capability fixed using mixed-outcome model×task units.
Evidence: 22 frontier models × 108 Toolathlon tasks × three independent runs. In 488 analyzable mixed-outcome units, successful runs have +0.060 Jaccard adherence to canonical tools vs failed runs (p<0.0001, 95% CI [+0.043,+0.077]); the gap is indistinguishable from zero through the first 50% and emerges later. One off-canonical call raises probability of the next off-canonical call by +22.7 percentage points (p<0.0001). A simple monitor that restarts bottom-tercile runs by mid-trajectory adherence improves success by +8.8 points among intervened runs.
Judgment: VERY HIGH. This gives a causal runtime-recovery trigger rather than only an end-state detector. For O, exact canonical tool sets may be unavailable on novel tasks, but analogous learned/reference invariants (required artifact states, expected work-unit sequence, or successful task-family traces) could provide a drift signal. Must test false positives on valid novel strategies.

### 2. AgentRewind: restore both reasoning context and environment, but carry forward lessons from the discarded branch
Primary: https://arxiv.org/abs/2608.14380
Date: 2026-08-14
Mechanism: record aligned checkpoints `(agent context, controlled environment state)`. When stuck, select a prior checkpoint, summarize/fossilize lessons from the failed suffix as rewind memory, restore both context and environment, then resume from the old point with the new lesson injected.
Evidence: primary abstract reports improved task success and checklist progress across MettleBench, multiple models, strategies, and agent harnesses. A current full-text index reports GPT-5.4 Continue 62.2%, Restart-with-experience 78.0%, AgentRewind 87.8%; ablations reportedly fall to 43.9% without environment rewind, 65.9% without context rewind, and 51.2% without rewind memory. These exact table numbers are SECONDARY-INDEXED and must be rechecked against the primary paper before O-feed promotion.
Judgment: VERY HIGH mechanism relevance. O already has durable continuation and version-controlled execution artifacts; the distinct candidate is *coordinated rollback of both world state and reasoning state while preserving only diagnosed lessons from the failed future*. This can remove contaminated context without repeating a known failure.

### 3. Agent Skills can cause both functional failures and process-cost regressions even when semantically relevant
Primary: https://arxiv.org/abs/2608.11888
Date: 2026-08-12
Mechanism/evaluation: differential paired attribution—compare a skill-guided run to a no-skill or semantically matched reference run that succeeds or succeeds more cheaply.
Evidence: SkillsBench + SWE-Skills-Bench yield 307 attributed skill-induced regressions: 125 functional failures and 182 efficiency regressions. Failures are rarely due to obviously irrelevant skills; apparently relevant skills can cause omitted/incorrect task elements. Excessive Procedure includes 67 excessive-verification and 30 heavy-implementation-pipeline cases. Efficiency regressions are not explained by prompt length alone.
Judgment: VERY HIGH for O's recursive Skill-in-Skill architecture. Loading/routing a relevant Skill is not sufficient evidence that the Skill helps. Each Skill needs matched no-skill/alternative-skill evaluation on downstream success, elapsed time, and unnecessary procedure burden; verification checklists must remain conditional rather than becoming ritual.

### 4. Skills appear to work mainly as procedural anchors, but retrieval precision collapses as the skill pool grows
Primary: https://arxiv.org/abs/2608.14036
Official code: https://github.com/zhiyuanjiang04/demystify-agent-skills
Date: 2026-08-14
Mechanism/evaluation: controlled experiments + paired trajectory analysis across benchmarks, harnesses, and LLMs; isolates representation, outcome annotation, retrieval difficulty, and cross-framework robustness.
Evidence: 8,135 normalized trial records. Skills improve over Workflow Memory by 6.06 points in matched comparisons. Procedural anchoring accounts for 65.7% of observed skill-use cases versus only 4.5% explicit knowledge injection. As candidate pools grow from 5 to 100, actual-use retrieval precision drops from 29.6% to 3.3%. Exact ground-truth skill invocation is neither necessary nor sufficient for downstream success.
Judgment: VERY HIGH. This sharpens O's Skill-in-Skill hypothesis: the primary value may be stabilizing execution procedure, not adding facts. Recursive branching can reduce retrieval competition, but routing precision itself should not be the end metric; downstream action stability and cost matter more. Also suggests keeping local candidate sets small enough to avoid retrieval dilution.

### 5. Failures often begin early and become visible too late for recovery
Primary: https://arxiv.org/abs/2607.09510
Title: "Failure as a Process: An Anatomy of CLI Coding Agent Trajectories"
Mechanism/evaluation: annotate failure onset, evolution, and recovery rather than only terminal outcome.
Evidence: 3,843 raw trajectories from seven frontier models × three agent scaffolds on Terminal-Bench; 1,794 complete valid trajectories and >63,000 annotated steps. Primary abstract reports epistemic errors dominate, failures typically begin in the first few execution steps, and often remain hidden until recovery is no longer possible.
Judgment: HIGH. O should place verification early at assumption-setting/branch-selection moments, not concentrate evaluation at the end of a long work unit. This complements AgentRewind: early detection determines whether rollback retains more useful progress.

### 6. Failed trajectories can directly generate inference-time agent improvements without retraining
Primary: https://arxiv.org/abs/2606.31270
Date: 2026-06-30
Mechanism: diagnose failed computer-use trajectories with an LLM, propose inference-time fixes, generate/verify code patches to the agent scaffold; no model training required.
Evidence: OpenCUA-72B on OSWorld improves from 42.3% to 48.9% success (+6.6 pp) with no additional training and modest inference overhead.
Judgment: HIGH but likely shared with self-improvement worker. For long-horizon O, the useful lesson is to extract *mechanism-level scaffold changes* from failed trajectory classes, not merely store failure summaries. Changes still require matched regression testing.

### 7. Failure location can shift across model generations, so fixed bottleneck assumptions age quickly
Primary: https://arxiv.org/abs/2608.20563
Date: 2026-08-20
Title: "Beyond End-to-End Success: Diagnosing Failures in Long-Horizon Security LLM Agents"
Mechanism/evaluation: instrument long-horizon tasks with checkpoints, split failures before/after capability exposure, and intervene at suspected upstream bottlenecks.
Evidence: on observed-state reuse, a pre-specified 92-seed study with Gemini 2.5 Flash increases state observation from 65.5% under matched non-guidance control to 95.4% with protocol-disambiguation guidance. Repeating the design with Gemini 3.7 Flash gives the opposite intervention effect, and state observation no longer reliably predicts final completion.
Judgment: VERY HIGH evaluator-design evidence. O should not fossilize a previously identified bottleneck into permanent architecture. Intervention effects and failure localization must be periodically recalibrated as base models/harnesses change.

## Cross-paper synthesis

- **Recovery should combine a trigger + rollback target + retained lesson**: canonical-path deviation supplies a measurable trigger; AgentRewind supplies aligned context/environment rollback; failure-process analysis motivates early detection; failure-driven improvement supplies a route from repeated failure classes to scaffold changes.
- **Skills require causal attribution, not relevance intuition**: the two August skill studies independently show that seemingly relevant Skills can hurt and that procedural stabilization—not knowledge injection—is their dominant observed value.
- **Recursive Skill routing can solve retrieval competition only if it does not turn local procedures into mandatory bureaucracy**: pool growth damages retrieval precision, while overly prescriptive skill procedures create cost and functional regressions.
- **Evaluator targets must remain model-generation contingent**: checkpoint interventions that help one generation can hurt the next.

## Candidate interventions for O

1. **Drift-triggered rewind experiment**: define task-family reference invariants from successful O runs; at mid-unit boundaries measure deviation and compare continue vs clean-context rollback + retained failure lesson.
2. **Aligned rollback artifact**: treat authoritative repo/environment SHA + O request/context manifest as one recoverable checkpoint; never rollback one without checking alignment to the other.
3. **Skill differential gate**: for any high-impact routed Skill, compare matched no-skill / alternative-skill trajectories on success, elapsed time, tool calls, context load, and procedure burden before making it default.
4. **Local retrieval fanout metric**: measure child-candidate count vs actual useful-selection precision and downstream task success. Hierarchical routing should be rewarded for shrinking confusable local pools, not merely deeper nesting.
5. **Early epistemic checks**: identify first irreversible assumption/action in each unit and place a cheap validation before it; compare against terminal-only evaluation.
6. **Bottleneck recertification**: periodically rerun causal interventions after base-model/harness changes instead of assuming a previously diagnosed failure mechanism remains dominant.

## Evidence-scope cautions
- Canonical-path monitoring can punish genuinely novel successful strategies; use it as a probabilistic risk signal, not an invariant constraint, unless the task has a formally required path.
- AgentRewind exact table values are not yet primary-table verified in this run; only its abstract-level cross-model improvement claim is primary-confirmed.
- Skill failure counts are benchmark/harness-specific and should not be generalized to all skills. Their matched attribution method is more transferable than the raw rates.
- The security checkpoint study shows a sign reversal across model generations, reinforcing that intervention efficacy is conditional.
