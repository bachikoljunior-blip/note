## New evidence since checkpoint 2

### 1. STALE: retrieval can update while behavior remains stale
Primary: https://arxiv.org/abs/2605.06527
Code reported by paper-review index: https://github.com/icedreamc/STALE
Date: 2026-05-07
Mechanism/evaluation: later observations can implicitly invalidate older memory without saying "that old fact is false." STALE evaluates three distinct abilities: State Resolution (identify current state), Premise Resistance (reject a query that presupposes stale state), and Implicit Policy Adaptation (actually behave according to the update).
Evidence: 400 expert-validated scenarios, 1,200 queries, >100 topics, contexts up to 150K tokens. Primary abstract reports even the best evaluated model at only 55.2% overall and a recurring gap between retrieving newer evidence and acting on it. CUPMem prototype uses structured state consolidation and propagation-aware search.
Judgment: VERY HIGH. This directly matches O's concern that available/understood constraints can fail to control later actions. Context-freshness evaluation should explicitly separate (a) noticing updated evidence, (b) rejecting stale premises, and (c) downstream action adaptation.

### 2. Supersede: bounded self-maintained memory has a distinct update gap not fixed by capacity alone
Primary: arXiv 2606.27472, "Supersede: Diagnosing and Training the Memory-Update Gap in LLM Agents"
Official/open environment: https://github.com/Vrin-cloud/supersede
Date: 2026-06-25
Mechanism/evaluation: isolate temporal fact currency—use the newest still-valid fact and suppress superseded values—and provide an RL environment with verifiable reward for current-vs-stale answers.
Evidence: on LongMemEval knowledge-update, a frontier gpt-5.4 system drops from 92% with full context to 77% with bounded self-maintained memory (paired McNemar p<0.005). The paper reports that growing the conversation 24x drops memory accuracy from 68% to 28%, and proportionally increasing memory capacity does not recover it (28% to 28%, n=25). Released GRPO/LoRA environment includes conflict detection, supersession logic, temporal timelines, rollout state, and stale penalties.
Judgment: VERY HIGH diagnostic. More memory is not the same as better revision. O's ledger/context kernel needs explicit supersession/invalidation semantics and tests where old directives/plans/facts remain retrievable but must no longer govern.

### 3. A simple deterministic current-value resolver can beat LLM-mediated conflict resolution in the narrow case
Primary: https://arxiv.org/abs/2606.01435
Title: "Don't Ask the LLM to Track Freshness: A Deterministic Recipe for Memory Conflict Resolution"
Mechanism: for FactConsolidation tasks where serial/timestamp order defines current value, extract candidates and deterministically choose max(serial/timestamp) instead of asking an LLM to adjudicate freshness.
Evidence: paper reports +10.8 points on MemoryAgentBench FC-SH under a matched setup, reaching 78.0% with gpt-4o-mini and 94.8% with gpt-4o; multi-hop improves to 30.2% / 51.5% respectively. On a 45-item LongMemEval knowledge-update check, deterministic timestamp aggregation only ties/underperforms broader LLM judgment (57.8% vs 64.4%), explicitly limiting the mechanism's scope.
Judgment: HIGH as an engineering control, not a universal solver. If O has an authoritative revision/sequence/timestamp contract, currentness should be resolved deterministically where semantics permit; reserve model reasoning for implicit supersession.

### 4. HORMA: hierarchical raw-linked memory + learned navigation + failure-attributed organization
Primary: https://arxiv.org/abs/2606.11680
Date: 2026-06-10
Mechanism: organize experience into a file-system-like hierarchy where summaries/entities retain links to raw trajectories; separate memory construction from retrieval. A lightweight RL-trained navigation agent selects minimal sufficient context. Memory organization is iteratively refined by distinguishing failures caused by missing information from failures caused by misleading/overloaded context.
Evidence: primary abstract reports improved task performance under constrained context budgets across ALFWorld, LoCoMo, and LongMemEval, while using at most 22.17% of baseline tokens in long-conversation tasks, with generalization to unseen tasks.
Judgment: VERY HIGH. This independently converges on O's recursive Skill-in-Skill idea but adds two testable details: raw provenance links at each summarized node, and explicit blame attribution between *construction failure* and *retrieval failure* before changing the policy. That blame split can prevent fixing the wrong layer.

### 5. Proactive Memory Agent implementation details sharpen the intervention hypothesis
Primary: https://arxiv.org/abs/2607.08716
Official code: https://github.com/yifannnwu/proactive-memory-agent
Additional primary-paper text surfaced in indexed full text: memory agent uses a recent window k=8 messages, runs bank management then intervention selection; baseline/action model is unchanged. For Sonnet 4.5, the paper reports Terminal-Bench 37.6% -> 45.9% and tau^2-Bench 55.0% -> 61.8%; stronger Opus 4.6 still gains +2.4 pp and +2.5 pp. The full-bank/always-inject ablations are weaker than selective intervention.
Official repo confirms both Terminal-Bench configurations run all 89 Terminal-Bench 2.0 tasks and exposes resumable runs and model-pair configuration.
Judgment: VERY HIGH. The relevant mechanism is not merely a second model; it is a two-stage bank-update + selective-control-intervention design with a silent action. O should compare no intervention, full-bank exposure, always-remind, and selective-remind at equal or explicitly accounted cost.

### 6. WorldEvolver: planning can improve by updating a deployment-time world model from prediction errors
Primary: https://arxiv.org/abs/2606.30639
Date: 2026-06-29
Mechanism: keep downstream action agent/model weights frozen while evolving context used for foresight: episodic memory retrieves real transitions for simulation; semantic memory extracts persistent rules from prediction-vs-observation mismatch; selective foresight suppresses low-confidence predictions before they enter the planner's context.
Evidence: primary abstract says highest world-model prediction accuracy across three backbones and leading downstream AgentBoard success against world-model baselines on ALFWorld/ScienceWorld; exact deltas were not yet retrieved in this run.
Judgment: HIGH but pending exact ablation numbers. The novel O-relevant hypothesis is to learn persistent transition/failure rules from *predicted vs observed outcome mismatches*, while gating uncertain foresight rather than injecting every learned heuristic.

## Updated synthesis

- **Freshness has at least three layers**: explicit authoritative ordering (deterministic sequence/timestamp), implicit semantic supersession (model/state consolidation), and behavioral application (whether new state actually changes action). STALE + Supersede + deterministic freshness work show these should not be collapsed into one "memory retrieval" metric.
- **Hierarchical memory needs blame attribution**: HORMA's construction-vs-retrieval failure split suggests O should identify whether missing decision context came from bad durable organization, bad branch selection, or downstream reasoning before changing the Context Kernel.
- **Memory intervention timing is a separate selector**: even with well-organized/retrievable memory, Proactive Memory Agent finds value in deciding whether to reactivate it now. This is distinct from branch selection and may be measured as context-to-action influence.
- **Prediction-error memory may improve planning**: WorldEvolver suggests storing persistent rules specifically from model prediction mismatches, with confidence gating, rather than treating all failed actions as equivalent lessons.

## New candidate matched tests for O

1. **Stale-state triplet**: construct O-local scenarios with old directive/fact -> implicit update -> later action. Score state resolution, stale-premise resistance, and actual action adaptation separately.
2. **Deterministic-authority control**: where sequence/revision defines truth, compare model freshness judgment to deterministic newest-valid selection. Do not spend reasoning tokens on a solved ordering problem.
3. **Hierarchy blame test**: when a needed fact is absent from active context, replay with oracle retrieval and oracle organization separately to classify construction vs selection vs reasoning failure.
4. **Selective intervention test**: same durable memory, compare never/full-bank/always-remind/selective-remind, accounting for extra memory-agent calls and elapsed time.
5. **Prediction-mismatch rule test**: extract candidate transition rules only from forecast-vs-observation errors; test whether confidence-filtered rules improve planning over raw failure summaries.

## Dead ends / scope cautions
- Deterministic max(timestamp/serial) only solves explicit current-value ordering; the same paper shows it does not dominate on broader knowledge-update QA.
- STALE is personalized-memory oriented; use its failure decomposition, not its exact benchmark distribution, as the general lesson.
- HORMA abstract establishes efficiency/performance claims but no official code repository was identified in this pass; reproducibility status remains weaker than ACON/AMA/ECHO/Proactive Memory.
- WorldEvolver exact numerical deltas/ablations remain unresolved; do not promote it above the stronger context-memory candidates until retrieved.
