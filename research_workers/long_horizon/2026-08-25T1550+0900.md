## Newly covered high-value evidence

### 1. ECLoop: block high-consequence coding actions until required repository evidence has actually been observed
Primary: https://arxiv.org/abs/2607.28815
Mechanism: compile structured preconditions from issue + repository structure for action classes such as code modification or patch submission. During execution, track which evidence conditions the trajectory has satisfied. If the agent proposes an action before its required evidence exists, postpone/redirection occurs rather than allowing premature commitment.
Evidence: all 500 SWE-bench Verified instances, two language models × two agent scaffolds. Pass@1 improves by +4.8 to +11.8 percentage points without model retraining or scaffold modification. Ablations report each of three operations contributing distinct value; structured evidence conditions outperform an equivalent natural-language summary. Average token use falls by up to 12.1% because unsupported branches are stopped before consuming more reasoning.
Judgment: VERY HIGH. This is unusually close to an immediately testable O mechanism: for selected irreversible/high-cost development actions, compile a small set of mechanically observable evidence preconditions and enforce them outside the model. It is not a giant workflow; only evidence necessary to justify a specific commitment should gate that commitment.

### 2. AgentForesight: online failure auditing can localize the earliest decisive error using only the current prefix
Primary: https://arxiv.org/abs/2605.08715
Project page: https://zbox1005.github.io/agent-foresight/
Mechanism: at each step, an auditor sees only the trajectory prefix and decides continue vs alarm, with the training target being the earliest decisive failure boundary. A 7B auditor is trained first on adjacent safe/unsafe prefix pairs for risk anticipation, then on what/where/who localization.
Evidence: AFTraj-2K spans Coding, Math, and Agentic domains; external Who&When evaluation included. Primary abstract reports up to +19.9% performance gain over leading proprietary models including GPT-4.1 and DeepSeek-V4-Pro, with 3× lower step-localization error.
Judgment: HIGH, but intervention efficacy must be tested separately from prediction quality. The most useful idea is boundary-localized auditing rather than post-hoc blame after the full long-horizon run is lost.

### 3. Accurate failure prediction can still make the agent much worse when used as an intervention trigger
Primary: https://arxiv.org/abs/2602.03338
Mechanism/evaluation: deploy a binary critic with high offline failure-prediction quality, then measure the causal effect of actually interrupting/intervening rather than assuming a good classifier implies a good controller.
Evidence: an LLM critic with AUROC 0.94 causes a 26 percentage-point performance collapse on one model while having near-zero effect on another. Across tested tasks, intervention ranges from 0 to -26 pp on high-success regimes but gives +2.8 pp on high-failure ALFWorld (p=0.014). A small 50-task pre-deployment pilot correctly predicts whether intervention is likely to help or harm.
Judgment: VERY HIGH evaluator/control-policy evidence. O should never adopt a monitor solely because it predicts failure well. The complete intervention must be evaluated end-to-end, including false alarms, disruption of trajectories that would self-recover, and recovery benefit. This also constrains how AgentForesight/canonical-drift/commitment signals should be used.

### 4. PIVOT: refine executable trajectories using structured plan-execution discrepancies with monotonic acceptance
Primary: https://arxiv.org/abs/2605.11225
Mechanism: PLAN candidate trajectory -> INSPECT by executing and computing structured losses/textual gradients -> EVOLVE trajectory -> VERIFY global constraints. Accept revisions monotonically so refinement cannot knowingly replace a higher-scoring trajectory with a lower-scoring one.
Evidence: on DeepPlanning and GAIA, HITL variant reports up to 94% relative improvement in constraint satisfaction; fully autonomous variant retains substantial gains. Paper reports 3–5× fewer tokens than competing refinement methods.
Judgment: MEDIUM-HIGH. Main O-relevant mechanism is to turn plan-vs-world discrepancies into explicit revision signals and require a measurable acceptance criterion for replacing a current plan, rather than free-form replanning after every setback.

## Cross-paper synthesis update

- **Evidence-gated action is stronger than evidence in context alone.** ECLoop directly supports O's prior context-to-action gap: having repository evidence available is not enough; selected actions can be mechanically conditioned on whether required evidence was actually observed.
- **Prediction and intervention are separate causal objects.** AgentForesight may tell where failure starts; canonical-path monitoring may tell drift risk; commitment detectors may tell rigidity. None should be assumed helpful until the interrupt/recovery policy itself passes matched end-to-end evaluation.
- **Intervention threshold should depend on base failure rate/recoverability.** The same monitor can help a brittle regime and hurt a strong self-recovering one.
- **Structured conditions can outperform natural-language reminders while using fewer tokens.** This converges with deterministic freshness, version bindings, terminal gates, and outcome contracts: use model reasoning where semantics are open-ended, software contracts where the condition is already well defined.

## Candidate matched interventions for O

1. **Evidence-conditioned commitment gate**: choose a narrow action class (merge, publish, destructive edit, evaluation conclusion, irreversible effect). Compile only the evidence predicates necessary for that action and compare enforce-vs-remind-vs-no-gate.
2. **Intervention causal pilot**: before enabling any failure/drift monitor broadly, run a small matched pilot measuring total downstream success with and without intervention, not just AUROC/localization.
3. **Recoverability-aware threshold**: estimate whether flagged trajectories often self-recover if left alone; only intervene where expected recovered failures exceed disrupted would-be successes plus added cost.
4. **Failure-boundary dataset**: label the earliest step where O's future success probability collapses on historical runs, using same-prefix counterfactuals where possible; train/evaluate cheap boundary predictors after obtaining trustworthy labels.
5. **Monotonic plan replacement**: when replanning, require the proposed plan to fix a named plan-execution discrepancy and improve a precommitted executable/constraint score before superseding the prior plan.

## Evidence-scope cautions
- ECLoop's conditions are compiled for coding repositories; conditions that are too broad or speculative would recreate procedural rigidity. Gate only mechanically relevant evidence.
- AgentForesight training labels are based partly on multi-LLM consensus; prediction quality may inherit judge bias, and its abstract does not establish the effect of a particular intervention policy.
- The failure-prediction paper is direct evidence that a good monitor can be harmful; monitor accuracy is not a surrogate for O outcome improvement.
- PIVOT's strongest relative gain uses HITL and is a system-level refinement result; autonomous exact deltas need deeper extraction before prioritizing over cleaner mechanisms.
