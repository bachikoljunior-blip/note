## Newly covered high-value evidence

### 1. FLARE: explicit lookahead + backward value propagation + receding-horizon commitment
Primary: https://arxiv.org/abs/2601.22311
Mechanism: separate planning from ordinary chain-of-thought. Generate short action branches, evaluate/propagate future value backward, commit only to the first action of the best branch, then replan from the new state. This is receding-horizon control rather than committing to a long speculative plan.
Evidence: primary paper reports an 87.8 average across eight evaluated planning environments for FLARE. On ALFWorld, ReAct is 61.3% success, ReAct+Beam 66.7, Reflexion 64.2, RL-greedy 69.4, RL-think 77.4, ReAct+MCTS 73.5, and ReAct+FLARE 77.8. A planning-dynamics diagnostic reports the SingleStep baseline entering the first error at depth 1.6 and recovering only 5.4% of the time; FLARE delays first error to 3.2 and recovers 29.7%, while reducing trap-at-first-action from 55.6% to 17.8%. An efficiency ablation shows the full method at 74.9 Hits@1 using ~21K tokens; a performance-matched unpruned variant reaches 75.4 but uses ~61K tokens.
Judgment: VERY HIGH. This is distinct from better memory: long-horizon reasoning can fail because it commits too early. O should test short lookahead with value comparison and execute only a bounded prefix/first action, then reobserve authoritative state and replan. The mechanism may shift the residual bottleneck to exploration/termination, so failure localization should be rerun after adoption rather than assumed fixed.

### 2. CapLease: rollback/retry safety requires durable semantic action identity, not one-shot token identity
Primary: https://arxiv.org/abs/2608.01710
Mechanism: retries, delegation, replanning, or crash recovery can reissue semantically identical authorized actions under fresh request/token IDs. CapLease maintains monotonic durable state over a canonical semantic action, user confirmation, and remaining budget, using an Issue–Prepare–Commit protocol. A server-side ledger is an alternative stateful enforcement point.
Evidence: paper demonstrates that single-use token/request-ID defenses can still admit duplicate semantically identical effects after reissuance; both CapLease and an equivalently stateful server ledger prevent duplicate admission, and combining this with an idempotent external sink prevents duplicate external effects.
Judgment: VERY HIGH for O recovery. Any checkpoint/rewind/replay design must carry an irreversible-effect ledger keyed by semantic action identity and authority, not merely invocation UUID. Restoring reasoning state without restoring/consulting this ledger can resurrect already-spent authority.

### 3. ACRFence: naive context restore can become a semantic replay attack
Primary: https://arxiv.org/abs/2603.20625
Mechanism: checkpointing an agent before an irreversible effect and restoring it afterward can cause the LLM to re-synthesize a slightly different request for the same real-world action. ACRFence records irreversible effects across checkpoints and enforces replay-or-fork semantics instead of treating restored context as a fresh authorization universe.
Evidence: primary paper establishes the rollback/replay failure class and proposes the fence. Secondary project reporting shows repeated duplicate commits under naive restore, but those exact counts were not primary-table verified in this run.
Judgment: VERY HIGH mechanism relevance. O's exact continuation/checkpoint architecture should explicitly distinguish reversible cognitive state from monotonic external-effect state.

### 4. Verified Tool Calls: verify postconditions before retrying non-atomic tool calls
Primary: https://arxiv.org/abs/2608.02645
Mechanism: after uncertain/non-atomic tool execution, first check the intended postcondition before issuing a retry; use idempotency keys where the environment supports them.
Evidence: primary paper reports significant reduction in duplicate actions while maintaining comparable task success under injected non-atomic failures.
Judgment: HIGH engineering control. This complements CapLease: semantic authorization state prevents duplicate admission, while postcondition verification prevents blind duplicate execution when the first call's outcome is ambiguous.

### 5. DeltaBox: frequent environment checkpoint/rollback can be cheap enough for search/recovery
Primary: https://arxiv.org/abs/2605.22781
Mechanism: differential sandbox snapshots store only changed state and support very fast branch/rollback for agent search.
Evidence: paper reports ~14 ms checkpoint and ~5 ms rollback in its environment, enabling more search nodes under a fixed wall-clock budget. A project page reports end-to-end MCTS improvements, but those exact aggregate values were not primary-verified here; repository currently indicates code artifacts are not yet public.
Judgment: MEDIUM-HIGH. The main decision-relevant point is feasibility: if O needs aligned environment+context rewind or same-prefix counterfactual experiments, environment snapshots need not dominate latency in a suitable sandbox. Reproducibility is currently weaker than open-code systems.

### 6. Agentic Transaction: semantic ACID for multi-step agent work
Primary: https://arxiv.org/abs/2608.13900
Mechanism: model exploration, execution, validation, and skill/tool use as semantic transactions with atomicity, consistency, isolation, and durability; prevent partially completed branches from leaking invalid assumptions/effects into later work.
Evidence: primary abstract reports a 10.6% improvement over compared state-of-the-art coding-agent systems including Claude Code.
Judgment: MEDIUM-HIGH. Broad system-level evidence rather than a clean single-mechanism ablation, but it converges with O's fenced execution/state contracts. Candidate value is strongest for multi-writer/multi-branch work where semantic dependency isolation is more important than raw concurrency.

### 7. Commitment-state detection is not a correctness detector
Primary: https://arxiv.org/abs/2606.22936
Title: "When Agents Commit Too Soon"
Mechanism/evaluation: hidden-state convergence can detect when an agent has behaviorally committed to a plan.
Evidence: commitment detection reaches AUROC as high as 0.97 in some settings (roughly 0.85–0.88 under stricter evaluation). Prompting can reduce behavioral variance by 28%, but accuracy does not improve significantly; a simple output-based baseline can match harder routing settings.
Judgment: HIGH diagnostic caution. O can use commitment as a risk/state signal, but not as evidence that the chosen plan is good. Intervention needs an independent value/freshness/constraint signal, as in FLARE/COTA/canonical-drift monitoring.

### 8. LLM Proposes, Executive Disposes: deterministic belief/commitment state improves instrumentation, not necessarily task ability
Primary: https://arxiv.org/abs/2608.04066
Mechanism: a deterministic executive owns beliefs/commitments and the LLM emits typed proposals; predictions are mechanically checked against observations before state transition.
Evidence: an ablation reportedly changes goal-abandonment behavior while keeping binding errors controlled, but the evaluated ARC-AGI-3 gated task set has zero level completions across 52 runs, so there is no demonstrated task-efficacy gain.
Judgment: MEDIUM as instrumentation architecture, LOW as capability evidence. Useful reminder that clean state machines can improve observability without improving underlying problem-solving.

## Cross-paper synthesis

- **Planning and persistence should be receding-horizon, not irrevocably long-plan based**: FLARE shows explicit lookahead/value propagation plus first-step commitment can materially improve recovery and efficiency.
- **Cognitive rollback must not roll back irreversible authority/effects**: CapLease + ACRFence imply a two-layer checkpoint model: reversible reasoning/environment state where safe, plus monotonic external-effect/authorization state that survives restores.
- **Ambiguous tool outcomes require verify-before-retry**: retries should be conditioned on observed postconditions, not solely on client timeout/error status.
- **Checkpointing can support both recovery and causal evaluation**: fast differential snapshots make same-prefix branches and rewind controls practical in suitable environments.
- **Commitment is a process variable, not a quality score**: detect it to know when an agent is becoming rigid, but use independent evidence to decide whether to interrupt/replan.

## Candidate matched interventions for O

1. **Receding-horizon execute control**: compare current planning against short branch lookahead + value comparison + one-action/bounded-prefix execution + authoritative reobservation/replan.
2. **Monotonic effect ledger**: every irreversible/external action receives a canonical semantic identity, authority/budget record, and terminal/ambiguous outcome that is never erased by context restore.
3. **Verify-before-retry wrapper**: on timeout/unknown result, query/verify the intended postcondition before retrying; only retry when non-occurrence is established or the sink provides idempotent semantics.
4. **Aligned checkpoint experiment**: checkpoint reasoning context + reversible environment state together, but explicitly exclude monotonic effect ledger from rollback.
5. **Commitment-risk trigger**: combine commitment/drift detection with value/freshness checks; do not restart merely because hidden-state convergence is high.
6. **Same-prefix action counterfactuals**: use cheap snapshots to compare alternative actions from identical state and learn intervention/value models without confounding earlier trajectory history.

## Evidence-scope cautions
- FLARE gains are benchmark-specific and include extra planning computation; compare wall-clock and tool cost, not just task success.
- CapLease/ACRFence are primarily correctness/safety mechanisms for duplicated effects; they do not improve reasoning capability directly but can make aggressive recovery safe enough to use.
- Agentic Transaction's 10.6% is a system-level result and should not be attributed to one ACID component without ablations.
- Commitment AUROC does not establish that the committed plan is correct; the paper explicitly shows reduced variance need not improve accuracy.
- DeltaBox's strongest end-to-end numbers remain insufficiently primary-verified and code availability is currently limited.
