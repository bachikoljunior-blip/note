## Newly covered high-value evidence

### A. Selective proactive memory intervention beats passive retrieval/exposure
Primary: https://arxiv.org/abs/2607.08716
Official implementation: https://github.com/yifannnwu/proactive-memory-agent
Date: 2026-07-09
Mechanism: a separate memory agent maintains structured status/knowledge/procedural state from recent trajectory and explicitly decides whether to inject a concise memory-grounded reminder into the unchanged action agent or remain silent. This targets "behavioral state decay": information can still exist but cease to influence action.
Evidence: across Terminal-Bench 2.0 and tau^2-Bench, the primary abstract reports pass@1 gains of +8.3 percentage points and +6.8 points, respectively, across weaker and stronger action agents. Ablations report selective intervention outperforming passive memory-bank exposure, always-on injection, advisor-only guidance, and general retrieval. Official code is public and supports multiple LiteLLM-compatible action/memory model pairs and interrupted-run resume.
Judgment: VERY HIGH. This is more specific than generic retrieval: deciding *whether current behavior needs memory intervention* is itself a policy. For O, a matched intervention could compare silent/no-op vs selective reminders at Root/Execute boundaries rather than merely making historical context reachable.

### B. Full history can be causally worse than selective recent context
Primary: https://arxiv.org/abs/2606.10209
Date: 2026-06-08
Mechanism: prune tool history to the last five tool call/response pairs, optionally with automated summary, instead of retaining full conversation history.
Evidence: 50 hotel-expense tasks, five independent runs, GPT-5; user model held constant for the context-management comparison. Full history: 71.0% complete itemization, 1,480,996 tokens, 14.56 h/benchmark. Last-five pruning: 79.0%, 535,274 tokens, 5.39 h. Pruning + summarization: 91.6% complete, 99.64% average amount itemized, 553,374 tokens, 5.79 h. Paper reports CIs, effect sizes, window sensitivity, failure analysis, and Claude Sonnet 4.5 cross-model evidence.
Judgment: VERY HIGH as an external matched control for O. It directly falsifies any assumption that more accumulated context is monotonically better in verbose tool workflows. Scope is enterprise expense/tool-use; do not generalize the exact window size.

### C. Learn compression rules from compression-caused failures (ACON)
Primary: https://arxiv.org/abs/2510.00615
Official code: https://github.com/microsoft/acon
Latest paper revision: 2026-06-01; ICML 2026
Mechanism: compare trajectories where full context succeeds but compressed context fails; a capable LLM diagnoses what critical state was lost and iteratively updates a natural-language compression guideline. Optional distillation moves the resulting compressor to a smaller model. No action-policy fine-tuning is required for the guideline optimization itself.
Evidence: AppWorld, OfficeBench, multi-objective QA. Primary abstract reports 26-54% lower peak token usage while improving task success over existing compression baselines, and up to 46% performance improvement for smaller long-horizon LMs through reduced context distraction. Official repo contains benchmark pipelines.
Judgment: HIGH. Novel O-relevant mechanism is *failure-driven context-policy learning*: routing/compaction criteria should be revised specifically from cases where omitted context changes downstream success, rather than hand-designed indefinitely.

### D. Causality + active tool retrieval beats similarity-only memory (AMA-Agent)
Primary: https://arxiv.org/abs/2602.22769
Project/code: https://ama-bench.github.io/ and https://github.com/AMA-Bench/AMA-Bench
Accepted ICML 2026 per official repository.
Mechanism: memory includes a causality graph over actions/state changes and tool-augmented retrieval that can query/filter/verify trajectory evidence, rather than only nearest-neighbor similarity retrieval.
Evidence: AMA-Bench includes real agent trajectories plus arbitrarily long synthetic trajectories and evaluates recall, causal inference, state updating, and state abstraction. Primary abstract: AMA-Agent reaches 57.22% average accuracy, +11.16 points over strongest memory baseline. Project page says ablations show both causality graph and tool-augmented retrieval are important.
Judgment: VERY HIGH for O's Event-Ledger/manifest direction. It suggests provenance should encode objective/causal relationships and support active queries, not just semantic similarity. This is a concrete hypothesis for ledger schema/evaluator design.

### E. Query-adaptive composition of multiple memory structures (MESA)
Primary: https://arxiv.org/abs/2608.10108
Date: 2026-08-10
Mechanism: construct five complementary structural views of each long trajectory, then select and fuse a query-specific *subset* of structures. Selection is learned from end-to-end answer feedback with prior-guided search and UCB scheduling. Controlled AMA-Bench analysis finds the best configuration is typically neither one structure nor the full union and varies with query/task.
Evidence: primary abstract reports +8.5% over strongest baseline while using 41% fewer evidence tokens than the all-structure alternative.
Judgment: VERY HIGH and unusually close to O's recursive Skill-in-Skill context routing. Important extension: selection should allow composition of several complementary branches/views when useful; neither single-child routing nor eager all-child materialization should be presumed optimal. Train/evaluate selection on downstream outcomes plus evidence-token cost.

### F. Preserve source addresses through compression to improve both acting and learning (ECHO)
Primary: arXiv 2606.31650 (paper title: "ECHO: Prune to act, trace to learn with selective turn memory in agentic RL")
Mechanism: compress each completed environment turn into a compact record, reconstruct bounded policy context by selecting records, and retain source indices so positive outcome credit can be routed back to historical evidence/selection actions.
Evidence: primary abstract reports 43.4% held-out BrowseComp-Plus accuracy versus GRPO 28.9% and rolling-summary SUPO 36.1%, with fewer turns/lower trajectory volume than SUPO; reports zero-shot generalization to multi-objective QA, code generation, and deep information seeking across dense and MoE backbones.
Judgment: VERY HIGH if O learns from its own trajectories. Provenance is not only an audit feature: source-addressable compact context can support more precise retrospective credit assignment. This is a distinct causal use of provenance worth testing.

### G. Prospective memory remains an independent long-horizon failure mode
Primary: https://arxiv.org/abs/2607.12385
Date: 2026-07-14
Mechanism/evaluation: PM-Bench tests remembering to execute a deferred intention when a future cue/state occurs while continuing unrelated ongoing activity, over simulated seven-day episodes.
Evidence: eight SOTA LLMs x eight agent configurations; best GPT-5.4 configuration reaches only 65.1% F1. No one prospective-memory strategy dominates across models.
Judgment: HIGH diagnostic value. O's pending user input, deferred operations, retry conditions, and safe-boundary actions are prospective-memory problems, not merely retrieval problems. Add a matched cue-trigger/deferred-task evaluation rather than inferring reliability from ordinary memory QA.

### H. Reuse completed planning work via test-time plan caching
Primary: https://arxiv.org/abs/2506.14852
Mechanism: extract structured plan templates from completed agent executions, match semantically similar future tasks, then adapt templates with a lightweight model and current context.
Evidence: primary abstract reports 46.62% average serving-cost reduction across multiple real-world agentic applications while maintaining performance.
Judgment: MEDIUM-HIGH for repeated work families. Potential O use: procedural plan cache keyed by task family, but every reuse must be freshness/world-state validated to avoid replaying stale assumptions. This is primarily efficiency evidence, not proof of better capability.

### I. Make compression explicitly budget-aware (ContextBudget / BACM)
Primary: https://arxiv.org/abs/2604.01664
Official code: https://github.com/yw-0311/ContextBudget
Mechanism: formulate context management as sequential decisions under an explicit context budget; the agent observes remaining budget and decides *when* and *how much* to compress. BACM-RL uses curriculum training across varying budgets.
Evidence: compositional multi-objective QA and long-horizon web browsing; primary abstract reports >1.6x gains over strong baselines in high-complexity settings and resilience as budgets shrink.
Judgment: HIGH for resource-sensitive routing. O should expose context/time/cost budget to the selector rather than optimize routing under one fixed window and assume transfer.

### J. Query-conditioned submodular prompt assembly (PACMS) — promising but evidence needs primary recheck
Paper: arXiv 2606.20047, "PACMS: Submodular Context Selection as a Pluggable Engine for LLM Agents"
Mechanism: pool memory, conversation turns, and tool outputs; choose a token-budgeted subset with query-relevant facility-location/submodular coverage so selected items jointly cover relevant regions while suppressing redundancy.
Evidence status: paper abstract confirms the method and motivation. A full-text mirror reports a 100-question LongMemEval sample where PACMS ties LangChain MMR on evidence-round recall but improves end-to-end QA by +8 to +12 points under two GPT-5-family readers; exact table should be primary-verified before O-feed promotion.
Judgment: MEDIUM-HIGH. Useful deterministic/non-LLM selector baseline against model-reasoned Skill routing. Especially valuable because it optimizes diversity/coverage, not just top-k relevance.

### K. Very aggressive tool-output pruning can preserve evidence locally (Squeez)
Primary: https://arxiv.org/abs/2604.04979
Mechanism: focused query + one tool output -> smallest verbatim evidence block worth showing next; Qwen3.5-2B LoRA selector.
Evidence: 11,477 examples, curated 618-example test; reports 0.86 recall / 0.80 F1 while removing 92% of input tokens and beating much larger zero-shot models on recall.
Judgment: MEDIUM. This is local evidence-selection quality, not end-to-end agent success, but suggests small specialized selectors may cheaply prune verbose tool observations before they ever enter O's decision context.

### L. Procedural memory benefits from diverse traces, but transfer can fail
Primary: https://arxiv.org/abs/2606.23127
Benchmark: AFTER, 382 enterprise tasks, six roles, 22 procedural skills.
Evidence: one refinement round improves aggregate performance by 3.7-6.7 points; skills evolved from diverse multi-model traces reach 73.1% cross-model test accuracy and outperform single-model trace sources. Some skills transfer broadly; others become role-specific and lose effectiveness under transfer.
Judgment: MEDIUM-HIGH. If O turns successful executions into reusable Skills, diversity of source traces and held-out cross-task/cross-model transfer should be explicit gates; local success is insufficient evidence of reusable procedure quality.

### M. Version-controlled session state with mechanically lossless trimming (CMV)
Primary: arXiv 2602.22402
Reference implementation: https://github.com/CosmoNaught/claude-code-cmv
Mechanism: model session state as DAG snapshots/branches/trims; remove mechanical tool/base64/metadata bloat while preserving user and assistant messages verbatim.
Evidence: single-user 76 coding-session case study; mean 20% token reduction, up to 86% in high-overhead sessions; mixed tool sessions average 39% reduction and prompt-caching break-even within 10 turns.
Judgment: MEDIUM as engineering control. It does not establish capability gains, but gives a low-semantic-risk baseline for long-lived parallel session state and branching.

## Cross-paper synthesis / candidate interventions

1. **Behavioral state decay vs storage failure**: Proactive Memory Agent shows a fact can be present/retrievable yet not control the next action. Evaluate whether O's known constraints actually alter actions; selective reminder intervention should be a separate mechanism from retrieval.
2. **Selector must be outcome-calibrated**: ACON learns from compression-caused failures; MESA learns multi-view selection from answer outcomes; ECHO routes credit through selected source IDs. Together they support learning context policy from downstream consequences instead of static heuristics.
3. **Multiple complementary context views**: MESA argues against both single-view routing and full-union context. O's recursive hierarchy should permit selecting several branches/views and compare this to one-branch and eager-all controls.
4. **Causal/provenance structure matters**: AMA-Agent and ECHO independently make provenance structurally useful: causal edges improve memory QA; source IDs enable credit assignment. O's ledger should be evaluated for these functions, not merely persistence/auditability.
5. **Cheap controls remain mandatory**: full context can underperform simple pruning; deterministic masking/submodular selection/small tool-output pruners can rival or beat more semantic methods. Any learned routing claim needs matched cheap baselines.
6. **Budget is part of state**: BACM suggests routing/compaction behavior should condition on remaining context/cost budget, not use one fixed threshold.
7. **Deferred intention reliability is distinct**: PM-Bench should inform an O-specific prospective-memory test covering retries, future cues, pending user input, and safe-boundary actions.

## Evidence-scope cautions
- Enterprise expense workflows, SWE-bench coding, browsing, AMA-Bench memory QA, and Terminal-Bench each exercise different failure modes. Do not promote exact gains across domains without matched O evaluation.
- End-to-end success evidence is stronger for O decisions than standalone compression recall/F1.
- Model/context-manager training can add extra inference/tool cost; compare elapsed time and total token/tool cost, not active-context length alone.
- Preserve raw provenance externally when compression is lossy; "source retained somewhere" still does not guarantee successful recall/intervention.
- Plan/procedural reuse must have freshness/invalidation checks before execution.
