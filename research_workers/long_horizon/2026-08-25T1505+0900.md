## High-value mechanisms found so far

### 1. Agent-initiated context editing with reversible archive (ACM)
Primary: https://arxiv.org/abs/2607.23809
Official code/data/checkpoints: https://github.com/lixiaochuan2020/agentic-context-management
Mechanism: expose `manage_context` and `query_memory` as agent actions; when compressing, offload raw discarded history to external memory and allow on-demand retrieval. Train timing *and restraint* via teacher-guided post-training rather than fixed token thresholds.
Evidence: arXiv abstract reports improvements over ReAct/summary baselines on BrowseComp-Plus, DeepSearchQA, and SWE-Bench Verified; code/data/checkpoints are released. Source-derived Table-2 reproductions report ReAct -> base ACM -> post-trained ACM Pass@1 of 0.570 -> 0.635 -> 0.727 on BrowseComp-Plus, 0.367 -> 0.405 -> 0.425 on DeepSearchQA, and 0.489 -> 0.508 -> 0.530 on SWE-Bench Verified. Peak active context reportedly drops from about 63K to 54K on BrowseComp-Plus while tool calls rise strongly, suggesting context savings can buy additional exploration rather than merely lower cost.
Judgment: HIGH interest for O. Closely matches O's selective context materialization direction, but adds a distinct falsifiable mechanism: model-controlled *when-to-compact / when-not-to-compact* plus reversible raw-event recall. Do not treat the paper's `lossless` label as operationally lossless: the archive preserves bytes, but retrieval can still fail. Table values should be rechecked against the primary paper before final O-feed promotion.

### 2. Simple observation masking can beat LLM summarization
Primary: https://arxiv.org/abs/2508.21433
Official code/data: https://github.com/JetBrains-Research/the-complexity-trap and https://huggingface.co/datasets/JetBrains-Research/the-complexity-trap
Mechanism: keep reasoning/action history and recent turns, but replace older *environment/tool observations* with placeholders instead of asking another LLM to summarize them.
Evidence: SWE-agent on SWE-bench Verified across five model configurations. Abstract reports masking roughly halves cost versus raw context while matching or slightly exceeding summarization. For Qwen3-Coder 480B, solve rate is reported as 54.8% with masking versus 53.8% raw; source analysis reports about 52.7% cost reduction. Authors also report a hybrid masking+summarization method cutting cost another 7% vs masking alone and 11% vs summarization alone, with initial transfer to OpenHands. Raw trajectories/configs are released.
Judgment: VERY HIGH interest as a diagnostic/control. This directly warns against assuming semantically sophisticated compression is better. O's context-routing experiments should include deterministic old-tool-output masking as a cheap matched control, especially because tool observations dominate long coding trajectories. Evidence scope is SWE-agent/SWE-bench-like workflows; do not generalize to all agent domains.

### 3. Constant-size learned state jointly optimized with reasoning (MEM1)
Primary: https://arxiv.org/abs/2506.15841
Official code/checkpoint: https://github.com/OuXianHao/MEM
Mechanism: at every turn update one compact shared internal state from prior memory + new observation, jointly learning memory consolidation and reasoning by RL; memory size remains constant instead of growing with trajectory length.
Evidence: abstract reports MEM1-7B improves performance by 3.5x while using 3.7x less memory than Qwen2.5-14B-Instruct on a 16-objective multi-hop QA task and generalizes beyond the training horizon; evaluations span internal retrieval QA, open-domain web QA, and WebShop. Training/eval code and a model checkpoint are public.
Judgment: HIGH interest as a more aggressive alternative to O's selective tree materialization: replace accumulated explicit history with a learned recurrent sufficient-state candidate. Main risk is irreversible omission and difficult provenance; matched evaluation should test whether explicit reversible context remains superior for correctness-critical work.

### 4. Context management as a policy action trained end-to-end (MemAct/DCPO)
Primary: https://arxiv.org/abs/2510.12635
Official code: https://github.com/ADaM-BJTU/MemAct
Mechanism: treat working-memory edits as explicit actions in the same policy as task actions; Dynamic Context Policy Optimization segments trajectories at non-prefix memory edits so policy-gradient training remains valid.
Evidence: primary abstract states joint optimization reduces compute and improves task performance; code is released. Secondary research notes report ~51% average context reduction and strong model-scale comparisons, but these exact quantitative claims are NOT yet primary-verified in this run.
Judgment: MEDIUM-HIGH. Distinct from giving O context tools by prompt alone: learn the curation policy. Relevant if O's heuristic/model-reasoned routing shows benefits but unreliable timing. Expensive to test and likely downstream of simpler harness-level controls.

### 5. Context folding / subtrajectory abstraction
Primary: https://arxiv.org/abs/2510.11967
Mechanism: branch into a subtrajectory for a subtask, then `fold` it on completion so detailed intermediate steps disappear from active context while a concise result remains; FoldGRPO trains both decomposition and folding.
Evidence: abstract reports matching or beating ReAct on deep-research and SWE tasks with ~10x smaller active context and beating summarization-based management.
Judgment: HIGH conceptual relevance. This resembles O's Skill-in-Skill hierarchy but introduces an explicit *lifecycle boundary*: child-subtask traces can be folded when resolved. Important hypothesis: retaining a typed completion artifact + raw provenance may outperform indefinite child-context reachability.

### 6. Periodic restartable reasoning state (ReSum)
Primary: https://arxiv.org/abs/2509.13313
Official implementation: https://github.com/Alibaba-NLP/DeepResearch/tree/main/WebAgent/WebResummer
Mechanism: periodically summarize growing web-agent history into a compact restartable reasoning state; ReSum-GRPO trains summary-conditioned continuation using segmented trajectories and advantage broadcasting.
Evidence: abstract reports +4.5 percentage points average over ReAct across three benchmarks; up to +8.2 points after training. Official repo reports WebResummer-30B-A3B 33.3% Pass@1 BrowseComp-zh and 18.3% BrowseComp-en with 1K training samples.
Judgment: MEDIUM. Stronger than append-only context, but unlike ACM it discards source-level detail unless separately archived. Useful baseline, not preferred architecture by default.

## Important negative/diagnostic evidence
- LongMINT (https://arxiv.org/abs/2605.18565): 15.6K QA pairs, average 138.8K-token contexts, up to 1.8M; seven representative long-context/RAG/memory systems average only 27.9% accuracy. Paper attributes major failure to retrieval and memory construction, especially under repeated updates/interference. This argues that persistence alone is not enough; revision/interference handling must be evaluated explicitly.
- The Complexity Trap shows sophisticated LLM summaries are not automatically superior to deterministic masking; context-management evaluation needs cheap controls and end-to-end success/cost, not compression quality alone.
- ACM appears to help models already willing/able to sustain exploration; it should not be assumed to create long-horizon persistence in a policy that terminates early.

## Dead ends / cautions
- Avoid treating vendor/single-author memory-system benchmark claims as general evidence without matched ablations.
- Avoid equating physical preservation of archived raw text with successful future recall.
- Avoid comparing headline accuracy across different model scales/harnesses as causal evidence for the context mechanism.
