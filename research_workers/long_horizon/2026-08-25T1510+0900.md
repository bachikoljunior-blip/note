## Newly covered decision-relevant evidence

### 1. MemoryArena: memory QA saturation does not imply action-useful persistence
Primary: https://arxiv.org/abs/2602.16313
Official code: https://github.com/ZexueHe/MemoryArena
Mechanism/evaluation: evaluates memory inside multi-session, interdependent agent-environment loops rather than isolated conversational recall. Domains include shopping, group travel/planning, progressive search, and formal reasoning; later decisions depend on earlier observations/actions.
Evidence: primary abstract reports agents that are near-saturated on LoCoMo still perform poorly in these interactive settings. Official repository supports long-context, Letta, Mirix, Mem0, ReasoningBank, BM25/RAG/GraphRAG/MemoRAG backends.
Judgment: VERY HIGH evaluation relevance. O should not infer memory competence from retrieval/QA alone; context mechanisms need downstream task success under interdependent multi-session state.

### 2. MiRA / subgoal-driven reasoning: explicit active subgoals can sharply improve long-horizon execution
Primary: https://arxiv.org/abs/2603.19685
Mechanism: dynamically decompose tasks at inference time into current subgoals and use milestone-based intermediate reward rather than relying only on terminal success.
Evidence: primary abstract reports roughly +10 percentage-point absolute WebArena-Lite success for Gemini under subgoal-driven inference. For learned agents, MiRA raises Gemma3-12B from 6.4% to 43.0% WebArena-Lite success; paper compares WebRL at 38.4%. A separate prior-work number reported elsewhere is higher, so do not interpret the paper's framing as a universal SOTA claim.
Judgment: VERY HIGH. Long-horizon O execution should expose one explicit current subgoal/milestone with completion evidence rather than only a global objective plus unconstrained continuation. This is separate from memory compression.

### 3. BEACON: preserve local credit for completed trajectory segments
Primary: https://arxiv.org/abs/2605.06078
Official code: https://github.com/ZJU-REAL/BEACON
Venue: ICML 2026
Mechanism: detect meaningful milestones, partition trajectories into segments, apply temporal reward shaping and dual-scale advantages so terminal failure does not erase credit for earlier correct segments.
Evidence: primary paper reports 92.9% success on long ALFWorld tasks versus 53.5% for GRPO, and effective-sample utilization increasing from 23.7% to 82.0%. Official project reports the relative advantage increasing with horizon length.
Judgment: VERY HIGH for O learning/evaluation. When a long O unit fails late, earlier verified-good substeps should remain positive evidence. This can prevent repeated relearning and overgeneralized negative updates.

### 4. Hierarchical planning helps, but low-level execution can remain the dominant bottleneck
Primary: ACL 2026 paper, "Why Do LLM-based Web Agents Fail? A Systematic Failure Analysis with Hierarchical Planning"
Official code: https://github.com/Ziyu-Yao-NLP-Lab/llm-hierarchical-web-agents
Mechanism/evaluation: separates high-level planning, low-level action execution, and replanning; compares natural-language and PDDL-like plans.
Evidence: paper finds symbolic/PDDL plans are more concise and goal-directed, but low-level execution/grounding remains the dominant failure source.
Judgment: HIGH diagnostic. O should evaluate planning quality, context quality, and execution fidelity independently. Better decomposition is not sufficient evidence of end-to-end progress if tool execution remains the bottleneck.

### 5. MemexRL: bounded active context with stable external addresses and learned read/write policy
Primary: https://arxiv.org/abs/2603.04257
Official code: https://github.com/Accenture/MemexRL
Mechanism: keep compact structured summaries and stable indices inside active context while full-fidelity interactions live externally; train the agent to decide what to write, read, index, and dereference under a budget.
Evidence: primary abstract reports improved task success with substantially smaller working context across long-horizon tasks.
Judgment: MEDIUM-HIGH. Some overlap with ACM/HORMA/ECHO, but stable addresses are a useful implementation detail: compact context can remain auditably reversible without copying raw history back into every turn.

### 6. YC-Bench: persistent strategy memory and bounded commitments matter over hundreds of turns
Primary: https://arxiv.org/abs/2604.01212
Official code: https://github.com/collinear-ai/yc-bench
Mechanism/evaluation: simulated startup operation for a year over hundreds of turns with partial observability, compounding consequences, adversarial clients, and cross-truncation memory via a persistent scratchpad.
Evidence: 12 models x 3 seeds; only three consistently finish above the initial $200K. Paper reports Claude Opus 4.6 averaging ~$1.27M and GLM-5 ~$1.21M at much lower inference cost. Persistent scratchpad quality is reported as the strongest predictor of success; adversarial-client detection explains a large fraction of bankruptcies, and over-parallelizing commitments is a recurrent failure mode.
Judgment: HIGH as a long-horizon strategy diagnostic. O's parallelism should be bounded by coordination/state-tracking capacity, and a compact persistent strategy/state summary may matter more than raw transcript retention.

### 7. InfiAgent: fixed recent-action window + persistent file state can keep context strictly bounded
Primary: https://arxiv.org/abs/2601.03204
Official code: https://github.com/ChenglinPoly/infiAgent
Mechanism: persistent file-centric state snapshot plus fixed recent action window; no task-specific fine-tuning required.
Evidence: primary paper reports competitive long-horizon performance for an open 20B model and higher coverage on deep-research/large literature-review tasks while keeping active context bounded.
Judgment: MEDIUM-HIGH as a simple systems baseline against recursive model-driven routing.

### 8. Reliability Science: long-horizon reliability decays differently from short-horizon capability
Primary: https://arxiv.org/abs/2603.29231
Mechanism/evaluation: 10 open-source models, 23,392 episodes, 396 tasks, multiple domains and duration buckets; studies reliability decay, meltdowns, decomposition, and memory scaffolds.
Evidence: capability rankings change with horizon, some frontier models exhibit catastrophic long-horizon meltdowns (paper reports rates up to ~19% in some settings), and the particular episodic-memory scaffold tested is neutral for four models and harmful for six rather than reliably improving long-horizon goal-directed success. The paper identifies task decomposition as a stronger intervention and discusses checkpoint/context reset after detected meltdown.
Judgment: VERY HIGH evaluation/recovery relevance. Do not generalize the negative memory result to all memory systems: it is evidence against a specific naive scaffold. O should measure horizon-conditioned reliability and use detected behavioral meltdowns as a trigger for checkpoint/recovery or context reset rather than blindly continuing.

## Cross-paper synthesis

- **Long-horizon failure is not one thing**: MemoryArena separates memory usefulness from recall; hierarchical-web work separates planning from execution; STALE separates current-state recognition from behavioral adaptation; Reliability Science separates capability from horizon-conditioned reliability.
- **Explicit milestones/subgoals are high-value**: MiRA and BEACON independently show benefits from exposing intermediate structure and credit. This suggests O's logical work units should have machine-checkable milestone evidence, not only terminal success/failure.
- **Recovery should be event-driven**: long-horizon meltdowns can justify restoring a clean checkpoint/context rather than preserving a contaminated trajectory indefinitely.
- **Parallelism can itself create long-horizon failure**: YC-Bench's over-commitment pattern supports treating number of simultaneous commitments as a controlled resource, not maximizing it unconditionally.
- **Persistent state should be compact but reversible**: MemexRL/InfiAgent provide simpler external-state controls against more complex learned hierarchy/routing systems.

## New candidate matched interventions for O

1. **Active-subgoal state**: require each Execute cycle to expose exactly one current subgoal or a small bounded set, with explicit completion/failure evidence before replanning.
2. **Segment credit ledger**: preserve verified-good substeps even when a later step fails; prevent candidate/family rejection based on terminal outcome alone.
3. **Horizon reliability curve**: replay matched task families at increasing duration/context/tool-call count and measure success decay, stuck states, repeated actions, and meltdown probability.
4. **Recovery trigger**: on detected meltdown (repetition, contradiction, stale-plan persistence, no-progress loop), restore authoritative durable state into a fresh reasoning context and compare continuation success against uninterrupted execution.
5. **Planning/execution split diagnosis**: use oracle high-level plan and oracle low-level action controls separately to locate the limiting layer.
6. **Parallel-commitment budget**: evaluate whether fewer concurrent unresolved subgoals improve completion time/reliability despite lower nominal parallelism.

## Evidence-scope cautions
- MiRA/BEACON improvements come from web/embodied benchmark regimes and training setups; test mechanisms, not headline percentages, in O.
- YC-Bench is a simulated business environment; use its failure patterns as hypotheses rather than direct AGI evidence.
- Reliability Science's negative memory result applies to its particular episodic-memory scaffold; it does not contradict stronger structured/selective-memory results such as Proactive Memory, ACON, HORMA, AMA, or MESA.
- InfiAgent and MemexRL system-level gains do not isolate each memory component causally.
