# ユーザー操作依頼前の自動化ゲート

## 目的

ユーザーへ「これをしてください」と依頼する前に、assistant側で代替実行・自動化・半自動化・一括化・事前入力を先に終わらせる。

この文書は提案ではなく、`scripts/check_user_action_gate.py` が検査する運用規則である。

## 評価順序

候補となるユーザー操作ごとに、次の順で評価する。

1. **直接実行**
   - 接続済みツールで読み書きできるか。
   - 既に与えられた権限で安全に実行できるか。

2. **公式インターフェースによる自動化**
   - 公式API、Webhook、GitHub Actions、Cron、メール・カレンダー連携で実行できるか。
   - 前払い・月額費用0円、または承認済み予算内か。

3. **半自動化**
   - Web Share API、事前入力リンク、クリップボード、iPhoneショートカット、共有シートで手数を減らせるか。
   - 本文、URL、価格、時刻、検証を事前に埋められるか。

4. **一括化**
   - 5手を1〜3手へまとめられないか。
   - 同じ情報を複数画面へ転記させずに済むか。

5. **自動検証**
   - URL、価格、本文、ファイル、公開状態、時刻をassistant側で確認できるか。
   - 操作結果を自動または半自動で記録できるか。

6. **本人操作として残す判断**
   - 認証、本人確認、契約、決済、最終公開、公開先の最終選択など、本人意思が必要か。
   - その理由を具体的に記録する。

## 必須記録

`state/user_action_requests.json` の各依頼には、最低限次を含める。

- `id`
- `description`
- `status`
- `automation_review.completed`
- 6分類すべての評価結果
- 実装済みの自動化
- 実装しなかった理由
- 残存するユーザー操作
- 残存手数
- 本人操作でなければならない理由
- 失敗時の代替手段

## 禁止される依頼

- 「この環境からできない」だけを理由にした手動依頼
- コピー、URL確認、時刻記録、定型文生成をユーザーへ丸投げすること
- 自動化評価前に5手以上の手順を提示すること
- 認証情報やCookieを平文で送らせること
- 公式手段を確認せず、壊れやすい非公式自動化を優先すること
- 高額または継続課金の環境を、無料・格安の代替評価前に要求すること

## 例外

緊急停止、安全確保、法的同意、支払い確定など、ユーザーの即時判断が必要な場合は先に止めてもよい。その場合も、なぜ自動化できないかを後から記録する。

## 合格条件

- すべての未完了ユーザー操作に自動化評価がある。
- 残存手数が3以下、または例外理由がある。
- 実装済みと記載した自動化に検証証跡がある。
- `state/current.json` のユーザー作業と、`state/user_action_requests.json` の依頼IDが一致する。
- `python scripts/check_user_action_gate.py` が終了コード0で完了する。

## 外部変更・承認の事前検査

自動レビューや本人承認の対象になり得る操作では、上記6分類に加えて次を必須とする。

1. 読み取りで既存リソース、重複、現在の公開状態を確認する。
2. 外部変更なしで完了できる実装、テスト、法定・安全表示、復旧手段を先に完了する。
3. 最小かつ可逆な1操作へ集約し、同時に複数の承認要求を発生させない。
4. 拒否または期限切れ後は、意味的に同じ操作を別経路で反復しない。対象だけを保留し、他の収益寄与作業を続ける。
5. 保留時は、現在の安全状態、既存リソースID、未送信の秘密情報、次の単一操作、再開条件を正本へ保存する。
6. 承認後は実行直前の再読、冪等性検査、1回の実行、読み取りによる事後検証を行う。

自動レビュー画面がターンを終了させ得ることを、プロジェクト全体の停止理由にしない。
