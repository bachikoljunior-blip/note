分類: AI補助方針。ユーザー恒久指示ではない。恒久指示の正本は `OPERATIONS/CORE_DIRECTIVE.md`。

作成 2026-08-08。正本は `state/watchdogs.json`、検査は `scripts/check_watchdogs.py`。

| | 何のためか | 落とす条件 |
| --- | --- | --- |

| `state/watchdogs.json` | **目を離してはいけない数字** | 古い／更新経路がない／代用品を正本にしている |

改善しなくてよいが、古くなったり壊れたりしたら気づかねばならないものは、ここ。

## なぜ作るか

2026-08-08 のオーナーの指摘。

> 使用量とか定期的に監視しないとダメじゃない？そういう抜けが他にもないように設計してよ

そのとき、次の3つが**同時に**成立していた。ここが肝心で、
「監視が無かった」のではない。

1. 使用量は毎時集められていた ——— **監視は在った**
2. しかし**古さの判定が壊れていた**。`show-usage.mjs` は経過時間だけを見ており、
   セッション枠（5時間）は上限（150分）より短いので、**リセット済みの枠の残量が
   現在値として印字された**。2026-08-08 10:10Z に「37% left (resets 09:20Z)」
3. そして**当てにならない代用品が2つのリポジトリに在った**。
   `Simple` の `promo/youtube/usage.mjs` と `youtube` の `scripts/usage.py`。
   どちらもローカルのトランスクリプトからトークン数を数えて%に換算しているだけで、
   実メーターを見ていない。オーナーは「なんの当てにもならない」と明言した

**「監視が在る」と「監視が効いている」は別のことだ、というのが今回の教訓。**
だから登録簿は、監視の存在ではなく次の4つを要求する。

## 各項目が持つもの

| 欄 | 意味 |
| --- | --- |
| `what` | 何を見張るか |
| `source_of_truth` | **正本**。ファイル名かAPIのエンドポイントまで書く |
| `read_with` | 実際に読むコマンド |
| `max_age_hours` | これを超えたら測り直す |
| `refresh_without_owner` | **オーナー操作なしで新しくする方法。無ければ検査が落ちる** |
| `consumer` | 誰が読んで動くか |
| `not_a_source` | **当てにならないと分かっている代用品と、その理由** |

### `refresh_without_owner` が必須な理由

A1: 「私側への指示をしてもいいですが、それを私が必ず読むとは限りません」。

**オーナーが動かないと新しくできない監視は、監視ではない。**
`scripts/check_watchdogs.py` は、この欄に「オーナー」「本人」等が入っていると落とす。

### `not_a_source` が必須な理由

消すだけでは足りない。**なぜ駄目かを書かないと、次の周で復活する。**
実際、`usage.mjs` は自分のヘッダーに「2つの観測が約10倍食い違う」「正しいレートは
存在しない」と正直に書いてあった。**それでも読まれ得る場所に在った。**

検査は、`not_a_source` に挙げたものが `source_of_truth` に混ざっていたら落とす。

## 古さの判定について

**経過時間だけで古さを判定しないこと。**
窓に自分のリセット時刻があるなら、それを現在時刻と比べる。
リセット済みの枠の残量は、ファイルがどれだけ新しくても無効。

しかもこの向きの誤りは危ない。**実際より少なく見える**ので、
本当は使えたはずの作業を「残量が無い」と言って見送らせる。
